이 매뉴얼은 **Infra Query Agent**를 쓰는 분을 위한 안내서입니다. 서버·성능·알람 데이터를 한국어로 물어보면 답을 표로 돌려주고, Excel·Word 양식도 채워 줍니다.

- 처음이라면 [1장 시작하기](#ch-1)와 [3장 질의하기](#ch-3)부터 보세요.
- 각 기능은 **사례 → 사용 방법 → 화면 요소 → 주의** 순서로 설명합니다. 사례의 「입력」은 그대로 복사해 쓸 수 있습니다.
- 사례의 결과는 테스트용 샌드박스 데이터로 실제로 실행한 결과입니다. 운영 환경에서는 서버 이름과 숫자가 다르게 나옵니다.
- 관리자 기능은 [관리자 매뉴얼](/manual/admin)에 있습니다.

## 1. 시작하기

계정을 만들고 로그인해서 첫 화면을 둘러봅니다.

### U-01
::: what
이 시스템은 인프라 관측 데이터를 **자연어로 조회**하는 도구입니다. 할 수 있는 일은 크게 네 가지입니다.

| 할 수 있는 일 | 예 | 설명 장 |
|---|---|---|
| 서버 구성·성능·알람 조회 | 「2026년 6월 메모리 사용률 평균 상위 3대」 | [3장](#ch-3) |
| 양식(Excel·Word) 채우기 | 서버 목록 양식을 올리고 「채워줘」 | [6장](#ch-6) |
| 실시간 알람 받기 | 알람 카드에서 바로 조회 | [9장](#ch-9) |
| 알람이 왜 걸러졌는지 보기 | 노이즈 관제 화면 | [10장](#ch-10) |

조회만 합니다. 데이터를 바꾸거나 지우는 요청은 실행하지 않습니다.
:::
::: how
1. 로그인하면 질의응답 화면이 열립니다.
2. 아래 입력창에 궁금한 것을 한국어로 적고 **Enter**를 누르세요.
3. 답이 표로 나오면 그대로 읽거나 CSV로 내려받습니다.
:::
::: ui main-welcome 첫 화면
1. 예시 질문 버튼 — 누르면 입력창에 예시 문장이 채워집니다([U-17](#u-17)).
2. 「❓ 사용법」 — 지금 조회할 수 있는 데이터를 안내받습니다([U-18](#u-18)).
3. 입력창 — 여기에 질문을 적습니다.
:::
::: caution
- 답은 조회 시점에 수집된 데이터를 기준으로 합니다. 성능 통계는 시간·일·월 단위로 모아 둔 값이라 「지금 이 순간」 값과 다를 수 있습니다.
- 조회할 수 있는 DB는 관리자가 정해 줍니다. 원하는 데이터가 나오지 않으면 관리자에게 권한을 확인하세요.
:::
::: related

### U-02
::: what

   - 사용자 ID: 영문·숫자·밑줄(_)로 3~50자

:::
::: ui register 회원가입 화면

4. 부서
5. 가입하기

- 비밀번호를 잊으면 관리자에게 초기화를 요청하세요. 화면에서 직접 바꾸는 기능은 없습니다.

## 3. 질의하기

한국어로 질문하고 답을 받는 방법입니다. 이 장의 사례가 이 시스템의 핵심 사용법입니다.

### U-11
::: what
입력창에 질문을 적고 보내면, 시스템이 알맞은 데이터를 찾아 조회하고 답을 표로 정리합니다.
:::
::: case Q-SERVER-LIST
포인트: 무엇을(「서버」) + 어떤 항목을(「호스트명, OS종류, 벤더」) 순서로 적으면 가장 잘 알아듣습니다. 항목 이름은 화면에 보이는 말 그대로 써도 됩니다.
바꿔 보기: 전체 서버의 IP와 OS 버전을 보여줘 | 서버 수를 조회해줘
:::
::: how
1. 입력창을 누르고 질문을 적으세요.
2. **Enter**를 누르거나 오른쪽 전송 버튼(▷)을 누르세요. 줄을 바꾸려면 **Shift+Enter**입니다.
3. 답이 나올 때까지 진행 상황이 표시됩니다([U-14](#u-14)).
:::
::: ui query-input 입력줄
1. 질문 입력창
2. 파일 첨부([6장](#ch-6))
3. 전송
4. 조회 대상 칩([U-24](#u-24))
5. 단축키 안내
:::
::: caution
- 질문 하나에 한 가지를 묻는 것이 가장 정확합니다. 여러 가지를 묻는 복합 질문도 되지만 시간이 더 걸립니다.
- 조회 결과는 기본으로 최대 1,000행까지 가져옵니다.
:::
::: related
- [U-19 질문 잘 쓰는 법](#u-19)
- [U-20 결과 읽기](#u-20)
:::

### U-12
::: what
전에 보낸 질문을 다시 불러와 고쳐 쓸 수 있습니다.
:::
::: how
1. 커서가 입력창 첫 줄에 있을 때 **↑** 키를 누르면 바로 전 질문이 채워집니다. 쓰던 문장은 따로 기억해 두었다가 **↓** 끝에서 돌려줍니다.
2. 더 누르면 더 이전 질문으로, **↓** 키는 다시 최근 쪽으로 이동합니다.
3. 고친 뒤 **Enter**로 보내세요.
:::
::: ui -
화면 캡처가 없습니다. 입력창 아래 안내 「↑↓ 이전 질의」가 이 기능입니다([U-11](#u-11) 그림 5번).
:::
::: caution
- 불러오는 목록은 이 브라우저에 저장된 질문입니다([U-36](#u-36)).
:::
::: related
- [U-36 질의 이력 — 질의](#u-36)

### U-14
::: what
답이 완성되기 전에도 무엇을 하고 있는지 보입니다. 오래 걸리는 질문도 멈춘 것인지 진행 중인지 알 수 있습니다.
:::
::: case Q-SERVER-LIST
포인트: 답의 글자가 먼저 흘러나오고, 아래에 단계 칩(입력 분석 → 에이전트 실행 → 스키마 탐색 → SQL 생성 → 쿼리 실행 → 결과 정리)과 경과 시간이 보입니다.
:::
::: how
1. 질문을 보내면 답 말풍선이 바로 생기고 글자가 조금씩 채워집니다.
2. 말풍선 아래 단계 칩에서 지금 단계가 강조됩니다.
3. 완료되면 칩이 사라지고 결과 정보가 표시됩니다.
:::
::: ui query-streaming 답을 만드는 중
1. 답 말풍선 — 글자와 단계 칩, 경과 시간
2. 응답 중단(■)
3. 처리 현황 패널 — 단계별 상세

### U-19
::: what
같은 내용도 질문을 어떻게 쓰느냐에 따라 결과가 달라집니다. 아래 사례로 잘 쓰는 법과 잘 안 되는 경우를 익히세요.

**잘 쓰는 법 다섯 가지**

1. **대상을 분명히** — 「서버」, 「cocm-hdkapp01 서버」, 「김포 서버」
2. **항목을 나열** — 「OS 종류, IP, 메모리 용량」
3. **기간은 구체적으로** — 「2026년 5월」, 「지난 30일」. 「이번 달」은 월초에는 데이터가 거의 없습니다.
4. **순서·개수를 명시** — 「큰 순서로 상위 3대」
5. **조건은 숫자로** — 「메모리 이용률 90% 초과」, 「논리코어 8개 이상」
:::
::: case Q-TOP-MEMORY
포인트: 「높은 순서로 상위 3대」처럼 정렬과 개수를 함께 쓰면 그 수만큼만 가져옵니다. 기준 월(「2026년 6월」)도 함께 적었습니다.
바꿔 보기: 2026년 6월 CPU 사용률 평균이 낮은 서버 5대 | 논리코어가 많은 순서로 상위 5대 서버
:::
::: case Q-SERVER-DETAIL
포인트: 서버 이름(호스트명)을 정확히 쓰면 그 서버 한 대의 여러 항목을 한 번에 봅니다.
:::
::: case Q-CORE-FILTER
포인트: 조건(「8개 이상」) · 보여줄 항목 · 정렬을 한 문장에 담았습니다.
:::
::: case Q-CPU-MONTH
포인트: 성능 통계는 「2026년 5월」처럼 기준 월을 적어야 정확합니다. 데이터가 있는 달만 결과가 나옵니다.
바꿔 보기: 지난달 서버별 메모리 사용률 평균 상위 10대 | 2026년 1월부터 6월까지 메모리 사용률 최대값
:::
::: case Q-MEM-OVER
포인트: 「초과한 적이 있는」처럼 기간 중 한 번이라도 조건을 넘은 서버를 찾습니다. 요약 문장의 「2026년 9월 기준」은 조회한 시점을 말한 것이고, 표의 95.2%는 월 통계의 최댓값입니다. **숫자는 요약 문장보다 표를 기준으로 읽으세요.**
:::
::: case Q-ALARM-HISTORY
포인트: 「최근 발생 순으로 20건」처럼 정렬과 건수를 주면 목록이 짧고 읽기 좋습니다. 요약 문장이 심각도를 「3(중요)·2(주의)」로 불렀지만 표준 표기는 **3=심각, 2=경고**입니다. 설명 문장의 이름보다 표의 숫자를 기준으로 보세요.
:::
::: case Q-COMPOSITE
포인트: 알람 데이터와 서버 구성 데이터를 이어 붙이는 **복합 질문**입니다. 시스템이 두 단계로 나눠 처리합니다.
:::
::: case Q-GENERAL
포인트: 데이터 조회가 아닌 일반 지식 질문에도 답합니다. 이런 답은 DB를 조회하지 않은 **참고용 설명**이라 용어가 부정확할 수 있습니다(이 사례에서는 High Availability를 「고용량」이라고 옮겼습니다).
:::
::: case Q-BAD-DELETE
포인트: **잘 안 되는 예** — 데이터를 바꾸거나 지우는 요청은 실행하지 않습니다. 이 시스템은 조회 전용입니다. 다만 현재 버전은 이 사례처럼 거절 이유를 말하지 않고 「데이터가 없다」고 답할 수 있습니다. 데이터가 지워진 것이 아닙니다.
:::
::: case Q-BAD-UPTIME
포인트: **잘 안 되는 예** — 「가동률」은 모니터링 데이터에 집계되지 않는 지표입니다. 시스템이 그 이유를 설명하고 대신 쓸 질문을 제안합니다. 제안된 문장을 그대로 보내면 됩니다.
바꿔 보기: 가용 상태가 비정상인 서버 목록 보여줘 | 지난달 CPU 사용률이 낮은 서버 순으로 보여줘
:::
::: case Q-BAD-TYPO
포인트: **잘 안 되는 예** — 서버 이름을 틀리게 쓰면(`hdkapp1` ↔ `hdkapp01`) 결과가 없습니다. 현재 버전은 이때 「SQL 문법 오류」 같은 내부 문구를 함께 보여 줄 수 있습니다. 이름은 결과 표에서 복사해 쓰세요.
바꿔 보기: cocm-hdkapp01 서버의 OS
:::
::: how
1. 위 다섯 가지를 떠올리며 질문을 적으세요.
2. 결과가 기대와 다르면 [처리 현황](#u-15)에서 어떻게 이해했는지 보고, 질문을 고쳐 다시 보내세요.
3. 이어서 좁혀 가려면 「그 서버들의 ~」처럼 이어서 물으세요([U-34](#u-34)).
:::
::: ui answer-table 표로 나온 답
결과 표 아래의 ROWS(건수)·TIME(걸린 시간)을 확인하세요([U-20](#u-20)).
:::
::: caution
- 데이터에 없는 개념(가동률, 응답 시간, 패킷 손실률 등)은 정확히 답할 수 없습니다. 답의 설명 문장을 꼭 읽으세요.

- 결과 끝에 「컬럼 설명 미등록」 같은 **관리자 안내**가 붙을 수 있습니다. 조회는 정상이며, 관리자가 DB 설명을 등록하면 사라집니다.

## 5. 조회 범위와 역질문

어느 DB·존을 조회할지 정하는 방법입니다.

### U-24
::: what
입력줄 위의 **조회 대상** 칩은 이 대화가 어느 DB를 조회하고 있는지 보여 줍니다. 한 번 조회한 DB는 이어지는 질문에서 계속 쓰입니다(「승계 중」).
:::
::: how
1. 첫 질문 전에는 「존 미지정 — 첫 질의처럼 확인」으로 표시됩니다.
2. 조회하면 칩에 DB 이름이 나오고 「승계 중」이 붙습니다.
3. **▾**를 누르면 조회 대상을 직접 고를 수 있습니다.
4. **×**를 누르면 승계를 풀고 다음 질문을 처음처럼 판단합니다.
:::
::: ui scope-chip 조회 대상 고르기
1. 조회 대상 칩 — 누르면 선택 창이 열립니다
2. 선택 창 — 조회할 DB·존을 고릅니다

한 번 조회한 뒤에는 칩 오른쪽에 **×**(승계 해제)가 생깁니다. 화면은 테스트 환경의 존 구성입니다.
:::
::: caution
- 다른 지역 서버를 물을 때 이전 대상이 승계돼 결과가 없으면 **×**로 풀고 다시 물으세요.
- 권한이 없는 DB는 선택지에 나오지 않습니다.
:::
::: related
- [U-25 존 선택 역질문](#u-25)
- [U-34 이어서 묻기](#u-34)
:::

### U-25
::: what
존(은행존·공동존)을 적지 않고 전체를 묻는 대량 조회는, 어느 존을 조회할지 먼저 되묻습니다. 여러 존을 한 번에 조회하면 오래 걸리고 결과가 섞이기 때문입니다.
:::
::: how
1. 예: 「ㅇㅇ존 서버 CPU 사용률」처럼 존을 정하지 않고 보내면, 답 말풍선에 존 선택 상자가 나옵니다(조회는 아직 하지 않습니다).
2. 조회할 존을 체크하세요. 여러 개를 고르면 존마다 차례로 조회합니다.
3. **선택한 존으로 조회**를 누르세요.
4. 존과 상관없이 전체를 보려면 **건너뛰고 전체 조회**를 누르세요.
:::
::: ui zone-clarify 존 선택(화면 예시 — 테스트 환경의 존 구성)
1. 존 선택 상자
2. 선택한 존으로 조회

질문에 따라 **건너뛰고 전체 조회** 버튼이 함께 나올 수 있습니다(존을 고르지 않고 전체를 조회).
:::
::: caution
- 기본 설정에서는 은행존과 공동존을 함께 고를 수 있습니다. 관리자가 존 그룹 상호배타(`ZONE_GROUP_EXCLUSIVE`)를 켠 환경에서는 한 그룹(은행존 또는 공동존) 안에서만 고를 수 있으니, 둘 다 필요하면 따로 두 번 물으세요.
- 질문에 「김포」, 「여의도」, 「은행존」처럼 위치를 적으면 되묻지 않고 바로 조회합니다.
- 선택지에는 **내 계정이 조회할 수 있는 DB가 속한 존만** 나옵니다. 원하는 존이 없으면 관리자에게 권한을 요청하세요.
- 이 사례 화면은 테스트 환경에서 찍었습니다. 선택지는 설치 환경의 존 구성에 따라 다릅니다.
:::

3. 검색창으로 대화를 찾습니다.
4. 항목의 삭제 버튼으로 하나씩, **모두 지우기**로 전부 지웁니다.
5. 지난 대화를 보다가 새 주제로 묻고 싶으면 **+ 새 대화**를 누르세요. 화면이 비워지고 다음 질문부터 새 대화로 시작합니다. 이력을 접어 두었을 때는 왼쪽 가장자리의 `+` 아이콘이 같은 버튼입니다.
:::
::: ui history-threads 질의 이력 — 대화
1. 대화 모드
2. 검색
3. 모두 지우기
4. 대화 목록

## 8. 채팅으로 하는 일

화면에 버튼이 없고, 입력창에 문장으로 요청하는 기능입니다.

### U-37
::: what
우리 팀에서 쓰는 말을 시스템에 가르칩니다. 예를 들어 「vcore」와 「cpu」가 같은 뜻이라고 등록하면, 다음부터 「vcore」로 물어도 알아듣습니다.
:::
::: case Q-SYNONYM answer-synonym
포인트: 1번 입력처럼 **기준이 되는 항목(컬럼) 없이** 낱말끼리만 묶으면, 어느 항목의 유사어인지 알 수 없어 등록하지 않고 방법을 안내합니다. 2번 입력처럼 기준 항목(`hostname`)을 밝히면 등록합니다.
:::
::: how
1. 입력창에 「(항목)에 '(낱말)' 유사 단어를 추가해줘」처럼 **기준 항목**과 낱말을 함께 적으세요.
2. 답에서 무엇이 어떤 항목에 등록됐는지 확인하세요.
3. 기준 항목을 모르면 낱말만 묶어 보내 보세요. 시스템이 기준 항목을 찾을 수 있으면 등록하고, 못 찾으면 방법을 안내합니다.

::: ui answer-synonym 유사어 등록 답변
:::
::: caution
- 등록한 말은 모든 사용자에게 적용됩니다. 확실한 것만 등록하세요.
- 뜻이 모호하면 등록하지 않고 다시 묻습니다.
- 잘못 등록했으면 관리자에게 삭제를 요청하세요.

## 10. 노이즈 관제

받은 알람이 어디서, 왜 걸러졌는지 보는 읽기 전용 화면입니다. 머리글의 **노이즈 관제**로 엽니다.

### U-44
::: what
알람 거르기(노이즈 게이트)가 내린 판단을 기간별로 봅니다. 판단은 네 가지입니다.

| 판단 | 뜻 |
|---|---|
| PAGE | 즉시 통보 |
| TICKET | 즉시 호출 없이 대기열·기록으로 |
| DASHBOARD | 통보 없이 화면에만 |
| SUPPRESS | 통보하지 않고 기록만(삭제가 아님) |
:::
::: how
1. 위쪽 기간 버튼(**1H·24H·7D·30D**)을 고르세요.
2. **KPI 카드**에서 수신 알람 수와 판단별 건수, 억제율을 봅니다.
3. **노이즈 캔슬링 퍼널**에서 어느 단계에서 몇 건이 걸러졌는지 봅니다.
4. **티어 분포 추이**에서 시간대별 변화를 봅니다.
5. **결정 이력**에서 티어·단계·검색어로 찾고, 행을 누르면 **결정 추적**이 열립니다.
6. 항목 옆 **(!)** 를 누르면 그 지표의 정의와 읽는 법이 나옵니다.
:::
::: ui noise-user 노이즈 관제
:::
::: ui noise-drawer 결정 추적 — 이 알람이 왜 이렇게 판단됐는지
판단 경로(통과한 단계와 결정한 단계)와 판단 순간의 신호 값이 나옵니다.
:::
::: caution
- 이 화면은 조회만 합니다. 알람을 멈추는(침묵) 설정은 관리자 기능입니다.
- 모든 존의 판단이 합산되어 보입니다.
:::
::: related
- [U-40 알람 탭과 알람 카드](#u-40)
:::

### U-45
::: what
알람 거르기(노이즈 게이트)는 **미리 정한 규칙**으로 판단합니다. AI(LLM)는 알람을 요약하고 "평소와 같은 알람인지" 같은 참고 의견을 낼 뿐, 걸러낼지 말지는 규칙이 정합니다. 학습된 머신러닝 모델은 쓰지 않습니다.

규칙은 아래 순서로 적용되고, **먼저 걸린 규칙이 결과가 됩니다.**

| 순서 | 규칙 | 결과 |
|---|---|---|
| 1 | 같은 서버·같은 알람·같은 자원이 정해진 시간(기본 4시간) 안에 다시 오면 | 다시 알리지 않고 횟수만 기록 |
| 2 | **심각** 알람이면 | **항상 즉시 통보(PAGE)** — 아래 규칙을 거치지 않습니다 |
| 3 | 해소 알람이거나, 발생 뒤 금방 스스로 복구됐으면 | 통보하지 않고 기록 |
| 4 | 서버가 유지보수 중이거나 관리자가 건 침묵 규칙에 걸리면 | 통보하지 않고 기록 |
| 5 | 상위 장비 장애로 생긴 연쇄 알람, 짧은 시간에 몰린 알람, 켜졌다 꺼졌다를 반복하는 알람 | 대표만 알리거나 보류(관리자가 켠 경우) |
| 6 | 위에 걸리지 않으면 **심각도 × 서버 중요도** 표로 기본 판단 | PAGE·TICKET·DASHBOARD 중 하나 |
| 7 | 보조 신호(모니터링 시스템의 통보 정책, AI 의견, 운영자 피드백, 최근 변경 작업)로 조정 | **최대 한 단계** 올리거나 내림. 올릴 이유가 하나라도 있으면 내리지 않습니다 |
:::
::: how
1. **노이즈 관제**를 열고 **결정 이력**에서 궁금한 알람 행을 누르세요.
2. **결정 추적**의 **판단 경로**에서 어느 단계에서 결과가 정해졌는지 봅니다.
3. **신호 스냅샷**에서 판단 순간의 값(실효 심각도, 중요도, 일상 반복, 통보 정책, LLM 액션가능성 등)을 봅니다.
4. 7번 조정이 있었다면 사유에 「승격:」 또는 「강등:」 뒤에 이유가 적혀 있습니다.
:::
::: ui -
화면 캡처가 없습니다. [U-44](#u-44)의 결정 추적 그림을 보세요.
:::
::: caution
- **심각 알람은 침묵 규칙이나 피드백으로 걸러지지 않습니다.** 예외는 하나뿐입니다 — 관리자가 비운영 알람 필터를 켠 환경에서, 알람 표시 없이 승인·안내 문구만 있는 메시지는 심각도와 관계없이 기록만 남깁니다.
- 걸러진 알람도 지워지지 않습니다. 판단 이유와 함께 기록에 남습니다.
- 5번과 7번의 일부는 관리자가 켜야 동작합니다. 그래서 환경마다 걸러지는 양이 다를 수 있습니다.
- **노이즈** 피드백은 그 알람을 바로 막지 않습니다. 같은 이름의 **다음** 알람을 판단할 때 참고 예시로 쓰이고, 그것도 최대 한 단계만 내립니다.
:::

#### 자주 묻는 질문

**무엇부터 물어보면 좋을까요?**
서버 목록부터 조회해 보세요. 예: 「전체 서버의 호스트명, OS종류, 벤더를 조회해줘」. 질문을 잘 쓰는 요령은 [U-19](#u-19)에 있습니다.

**「상위 N대」는 어떻게 묻나요?**
기준 기간, 지표, 정렬 방향, 개수를 한 문장에 담으세요. 예: 「2026년 6월 메모리 사용률 평균이 높은 순서로 상위 3대 서버를 보여줘」. 사용률(%)이나 코어 수처럼 숫자로 저장된 항목을 기준으로 삼으세요. 메모리·디스크 용량처럼 단위가 붙어 저장된 값으로 정렬하면 순서가 틀릴 수 있습니다([U-19](#u-19)).

**앞 질문의 결과에 이어서 물을 수 있나요?**
네. 같은 대화에서 「그 서버들의 ~」처럼 물으면 됩니다. 예: 「2026년 6월 CPU 사용률 평균이 높은 상위 3대 서버를 알려줘」 다음에 「그 서버들의 제조사와 OS 종류」. 자세한 내용은 [U-34](#u-34)를 보세요.

**결과를 Excel로 받고 싶어요.**
모든 조회 결과 아래에 **CSV 다운로드** 버튼이 있습니다. CSV는 Excel에서 바로 열립니다([U-22](#u-22)). 「전체 서버 목록을 엑셀로 만들어줘」처럼 양식 없이 요청하면 Excel 파일은 만들어지지 않습니다. 정해진 모양의 파일이 필요하면 양식을 첨부하세요([6장](#ch-6)).

**데이터를 고치거나 지울 수 있나요?**
아니요. 이 시스템은 조회만 합니다. 「서버 테이블 전부 삭제해줘」 같은 요청은 실행하지 않습니다([U-19](#u-19)).

**「가동률」을 물었더니 원하는 답이 나오지 않아요.**
가동률은 모니터링 데이터에 집계되지 않는 지표입니다. 답에 함께 나오는 대체 질문을 그대로 보내 보세요([U-19](#u-19)).

**우리 팀에서 쓰는 말로 물어도 되나요?**
유사어를 등록하면 됩니다. 예: 「hostname에 '장비이름' 유사 단어를 추가해줘」. 등록한 말은 모든 사용자에게 적용되니 확실한 것만 등록하세요([U-37](#u-37)).

**비밀번호를 바꾸고 싶어요.**
사용자 화면에는 비밀번호 변경 기능이 없습니다. 관리자에게 비밀번호 초기화를 요청하세요. 관리자가 임시 비밀번호를 발급해 전달합니다.

**비밀번호를 여러 번 틀려 계정이 잠겼어요.**
기본 설정에서는 30분이 지나면 다시 로그인할 수 있습니다(설치 설정에 따라 다름). 급하면 관리자에게 잠금 해제를 요청하세요([U-03](#u-03)).

**원하는 DB가 조회 대상에 없어요.**
조회할 수 있는 DB는 관리자가 정합니다. 권한이 없는 DB는 선택지에 나오지 않으니 관리자에게 권한을 요청하세요([U-24](#u-24)).

#### 오류 메시지와 대응

화면에 나오는 문구를 그대로 적었습니다. 괄호 안의 숫자(N)는 설치 설정에 따라 다릅니다.

**로그인 화면**

| 표시 문구 | 뜻 | 대응 |
|---|---|---|
| ID 또는 비밀번호가 올바르지 않습니다. | ID가 없거나 비밀번호가 틀렸습니다. | 입력값을 확인하고 다시 입력하세요. |
| 로그인 N회 실패로 계정이 잠겼습니다. | 비밀번호를 연속으로 틀려 계정이 잠겼습니다(기본 5회). | 잠금 시간이 지난 뒤 다시 로그인하거나 관리자에게 해제를 요청하세요. |
| 계정이 잠겼습니다. N분 후 다시 시도하세요. | 잠긴 계정으로 로그인을 시도했습니다(기본 30분). | 표시된 시간이 지난 뒤 다시 로그인하세요. |
| 비활성 계정입니다. | 관리자가 계정을 사용 중지했습니다. | 관리자에게 문의하세요. |
| 로그인에 실패했습니다. | 서버가 이유를 알려 주지 않은 실패입니다. | 잠시 후 다시 시도하고, 계속되면 관리자에게 알리세요. |

**로그인이 만료됐을 때**

- 화면을 열거나 새로고침했을 때 로그인이 만료되어 있으면 **안내 없이 로그인 화면으로 이동**합니다. 다시 로그인하세요.
- 질문을 보내는 중에 만료되면 답 말풍선에 「⚠ 토큰이 만료되었습니다.」와 응답 코드 401이 나옵니다. 이때는 **다시 시도**를 눌러도 같은 오류가 납니다. 화면을 새로고침해 다시 로그인한 뒤 질문을 다시 보내세요.

**DB 연결 경고 배너**

대화 영역 위에 뜨는 배너입니다. 30초마다 상태를 다시 확인하고, 정상이 되면 저절로 사라집니다([U-07](#u-07)).

| 표시 문구 | 뜻 | 대응 |
|---|---|---|
| 일부 DB 연결 불가: (DB 이름). 쿼리 결과가 불완전할 수 있습니다. | 적힌 DB에만 연결할 수 없습니다. 상태 배지는 WARNING입니다. | 다른 DB에 대한 질문은 정상입니다. 적힌 DB가 필요한 질문은 미루고 관리자에게 알리세요. |
| 모든 DB 서버에 연결할 수 없습니다. MCP 서버 상태를 확인하세요. | 어떤 DB에도 연결할 수 없습니다. 상태 배지는 OFFLINE입니다. | 조회가 되지 않습니다. 관리자에게 알리세요. |
| DB 서버(MCP Server)에 연결할 수 없습니다. 쿼리 실행이 불가능합니다. MCP 서버 상태를 확인하세요. | DB 하나만 쓰는 설치에서 그 DB에 연결할 수 없습니다. 상태 배지는 DB OFFLINE입니다. | 관리자에게 알리세요. |
| API 서버에 연결할 수 없습니다. 서버가 실행 중인지 확인하세요. | 이 화면이 서버와 통신하지 못했습니다. | 잠시 후 새로고침하고, 계속되면 관리자에게 알리세요. |

**질문 처리 중 오류**

| 표시 문구 | 뜻 | 대응 |
|---|---|---|
| ⚠ 처리 시간이 초과되었습니다. 질의를 단순화해주세요. | 답을 만드는 시간이 상한을 넘었습니다. 말풍선에 「상한 N초 · 경과 …」와 멈춘 단계가 함께 나올 수 있습니다. | 기간·서버·항목을 줄여 다시 물으세요. 같은 질문을 한 번 더 해 보려면 **다시 시도**를 누르세요([U-16](#u-16)). |
| ⚠ 서버와의 통신에 실패했습니다: (사유) | 답을 받는 도중 연결이 끊겼습니다. | **다시 시도**를 누르세요. 계속되면 DB 연결 경고 배너가 떠 있는지 확인하세요. |
| ⚠ 처리 중 오류가 발생했습니다. | 서버가 질문을 처리하지 못했습니다. | **다시 시도**를 누르고, 계속되면 질문을 바꿔 보세요. |
| ⏹ 응답이 중단되었습니다 | 내가 **■**(응답 중단)을 눌러 멈췄습니다. 오류가 아닙니다. | 다시 보내려면 ↑ 키로 질문을 불러오세요([U-13](#u-13)). |
| 처리 중인 질의가 끝난 뒤 다시 시도해 주세요. | 다른 질문을 처리하는 중에 **다시 시도**를 눌렀습니다. | 진행 중인 답이 끝난 뒤 누르세요. |

**다시 시도**는 자동으로 실행되지 않습니다. 누를 때만 같은 질문을 다시 보냅니다.

#### 용어집

| 용어 | 뜻 |
|---|---|
| 존 | 데이터를 조회하고 알람을 받는 지역 단위입니다. 예: 은행존, 공동존. 어떤 존의 알람을 받을지는 관리자가 정합니다([U-09](#u-09)). |
| 존 그룹 | 존을 묶은 상위 구분입니다. 여러 존을 조회할 때 조회 순서와 선택 범위를 정합니다. 관리자가 존 그룹 상호배타를 켠 환경에서는 한 번에 한 그룹 안에서만 존을 고를 수 있습니다([U-25](#u-25)). |
| 조회 대상 | 이 대화가 조회하는 DB입니다. 입력줄 위 칩에 표시됩니다([U-24](#u-24)). |
| 승계 | 한 번 조회한 대상을 다음 질문에서도 그대로 쓰는 것입니다. 칩의 **×**로 풀 수 있습니다([U-24](#u-24)). |
| 역질문 | 질문만으로 정할 수 없는 것(존, 양식 항목 등)을 시스템이 되묻는 것입니다([U-25](#u-25), [U-29](#u-29)). |
| 유사어 | 같은 뜻으로 쓰는 다른 말입니다. 등록하면 그 말로 물어도 알아듣습니다([U-37](#u-37)). |
| 심각도 | 알람의 심한 정도입니다. 3=심각, 2=경고입니다. |
| 노이즈 게이트 | 받은 알람을 미리 정한 규칙으로 걸러, 통보할지와 어떻게 통보할지 판단하는 기능입니다([U-45](#u-45)). |
| 티어 | 노이즈 게이트의 판단 결과입니다. PAGE(즉시 통보) · TICKET(즉시 호출 없이 대기열·기록으로) · DASHBOARD(통보 없이 화면에만) · SUPPRESS(통보하지 않고 기록만) 네 가지입니다([U-44](#u-44)). |
| 억제 | 알람을 통보하지 않고 기록만 남기는 판단(SUPPRESS)입니다. 삭제가 아니며 결정 추적에서 이유를 볼 수 있습니다. 심각 알람은 억제되지 않습니다(비운영 알람 예외 — [U-45](#u-45)). |
| 억제율 | 받은 알람 중 억제(SUPPRESS)된 비율입니다. |
| 침묵 | 관리자가 기간을 정해 특정 서버·알람·자원의 통보를 멈추는 규칙입니다. 기록은 남고, 심각 알람은 침묵되지 않습니다. |
| 결정 추적 | 알람 하나가 왜 그렇게 판단됐는지 판단 경로와 당시 신호 값을 보여 주는 화면입니다([U-44](#u-44)). |
