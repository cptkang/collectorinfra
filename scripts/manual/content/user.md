이 매뉴얼은 **KB AIOps 포탈**을 쓰는 분을 위한 안내서입니다. 서버·성능·알람 데이터를 한국어로 물어보면 답을 표로 돌려주고, Excel·Word 양식도 채워 줍니다.

- 처음이라면 [1장 시작하기](#ch-1)와 [3장 질의하기](#ch-3)부터 보세요.
- 각 기능은 **사례 → 사용 방법 → 화면 요소 → 주의** 순서로 설명합니다. 사례의 「입력」은 그대로 복사해 쓸 수 있습니다.
- 사례의 결과는 테스트용 샌드박스 데이터로 실제로 실행한 결과입니다. 운영 환경에서는 서버 이름과 숫자가 다르게 나옵니다.
- 관리자 기능은 [관리자 매뉴얼](/manual/admin)에 있습니다.

## 1. 시작하기

계정을 만들고 로그인해서 첫 화면을 둘러봅니다.

### U-01
::: what
이 시스템은 인프라 관측 데이터를 **자연어로 조회**하는 도구입니다. 할 수 있는 일은 크게 네 가지입니다.

| 할 수 있는 일 | 예 | 설명 장 |
|---|---|---|
| 서버 구성·성능·알람 조회 | 「2026년 6월 메모리 사용률 평균 상위 3대」 | [3장](#ch-3) |
| 양식(Excel·Word) 채우기 | 서버 목록 양식을 올리고 「채워줘」 | [6장](#ch-6) |
| 실시간 알람 받기 | 알람 카드에서 바로 조회 | [9장](#ch-9) |
| 알람이 왜 걸러졌는지 보기 | 노이즈 관제 화면 | [10장](#ch-10) |

조회만 합니다. 데이터를 바꾸거나 지우는 요청은 실행하지 않습니다.
:::
::: how
1. 로그인하면 질의응답 화면이 열립니다.
2. 아래 입력창에 궁금한 것을 한국어로 적고 **Enter**를 누르세요.
3. 답이 표로 나오면 그대로 읽거나 CSV로 내려받습니다.
:::
::: ui main-welcome 첫 화면
1. 예시 질문 버튼 — 누르면 입력창에 예시 문장이 채워집니다([U-17](#u-17)).
2. 「❓ 사용법」 — 지금 조회할 수 있는 데이터를 안내받습니다([U-18](#u-18)).
3. 입력창 — 여기에 질문을 적습니다.
:::
::: caution
- 답은 조회 시점에 수집된 데이터를 기준으로 합니다. 성능 통계는 시간·일·월 단위로 모아 둔 값이라 「지금 이 순간」 값과 다를 수 있습니다.
- 조회할 수 있는 DB는 관리자가 정해 줍니다. 질문이 권한 밖 DB만 가리키면 조회하지 않고 「조회할 수 있는 DB가 없습니다…」라고 답합니다. 여러 DB 중 일부만 권한이 있으면 권한 있는 DB만 조회하고 나머지는 따로 알리지 않으니, 원하는 존의 결과가 빠졌으면 관리자에게 권한을 확인하세요.
:::
::: related
- [U-11 질문 입력과 전송](#u-11)
- [U-19 질문 잘 쓰는 법](#u-19)
:::

### U-02
::: what
처음 쓰는 분은 계정을 직접 만듭니다.
:::
::: how
1. 로그인 화면 아래의 **회원가입**을 누르세요.
2. 사용자 ID, 이름, 비밀번호, 부서를 입력하세요.
   - 사용자 ID: 영문·숫자·밑줄(_)로 3~50자
   - 비밀번호: 8자 이상. 확인란에 한 번 더 입력합니다.
3. **가입하기**를 누르면 로그인 화면으로 돌아갑니다.
:::
::: ui register 회원가입 화면
1. 사용자 ID
2. 이름 — 화면 오른쪽 위에 표시되는 이름입니다.
3. 비밀번호(확인 포함)
4. 부서
5. 가입하기
:::
::: caution
- 가입만으로는 조회할 수 있는 DB가 없을 수 있습니다. 설치 설정에 따라 기본 권한이 없으면 관리자가 「조회 가능 DB」를 지정해 줘야 합니다. 그 전에는 데이터 질문에 「조회할 수 있는 DB가 없습니다…」로 답합니다(사용법·일반 질문에는 답합니다).
- 비밀번호를 잊으면 관리자에게 초기화를 요청하세요. 화면에서 직접 바꾸는 기능은 없습니다.
:::
::: related
- [U-03 로그인](#u-03)
:::

### U-03
::: what

:::
::: how
1. 사용자 ID와 비밀번호를 입력하세요.
2. **로그인**을 누르세요.
:::
::: ui login 로그인 화면
1. 사용자 ID
2. 비밀번호
3. 로그인
4. 회원가입 — 계정이 없을 때
:::
::: caution
- 비밀번호를 여러 번 틀리면 계정이 잠깁니다. 잠긴 계정은 일정 시간이 지나거나 관리자가 풀어 줘야 합니다.
- 로그인은 8시간 동안 유지됩니다(설치 설정에 따라 다름). 시간이 지나면 다시 로그인하세요.

## 2. 머리글

화면 맨 위 머리글의 표시와 버튼입니다.

### U-06
::: what
**ONLINE** 배지는 서버와 DB 연결 상태를 보여 줍니다. 마우스를 올리면 DB별 연결 상태가 나옵니다.
:::
::: how
1. 배지 색을 보세요. 초록이면 정상입니다.
2. 배지에 마우스를 올리면 DB마다 연결 여부가 보입니다.
:::
::: ui header-status 상태 배지에 마우스를 올린 모습
DB 이름 옆 점이 초록이면 연결, 빨강이면 끊김입니다.
:::
::: caution
- 배지가 빨갛다면 질문해도 해당 DB의 답이 나오지 않습니다. 관리자에게 알리세요.
:::
::: related
- [U-07 DB 연결 경고 배너](#u-07)
:::

### U-07
::: what
DB 연결에 문제가 생기면 대화 영역 위에 경고 배너가 뜹니다. 정상일 때는 보이지 않습니다.
:::
::: how
1. 배너 문구에서 어느 DB가 문제인지 확인하세요.
2. 그 DB를 쓰는 질문은 잠시 미루고, 관리자에게 알리세요.
:::
::: ui -
화면 캡처가 없습니다. 장애가 있을 때만 나타나는 표시라 정상 환경에서는 찍히지 않습니다.
:::
::: caution
- 배너가 떠 있어도 다른 DB에 대한 질문은 정상으로 동작합니다.

::: related

## 3. 질의하기

한국어로 질문하고 답을 받는 방법입니다. 이 장의 사례가 이 시스템의 핵심 사용법입니다.

### U-11
::: what
입력창에 질문을 적고 보내면, 시스템이 알맞은 데이터를 찾아 조회하고 답을 표로 정리합니다.
:::
::: case Q-SERVER-LIST
포인트: 무엇을(「서버」) + 어떤 항목을(「호스트명, OS종류, 벤더」) 순서로 적으면 가장 잘 알아듣습니다. 항목 이름은 화면에 보이는 말 그대로 써도 됩니다.
바꿔 보기: 전체 서버의 IP와 OS 버전을 보여줘 | 서버 수를 조회해줘
:::
::: how
1. 입력창을 누르고 질문을 적으세요.
2. **Enter**를 누르거나 오른쪽 전송 버튼(▷)을 누르세요. 줄을 바꾸려면 **Shift+Enter**입니다.
3. 답이 나올 때까지 진행 상황이 표시됩니다([U-14](#u-14)).
:::
::: ui query-input 입력줄
1. 질문 입력창
2. 파일 첨부([6장](#ch-6))
3. 전송
4. 조회 대상 칩([U-24](#u-24))
5. 단축키 안내
:::
::: caution
- 질문 하나에 한 가지를 묻는 것이 가장 정확합니다. 여러 가지를 묻는 복합 질문도 되지만 시간이 더 걸립니다.
- 조회 결과는 기본으로 최대 1,000행까지 가져옵니다.
:::
::: detail
#### 입력 규칙과 한도
- 질문은 2,000자까지 보낼 수 있습니다. 넘으면 서버가 받지 않으니 표나 긴 목록을 붙여 넣지 말고 조건만 문장으로 적으세요.
- 입력창은 내용이 늘면 따라 커지다가 일정 높이부터는 안에서 스크롤됩니다.
- 한 번에 가져오는 행 수는 질문에 쓴 표현에 따라 달라집니다(기본값이며 설치 설정에 따라 다를 수 있습니다).

| 질문에 이런 말이 있으면 | 가져오는 행 수 |
|---|---|
| 「100건」, 「상위 10」처럼 건수 | 그 수만큼(최대 10,000행) |
| 「전체」, 「모든」, 「모두」, 「서버별」, 「서버들」, 「각 서버」 | 최대 10,000행 |
| 위 표현이 없음 | 1,000행 |

#### 이렇게 동작합니다
- 답을 만드는 동안 전송 버튼은 **■**(중단)으로 바뀝니다. 이때 **Enter**를 누르면 새 질문이 가지 않고 진행 중인 답이 멈춥니다. 다음 질문은 답이 끝난 뒤 보내세요.

### U-16
::: what
답을 만들다 실패하면 이유와 함께 **다시 시도** 버튼이 나옵니다. 자동으로 다시 보내지는 않습니다.
:::
::: how
1. 실패 메시지를 읽으세요. 시간 초과인지, 어느 단계에서 멈췄는지 나옵니다.
2. 같은 질문으로 다시 해 보려면 **다시 시도**를 누르세요.
3. 계속 실패하면 질문을 더 좁혀 보세요(기간·서버·항목 줄이기).
:::
::: ui -
화면 캡처가 없습니다. 오류가 있을 때만 나타나는 버튼입니다.
:::
::: caution
- 시간 초과는 대개 질문 범위가 너무 넓을 때 납니다. 「전체 서버 × 2년 × 시간 단위」 같은 질문은 나눠서 하세요.
- 처리 시간 상한은 **첫 답(표 또는 첫 글자)이 나올 때까지**의 시간입니다. 표가 나온 뒤에는 답이 30초 넘게 멈추거나 전체가 상한 + 60초를 넘길 때만 끊기며, 그때도 이미 받은 답은 남고 끊긴 사유가 아래에 붙습니다.
- 요약 문장을 쓸 시간이 모자라면 요약 없이 **표와 「요약은 처리 시간 상한으로 생략했습니다」**로 끝납니다. 표는 조회 결과 그대로입니다.
- 조회 단계에서 상한을 넘겨도 조회한 행이 있으면 오류 대신 **조회 결과 표**가 나옵니다. 맨 윗줄에 표로 대신한 사유가 붙고, 표에는 상위 20건만 실립니다 — 전체는 CSV로 내려받으세요.
- 여러 단계로 나눠 조회하는 질문은 남은 시간이 한 단계를 더 돌기에 부족하면 **추가 조회를 멈추고 지금까지의 결과로** 답합니다. 답 끝에 「응답 시간 상한이 가까워 …」 안내가 붙습니다 — 더 필요하면 그 부분만 따로 물어보세요.
- SQL을 여러 번 다시 만들어도 검증을 통과하지 못하면 같은 조회를 되풀이하지 않고 지금까지의 결과로 답합니다. 답 끝에 그 사유(「SQL을 재시도 한도까지 다시 만들었지만 검증을 통과하지 못했습니다」 등)가 붙습니다 — 조건을 더 구체적으로 적어 다시 물어보세요.
- 같은 서버명·IP를 모든 DB에서 두 번 연속 찾지 못하면 세 번째로 다시 찾지 않고 「조건에 맞는 … 을(를) 찾지 못했습니다(조회한 DB: …)」로 끝냅니다. 서버명 철자를 확인하거나 다른 식별자(IP 등)로 물어보세요.
- 조회 자체가 실패하면(SQL 검증 재시도 한도 · 응답 시간 상한 · DB 오류) 「조건에 해당하는 데이터가 없습니다」가 아니라 「「…」 조회는 … 결과를 얻지 못했습니다. **데이터가 없다는 뜻이 아닙니다.**」와 마지막 사유가 나옵니다. 대상이 없는 것이 아니니 질문을 좁혀 다시 물어보세요.
- 데이터를 지우거나 바꾸는 요청이 SQL로 만들어져 읽기 전용 검사에 막히면 「삭제·수정 같은 데이터 변경 요청은 수행할 수 없습니다(읽기 전용)」로 답합니다.

### U-19
::: what
같은 내용도 질문을 어떻게 쓰느냐에 따라 결과가 달라집니다. 아래 사례로 잘 쓰는 법과 잘 안 되는 경우를 익히세요.

**잘 쓰는 법 다섯 가지**

1. **대상을 분명히** — 「서버」, 「cocm-hdkapp01 서버」, 「김포 서버」
2. **항목을 나열** — 「OS 종류, IP, 메모리 용량」
3. **기간은 구체적으로** — 「2026년 5월」, 「지난 30일」. 「이번 달」은 월초에는 데이터가 거의 없습니다. 어떤 기간으로 조회했는지는 답 끝의 「[조회 기간]」 줄로 확인하세요([U-53](#u-53)).
4. **순서·개수를 명시** — 「큰 순서로 상위 3대」
5. **조건은 숫자로** — 「메모리 이용률 90% 초과」, 「논리코어 8개 이상」
:::
::: case Q-TOP-MEMORY
포인트: 「높은 순서로 상위 3대」처럼 정렬과 개수를 함께 쓰면 그 수만큼만 가져옵니다. 기준 월(「2026년 6월」)도 함께 적었습니다.
바꿔 보기: 2026년 6월 CPU 사용률 평균이 낮은 서버 5대 | 논리코어가 많은 순서로 상위 5대 서버
:::
::: case Q-SERVER-DETAIL
포인트: 서버 이름(호스트명)을 정확히 쓰면 그 서버 한 대의 여러 항목을 한 번에 봅니다.
:::
::: case Q-CORE-FILTER
포인트: 조건(「8개 이상」) · 보여줄 항목 · 정렬을 한 문장에 담았습니다. 요약 문장의 분포(「16개 38대」)는 틀렸습니다 — 표로 세면 32개 5대 · 16개 18대 · 8개 20대입니다. **개수는 요약 문장보다 표와 결과 건수를 기준으로 보세요.**
:::
::: case Q-CPU-MONTH
포인트: 성능 통계는 「2026년 5월」처럼 기준 월을 적어야 정확합니다. 이 샌드박스에는 5월 통계가 있는 서버가 4대뿐이라, 다섯 번째 줄은 값이 빈(null) 서버로 채워졌습니다. 요약 문장이 이 누락을 함께 알려 줍니다.
바꿔 보기: 지난달 서버별 메모리 사용률 평균 상위 10대 | 2026년 1월부터 6월까지 메모리 사용률 최대값
:::
::: case Q-MEM-OVER
포인트: 「초과한 적이 있는」처럼 기간 중 한 번이라도 조건을 넘은 서버를 찾습니다. 이 사례에서는 통계의 최댓값(95.2%)과 함께 그때 울린 임계 초과 알람까지 붙여 보여 줍니다. 요약 문장의 날짜(7월 10일)는 알람이 발생한 날이고, 최댓값은 월 통계에서 나온 값입니다. **숫자는 요약 문장보다 표를 기준으로 읽으세요.**
:::
::: case Q-ALARM-HISTORY
포인트: 「최근 발생 순으로 20건」처럼 정렬과 건수를 주면 목록이 짧고 읽기 좋습니다. 「경고 이상」은 심각도 2(경고)와 3(심각)을 뜻하고, 표의 `severity_grade` 열에 이름이 함께 나옵니다. 조건에 맞는 이력이 5건뿐이라 20건보다 적게 나왔습니다.
:::
::: case Q-COMPOSITE
포인트: 알람 데이터와 서버 구성 데이터를 이어 붙이는 **복합 질문**입니다. 시스템이 두 단계로 나눠 처리합니다. 이 사례처럼 두 결과를 서버 기준으로 합칠 수 있으면 한 표로 보여 주고, 합칠 수 없으면 **단계마다 표와 짧은 요약**을 차례로 보여 줍니다([U-20](#u-20)).
:::
::: case Q-GENERAL
포인트: 데이터 조회가 아닌 일반 지식 질문에도 답합니다. 이런 답은 DB를 조회하지 않은 **참고용 설명**이라 용어나 세부 내용이 부정확할 수 있습니다. 답 끝에 이 시스템으로 조회할 수 있는 데이터도 함께 안내합니다.
:::
::: case Q-BAD-DELETE
포인트: **잘 안 되는 예** — 데이터를 바꾸거나 지우는 요청은 실행하지 않습니다. 이 시스템은 조회 전용입니다. 이 사례에서는 삭제 대신 서버 목록을 조회해 보여 주며, 삭제는 DB 관리자가 해야 한다고 안내합니다. 표가 나왔다고 해서 무엇이 지워진 것은 아닙니다.
:::
::: case Q-BAD-UPTIME
포인트: **잘 안 되는 예** — 「가동률」은 모니터링 데이터에 집계되지 않는 지표입니다. 시스템이 그 이유를 설명하고 대신 쓸 질문을 제안합니다. 제안된 문장을 그대로 보내면 됩니다.
바꿔 보기: 가용 상태가 비정상인 서버 목록 보여줘 | 지난달 CPU 사용률이 낮은 서버 순으로 보여줘
:::
::: case Q-BAD-TYPO
포인트: **잘 안 되는 예** — 서버 이름을 틀리게 쓰면(`hdkapp1` ↔ `hdkapp01`) 「조건에 해당하는 데이터가 없습니다」라고 답합니다. 결과가 없으면 먼저 이름을 확인하세요. 이름은 결과 표에서 복사해 쓰면 정확합니다.
바꿔 보기: cocm-hdkapp01 서버의 OS
:::
::: how
1. 위 다섯 가지를 떠올리며 질문을 적으세요.
2. 결과가 기대와 다르면 [처리 현황](#u-15)에서 어떻게 이해했는지 보고, 질문을 고쳐 다시 보내세요.
3. 이어서 좁혀 가려면 「그 서버들의 ~」처럼 이어서 물으세요([U-34](#u-34)).
:::
::: ui answer-table 표로 나온 답
결과 표 아래의 ROWS(건수)·TIME(걸린 시간)을 확인하세요([U-20](#u-20)).
:::
::: caution
- 데이터에 없는 개념(가동률, 응답 시간, 패킷 손실률 등)은 정확히 답할 수 없습니다. 답의 설명 문장을 꼭 읽으세요.
- 메모리·디스크 용량처럼 단위가 붙어 저장된 값(「8.0 GB」, 「1.0 TB」)은 단위를 GB로 환산해 크기 순으로 정렬합니다. 단위 없이 숫자만 저장된 값은 그 숫자 그대로 비교하므로, 표의 값과 단위를 함께 확인하세요.
- 「메모리 64MB 이상」처럼 값의 단위가 서버 메모리·디스크 용량으로는 지나치게 작으면 답 끝에 「'64MB'은(는) 서버 메모리 용량으로는 매우 작은 값입니다 …」 안내가 붙습니다. 조회는 적은 그대로 했습니다 — GB를 뜻했다면 단위를 고쳐 다시 물으세요.
- 조회 SQL을 만들면서 조건 일부를 무시·생략했다고 스스로 적었으면 그 메모가 「조회 SQL에 생성기가 남긴 메모: 「…」」로, 질문의 수치 조건이 실행한 SQL에서 빠지거나 방향·결합(그리고→또는)이 바뀌었으면 그 사실이 답 끝에 붙습니다. 이런 안내가 있으면 표가 질문과 다른 조건의 결과일 수 있으니 조건을 나눠 다시 물으세요.
- 존(은행존·공동존)을 적지 않고 전체를 묻는 대량 조회는 존을 되묻습니다([U-25](#u-25)).
- 권한이 없는 존·DB를 콕 집어 물으면 조회하지 않고 「조회할 수 있는 DB가 없습니다…」로 답합니다. 권한 있는 존으로 바꿔 묻거나 관리자에게 권한을 요청하세요.
- 결과 끝에 「컬럼 설명 미등록」 같은 **관리자 안내**가 붙을 수 있습니다. 조회는 정상이며, 관리자가 DB 설명을 등록하면 사라집니다.
- 질문에 적은 데이터 소스(예: 「ITAM에서」)가 지금 연결되어 있지 않으면 답 끝 「순차 처리 경과」에 「요청하신 「ITAM」 데이터 소스는 현재 활성화되어 있지 않아 조회하지 않았습니다」가 붙습니다. 그때 나온 표는 연결된 다른 DB에서 조회한 결과이니, 원하던 데이터인지 확인하세요.
- 결과가 없을 때 조건을 하나씩 적용한 **단계별 건수 표**와 「← 여기서 끊겼습니다」가 붙으면, 그 단계의 조건(서버 이름·기간·임계값)부터 확인하세요. 여러 단계로 나눠 처리한 복합 질문에도 같은 표가 붙습니다.
- 서버 이름(호스트명·IP)만 적은 질문의 결과가 없으면 「임계값 낮추기」 대신 「대상 이름(서버명·호스트명·IP)이 정확한지 확인해보세요」가 붙습니다. 조건이 이름뿐이니 이름이 틀렸을 가능성이 큽니다 — 서버 목록을 조회해 정확한 이름을 확인한 뒤 다시 물으세요.
- 답 끝 경과 안내에 「조회 대상 시스템을 분류하지 못해 … 첫 활성 DB(…)로 조회했습니다」가 붙으면 질문만으로는 어느 시스템을 조회할지 정하지 못해 기본 DB에서 조회한 것입니다. 원하던 데이터가 아닐 수 있으니 위치(김포·여의도·은행존)나 시스템 이름을 넣어 다시 물으세요.
- 「… 순차 분해가 적용되지 않았고 한 번의 조회로 처리했습니다」가 붙으면 「찾아서 그 서버의 ~」처럼 앞 결과를 뒤 조회의 대상으로 쓰는 질문을 단계로 나누지 못하고 한 번에 조회한 것입니다. 두 번으로 나눠 물으세요([U-34](#u-34)).
- 「재계획 상한(N회)에 도달해 …」 또는 「추가 조회가 필요한지 판단하는 단계가 실패해 …」가 붙으면 추가 조회를 멈추고 그때까지 얻은 결과로 답한 것입니다. 결과를 확인하고, 부족하면 조건을 좁혀 다시 물으세요.
:::

### U-53
::: what
질문에 쓴 기간 표현(「지난달」·「최근 30일」·「어제」 등)은 시스템이 **질문을 보낸 시각을 기준으로** 정해진 규칙에 따라 날짜로 바꿔 조회합니다. 어떤 기간으로 조회했는지는 답 끝에 **「[조회 기간]」** 한 줄로 알려 줍니다. 기간을 말하지 않았거나 시스템이 표현을 풀이해서 정한 기간이면 그 사실도 함께 적습니다.

예: `[조회 기간] 2026-08-30 ~ 2026-09-28 · 일 단위 (「최근 30일」)`
:::
::: how
1. 질문에 기간을 넣으세요. 아래 표는 **9월 29일(화) 오전 10시에 물었을 때** 조회하는 기간입니다.

| 이렇게 물으면 | 조회하는 기간 | 집계 단위 |
|---|---|---|
| 지난달 · 전월 | 8월 1일 ~ 8월 31일 | 월 |
| 이번 달 · 당월 | 9월 1일 ~ 어제(9월 28일) | 일 |
| 최근 30일 · 지난 30일 | 8월 30일 ~ 어제(9월 28일) — 오늘은 빼고 30일 | 일 |
| 어제 | 9월 28일 하루 | 일 |
| 지난주 | 지난 월요일 ~ 일요일(9월 21일 ~ 9월 27일) | 일 |
| 오늘 | 오늘 0시 ~ 지금 시각의 정시(10시) | 시간 |
| 최근 3시간 | 오전 7시 ~ 10시(정시 기준) | 시간 |
| 올해 | 1월 ~ 지난달(8월) — 이번 달 제외 | 월 |
| 6월 · 1월부터 3월까지(연도 없이) | 지나간 가장 최근의 그 달(2026년 6월 등) | 월 |
| 「시간 단위로」·「시간별」 + 기간 | 기간은 위와 같고 시간 단위로 모아서 | 시간 |
| ~한 적이 있는(예: 「CPU 90%를 넘은 적이 있는 서버」) | 보관된 전체 기간 | — |
| 기간을 말하지 않음 | 지난달(8월 1일 ~ 8월 31일) | 월 |

2. **알람**은 기간 규칙이 조금 다릅니다.

| 알람 질문 | 조회하는 기간 |
|---|---|
| 기간을 말하지 않음(예: 「최근 발생 순으로 100건」) | 기간 조건 없이 최신 순 |
| 이번 달 · 오늘 · 올해 알람 | 그 기간의 시작 ~ **지금 시각까지** |
| 지난달 · 어제 · 지난주 알람 | 그 기간 전체 |

3. 답 끝의 「[조회 기간]」 줄을 읽으세요. 날짜 · 집계 단위 · 질문에서 읽은 표현 순서이고, 필요하면 덧붙임이 따라옵니다.

| 안내 줄 예 | 뜻 |
|---|---|
| `[조회 기간] 2026-08-30 ~ 2026-09-28 · 일 단위 (「최근 30일」)` | 「최근 30일」을 8월 30일 ~ 9월 28일로 보고 일 단위 통계로 조회했습니다 |
| `[조회 기간] 기간 미지정 — 지난달 기준(2026-08-01 ~ 2026-08-31) · 월 단위` | 기간을 말하지 않아 지난달로 조회했습니다. 다른 기간이 필요하면 기간을 넣어 다시 물으세요 |
| `… · 월 단위 (「올해」) · 이번 달 제외` | 월 통계는 끝난 달만 있어 진행 중인 이번 달은 빠졌습니다 |
| `[조회 기간] 2026-09-01 00:00 ~ 2026-09-29 10:00 (「이번 달」) · 현재 시각까지` | 알람을 이번 달 1일부터 질문한 시각까지 조회했습니다 |
| `… · 연도 미지정 — 가장 최근 연도로 해석` | 연도를 적지 않아 지나간 가장 최근의 그 기간으로 보았습니다 |
| `… · 모델 해석 — 다르면 날짜를 직접 적어 주세요` | 정해진 규칙에 없는 표현을 AI가 풀이해 정한 기간입니다. 맞는지 꼭 확인하세요 |

4. 기간이 기대와 다르면 날짜를 직접 적어 다시 물으세요. 예: 「2026년 9월 1일부터 9월 15일까지」
:::
::: ui -
화면 캡처가 없습니다. 「[조회 기간]」 줄은 답의 표와 요약 문장 아래, 다른 안내([안내]) 줄과 함께 붙습니다. 여러 단계로 처리한 답에서 단계마다 기간이 같으면 한 번만 나오고, 단계마다 기간이 다르면 단계별로 나옵니다.
:::
::: caution
- 「[조회 기간]」 줄은 실제로 실행한 조회에 그 기간이 들어갔을 때만 붙습니다. 서버 목록·구성처럼 기간과 상관없는 조회에는 붙지 않습니다. 제니퍼(WAS)·실시간 조회처럼 SQL을 쓰지 않는 조회에도 아직 붙지 않습니다.
- 월별 칸이 있는 양식을 채울 때는 양식의 칸 수가 조회 기간을 정하므로 이 줄 대신 「[기준월 안내]」가 실제로 채운 달을 알려 줍니다([U-27](#u-27)).
- **해석할 수 없는 기간은 조회하지 않고 되묻습니다.** 「13월」·「2월 30일」처럼 달력에 없는 날짜, 「내년 3월」처럼 아직 오지 않은 기간은 「[조회 기간] 요청하신 기간에 달력에 없는 날짜가 있어 조회하지 않았습니다. …」처럼 이유와 함께 기간을 다시 묻습니다. 기간을 고쳐 다시 보내세요.
- 「현재」·「지금」·「실시간」은 기간으로 보지 않습니다. 이런 질문은 지난달 기본값을 쓰지 않습니다.
- 매월 1일에 「이번 달」을 물으면 아직 끝난 날이 없어 결과가 0건인 것이 정상입니다. 안내 줄에 「완결된 구간이 아직 없습니다」가 붙습니다.
- 시간 단위 기간의 끝 시각은 들어가지 않습니다 — 「07:00 ~ 10:00」은 10시 직전까지입니다.
- 두 기간을 비교하는 질문(「5월과 6월」)은 두 기간을 모두 덮는 구간으로 조회하고 「여러 기간을 모두 포함」이 붙습니다.
- 기준 시각은 질문을 보낸 시각입니다. 같은 질문이라도 보낸 날이 다르면 조회 기간이 달라집니다.

## 4. 결과 읽기·내려받기

답을 읽고 파일로 내려받는 방법입니다.

### U-20
::: what
답은 **표 → 요약 문장(2~3줄) → 참고사항** 순서로 나오고, 맨 아래에 결과 정보가 붙습니다. 표는 조회가 끝나자마자 먼저 나오고, 요약 문장은 그 아래에 이어서 써집니다.
:::
::: case Q-SERVER-LIST answer-table
포인트: 표는 앞부분만 보여 주고(예: 54건 중 20건), 전체는 CSV로 받습니다. 요약 문장에 전체 건수가 나옵니다.
:::
::: how
1. 표를 읽으세요. 조회된 항목(열)은 모두 나옵니다. 열 이름은 DB 항목 이름 그대로일 수 있습니다(예: `os_type`). 20건이 넘으면 표 아래에 「전체 N건 중 20건 표시」가 붙습니다 — 전체는 CSV로 받으세요.
2. 표 아래 요약 문장에서 전체 건수와 눈에 띄는 값을 확인하세요.
3. 아래 **ROWS**(결과 건수), **TIME**(걸린 시간), **ID**(질의 번호)를 확인하세요. 문의할 때 ID를 알려 주면 찾기 쉽습니다.
:::
::: ui answer-table 결과
1. 결과 표

- 서로 다른 시스템(예: 폴스타와 ITAM)에서 온 값은 합계·전체 순위로 합치지 않습니다. 결과 정보 줄에 「서로 다른 시스템의 값이라 DB별 집계 값을 합치지 않았습니다」처럼 이유가 붙습니다.

### U-50
::: what
제니퍼(WAS 모니터링) 조회가 오래 걸리면(여러 서버 · 긴 기간 · 많은 건수) 답을 붙잡고 기다리지 않고 **작업으로 접수**합니다. 답 아래에 **작업 카드**가 붙고, 카드에서 진행 상황을 보다가 끝나면 결과를 미리 보고 **전체 결과를 CSV로** 받습니다. 결과가 너무 커서 화면 표에 앞부분만 실린 답에도 같은 카드가 붙습니다.
:::
::: how
1. 평소처럼 제니퍼 질문을 보내세요. 예: 「web01 WAS 느린 트랜잭션 보여줘」
2. 처리 시간 안에 끝나면 평소처럼 표로 답합니다. 끝나지 않으면 「… 오래 걸리는 조회라 작업으로 실행 중입니다(예상 약 N초 · 진행 a/b API 호출). 끝나면 작업 카드에서 결과를 보고 내려받을 수 있습니다.」라고 답하고 그 아래에 작업 카드가 붙습니다. 이 답은 **아직 조회 결과가 아닙니다**.
3. 카드는 몇 초마다 스스로 상태를 다시 봅니다. 상태 표지(대기 중 · 진행 중 · 완료 · 일부 결과 · 실패 · 취소됨 · 중단됨), 진행 막대, 진행·예상 시간 줄이 바뀝니다. 진행 총량을 모르면 막대가 좌우로 흐릅니다. 오른쪽 처리 현황과 진행 단계 목록에는 그 조회가 「완료」가 아니라 **작업 접수**로 표시됩니다.
4. 「완료」 또는 「일부 결과」가 되면 **결과 보기**로 앞 20행을 미리 보고, **전체 결과 받기(CSV)**로 전체 행을 받으세요.
5. 더 기다릴 필요가 없으면 진행 중에 **작업 취소**를 누르세요. 그때까지 받아 둔 조각도 지워집니다.
6. 결과가 커서 화면 표와 「CSV 다운로드」에는 앞부분만 실린 답에는 「화면·CSV는 앞 N행입니다 — 전체 M행은 작업 카드의 「전체 결과 받기」로 내려받으세요.」가 붙습니다. 전체는 카드에서 받으세요.
:::
::: ui -
화면 캡처가 없습니다. 작업 카드는 답 말풍선 아래에 붙는 상자이고, 위에서부터 「제니퍼 조회 작업」 제목과 상태 표지 · 조회 범위(보기 · 서버 · 구간) · 진행 막대 · 진행·예상 시간 줄 · 버튼(작업 취소 · 결과 보기 · 전체 결과 받기(CSV) · 다시 확인) 순서입니다. 버튼은 상태에 맞는 것만 나옵니다.
:::
::: caution
- 접수 답은 데이터 답이 아닙니다. 카드가 「완료」나 「일부 결과」가 되기 전에는 결과가 없습니다.
- 「일부 결과」는 일부 소스·구간 조회가 실패한 결과입니다. 받은 파일 이름 끝에 `_partial`이 붙습니다 — 전체 결과로 쓰지 마세요.
- 결과는 기본 하루(24시간) 동안 보관됩니다. 지나면 카드가 「확인 불가」로 바뀌니 질문을 다시 보내세요. 제니퍼 연결 서버가 다시 시작되면 진행 중이던 작업은 「중단됨」이 됩니다.
- 작업 카드와 결과는 질문한 본인(과 관리자)만 볼 수 있습니다. 비밀번호·토큰 같은 칸은 화면의 답과 같은 규칙으로 가려져 들어갑니다(값 안에 들어 있는 칸까지).
- 작업 상태를 확인하지 못하면(서버·제니퍼 연결 서버 오류) 카드가 안내를 띄우고 점점 길게(최대 1분 간격) 다시 확인합니다. 세 번 연달아 실패하면 **다시 확인** 버튼이 나옵니다 — 누르면 바로 다시 확인합니다.
- 작업으로 접수된 조회의 결과를 쓰는 다음 단계(예: 「그 서버들의 CPU」)는 실행하지 않고 「선행 작업이 … 작업으로 접수돼 아직 결과가 없어…」로 알립니다. 작업이 끝난 뒤 다시 물어 주세요.
- 화면을 새로 고치거나 다른 대화로 옮겨 간 뒤에는 질의 이력의 「대화」에서 그 대화를 다시 불러오세요([U-35](#u-35)). 작업 카드도 다시 붙고 결과 보관 기간 안이면 그대로 받을 수 있습니다. 이 기능이 생기기 전에 남은 대화에는 카드가 없습니다.
- 서버가 작업 기록을 메모리에만 두는 환경이면 답과 카드에 그 사실이 나오고, 서버가 다시 시작되면 카드로 결과를 받을 수 없습니다.

### U-25
::: what
존(은행존·공동존)을 적지 않고 전체를 묻는 대량 조회는, 어느 존을 조회할지 먼저 되묻습니다. 여러 존을 한 번에 조회하면 오래 걸리고 결과가 섞이기 때문입니다.

2. 조회할 존을 체크하세요. 여러 개를 고르면 존마다 차례로 조회합니다.
3. **선택한 존으로 조회**를 누르세요.
4. 존과 상관없이 전체를 보려면 **건너뛰고 전체 조회**를 누르세요.
:::
::: ui zone-clarify 존 선택(화면 예시 — 테스트 환경의 존 구성)
1. 존 선택 상자
2. 선택한 존으로 조회

질문에 따라 **건너뛰고 전체 조회** 버튼이 함께 나올 수 있습니다(존을 고르지 않고 전체를 조회).
:::
::: caution
- 기본 설정에서는 은행존과 공동존을 함께 고를 수 있습니다. 관리자가 존 그룹 상호배타(`ZONE_GROUP_EXCLUSIVE`)를 켠 환경에서는 한 그룹(은행존 또는 공동존) 안에서만 고를 수 있으니, 둘 다 필요하면 따로 두 번 물으세요.
- 질문에 「김포」, 「여의도」, 「은행존」처럼 위치를 적으면 되묻지 않고 바로 조회합니다.
- 「운영」은 **김포**, 「개발」·「스테이징」·「DR」은 **여의도** 폴스타를 가리키는 말로 알아듣습니다(예: 「운영 서버 목록」 → 김포 조회 · 「DR 서버 CPU 사용률」 → 여의도 조회). 「운영체제」·「운영 중인」·「운영자」·「운영팀」의 「운영」이나 「DRM」처럼 다른 뜻으로 쓴 말은 위치로 보지 않습니다(예: 「운영 중인 서버 목록」은 존을 되묻습니다).
- 선택지에는 **내 계정이 조회할 수 있는 DB가 속한 존만** 나옵니다. 원하는 존이 없으면 관리자에게 권한을 요청하세요. 권한 있는 존이 하나도 없으면 되묻지 않고 「조회할 수 있는 DB가 없습니다…」로 답합니다.
- 이 사례 화면은 테스트 환경에서 찍었습니다. 선택지는 설치 환경의 존 구성에 따라 다릅니다.
- 존을 일부만 골라 조회하면 답 끝에 「공동존 김포만 조회했습니다. **은행존, 공동존 여의도은(는) 조회하지 않았습니다**」와 **전체 범위로 다시 조회** 버튼이 붙습니다. 같은 공동존이라도 김포만 골랐으면 여의도는 미조회로 적힙니다. 질문에 「전체」가 있었으면 문장 앞에 「전체가 아니라」가 붙습니다.
- 존을 고르지 않았는데도 「전체」 질문이 일부 존만 조회된 경우에도 「전체가 아니라 …만 조회했습니다(… 미조회)」가 붙습니다. 권한이 없는 존 이름은 나오지 않습니다.
- 등록되지 않은 존(예: 「판교존」)을 적으면 조회할 수 있는 존을 되묻습니다. 존을 골라 보내면 답 끝에 「'판교존'은(는) 등록된 존이 아니어서 선택하신 …(으)로 조회했습니다」가 붙습니다.
:::

## 6. 양식 채우기(Excel·Word)

정해진 양식 파일을 올리면 알맞은 데이터로 채워 돌려줍니다.

### U-26
::: what
Excel(.xlsx) 또는 Word(.docx) 양식을 질문과 함께 보냅니다.
:::
::: case F-SERVER-LIST
포인트: 양식을 첨부하고 **어떤 데이터로** 채울지와 「파일로 만들어줘」를 함께 말하세요. 열 이름은 양식에서 읽습니다. 「채워줘」 한마디만 쓰기보다 이 사례처럼 풀어 쓰는 편이 정확합니다.
:::
::: how
1. 입력줄의 **클립(📎)** 버튼을 누르고 파일을 고르세요.
2. 입력줄 위에 파일 이름과 크기가 표시됩니다. 잘못 골랐으면 **Remove**로 빼세요.
3. 질문을 적고 보내세요.
:::
::: ui file-attached 파일을 첨부한 입력줄
1. 첨부한 파일
2. 첨부 취소(Remove)
3. 채울 데이터를 말하는 질문
:::
::: caution
- .xlsx·.docx만 됩니다. .xls·.csv는 변환해서 올리세요.
- 파일 크기는 10MB까지입니다.
:::
::: detail
#### 입력 규칙과 한도
- 한 번에 파일 1개만 첨부됩니다. 다른 파일을 고르면 앞의 파일을 대신합니다.
- 파일만 올리고 질문을 비워 두면 보내지지 않고 「질의를 입력해주세요.」가 뜹니다. 질문은 2,000자까지입니다.
- 형식은 파일 이름의 확장자로 판단합니다. 다른 형식이면 「지원하지 않는 파일 형식입니다. .xlsx 또는 .docx 파일만 첨부할 수 있습니다.」, 크기를 넘으면 「파일 크기가 10MB를 초과합니다.」가 뜨고 첨부되지 않습니다.
- 양식은 조건에 맞는 행을 최대 10,000행까지 채웁니다. 「100건」처럼 건수를 적으면 그 수만큼만 채웁니다.

#### 이렇게 동작합니다
- 파일을 첨부한 질문은 앞 대화에서 이어받은 서버·DB 조건 없이 새로 시작합니다. 앞 질문의 대상으로 채우려면 그 대상을 질문에 다시 적으세요.
- 입력줄 위 조회 대상 칩에서 이번에 고른 DB는 파일 질문에도 적용됩니다([U-24](#u-24)).

#### 상황별 결과
- 질문에 지역(위치) 표현이 없고 조회 대상 칩에서 DB도 고르지 않았으면, 「양식을 채울 대상 존이 지정되지 않았습니다. 아래에서 대상 존을 선택해 주세요.」로 되묻습니다.
- 존을 골라 **선택한 존으로 조회**를 누르면 첨부했던 파일로 그대로 다시 보냅니다. 파일을 다시 올릴 필요가 없습니다([U-25](#u-25)).
:::
::: related
- [U-27 양식 채우기 결과 받기](#u-27)
- [U-32 양식 만드는 요령](#u-32)

### U-27
::: what

:::
::: case F-SERVER-LIST form-result
포인트: 답 말풍선에 **결과 파일 다운로드** 버튼이 생깁니다. 양식의 머리글(호스트명·IP주소·OS종류…)에 맞춰 행이 채워집니다. **받은 파일은 꼭 열어 확인하세요** — 이 사례에서는 호스트명이 없는 서버 4대가 빈 행으로 남았습니다(원본 데이터에 값이 없는 서버).
:::
::: case F-CPU-MONTH
포인트: 성능 양식은 기준 기간(「2026년 5월 기준」)을 꼭 적으세요. 그 기간에 통계가 있는 서버(이 샌드박스에서는 4대)만 채워지고 나머지는 빈칸으로 남습니다.
:::
::: case F-WORD
포인트: Word 양식의 **표**는 조회 결과로 채워집니다. 표 밖의 자리 표시는 질문에 적은 값(「부서는 인프라운영팀」 → `{{부서}}`)과 결과 건수(`{{서버수}}` → 54)로 채웁니다. 질문에도 결과에도 없는 자리 표시는 지어내지 않고 빈칸으로 둡니다 — 받은 파일에서 직접 채우세요.
:::
::: how
1. 답이 끝나면 **{파일명} 다운로드**를 누르세요.
2. 채우지 못한 항목이 있으면 되묻는 상자가 나옵니다([U-29](#u-29)).
:::
::: ui form-result 양식 채우기 결과
1. 결과 파일·매핑 보고서 내려받기
:::
::: caution
- 양식의 열 이름이 DB 항목과 전혀 다르면 채우지 못할 수 있습니다. 매핑 보고서로 어떻게 연결했는지 확인하세요([U-31](#u-31)).
:::

## 7. 대화와 이력

앞 질문에 이어서 묻고, 지난 대화를 다시 여는 방법입니다.

### U-34
::: what
앞 질문의 결과를 이어받아 「그 서버」, 「해당 서버」처럼 물을 수 있습니다. 앞 질문이 서버 한 대를 조회했으면 「그럼 메모리도 보여줘」처럼 대상을 빼고 물어도 그 서버를 이어받습니다. 이렇게 이어받으면 답 끝에 **[직전 서버 기준]** 안내가 붙습니다.
:::
::: case Q-MULTI-HOST multiturn

::: how

::: caution

### U-37
::: what

3. 기준 항목을 모르면 낱말만 묶어 보내 보세요. 시스템이 기준 항목을 찾을 수 있으면 등록하고, 못 찾으면 방법을 안내합니다.

### U-46
::: what
관리자가 **채팅 문서 검색**을 켠 환경에서는, 사내 규정·업무 절차·승인 기준·담당자별 역할과 책임(R&R)이나 시스템 설계 근거처럼 **문서의 내용**을 물으면 등록된 사내 문서에서 찾아 **문서 근거와 참고 문서 목록**을 붙여 답합니다. 기본은 꺼져 있습니다 — 꺼진 환경에서는 같은 질문을 문서에서 찾지 않습니다.
:::
::: how
1. 입력창에 문서 내용을 묻는 질문을 완전한 문장으로 적으세요. 예: 「계정 신청은 누가 승인하나요?」, 「백업 담당자의 역할은?」
2. 문서에 쓰인 **용어·문서명·조항 번호를 그대로** 넣으면 더 잘 찾습니다.
3. **반드시 문서에서 찾게 하려면** 문서 이름과 함께 검색을 명령하세요. 예: 「RAG에서 서버 관리자의 역할을 검색해줘」, 「본부 매뉴얼에서 백업 담당자의 역할을 찾아줘」, 「아키텍처 문서에서 서버 구성 단위를 찾아줘」. 이렇게 물으면 일반 지식으로 답하지 않고 문서에서만 찾습니다.
4. 「본부 매뉴얼에서」·「아키텍처 문서에서」처럼 **문서군을 지정하면** 그 문서군만 찾아 더 정확합니다. 「RAG에서」처럼 문서군 없이 지정하면 등록 문서군 전체에서 찾고, 답 첫 줄에 그 사실과 지정 방법을 알려 줍니다.
5. 답 아래의 **참고 문서** 목록에서 근거가 된 문서와 절을 확인하세요.
6. 서버 수치·목록·발생한 알람처럼 **지금 상태**를 묻는 질문은 종전처럼 조회로 답합니다. 두 가지를 한 번에 물으면 따로따로 답합니다.
:::
::: ui -
화면 캡처가 없습니다. 채팅 문서 검색은 사내망의 문서 검색 서비스에 연결된 환경에서만 동작해 캡처 환경에서 재현할 수 없습니다. 처리 현황에는 **문서 검색** 작업으로 표시됩니다.
:::
::: caution
- 문서에서 찾지 못하면 **지어내지 않고** 찾지 못했다고 답합니다. 같은 질문을 다시 보내도 결과가 같으니, 문서에 쓰인 말로 표현을 바꿔 보세요.
- 「문서 색인이 갱신되어 조회할 수 없습니다」는 관리자 조치가 필요하다는 뜻입니다. 관리자에게 알려 주세요.
- 문서 내용은 작성 시점 기준입니다. 조회 결과(현재 상태)와 다를 수 있습니다.
- 권한이 없으면 「요청하신 정보를 조회할 권한이 없습니다」로 답합니다. 필요하면 관리자에게 요청하세요.
- 문서 이름 + 검색 명령(3번)은 **다른 데이터 소스를 함께 지정하지 않았을 때만** 바로 문서로 갑니다. 「RAG에서 … 찾고 김포 폴스타에서 CPU 보여줘」처럼 섞으면 종전처럼 질문을 나눠 처리하니, 문서 질문은 따로 물으세요.
- 채팅 문서 검색이 꺼진 환경에서 문서 이름으로 검색을 명령하면 「요청하신 「RAG」 데이터 소스는 현재 연결되어 있지 않아 조회하지 않았습니다」로 답합니다(일반 지식으로 대신 답하지 않습니다).
- 어떤 문서가 등록돼 있는지는 「무엇을 할 수 있나요?」처럼 사용법을 물으면 안내합니다(기능이 켜져 있을 때만 보입니다).

### U-47
::: what
질문에 **데이터 소스 이름**을 넣으면 그 소스에서 조회합니다. 소스마다 다른 이름(유사어)으로 불러도 알아듣습니다. 지정한 소스가 이 환경에 연결되어 있지 않으면 **다른 소스의 값으로 대신 답하지 않고**, 연결되어 있지 않아 조회하지 않았다고 알려 줍니다.
:::
::: how
1. 질문에 소스 이름을 넣으세요. 예: 「제니퍼의 인스턴스 리스트를 보여줘」, 「자산관리 DB에서 담당자 목록 보여줘」
2. 아래 이름은 모두 알아듣습니다.

| 데이터 소스 | 이렇게 불러도 됩니다 | 주로 묻는 것 |
|---|---|---|
| 제니퍼(WAS 모니터링) | 제니퍼 · JENNIFER · APM | WAS 인스턴스 목록 · 응답시간 · JVM 힙 · 실행 중 서비스 |
| 자산관리 | ITAM · 자산관리 · 자산관리 DB | 자산 담당자 · 담당 부점 · 계약 · 지원 종료일 |
| 사내 문서 | RAG · 사내 문서 · 전산관리매뉴얼 · 본부 매뉴얼 · 전산관리규정 · 설계문서 · 아키텍처 문서 | 규정 · 절차 · 역할과 책임 · 설계 근거([U-46](#u-46)) |
| Prometheus | 프로메테우스 · Prometheus | 채팅 조회는 아직 지원하지 않습니다 — 지정하면 연결되어 있지 않다고 안내합니다 |
| 폴스타 | 폴스타 · 위치 이름(김포 · 여의도 · 은행존 등) | 서버 사양 · 사용률 · 알람 — 위치 지정은 [U-25](#u-25) |

3. 소스를 말하지 않으면 **묻는 정보**(예: WAS 인스턴스 · 자산 담당자 · 서버 CPU)를 가진 소스에서 조회합니다. WAS 인스턴스처럼 한 소스에만 있는 정보는 묻지 않고 그 소스로 바로 갑니다. 그 소스가 이 환경에 연결되어 있지 않으면 「요청하신 정보(WAS 인스턴스 목록…)를 가진 데이터 소스가 현재 연결되어 있지 않아 조회하지 않았습니다」처럼 안내하고 **다른 소스의 비슷한 값으로 대신 답하지 않습니다.**
   여러 소스가 답할 수 있는 정보면 어느 소스에서 볼지 한 번 묻습니다([U-48](#u-48)).
4. 제니퍼에 대상 서버 없이 「인스턴스 목록」을 물으면 인스턴스 목록을 보여 줍니다. 도메인 ID를 함께 적으면(예: 「도메인 ID 1000인 인스턴스 목록」) 그 도메인의 인스턴스만 보여 줍니다. 특정 서버의 응답시간을 원하면 서버 이름을 함께 적으세요.
:::
::: ui -
화면 캡처가 없습니다. 입력창에 이름을 넣는 것만으로 동작합니다. 처리 현황에는 지정한 소스의 조회 작업이 표시됩니다.
:::
::: caution
- 연결되지 않은 소스를 지정하면 「요청하신 「제니퍼」 데이터 소스는 현재 연결되어 있지 않아 조회하지 않았습니다. 다른 데이터 소스의 값으로 대신 답하지 않았습니다.」처럼 답합니다. 필요하면 관리자에게 연결을 요청하세요.
- 제니퍼가 연결돼 있어도 결과가 0건이거나 오류면 그 사유를 알려 주고, **다른 소스로 다시 조회하지 않습니다.**
- 권한이 없는 소스는 「요청하신 정보를 조회할 권한이 없습니다…」로 답합니다(관리자 「조회 가능 소스」).
- 「모니터링」·「서버」처럼 일반적인 말은 소스 이름으로 보지 않습니다. 표의 이름을 쓰세요.
- 두 소스를 한 질문에 함께 지정하면(예: 「자산관리 담당자와 제니퍼 인스턴스」) 질문을 나눠 묻는 편이 정확합니다.
:::

### U-48
::: what
여러 데이터 소스가 답할 수 있는 질문(예: 소스 이름 없이 묻는 「인스턴스 목록」)이면, 답하기 전에 **어느 데이터 소스에서 볼지** 선택 칩으로 한 번 묻습니다. 소스 이름을 넣었거나 한 소스에만 있는 정보는 묻지 않습니다.
:::
::: how
1. 답 칸에 「요청하신 정보(…)는 여러 데이터 소스에 있습니다. 조회할 데이터 소스를 선택해 주세요.」와 선택지가 나옵니다.
2. 소스 하나를 고르세요. 폴스타처럼 존이 있는 소스는 존 단위로 나와서 소스와 존을 **한 번에** 고릅니다(같은 소스의 존은 여러 개 고를 수 있습니다).
3. **선택한 데이터 소스로 조회**를 누르면 원래 질문을 그 소스에서 조회합니다. 선택은 「선택: …」으로 대화에 남습니다.
4. 같은 대화에서 비슷한 질문을 다시 하면 고른 소스로 바로 조회하고 다시 묻지 않습니다. 다시 고르고 싶으면 상단 조회 대상 칩을 해제하거나([U-24](#u-24)) 소스 이름을 넣어 물으세요.
:::
::: ui -
화면 캡처가 없습니다. 모양은 존 선택([U-25](#u-25))과 같은 체크 상자 묶음이고, 확인 버튼 이름만 「선택한 데이터 소스로 조회」입니다.
:::
::: caution
- 선택지에는 지금 연결되어 있고 **조회 권한이 있는** 소스만 나옵니다. 고를 소스가 하나뿐이면 묻지 않고 그 소스로 조회합니다.
- 관리자가 「소스 선택 기억」을 켠 환경에서는, 전에 비슷한 질문에서 고른 소스로 바로 조회하고 「이전에 비슷한 질문에서 ‘…’를 고르셔서 그 기준으로 조회했습니다」라고 알려 줍니다. 아래에 나오는 선택지로 다른 소스를 고르면 그 선택으로 바꿔 기억합니다([U-49](#u-49)).
- 일괄 처리·API 직접 호출처럼 대화가 아닌 경로에서는 묻지 않고 첫 후보 소스로 조회한 뒤 그 사실을 알려 줍니다.
:::

### U-49
::: what
소스 선택 칩에서 고른 소스를 시스템이 기억해 두었다가, 비슷한 질문에서 다시 묻지 않고 그 소스로 조회합니다(관리자가 켠 환경에서만 — 기본은 꺼짐). 내 기억은 채팅으로 보거나 지울 수 있습니다.
:::
::: how
1. 기억 보기: 「소스 기억 보여줘」라고 보내세요. 기억된 질문과 고른 소스, 사용 횟수가 나옵니다.
2. 기억 지우기: 「소스 기억 삭제해줘」라고 보내면 내 기억을 모두 지웁니다. 다음에 비슷한 질문을 하면 다시 묻습니다.
3. 한 건만 바꾸려면 기억으로 조회된 답 아래의 선택지에서 다른 소스를 고르세요 — 그 선택으로 바꿔 기억합니다.
:::
::: ui -
화면 캡처가 없습니다. 입력창에 명령을 보내는 것만으로 동작합니다.
:::
::: caution
- 기억은 **내 선택만** 내 질문에 쓰입니다. 다른 사람의 선택은 관리자가 「조직 공용」으로 올린 경우에만 쓰입니다.
- 오래 쓰지 않은 기억은 저절로 사라집니다(기간은 관리자 설정). 기능이 꺼져 있으면 「소스 선택 기억 기능이 꺼져 있습니다」로 답합니다.
- 소스 이름을 넣은 질문과 한 소스에만 있는 정보는 기억과 관계없이 그 소스로 갑니다.
:::

### U-51
::: what
제니퍼(WAS 모니터링)에 응답시간·JVM 힙·실행 중 서비스·느린 트랜잭션·WAS 이벤트를 물을 때 **기간 · 개수(상위 N) · 이벤트 레벨 · 오류 유형 · 「전부」**를 말하면 그 조건대로 조회합니다. **URL·SQL·외부 호출별 시 단위 통계**, **조회할 수 있는 지표 목록**, **소스(리소스) 변경 감지 시각**도 물을 수 있습니다. 서버 이름을 몰라도 **제니퍼 인스턴스 이름이나 업무명**으로 물을 수 있습니다. 답 아래에는 시스템이 계산한 **판정·집계** 블록(WAS 판정과 근거 · 구간 호출 수·오류율·p50·p95 · 시 단위 합계 · 오류 유형별 건수)이 붙습니다.
:::
::: how
1. 서버 이름과 묻는 것, 조건을 함께 적으세요.

| 이렇게 물으면 | 이렇게 조회합니다 |
|---|---|
| 「web01 지난 3시간 JVM 힙 추세」 | 말한 3시간 전체(잘라 내지 않습니다) |
| 「web01 느린 트랜잭션 상위 5개」 | 응답시간 순 상위 5건 |
| 「web01 최근 10분 트랜잭션 전부」 | 상위 N이 아니라 그 구간 전부 |
| 「web01 fatal 이벤트만」 | fatal 레벨만 |
| 「web01 warning 이상 이벤트」 | warning과 그보다 높은 레벨 |
| 「web01 OutOfMemory 오류 기록」 | 그 오류 유형의 오류 기록 목록 |
| 「web01 실행 중 서비스 상위 3개」 | 경과 시간이 긴 순서 3건 |
| 「web01 오늘 호출 많은 URL 상위 10개」 | URL(애플리케이션)별 시 단위 통계 — 호출 수 순 10건 |
| 「web01 지난 3시간 많이 호출된 SQL 상위 5개」 | SQL별 시 단위 통계 5건 |
| 「web01 오늘 외부 호출 통계 전부」 | 외부 호출(연계 대상)별 시 단위 통계 전부 |
| 「인스턴스 지표로 뭘 볼 수 있어?」 | 조회할 수 있는 인스턴스 지표 이름 목록(서버 이름 없이 물어도 됩니다) |
| 「web01 지난 6시간 힙 추세 10분 간격」 | JVM 힙 추세를 10분 간격으로 |
| 「web01 어제 소스 변경 있었어?」 | 소스(리소스) 변경 감지 시각 목록 |
| 「abc-was 응답시간」(가상 이름) | 이름이 「abc-was」이거나 비슷한 제니퍼 인스턴스를 찾아 그 인스턴스마다 응답시간 |
| 「결제 업무 WAS 힙 사용률」(가상 이름) | 업무명 「결제」로 찾은 제니퍼 인스턴스마다 JVM 힙 사용률 |

2. 기간을 말하지 않으면 정보마다 기본 구간으로 조회합니다(느린 트랜잭션 최근 10분 · WAS 이벤트 최근 30분).
3. 답 끝의 **판정·집계**를 확인하세요. 예: 「판정 힙 메모리 압박(CRITICAL) — web01 #1001: …」 · 「느린 트랜잭션 · web01: 구간 호출 1,234건 · 오류율 2.1% · p50 120ms · p95 980ms」. 이 줄은 시스템이 계산한 값을 그대로 싣습니다.
4. 결과가 아주 크거나 오래 걸리면 작업 카드로 받습니다([U-50](#u-50)).
5. 묻는 정보가 무엇인지 시스템이 한 번에 정하지 못하면, 고를 수 있는 제니퍼 정보만 놓고 한 번 더 판단합니다. 그래도 정하지 못하면 다른 정보(응답시간 등)로 대신 답하지 않고 「요청하신 정보(…)에 맞는 … 조회를 정하지 못해 조회하지 않았습니다. 다음 중 원하는 것을 골라 다시 물어 주세요: 「…」 · 「…」」처럼 되묻습니다. 고른 이름을 넣어 다시 물으세요.
6. 여러 정보를 함께 물었는데 일부만 정했으면, 정한 정보는 조회해 답하고 정하지 못한 부분만 「요청하신 정보 중 …에 맞는 … 조회를 정하지 못해 그 부분은 조회하지 않았습니다. 다음 중 원하는 것을 골라 다시 물어 주세요: 「…」」로 되묻습니다. 그 부분만 골라 다시 물으세요.
7. 서버 이름 대신 **인스턴스 이름이나 업무명**으로 물어도 됩니다(위 표의 「abc-was 응답시간」·「결제 업무 WAS 힙 사용률」). 이름이 정확하지 않아도 비슷한 인스턴스를 찾아 조회하고, 「[안내] '결제' → 제니퍼 인스턴스 3개(근거: 제니퍼 업무 정의 2 · 폴스타 비고 1)」처럼 무엇을 근거로 찾았는지 알려 줍니다. 찾지 못하면 다른 인스턴스로 대신 조회하지 않고 「'abc-wsa'에 해당하는 제니퍼 인스턴스를 찾지 못해 조회하지 않았습니다(검색: …). 다른 인스턴스로 대신 조회하지 않았습니다. 비슷한 이름: abc-was-01 · abc-was-02 — 자동으로 고르지 않았습니다.」처럼 비슷한 이름 후보를 보여 줍니다. 후보 중 원하는 이름을 넣어 다시 물으세요.
:::
::: ui -
화면 캡처가 없습니다. 입력창에 조건을 넣어 묻는 것만으로 동작합니다.
:::
::: caution
- 아래 안내는 답 끝에 「[안내] …」 줄로 붙습니다. 한 답에 이런 안내가 많으면 우선순위가 높은 3줄까지만 본문에 싣습니다. 해석하지 못한 조건·되묻기 같은 꼭 알려야 하는 안내는 줄 수와 관계없이 모두 싣습니다.
- 커넥션 풀·지금 실행 중인 서비스는 현재값만 있습니다. 기간을 말하면 「현재값 기준입니다 — 현재값만 있는 보기라 요청 기간의 값이 아닙니다」와 함께 지금 값을 보여 줍니다.
- 긴 구간의 응답시간에는 시 단위 통계가 붙을 수 있습니다. 「시 단위 통계라 요청 구간보다 넓은 정시 경계로 집계한 값입니다」가 붙으면 정시 경계로 묶인 값입니다.
- 알아듣지 못한 조건(예: 없는 레벨 이름)은 빼고 조회하고 「해석하지 못한 조건(…)은 빼고 조회했습니다」로 알립니다. 조건을 하나도 알아듣지 못해도 그 정보는 조건 없이 조회합니다 — 결과가 원하던 범위인지 확인하고, 아니면 조건을 다시 말씀해 주세요.
- 하루 넘게 지난 기간은 아직 조회하지 않습니다(「하루 넘게 지난 기간은 아직 조회하지 않습니다 — 보존 기간 확인 전」).
- URL·SQL·외부 호출 통계는 시 단위로만 모입니다. 「시 단위 통계라 요청 구간보다 넓은 정시 경계로 집계한 값입니다」가 붙습니다(예: 9시 10분~9시 40분을 물어도 9시~10시 값). 판정·집계의 「시 단위 합계 … — 받은 N행의 합계」는 받은 행(상위 N개를 물었으면 그 N개)만 더한 값입니다.
- 소스 변경은 제니퍼 데이터 서버가 **변경을 알아챈 시각**입니다. 「…배포 시각으로 확정할 수 없습니다」가 붙습니다 — 배포 기록과 함께 보세요.
- 지표 목록은 서버 이름 없이 물어도 됩니다. 추세에 지표 이름을 지정할 때는 지표 목록에 나온 이름을 그대로 쓰세요.
- SQL·URL처럼 아주 긴 값은 화면 표에서 300자까지만 보이고 「…(총 N자 — 전체는 CSV)」로 끝납니다. 전체는 CSV로 받으세요.
- 「전부」는 목록을 묻는 질문에만 쓰입니다. 이벤트 레벨은 fatal · warning · normal 중 하나로 적으세요(대소문자 무관). 오류 유형 이름은 제니퍼 화면의 표기 그대로 적으면 정확합니다.
- 사용자 ID처럼 개인정보·자격증명에 해당하는 칸은 값을 가려서 보여 줍니다. 가린 칸이 있으면 「개인정보·자격증명 보호를 위해 값을 가린 칸: …」 안내가 붙습니다(다른 안내가 많으면 우선순위가 낮아 빠질 수 있습니다).
- 인스턴스 이름이나 업무명으로 찾은 인스턴스는 **개수 제한 없이 모두** 조회합니다. 많이 찾으면 오래 걸릴 수 있습니다(작업 카드로 받을 수 있습니다 — [U-50](#u-50)). 「무엇을 근거로 찾았는지」 안내는 다른 안내가 많으면 본문에서 빠질 수 있습니다.
- 업무명을 제니퍼 업무 정의로 찾을 때는 그 업무를 **지금 처리 중이거나 최근 5분 안에 처리한** 인스턴스만 찾습니다(「업무 정의 근거는 최근 처리한 인스턴스만 찾는다…」 안내). 운영자가 업무와 인스턴스를 직접 묶어 둔 업무명은 그 목록만 씁니다.
- 업무명으로 처음 물으면 업무 정의를 읽느라 수십 초가 걸릴 수 있습니다. 10분 안에 다시 물으면 빠릅니다.
- 폴스타 서버 등록명·비고로 찾는 근거는 내가 조회 권한을 가진 DB에서만 찾습니다.

### U-52
::: what
제니퍼(WAS 모니터링)에서 **앞 답의 표를 이어 물을 수 있습니다** — 느린 트랜잭션·WAS 이벤트 목록의 「N번째 트랜잭션 프로파일(실행 구간 발췌·실행 SQL)」, 트랜잭션 목록의 「N번째 거래와 같은 GUID를 가진 연계 거래」, 실행 중 서비스 목록의 「N번째 요청 상세(SQL·HTTP 파라미터)」입니다. **소스 변경 감지 전후 비교**(오류율·평균 응답·오류 기록·호출 수)와 **제니퍼 설정·관리 정보**(이벤트 룰·응답시간 색상 경계·PID로 WAS 인스턴스 찾기·데이터 서버·도메인 DB 경로·수동 RDB Export 상태·로드된 클래스·WAS 환경변수와 JVM 옵션·제니퍼 사용자 계정)도 물을 수 있습니다.
:::
::: how
1. 목록을 먼저 조회한 뒤, 몇 번째인지 함께 이어 물으세요. 설정·관리 정보는 바로 물으면 됩니다.

| 이렇게 물으면 | 이렇게 조회합니다 |
|---|---|
| 「web01 느린 트랜잭션 상위 5개」 다음에 「두 번째 트랜잭션 프로파일 보여줘」 | 앞 답 표의 2번째 트랜잭션 프로파일(실행 구간 발췌·실행 SQL) |
| 「그 트랜잭션 실행 SQL 5개만」 | 앞 답에 트랜잭션이 하나뿐이면 그 트랜잭션의 실행 SQL 5개 |
| 「세 번째 거래 GUID로 연계 거래 찾아줘」 | 같은 GUID를 가진 거래를 볼 수 있는 제니퍼 전체에서 찾아 시각순으로 |
| 「GUID 0a1b2c3d 거래가 어느 서버를 거쳤어?」 | 적은 GUID로 연계 거래 찾기 |
| 「web01 실행 중 서비스」 다음에 「첫 번째 요청 상세 보여줘」 | 그 실행 중 요청의 SQL·HTTP 파라미터·사용자(가림) |
| 「web01 배포 전후 에러율 비교」 | 최근 24시간의 소스 변경 감지마다 전후 60분 비교 |
| 「web01 어제 변경 전후 30분 응답시간 비교」 | 말한 기간의 변경 감지마다 전후 30분 비교 |
| 「web01 이벤트 룰 보여줘」 · 「응답시간 색상 경계 설정」 | 이벤트 룰(오류·지표·비교) · 실행 중 서비스 색상 경계 |
| 「web01 PID 12345는 어느 WAS 인스턴스야?」 | 그 프로세스의 WAS 인스턴스 |
| 「제니퍼 데이터 서버 상태」 · 「web01 도메인 DB 경로」 | 데이터 서버 배치·자원·설정 · 그 서버 도메인의 DB 경로 |
| 「web01 로드된 클래스 중 OrderService」 | 로드된 클래스 목록에서 이름으로 찾기 |
| 「web01 JVM 시스템 속성 보여줘」 · 「web01 환경변수 JAVA_OPTS」 | JVM 시스템 속성 · 이름에 JAVA_OPTS가 들어간 변수(비밀 값은 가림) |
| 「제니퍼 사용자 목록」 · 「제니퍼 계정 admin 정보」 | 제니퍼 사용자 계정(개인정보 가림) |

2. 몇 번째인지 말하지 않았는데 앞 답에 고를 행이 여럿이면 바로 조회하지 않고 「… 후보가 N건이라 어느 것인지 정하지 못해 조회하지 않았습니다. 몇 번째인지 함께 다시 물어 주세요: 1번 「…」 · 2번 「…」 · 3번 「…」」처럼 되묻습니다. 번호를 넣어 다시 물으세요. 번호가 표보다 크거나, 알아볼 수 없는 번호(예: 「0번째」)이거나, 그 행에 고를 정보가 없을 때도 같은 방식으로 되묻습니다(고를 행이 하나뿐이어도 그렇습니다).
   앞 답에 고를 수 있는 표가 여럿이면(예: 느린 트랜잭션 표와 WAS 이벤트 표) 번호는 표마다 따로 세므로 어느 표인지 정하지 못해 「… 후보가 표 2개에 걸쳐 있어 …」로 표마다 후보를 들어 되묻습니다. 원하는 목록만 다시 조회한 뒤 몇 번째인지 물어 주세요.
3. 「PID로 WAS 인스턴스 찾기」는 PID가 꼭 필요합니다. 빠지면 「필요한 조건(프로세스 ID(PID))이 없거나 해석하지 못해 조회하지 않았습니다」로 되묻습니다.
4. 서버를 말하지 않은 설정·관리 질문(이벤트 룰·환경변수·PID 찾기 등)은 볼 수 있는 제니퍼 전체를 조회합니다. 앞 대화의 서버로 좁히려면 「그 서버의 JVM 옵션」처럼 가리켜 주세요.
5. 답 끝 **판정·집계**에 연계 거래 요약(「GUID …: 거래 N건 · 도메인 M곳(조회 …곳 · 실패 …곳) · 시작 ~ 끝 · 조회 구간 … ~ …(기간 미지정 — …) · 같은 GUID일 뿐 호출 관계가 아님 · 인스턴스 …」)과 변경 전후 비교(「… 변경 감지 … — 오류율 a → b(±%p) · 평균 응답 a → b(±%) · 오류 기록 a → b · 호출 a → b」)가 붙습니다. 시스템이 계산한 값을 그대로 싣습니다.
:::
::: ui -
화면 캡처가 없습니다. 입력창에 이어 묻는 것만으로 동작합니다.
:::
::: caution
- 「N번째」는 **같은 대화의 앞 답**(또는 한 질문 안의 앞 단계 결과)에서만 고릅니다. 다른 대화의 결과는 가리킬 수 없습니다. 고를 행이 없으면 다른 정보로 대신 답하지 않고 「앞 결과에 … 없어 조회하지 않았습니다」로 알립니다.
- 한 질문에서 목록과 N번째 상세를 함께 물으면(예: 「web01 느린 트랜잭션 보고 두 번째 프로파일도」) 목록 표와 상세 표가 차례로 따로 나옵니다 — 서버별 한 표로 합치지 않습니다.
- 바로 앞 답이 목록이 아니었으면(예: 프로파일 상세·서버 사용률) 그 앞의 목록을 이어서 씁니다. 결과 표의 서버·txid·시각으로 원하던 행인지 확인하세요.
- 권한은 매번 다시 확인합니다 — 앞 답을 볼 수 있었어도 지금 제니퍼 조회 권한이 없으면 조회하지 않습니다.
- 연계 거래는 **같은 GUID를 가진 거래 묶음**입니다 — 어디서 어디로 불렀는지(호출 관계)를 뜻하지 않습니다. 서버마다 시계가 조금씩 달라 순서는 각 서버 시각 기준입니다. 기간을 말하지 않으면 앞 답 거래 시각 앞뒤 5분(GUID를 직접 적었으면 최근 60분)을 봅니다 — 실제로 찾은 구간은 판정·집계 줄의 「조회 구간」으로 확인하세요(0건일 때도 나옵니다). 서버를 말하면 그 서버에서만 찾습니다(같은 거래는 한 번만 나옵니다).
- 변경 전후 비교는 변경 **감지** 시각 전후에 함께 일어난 변화입니다 — 원인이나 배포 시각으로 확정하지 않습니다. 방금 변경됐으면 변경 뒤 구간이 비교 폭보다 짧습니다. 값이 없는 칸은 N/A로 나옵니다(0으로 세지 않습니다). 하루 넘게 지난 기간은 아직 조회하지 않습니다.
- 환경변수·JVM 옵션·설정의 비밀번호·토큰 같은 비밀 값은 가려서 보여 주고, 사용자 계정의 ID·이름·이메일·전화번호·허용 IP도 가립니다. 비밀번호는 아예 싣지 않습니다.
- 로드된 클래스는 서버 이름이 필요합니다(말하지 않으면 인스턴스 목록에서 먼저 고릅니다). 프로세스 → 인스턴스 찾기와 일부 설정 조회는 제니퍼 버전에 따라 지원하지 않을 수 있습니다 — 조회하지 못하면 그 사유를 알려 드립니다.
- 실행 중 요청 상세는 지금 실행 중인 요청만 볼 수 있습니다 — 이미 끝난 요청이면 결과가 없습니다.

## 9. 이벤트 알람

### U-40
::: what

:::
::: how
1. **이벤트 알람** 탭을 누르세요.

#### 이렇게 동작합니다
화면 전체에 공통으로 걸리는 원리입니다. 각 항목을 열어 보세요.

##### 숫자는 모두 결정 기록에서 나옵니다
**무엇인가** — 이 화면의 숫자·그래프·목록이 읽는 단 하나의 출처입니다.

**어떻게 동작하나** — 알람 거르기가 알람 한 건을 판단할 때마다 판단 결과, 사유, 판단한 단계, 판단 순간의 신호 값을 결정 기록에 한 줄씩 남깁니다. 화면은 그 줄을 세고 늘어놓을 뿐 따로 계산한 값을 보관하지 않습니다.

**읽는 법** — 카드의 「건수」는 알람 수가 아니라 판단 수입니다. 같은 알람도 재통보 간격이 지나 다시 판단되면 두 번 셉니다.

##### 화면에 나오지 않는 알람
**무엇인가** — 판단까지 가지 못해 결정 기록에 줄이 없는 알람입니다.

**어떻게 동작하나** — 아래 두 경우는 판단 전에 끝나 이 화면 어디에도 나오지 않습니다.

- 같은 알람이 재통보 간격 안에 다시 와서 판단 전에 걸러진 경우(반복 횟수는 따로 남지만 이 화면은 세지 않습니다)
- 최소 심각도보다 낮아 판단 전에 버려진 경우 — 기본 설정에서는 「주의」 알람이 여기에 해당합니다(기본값이며 설치 설정에 따라 다를 수 있습니다)

**이상할 때** — 모니터링 시스템에는 있는데 여기서 찾을 수 없는 알람은 위 둘 중 하나입니다. AI 분석이 실패한 알람도 원문으로 판단되어 여기에 나옵니다. 흐름은 [U-45](#u-45)에서 확인하세요.

##### 기간과 읽는 범위
**무엇인가** — 기간 버튼이 정하는 「지금부터 거꾸로 얼마 동안」의 범위입니다.

**어떻게 동작하나** — 기간은 지금 시각에서 거꾸로 1시간·24시간·7일·30일입니다. 다만 결정 기록을 파일 끝에서부터 최근 20,000줄까지만 읽습니다(기본값이며 설치 설정에 따라 다를 수 있습니다).

**이상할 때** — 알람이 많은 환경에서 7D·30D를 고르면 기간의 앞부분이 빠질 수 있습니다. 30D 숫자가 7D와 거의 같다면 이 한도에 걸린 것입니다.

##### 화면의 시각
**무엇인가** — 목록·그래프·결정 추적에 적히는 시각입니다.

**어떻게 동작하나** — 기록에 남는 시각은 알람이 모니터링 시스템에서 발생한 시각이 아니라 **판단을 내린 시각**입니다. 화면은 이 시각을 지금 쓰는 브라우저의 시간대로 바꿔 보여 줍니다.

**읽는 법** — 알람이 모니터링 시스템에서 난 시각을 알고 싶으면 이 시각이 아니라 모니터링 시스템 화면을 보세요. 재통보 간격 안에 반복돼 판단 없이 걸러진 알람은 이 화면에 시각이 남지 않습니다.

##### 영역마다 새로 읽는 때
**무엇인가** — 화면이 서버에서 값을 다시 받아 오는 시점입니다.

**어떻게 동작하나** — 영역마다 새로 읽는 때가 다릅니다.

| 영역 | 새로 읽는 때 |
|---|---|
| KPI 카드·퍼널·퍼널 아래 티어 카드 | 60초마다, 그리고 기간 버튼을 누를 때 |
| 최근 결정 | 30초마다, 그리고 기간 버튼을 누를 때 |
| 티어 분포 추이·상위 억제 알람 유형 | 기간 버튼을 누를 때만 |
| 결정 이력 | 기간 버튼을 누를 때, 조회 버튼이나 검색창에서 Enter를 누를 때 |

**이상할 때** — 이미 켜져 있는 기간 버튼을 한 번 더 눌러도 모든 영역을 새로 읽습니다. 화면을 오래 열어 두었다면 이 방법으로 새로 고치세요.

##### 가림 표시
**무엇인가** — 민감해 보이는 값을 가려 보여 주는 규칙입니다.

**어떻게 동작하나** — 결정 목록과 결정 추적에 나오는 알람명·서버명·사유·자원명과 상위 억제 알람 유형의 알람명은 값 전체가 토큰·키·카드번호·주민번호 같은 모양이면 가림 표시로 바뀌어 나옵니다. 심각도 같은 숫자 신호와 참·거짓 신호는 가리지 않습니다.

**읽는 법** — 상위 억제 알람 유형의 알람명도 같은 규칙으로 가려집니다. 가려진 알람명들은 단계별로 한 줄로 모이며, 이 줄은 눌러도 열리지 않습니다.

##### 사용자 화면에 없는 것
**무엇인가** — 운영자 화면에만 있는 기능과 칸입니다.

**어떻게 동작하나** — 침묵 규칙 관리, 정책 표, 억제기 상태 점검, 실시간 스트림, 「이 패턴 침묵」 버튼, 알람이 울린 실제 값(「울린 값」)은 사용자 화면에 없습니다.

**읽는 법** — 같은 판단이라도 사용자 화면에서는 이 칸들이 빠진 채로 보입니다. 알람을 멈추게 하고 싶으면 관리자에게 요청하세요.

**어떻게 동작하나** — 제목 왼쪽의 파형은 움직이는 장식이며 데이터와 관계가 없습니다. 파형이 멈추거나 움직여도 수집 상태를 뜻하지 않습니다.

**무엇인가** — 머리글 오른쪽의 작은 알약 모양 표시입니다.

**어떻게 동작하나** — 처음 순간에는 「갱신 준비 중」이 보였다가 곧 「30초마다 갱신」으로 바뀝니다. 연결 상태를 재는 표시가 아니라 최근 결정 목록의 갱신 주기를 적은 고정 문구입니다.

**읽는 법** — 다른 영역의 주기는 「이렇게 동작합니다 › 영역마다 새로 읽는 때」를 보세요. 이 표시가 그대로여도 서버 오류가 없다는 보장은 아닙니다.

**어떻게 동작하나** — 새 탭에서 열리므로 노이즈 관제 화면의 기간 선택과 열린 창은 그대로 남습니다.

**무엇인가** — 서버에서 값을 받아 오지 못했을 때 안내 문단 위에 뜨는 붉은 띠입니다.

**어떻게 동작하나** — 띠 글자는 「집계 조회 실패」(KPI·퍼널), 「추이 조회 실패」(그래프), 「결정 이력 조회 실패」(최근 결정) 뒤에 까닭이 붙는 형태이며 6초 뒤 사라집니다. 띠는 처음 읽을 때와 기간 버튼을 누를 때만 뜹니다. 자동 갱신이 실패할 때는 띠가 뜨지 않고 이전 숫자가 그대로 남습니다. 상위 억제 알람 유형과 결정 이력 표는 처음 읽기에 실패해도 띠 없이 비어 있기만 합니다.

**이상할 때** — 로그인이 만료되면 로그인 화면으로 넘어가고, 로그인하면 이 화면으로 돌아옵니다. 이 화면을 볼 권한이 없으면 첫 화면으로 보냅니다. 띠가 계속 뜨면 잠시 뒤 기간 버튼을 다시 누르고, 그래도 뜨면 관리자에게 알리세요.

##### 수신 알람
**무엇인가** — 고른 기간에 알람 거르기가 내린 판단의 수입니다.

**어떻게 동작하나** — 판단은 반드시 네 결과 중 하나이므로 옆 PAGE·TICKET·DASHBOARD·SUPPRESS 카드를 더한 값과 같고, 퍼널 머리의 「수신」과도 같습니다. 숫자는 천 단위 쉼표로 적습니다. 카드 아래 줄은 「24H · 게이트 동작 중」처럼 기간과 알람 거르기의 켜짐 상태를 적으며, 처음 불러오기 전에는 영문 안내가 잠깐 보입니다.

**읽는 법** — 알람이 해소될 때 오는 해소 알림도 한 건의 판단으로 들어갑니다. 해소 알림은 대부분 SUPPRESS로 끝나므로, 이 숫자는 「장애 건수」보다 크고 SUPPRESS 비중도 그만큼 높아 보입니다. 카드를 누르면 기간 안 판단 전체가 세부 리스트로 열립니다.

**이상할 때** — 아래 줄이 「게이트 꺼짐」이면 새 판단이 만들어지지 않으며, 숫자는 꺼지기 전에 남은 기록만 셉니다.

##### PAGE
**무엇인가** — 즉시 통보로 끝난 판단의 건수입니다. 카드 부제 「즉시 통보」는 사람을 바로 불렀다는 뜻입니다.

**어떻게 동작하나** — PAGE로 끝난 알람은 설정된 통보 채널로 곧바로 나갑니다. PAGE가 되는 주요 경로는 다음과 같습니다(각 단계의 뜻은 [U-45](#u-45)).

- 실효 심각도가 심각(3)인 알람 — 유지보수·침묵·연쇄 같은 억제 단계를 거치지 않습니다
- 모니터링 시스템에서 부가 정보를 가져오지 못한 주의 이상 알람(수집 실패 보수화)
- 심각도 × 중요도 표에서 「경고 × 중요도 높음」
- 표에서 TICKET이 나왔지만 올리는 보조 신호(통보 정책 「통보」, AI가 본 비일상, 피드백 의견 「액션 필요」 등)로 한 단계 올라간 경우

**읽는 법** — 사람이 곧바로 대응해야 했던 양입니다. 갑자기 늘면 실제 장애이거나 오탐이 몰린 것입니다. 카드를 누르면 「왜 즉시 불렀나」 목록이 결정 경로·심각도·중요도·승격 근거·직전 창 재발 칸과 함께 열립니다.

##### TICKET
**무엇인가** — 곧바로 부르지 않고 대기열에 쌓아 둔 판단의 건수입니다. 부제는 「대기열·기록」입니다.

**어떻게 동작하나** — TICKET은 곧바로 보내지 않고 요약 대기열에 쌓으며 화면 알람으로도 알립니다. 주로 표에서 「경고 × 중요도 보통」이나 「주의 × 중요도 높음」이 나온 경우이고, DASHBOARD에서 한 단계 올라가거나 PAGE에서 한 단계 내려온 경우도 있습니다.

**읽는 법** — 오늘 안에 확인할 일의 양으로 보세요. 카드를 누르면 매트릭스 산식·조정·통보 정책·일상 패턴 칸이 붙은 목록이 열려, 어떤 계산으로 TICKET이 됐는지 볼 수 있습니다.

##### DASHBOARD
**무엇인가** — 통보하지 않고 화면에만 남긴 판단의 건수입니다. 부제는 「UI 표시만」입니다.

**어떻게 동작하나** — 메시지를 보내지 않고 화면 알람으로만 알립니다. 주요 경로는 짝 없는 해소(관리자가 화면 표시로 정한 경우), 근본원인이 아직 통보되지 않은 연쇄 알람, 뒷받침이 있는 계획 작업, 표 판단(경고 × 낮음, 주의 × 보통·낮음), 한 단계 내림입니다.

**읽는 법** — 퍼널에서는 통보되지 않았으므로 「캔슬」로 셉니다. 반면 억제율에는 들어가지 않습니다. 카드를 누르면 강등 경로와 경로별 근거가 붙은 목록이 열립니다.

##### SUPPRESS
**무엇인가** — 알리지 않았지만 기록은 남긴 판단의 건수입니다. 부제 「억제(기록 유지)」처럼 지운 것이 아닙니다.

**어떻게 동작하나** — 보내지도 화면 알람으로 알리지도 않습니다. 비운영 알람·자가복구·독립 해소·유지보수·침묵·연쇄·인히비션·플래핑·스톰·상관 같은 억제 단계에서 끝났거나, 표에서 DASHBOARD가 나온 뒤 한 단계 내려간 경우입니다.

**읽는 법** — 카드를 누르면 억제 단계·억제 사유·단계 근거가 붙은 목록이 열리므로, 어느 단계가 가장 많이 걸렀는지 볼 수 있습니다. 해소 알림이 많이 섞이므로 이 숫자가 큰 것 자체는 이상이 아닙니다.

**이상할 때** — 심각(3) 알람은 비운영 알람으로 분류된 경우를 빼고는 SUPPRESS가 되지 않습니다. 심각 알람이 여기 있다면 결정 추적에서 「비운영 알람」 단계를 확인하세요.

##### 억제율
**무엇인가** — 「억제율 / 액션가능」 카드의 큰 숫자로, SUPPRESS 건수를 수신 알람 수로 나눈 값입니다.

**어떻게 동작하나** — 소수 첫째 자리 백분율로 적고, 수신 알람이 0건이면 0%입니다. KPI 카드와 같은 주기(60초)로 다시 계산됩니다.

**읽는 법** — 퍼널의 「캔슬」은 DASHBOARD까지 세므로, 억제율은 퍼널 캔슬 합계를 수신 알람 수로 나눈 값보다 작거나 같습니다. 큰 숫자를 누르면 SUPPRESS 목록이 열리고, 목록 머리에 「SUPPRESS a ÷ 수신 b = x%」처럼 같은 나눗셈이 실제 건수로 나옵니다.

##### 액션가능
**무엇인가** — 같은 카드 아래 줄로, PAGE와 TICKET을 더해 수신 알람 수로 나눈 값입니다. 사람이 움직여야 했던 판단의 비중입니다.

**어떻게 동작하나** — 처음 불러오기 전에는 「액션가능 —」로 보이고, 읽은 뒤에는 소수 첫째 자리 백분율로 바뀝니다.

**읽는 법** — DASHBOARD는 억제율에도 액션가능에도 들지 않으므로 두 값을 더해도 100%가 되지 않는 것이 정상입니다. 아래 줄을 누르면 PAGE와 TICKET을 함께 모은 목록이 「(PAGE a + TICKET b) ÷ 수신 c = x%」 산식 줄과 함께 열립니다.

##### 노이즈 캔슬링 퍼널
**무엇인가** — 판단 단계마다 몇 건이 걸러졌는지 보여 주는 카드입니다. 제목 옆 「결정 파이프라인 · 단계별 억제량」이 이 뜻입니다.

**어떻게 동작하나** — 판단 한 건은 위에서 아래로 단계를 차례로 거치다 처음 해당하는 단계에서 정확히 한 번 끝납니다. 그래서 모든 행의 확정 건수를 더하면 수신 알람 수와 같습니다. 행 하나하나의 뜻은 「단계별로 자세히」를 보세요.

**읽는 법** — 막대 전체 폭이 수신 알람 수입니다. 채운 부분은 이 단계에서 끝나지 않고 다음 단계로 넘어간 양, 이어지는 빗금은 이 단계에서 통보 없이(DASHBOARD·SUPPRESS) 끝난 양입니다. 남는 빈 칸은 위 단계에서 이미 끝났거나 이 단계에서 통보(PAGE·TICKET)로 끝난 양이므로, 아래로 갈수록 채운 부분이 짧아집니다.

##### 수신(퍼널 머리)
**무엇인가** — 퍼널 카드 맨 위 왼쪽의 큰 숫자로, 수신 알람 카드와 같은 값입니다.

**어떻게 동작하나** — KPI와 같은 응답에서 함께 채워지므로 두 값은 늘 같습니다. 누르면 수신 알람 카드와 같은 판단 전체 목록이 열립니다.

**읽는 법** — 퍼널 막대의 전체 폭이 이 숫자에 해당합니다.

##### PAGE(퍼널 머리)
**무엇인가** — 퍼널 카드 맨 위 오른쪽의 큰 숫자로, PAGE 카드와 같은 값입니다.

**어떻게 동작하나** — 누르면 PAGE 카드와 같은 「왜 즉시 불렀나」 목록이 열립니다.

**읽는 법** — 왼쪽 「수신」과 나란히 두어, 들어온 판단 중 몇 건이 사람을 바로 불렀는지 한눈에 비교하게 한 것입니다.

##### 행 오른쪽 숫자
**무엇인가** — 퍼널 단계 행 끝의 「-12 (캔슬 9)」 같은 글자입니다.

**어떻게 동작하나** — 앞 숫자는 이 단계에서 확정된 건수, 괄호 안은 그중 통보 없이(DASHBOARD·SUPPRESS) 끝난 건수입니다. 캔슬이 0이면 괄호를 붙이지 않습니다. 마우스를 올리면 도달·종결·캔슬 세 숫자가 한 줄로 뜹니다. 어떤 단계에 「도달」한 건수는 수신 알람 수에서 그 위 단계들이 확정한 건수를 뺀 값입니다.

**읽는 법** — 앞 숫자와 괄호 숫자가 같으면 그 단계는 모두 걸렀다는 뜻이고, 괄호가 없으면 모두 통보로 끝났다는 뜻입니다.

##### 흐린 행
**무엇인가** — 확정 건수가 0이라 「—」로 적히고 흐리게 보이는 단계 행입니다.

**어떻게 동작하나** — 기간 안에 그 단계에서 끝난 판단이 없으면 흐려집니다. 꺼진 단계와, 켜져 있지만 해당 알람이 없었던 단계가 같은 모양으로 보입니다.

**읽는 법** — 흐린 행도 누를 수 있으며, 열린 목록이 비어 있는 까닭(꺼짐인지, 해당 알람이 없었는지)을 알려 줍니다. 행 옆 (!)의 상태 줄로도 구별할 수 있습니다.

##### 단계 행 (!)
**무엇인가** — 퍼널 각 단계 이름 옆의 동그란 도움말 버튼입니다.

**어떻게 동작하나** — 그 단계가 무엇을 보고 판단하는지에 대한 설명과 상태 줄을 보여 줍니다. 설명은 판정 규칙과 함께 관리되는 문장을 서버에서 받아 오며, 받지 못하면 「설명을 불러오지 못했습니다(집계 조회 뒤 다시 여십시오).」가 나옵니다. 상태 줄은 켜진 단계에서 「현재 설정에서 평가하는 단계입니다」, 꺼진 단계에서 「이 단계는 꺼져 있어 판단을 내리지 않습니다」입니다.

**읽는 법** — 꺼진 단계에는 켜는 설정 이름이 함께 나오는데, 관리자가 참고하는 이름입니다. 알람 거르기 자체가 꺼지면 모든 단계가 꺼진 것으로 나옵니다. (!)를 눌러도 행의 목록은 열리지 않습니다.

##### PAGE(퍼널 아래)
**무엇인가** — 퍼널 막대 아래 작은 티어 카드 네 장 중 첫째로, PAGE 건수와 비율을 함께 적습니다.

**어떻게 동작하나** — 건수는 위쪽 PAGE 카드와 같고, 비율은 건수를 수신 알람 수로 나눈 값(소수 첫째 자리)입니다. 뜻 글자는 「즉시 통보」입니다. 누르면 위쪽 PAGE 카드와 같은 목록이 열리고, 카드 옆 (!)도 같은 설명입니다.

**읽는 법** — 「3.2% · 즉시 통보」라면 판단 100건 중 약 3건이 사람을 바로 불렀다는 뜻입니다.

##### TICKET(퍼널 아래)
**무엇인가** — 퍼널 아래 둘째 티어 카드로, TICKET 건수와 수신 대비 비율을 적습니다.

**어떻게 동작하나** — 뜻 글자는 「대기열」입니다. 건수·목록·(!)는 위쪽 TICKET 카드와 같습니다.

**읽는 법** — 퍼널을 보다가 위로 올라가지 않고 결과 비중을 바로 비교하라고 둔 카드입니다.

##### DASHBOARD(퍼널 아래)
**무엇인가** — 퍼널 아래 셋째 티어 카드로, DASHBOARD 건수와 수신 대비 비율을 적습니다.

**어떻게 동작하나** — 뜻 글자는 「표시만」입니다. 건수·목록·(!)는 위쪽 DASHBOARD 카드와 같습니다.

**읽는 법** — 이 비율과 SUPPRESS 비율을 더하면 퍼널 캔슬 합계를 수신 알람 수로 나눈 값과 거의 같습니다(각자 반올림하므로 소수 끝자리는 다를 수 있습니다).

##### SUPPRESS(퍼널 아래)
**무엇인가** — 퍼널 아래 넷째 티어 카드로, SUPPRESS 건수와 수신 대비 비율을 적습니다.

**어떻게 동작하나** — 뜻 글자는 「기록 유지」입니다. 이 카드의 비율은 위쪽 억제율과 같은 나눗셈이라 값도 같습니다. 건수·목록·(!)는 위쪽 SUPPRESS 카드와 같습니다.

**읽는 법** — 억제된 판단도 모두 기록에 남아 목록에서 한 건씩 확인할 수 있습니다.

##### 티어 분포 추이
**무엇인가** — 기간을 일정한 구간으로 나눠, 구간마다 판단 결과가 어떻게 나뉘었는지 쌓은 막대 그래프입니다.

**어떻게 동작하나** — 막대 하나가 맡는 시간은 1H 5분, 24H 2시간, 7D 6시간, 30D 1일입니다. 제목 옆에 「24H · 2시간 구간 · 시각은 이 브라우저 기준」처럼 적힙니다. 기간 버튼을 누를 때만 새로 읽습니다.

**읽는 법** — 막대 높이 변화는 유입량 변화, 색 비중 변화는 결과 비중 변화입니다. 맨 위 색(PAGE)이 튀는 구간부터 보세요.

##### 읽는 법 한 줄
**무엇인가** — 추이 제목 아래에 나오는 한 줄 안내입니다.

**어떻게 동작하나** — 「막대 1개 = 2시간 동안 게이트가 내린 판단 수 · 색 = 판단 결과(위로 갈수록 시급)」처럼, 기간에 맞는 구간 길이가 끼워져 바뀝니다.

##### 건수
**무엇인가** — 추이 제목 오른쪽 버튼 둘 중 하나로, 막대 높이를 판단 수에 비례시키는 보기입니다. 처음 열면 이 보기입니다.

**어떻게 동작하나** — 서버에서 새로 읽지 않고 받아 둔 값으로 그래프만 다시 그립니다. 왼쪽 축 이름은 「판단 수(건/구간)」입니다.

**읽는 법** — 알람이 몰린 시간대를 찾을 때 씁니다.

##### 비율
**무엇인가** — 막대를 구간마다 100%로 맞추는 보기입니다.

**어떻게 동작하나** — 건수와 마찬가지로 새로 읽지 않고 다시 그리기만 합니다. 왼쪽 축 이름은 「구간 안 비율(%)」이고 눈금은 0·50·100%입니다.

**읽는 법** — 유입량과 상관없이 결과 비중이 어떻게 변했는지만 비교할 때 씁니다. 판단이 1건뿐인 구간도 100% 막대가 되므로 건수 보기와 함께 보세요.

##### 세로축
**무엇인가** — 그래프 왼쪽의 축 이름과 눈금입니다.

**어떻게 동작하나** — 건수 보기의 최댓값은 가장 높은 막대를 1·2·5·10의 배수로 올린 값이고, 눈금은 0·중간·최댓값입니다. 중간값이 정수가 아니면 생략합니다.

**읽는 법** — 최댓값이 기간마다 바뀌므로, 두 기간의 막대 높이를 눈으로 바로 비교하지 말고 눈금 숫자를 보세요.

##### 가로축
**무엇인가** — 그래프 아래의 시각 라벨과 축 이름 「구간 시작 시각(이 브라우저 시간대)」입니다.

**어떻게 동작하나** — 라벨은 최대 8개까지 적고 날짜가 바뀌는 첫 라벨에만 월/일을 붙입니다. 1일 구간은 월/일만 적습니다. 구간은 이 브라우저 시간대의 자정을 기준으로 자르므로, 한국 시간이면 2시간 구간은 짝수 시에, 1일 구간은 자정에 시작합니다.

**읽는 법** — 맨 왼쪽 막대는 기간이 시작되는 시각 이후만 세고, 맨 오른쪽 막대는 아직 진행 중인 현재 구간입니다. 그래서 양 끝 막대는 다른 막대보다 낮게 보이기 쉽습니다.

##### 막대 색 쌓기
**무엇인가** — 막대 하나 안에서 결과별 색이 쌓인 순서입니다.

**어떻게 동작하나** — 아래부터 SUPPRESS → DASHBOARD → TICKET → PAGE 순으로 쌓습니다.

**읽는 법** — 위쪽 색일수록 시급한 판단입니다. 막대 꼭대기 색이 두꺼워지는 구간이 사람을 많이 부른 구간입니다.

##### 막대 위 숫자
**무엇인가** — 막대 꼭대기에 적힌 그 구간의 합계입니다.

**어떻게 동작하나** — 범례로 숨긴 결과는 이 합계에서 빠집니다. 창이 좁아 막대가 가늘면 숫자끼리 겹치지 않도록 생략합니다.

**이상할 때** — 숫자가 안 보이면 창을 넓히거나, 막대에 마우스를 올려 풍선으로 확인하세요.

##### 기준선 위 점
**무엇인가** — 막대 대신 바닥선에 찍힌 작은 점입니다.

**어떻게 동작하나** — 그 구간에 판단이 0건이었을 때 찍습니다.

**읽는 법** — 자료가 없는 것과 구별하려는 표시입니다. 점이 있으면 그 구간을 읽었고 판단이 없었다는 뜻입니다.

##### 막대 풍선
**무엇인가** — 막대에 마우스를 올리거나 Tab으로 막대에 가면 뜨는 작은 상자입니다.

**어떻게 동작하나** — 구간 시간, 합계, 결과별 건수와 비율(정수 %)이 뜹니다. 숨긴 결과가 있으면 그 이름도 적습니다. 막대를 누르면 그 구간의 판단 목록이 열리고, 목록 총 건수는 막대 합계와 같습니다.

**읽는 법** — 막대 높이로 어림하지 말고 정확한 숫자가 필요할 때 씁니다.

##### 범례
**무엇인가** — 그래프 아래에 PAGE부터 결과 이름과 **기간 전체 합계**를 적은 줄입니다. 끝에 「기간 합계 · 막대는 아래 SUPPRESS → 위 PAGE 순으로 쌓음 · 범례를 누르면 그 티어를 숨기거나 보임」 안내가 붙습니다.

**어떻게 동작하나** — 항목을 누르면 그 결과를 막대에서 숨기거나 다시 보입니다. 숨긴 결과는 막대 높이·막대 위 합계·풍선 합계·비율 계산에서 빠지지만, 범례의 기간 합계는 원래 값 그대로입니다. 네 결과를 다 숨길 수는 없어 마지막 하나는 눌러도 숨겨지지 않습니다.

**읽는 법** — 숨긴 상태는 기간을 바꾸거나 값이 갱신돼도 이 화면을 닫을 때까지 유지됩니다. 숨긴 채로 막대를 누르면 열린 목록에도 숨긴 결과가 빠집니다.

##### 범례 옆 경고
**무엇인가** — 「시각을 읽을 수 없는 N건은 막대에서 제외(KPI에는 포함)」라는 글자입니다.

**어떻게 동작하나** — 판단 시각이 깨져 있거나 현재 구간보다 뒤로 기록된 판단이 있을 때만 나옵니다.

**이상할 때** — 이 경고가 있으면 범례 합계를 더한 값이 수신 알람 수보다 그만큼 작습니다. 경고가 없는데 차이가 나면 추이만 새로 읽지 않은 상태이니 기간 버튼을 한 번 더 누르세요.

##### 최근 결정
**무엇인가** — 기간 안에서 가장 최근 판단 60건을 새것부터 보여 주는 목록입니다. 제목 옆 「클릭 → 결정 추적」이 누르는 법을 알려 줍니다.

**어떻게 동작하나** — 30초마다 다시 읽고, 처음 읽는 동안에는 「결정 이력을 불러오는 중…」이 보입니다. 한 항목에는 알람명(기록되지 않았으면 「(알람명 미기록)」)과 결과 배지, 「서버 · 결정 단계 · 판단 시각」, 사유가 차례로 나옵니다.

**읽는 법** — 항목을 누르거나 Tab으로 옮긴 뒤 Enter를 누르면 그 판단의 결정 추적이 열립니다. 결정 이력과 같은 기록을 읽지만, 이쪽은 거르는 조건 없이 최근 것만 짧게 봅니다.

**이상할 때** — 기간 안에 판단이 없으면 「표시할 결정이 없습니다.」가 나옵니다.

##### 상위 억제 알람 유형
**무엇인가** — 통보 없이 끝난 판단(DASHBOARD와 SUPPRESS)을 「알람명 × 결정 단계」로 묶어 건수가 많은 순서로 10개까지 보여 주는 표입니다. 제목 옆 「무엇이 캔슬되는가」가 이 뜻입니다.

**어떻게 동작하나** — 건수가 같으면 알람명 순입니다. 왼쪽은 알람명, 오른쪽은 「건수 · 단계 이름」입니다. 제목에는 「억제」라고 적혀 있지만 DASHBOARD도 함께 셉니다. 기간 버튼을 누를 때만 새로 읽습니다.

**읽는 법** — 같은 알람이 어느 단계에서 반복해서 걸러지는지 보입니다. 한 알람이 두 단계에서 걸렸다면 두 줄로 나뉩니다. 줄을 누르면 그 알람명과 정확히 같고 그 단계에서 통보 없이 끝난 판단만 열리며, 총 건수는 그 줄의 건수와 같습니다.

**이상할 때** — 알람명이 기록되지 않은 판단은 「(미기록)」으로 묶이고, 가림 표시로 바뀐 알람명은 단계별로 한 줄로 묶입니다. 둘 다 알람명으로 거를 수 없어 눌러도 열리지 않습니다. 결정 이력에서 단계로 거르세요. 통보 없이 끝난 판단이 없으면 「억제된 알람이 없습니다.」가 나옵니다.

##### 결정 이력
**무엇인가** — 판단을 한 건씩 찾아보는 표입니다. 제목 옆 「알람 1건이 어디서 어떤 사유로 판단됐는가」가 이 용도를 적은 것입니다.

**어떻게 동작하나** — 검색어·티어·단계 조건에 맞는 판단 중 최신 100건을 보여 주며 다음 쪽이 없습니다. 기간 버튼, 조회 버튼, 검색창 Enter 때 새로 읽습니다.

**이상할 때** — 맞는 판단이 없으면 「조건에 맞는 결정이 없습니다.」가 나옵니다.

##### 검색창
**무엇인가** — 결정 이력 맨 왼쪽의 입력 칸으로, 빈 칸에 「알람명·서버명·사유 검색」이라고 적혀 있습니다.

**어떻게 동작하나** — 실제로는 알람명·서버명·사유에 더해 알람 ID까지 한꺼번에 찾습니다. 적은 글자가 들어 있기만 하면 되고(부분 일치) 대소문자는 가리지 않습니다. 특수 기호를 패턴으로 해석하지 않고 글자 그대로 찾습니다. 비워 두면 모두입니다.

**읽는 법** — 글자를 적기만 해서는 반영되지 않습니다. Enter를 누르거나 조회 버튼을 누르세요.

##### 전 티어
**무엇인가** — 결정 이력의 티어 선택 상자입니다. 처음 값이 「전 티어」입니다.

**어떻게 동작하나** — 「전 티어」 또는 PAGE·TICKET·DASHBOARD·SUPPRESS 중 하나를 고릅니다. 고르기만 해서는 표가 바뀌지 않고 조회 버튼이나 검색창 Enter를 눌러야 반영됩니다.

**읽는 법** — 걸러진 알람을 다시 보려면 SUPPRESS를 고르고 조회하세요.

##### 전 단계
**무엇인가** — 결정 이력의 단계 선택 상자입니다. 처음 값이 「전 단계」입니다.

**어떻게 동작하나** — 목록은 퍼널과 같은 단계 이름이며, 화면을 처음 읽을 때 한 번 채웁니다. 티어 선택과 마찬가지로 조회를 눌러야 반영됩니다.

**읽는 법** — 해소 알림이 얼마나 되는지 보려면 「독립 해소」나 「자가복구 상관」을 고르세요.

##### 조회
**무엇인가** — 검색어와 두 선택 상자를 표에 반영하는 버튼입니다.

**어떻게 동작하나** — 누르면 지금 조건으로 결정 이력을 새로 읽습니다. 검색창에서 Enter를 눌러도 같습니다.

**이상할 때** — 조건을 바꿨는데 표가 그대로면 이 버튼을 누르지 않은 것입니다.

##### 건수(결정 이력)
**무엇인가** — 조회 버튼 오른쪽의 「N건」 글자입니다.

**어떻게 동작하나** — 조건에 맞는 전체 건수이며, 표에 보이는 줄 수와 다를 수 있습니다.

**이상할 때** — 건수가 100을 넘으면 표에는 최신 100건만 나옵니다. 조건을 좁히거나 위쪽 카드·퍼널에서 세부 리스트를 여세요. 세부 리스트는 쪽을 넘길 수 있습니다.

##### 시각
**무엇인가** — 결정 이력 표 첫 칸으로, 판단을 내린 시각입니다.

**어떻게 동작하나** — 이 브라우저 시간대로 바꿔 연월일과 초까지 적습니다. 새것이 위에 옵니다.

##### 알람
**무엇인가** — 결정 이력 표의 알람명 칸입니다.

**어떻게 동작하나** — 모니터링 시스템이 보낸 알람 이름을 그대로 적고, 값이 없으면 「—」입니다. 값 전체가 토큰·키 같은 모양이면 가림 표시로 나옵니다.

##### 서버
**무엇인가** — 결정 이력 표의 서버 칸으로, 알람이 난 서버 이름입니다.

**어떻게 동작하나** — 호스트명만 온 알람은 모니터링 시스템에 등록된 서버 이름으로 맞춰 적습니다. 값이 없으면 「—」입니다.

##### 티어
**무엇인가** — 결정 이력 표의 판단 결과 칸입니다.

**어떻게 동작하나** — PAGE·TICKET·DASHBOARD·SUPPRESS 중 하나가 배지로 나옵니다.

**읽는 법** — 같은 알람이 줄마다 다른 티어면, 판단 순간의 신호가 달랐던 것입니다. 두 줄의 결정 추적을 열어 신호 스냅샷을 비교하세요.

##### 결정 단계
**무엇인가** — 결정 이력 표에서 판단이 확정된 단계 이름 칸입니다.

**어떻게 동작하나** — 퍼널의 단계 이름과 같은 말을 씁니다. 그래서 이 칸의 값을 단계 선택 상자에서 그대로 골라 같은 단계의 판단만 모아 볼 수 있습니다.

##### 사유
**무엇인가** — 결정 이력 표 마지막 칸으로, 판단 순간에 남긴 설명 문장입니다.

**어떻게 동작하나** — 우선순위 매트릭스에서 끝난 판단이면 「매트릭스(…) → 기본 결과 · 승격: … → 최종 결과」처럼 계산 흐름이 그대로 남습니다.

**읽는 법** — 행을 누르면 그 행의 판단 그대로 결정 추적이 열립니다. 같은 알람이 여러 번 판단됐어도 누른 행의 판단이 뜹니다.

##### 세부 리스트
**무엇인가** — KPI 카드 숫자, 퍼널 머리 숫자, 퍼널 단계 행, 퍼널 아래 티어 카드, 추이 막대, 상위 억제 줄을 누르면 오른쪽에 열리는 목록 창입니다.

**어떻게 동작하나** — 어디서 열든 같은 창이고, 여는 곳에 따라 거르는 조건과 칸만 달라집니다.

| 여는 곳 | 목록 | 칸(시각·알람·서버 뒤) |
|---|---|---|
| 수신 알람 카드 · 퍼널 「수신」 | 판단 전체 (칩: 티어·단계) | 존 · 자원 · 실효 심각도 · 중요도 · 티어 · 결정 단계 · 사유 |
| PAGE 카드 · 퍼널 「PAGE」 · PAGE 티어 카드 | 왜 즉시 불렀나 (칩: 단계) | 결정 경로 · 심각도 · 중요도 · 승격 근거 · 직전 창 재발 |
| TICKET 카드·티어 카드 | 어떤 산식으로 대기열에 갔나 (칩: 단계) | 매트릭스 산식 · 조정 · 통보 정책 · 일상 패턴 |
| DASHBOARD 카드·티어 카드 | 왜 통보 없이 화면에만 남았나 (칩: 단계) | 강등 경로 · 경로별 근거 · 실효 심각도 · 중요도 |
| SUPPRESS 카드·티어 카드 | 어떤 알람을 왜 억제했나 (칩: 단계) | 억제 단계 · 억제 사유 · 단계 근거 · 실효 심각도 |
| 억제율 큰 숫자 | SUPPRESS 목록 + 억제율 산식 줄 | SUPPRESS 목록과 같음 |
| 액션가능 아래 줄 | 사람이 움직여야 했던 것 (칩: 티어·단계) + 산식 줄 | 티어 · 결정 경로 · 심각도 · 중요도 · 승격 근거 · 직전 창 재발 |
| 추이 막대 | 이 구간에 무엇이 들어와 어디로 갔나 (칩: 티어·단계) | 수신 알람 목록과 같음 |
| 퍼널 단계 행 | 「단계별로 자세히」의 각 단계 (칩: 티어) | 각 단계 항목의 「목록 칸」 |
| 상위 억제 줄 | 이 알람이 이 단계에서 왜 캔슬됐나 (칩: 티어) | 티어 + 그 단계의 목록 칸 |

**읽는 법** — 목록 칸의 시각은 「월-일 시:분」으로 짧게 적고, 빈 값은 흐린 「—」입니다. 목록을 읽는 동안에는 「불러오는 중…」이 보입니다.

##### 목록 창 머리
**무엇인가** — 목록 창 맨 위의 제목, 그 목록의 (!), 「총 N건」, 기간 버튼 줄입니다.

**어떻게 동작하나** — 제목 옆 (!)는 지금 열린 목록에 맞는 설명으로 바뀝니다. 「총 N건」은 지금 조건에 맞는 전체 건수입니다.

##### 목록 창 기간 버튼
**무엇인가** — 목록 창 머리에 있는 1H·24H·7D·30D 버튼입니다.

**어떻게 동작하나** — 머리글의 기간 버튼과 같은 설정입니다. 여기서 바꾸면 뒤쪽 화면 전체도 그 기간으로 다시 읽고, 목록은 같은 조건으로 첫 쪽부터 다시 읽습니다.

**이상할 때** — 추이 막대에서 연 구간 목록은 그 구간 시간을 그대로 유지하므로, 기간을 짧게 바꿔 구간이 기간 밖으로 나가면 목록이 비어 보입니다. 목록을 닫고 새 기간의 막대를 다시 누르세요.

##### 질문 줄
**무엇인가** — 「이 목록이 답하는 질문 — …」으로 시작하는 한 줄입니다.

**어떻게 동작하나** — 여는 곳마다 정해진 질문이 나옵니다. 예를 들어 PAGE 목록은 「왜 즉시 불렀나」, TICKET 목록은 「어떤 산식으로 대기열에 갔나」입니다.

**읽는 법** — 이 질문에 답하도록 목록 칸이 골라져 있으니, 칸을 읽기 전에 먼저 보세요.

##### 단계 설명
**무엇인가** — 퍼널 단계 행이나 상위 억제 줄에서 연 목록에만 나오는, 그 단계가 무엇을 보고 판단하는지 적은 문단입니다.

**어떻게 동작하나** — 단계 행 (!)와 같은 설명을 씁니다. 꺼진 단계에서 열었으면 설명 대신 꺼져 있다는 안내가 나옵니다.

##### 산식 줄
**무엇인가** — 목록 머리에 나오는 계산식 한 줄입니다.

**어떻게 동작하나** — 억제율 목록은 「SUPPRESS a ÷ 수신 b = x%」, 액션가능 목록은 「(PAGE a + TICKET b) ÷ 수신 c = x%」, 단계 목록은 「이 단계에서 확정 N건 · 그중 캔슬 M건(DASHBOARD + SUPPRESS)」입니다. 검색어로 좁히거나 억제율·액션가능 목록에서 단계 칩을 켜면 끝에 「현재 조건 기준」이 붙고 그 조건 안의 값으로 다시 셉니다.

**읽는 법** — 티어 칩은 산식 숫자를 바꾸지 않습니다. 카드의 백분율이 어떤 건수에서 나왔는지 확인할 때 봅니다.

##### 조건 줄
**무엇인가** — 지금 걸린 조건을 풀어 적은 한 줄입니다.

**어떻게 동작하나** — 「조건: 티어 SUPPRESS · 단계 스톰 · 검색 '…'」처럼, 여는 곳이 정한 조건과 켠 칩, 검색어를 함께 적습니다.

**읽는 법** — 목록이 예상보다 적으면 이 줄에서 어떤 조건이 걸려 있는지 먼저 보세요.

##### 티어 칩
**무엇인가** — 「티어」 줄에 「전체」와 결과별 건수가 적힌 작은 버튼들입니다.

**어떻게 동작하나** — 칩을 누르면 그 결과만 남기고, 켜진 칩을 다시 누르면 풀립니다. 한 줄에서는 칩 하나만 켤 수 있습니다. 칩의 숫자는 티어 선택을 뺀 나머지 조건으로 세므로, 칩을 켜도 다른 티어 칩 숫자가 0으로 바뀌지 않습니다.

**읽는 법** — 티어 칩은 0건이어도 나오며 흐리게 보입니다. 여는 곳이 이미 한 결과로 정해진 목록(PAGE 카드 등)에는 이 줄이 없습니다.

##### 단계 칩
**무엇인가** — 「단계」 줄에 「전체」와 단계별 건수가 적힌 작은 버튼들입니다.

**어떻게 동작하나** — 1건 이상인 단계만 판단 순서대로 나옵니다. 누르고 푸는 방식과 숫자 세는 방식은 티어 칩과 같아, 단계 선택을 뺀 나머지 조건으로 셉니다.

**읽는 법** — 한 결과가 어느 단계들에서 나왔는지 분포를 볼 때 씁니다. 단계 목록(퍼널 행에서 연 목록)에는 이 줄이 없습니다.

##### 목록 검색창과 조회
**무엇인가** — 목록 창 안의 검색 칸과 조회 버튼입니다.

**어떻게 동작하나** — 결정 이력 검색창과 같은 규칙(알람 ID 포함 부분 일치, 대소문자 무시, 글자 그대로)입니다. 조회 버튼이나 Enter로 반영하며, 반영하면 첫 쪽으로 돌아갑니다.

##### 동작 칸과 결정 추적 버튼
**무엇인가** — 목록 표 맨 끝의 「동작」 칸과 그 안의 「결정 추적」 버튼입니다.

**어떻게 동작하나** — 버튼이나 행 아무 곳을 누르면 그 판단의 결정 추적이 목록 창 위에 열립니다.

**읽는 법** — 결정 추적을 닫으면 목록 창이 그대로 남아 있어 다음 행을 이어서 볼 수 있습니다.

##### 쪽 넘김
**무엇인가** — 목록 아래의 「‹ 이전」, 「n / m쪽 · 50건/쪽」, 「다음 ›」입니다.

**어떻게 동작하나** — 한 쪽에 50건씩 보이며, 50건을 넘을 때만 나옵니다.

**읽는 법** — 결정 이력 표와 달리 여기서는 조건에 맞는 판단을 끝까지 넘겨 볼 수 있습니다.

##### 빈 목록과 오류 문구
**무엇인가** — 목록이 비었거나 읽지 못했을 때 표 자리에 나오는 글자입니다.

**어떻게 동작하나** — 맞는 판단이 없으면 까닭과 함께 괄호 안에 지금 조건이 적힙니다. 서버에서 받지 못하면 「조회하지 못했습니다 — 」 뒤에 까닭이 붙습니다.

**이상할 때** — 오류 문구가 계속 나오면 창을 닫고 기간 버튼을 다시 누른 뒤 여세요.

##### 닫기(✕)
**무엇인가** — 목록 창 오른쪽 위의 ✕ 버튼입니다.

**어떻게 동작하나** — 누르면 창이 닫힙니다. 창 바깥의 어두운 영역을 누르거나 Esc를 눌러도 닫힙니다. 닫으면 창을 열었던 자리로 커서가 돌아갑니다.

##### (!) 도움말
**무엇인가** — 화면 곳곳의 동그란 (!) 버튼입니다. KPI 카드 여섯 장, 퍼널·추이·최근 결정·상위 억제·결정 이력 제목, 퍼널 단계 행마다, 퍼널 아래 티어 카드, 세부 리스트 제목, 결정 추적의 판단 경로·신호 스냅샷 제목 옆에 있습니다.

**어떻게 동작하나** — 누르면 버튼 근처에 설명 상자가 뜨고, 「무엇을 보나 · 산식 · 어떻게 읽나 · 주의 · 관련 설정」 가운데 그 항목에 있는 칸만 보입니다. 한 번에 하나만 열리며 같은 버튼을 다시 누르거나, 바깥을 누르거나, Esc를 누르거나, 화면을 스크롤하거나 창 크기를 바꾸면 닫힙니다.

**읽는 법** — 관련 설정은 관리자가 참고하는 설정 이름입니다. (!)를 눌러도 그 카드나 행의 목록은 열리지 않습니다.

##### 키보드로 쓰기
**무엇인가** — 마우스 없이 화면을 쓰는 방법입니다.

**어떻게 동작하나** — Tab으로 KPI 숫자, 퍼널 단계 이름, 추이 막대, 범례, 칩, 최근 결정 항목, 결정 이력 행, 목록의 「결정 추적」 버튼으로 옮겨 가고 Enter나 Space로 엽니다. Esc는 열린 창 가운데 **맨 위의 하나만** 닫습니다. 겹친 순서는 도움말 상자 → 막대 풍선 → 결정 추적 → 세부 리스트입니다.

**읽는 법** — 창을 닫으면 그 창을 열었던 자리로 커서가 돌아가고, 그사이 갱신으로 그 자리가 다시 그려졌으면 같은 항목이나 그 영역 제목으로 돌아갑니다. 결정 추적이나 세부 리스트가 열려 있는 동안 뒤쪽 화면은 Tab으로 들어가지 않습니다.

#### 단계별로 자세히
퍼널의 단계 행을 위에서 아래 순서대로 설명합니다. 행을 누르면 그 단계에서 확정된 판단 목록이 열리고, 목록에는 공통 칸(시각·알람·서버) 뒤에 각 항목의 「목록 칸」이 붙습니다. 근거가 기록된 행이 한 줄도 없으면 그 칸은 만들지 않습니다. 「켜야 동작」인 단계는 관리자가 켜지 않으면 늘 흐린 행입니다. 규칙의 더 자세한 원리는 [U-45](#u-45)에 있습니다.

##### 비운영 알람
**무엇인가** — 알람이 아니라 승인·안내 같은 메시지를 골라내는 단계입니다(켜야 동작). 판단 순서의 맨 처음입니다.

**어떻게 동작하나** — 알람명·조건 문구·자원 이름·설명 등을 모아, 알람을 뜻하는 말(가용성·사용률·임계·초과·장애 등)이 하나도 없고 승인·요청·안내·공지·문의 같은 말이 있으면 SUPPRESS합니다. 둘 다 있거나 둘 다 없으면 알람으로 보고 넘깁니다.

**읽는 법** — 목록은 「알람이 아니라고 본 근거는」에 답하며, 목록 칸은 사유 · 걸린 표지 단어입니다. 심각도 판단보다 앞이라 심각(3)으로 온 메시지도 여기서 걸리면 기록만 남습니다.

##### 심각도3 단락
**무엇인가** — 심각 알람을 억제 없이 곧바로 PAGE로 확정하는 단계입니다(항상 동작).

**어떻게 동작하나** — 모니터링 시스템이 보낸 심각도와 AI가 올리자고 제안한 심각도 중 큰 값을 실효 심각도로 씁니다. AI는 올릴 수만 있고 내릴 수는 없으며, 해소 알림에는 AI 제안을 쓰지 않습니다. 실효 심각도가 3이면 뒤 단계를 보지 않고 PAGE로 끝납니다.

**읽는 법** — 목록은 「무엇이 억제 없이 곧바로 PAGE였나」에 답하며, 목록 칸은 심각도(수신값과 AI 상향 여부) · 중요도입니다. 이 행의 괄호(캔슬)는 늘 비어 있어야 합니다.

**이상할 때** — 유지보수 중이거나 침묵 규칙에 맞는 서버에서 PAGE가 왔다면 대개 이 단계에서 결정된 것입니다.

##### 자가복구 상관
**무엇인가** — 발생 뒤 금방 스스로 복구된 알람의 **해소 알림**을 거르는 단계입니다(항상 동작 · 해소 알림만).

**어떻게 동작하나** — 해소 알림이 왔을 때 같은 알람의 발생이 자가복구 창(기본 5분) 안에 있었고 그 발생의 심각도가 억제 허용 상한(기본 경고) 이하였으면 해소 알림을 SUPPRESS합니다(기본값이며 설치 설정에 따라 다를 수 있습니다). 심각 발생은 짝 후보에서 빠집니다.

**읽는 법** — 목록은 「무엇이 스스로 복구됐고 얼마나 걸렸나」에 답하며, 알람 칸 제목이 「해소 알람」으로 바뀌고 원 발생 판단 · 발생→해소 소요 칸이 붙습니다. 앞서 온 발생 알람은 도착했을 때 따로 판단됐으며, 이 단계가 그 결과를 되돌리지 않습니다.

##### 독립 해소
**무엇인가** — 짝을 찾지 못한 해소 알림을 처리하는 단계입니다(항상 동작 · 해소 알림만).

**어떻게 동작하나** — 기본은 SUPPRESS로 기록만 남기고, 관리자가 정하면 DASHBOARD로 화면에만 남깁니다.

**읽는 법** — 목록은 「짝 없는 해소를 어떻게 처리했나」에 답하며, 목록 칸은 처리(화면 표시인지 기록만인지)입니다. 이 행이 크면 수신 알람 숫자의 상당 부분이 해소 알림이라는 뜻입니다.

##### 수집 실패 보수화
**무엇인가** — 판단에 필요한 부가 정보를 가져오지 못했을 때 부르는 쪽을 택하는 단계입니다(항상 동작).

**어떻게 동작하나** — 모니터링 시스템에서 자원 중요도·유지보수 여부 같은 부가 정보를 가져오지 못하면 중요도는 「보통」, 유지보수는 「아님」으로 두고, 심각도 1 이상인 알람을 PAGE로 확정합니다.

**읽는 법** — 목록은 「어떤 신호가 없어 보수적으로 불렀나」에 답하며, 목록 칸은 실효 심각도 · 결측 처리입니다.

**이상할 때** — 이 행이 갑자기 커지면 모니터링 시스템 연결에 문제가 있을 수 있으니 관리자에게 알리세요.

##### 유지보수
**무엇인가** — 유지보수 모드인 자원의 알람을 거르는 단계입니다(항상 동작).

**어떻게 동작하나** — 모니터링 시스템이 그 자원을 유지보수 모드라고 알려 주면 SUPPRESS합니다.

**읽는 법** — 목록은 「유지보수 중이라 억제된 것은」에 답하며, 목록 칸은 유지보수 신호 · 실효 심각도 · 자원입니다. 심각 알람은 앞 단계에서 이미 PAGE로 끝나므로 여기에 오지 않습니다.

##### 침묵 규칙
**무엇인가** — 관리자가 기간을 정해 건 침묵 규칙으로 거르는 단계입니다(켜야 동작).

**어떻게 동작하나** — 규칙은 존·서버·알람·자원 이름 패턴(*를 쓰는 글자 패턴, 대소문자 구분)과 심각도 상한, 만료 시각을 가집니다. 해제·만료되지 않은 규칙 중 패턴이 모두 맞고 실효 심각도가 상한 이하이면 SUPPRESS합니다. 여러 규칙이 맞으면 먼저 만든 규칙이 사유로 남고, 규칙 하나는 최대 7일까지만 유지됩니다(기본값이며 설치 설정에 따라 다를 수 있습니다).

**읽는 법** — 목록은 「어느 규칙이 무엇을 조용히 시켰나」에 답하며, 목록 칸은 규칙 ID · 규칙 사유 · 판단 시점 규칙입니다. 규칙을 만들고 푸는 일은 관리자 기능입니다.

##### 의존성 연쇄
**무엇인가** — 상위 장비·서비스 장애 때문에 생긴 하위 알람을 거르는 단계입니다(켜야 동작).

**어떻게 동작하나** — 기본 방식은 바로 위 한 단계만 보며, 상위 상태가 비정상이면 SUPPRESS합니다. 여러 단계 위까지 보는 방식이 켜져 있으면 근본원인 자원이 이미 통보됐을 때 SUPPRESS, 아직 통보되지 않았으면 DASHBOARD로 낮춥니다. 상위 상태를 모르면 억제하지 않고 넘깁니다.

**읽는 법** — 목록은 「어느 상위 장애의 연쇄로 봤나」에 답하며, 목록 칸은 부모 가용 상태 · 연쇄 판정 · 근본원인 자원 · 결과입니다.

##### 인히비션
**무엇인가** — 같은 서버에 더 심각한 다른 알람이 떠 있을 때 덜 심각한 알람을 누르는 단계입니다(켜야 동작).

**어떻게 동작하나** — 같은 존·같은 서버에서 **이름이 다른** 알람이 더 높은 심각도로 판정 창(기본 5분 — 기본값이며 설치 설정에 따라 다를 수 있습니다) 안에 발생해 있으면 지금 알람을 SUPPRESS합니다. 같은 이름의 알람은 자기 자신을 누르지 않습니다.

**읽는 법** — 목록은 「어떤 상위 알람이 누르고 있었나」에 답하며, 목록 칸은 사유 · 누른 상위 알람입니다.

##### 플래핑
**무엇인가** — 발생과 해소를 짧게 반복하며 진동하는 알람을 거르는 단계입니다(켜야 동작).

**어떻게 동작하나** — 같은 알람의 최근 상태를 최대 21번 기억하고, 상태가 바뀐 비율을 최근 변화일수록 무겁게 쳐서 계산합니다. 상태가 5번 이상 쌓인 뒤에만 판단하며(한 번 재발생한 알람은 진동으로 보지 않습니다), 20% 이상이면 진동 중으로 보고 5% 이하로 내려가야 풀립니다(기본값이며 설치 설정에 따라 다를 수 있습니다). 진동 중이어도 억제 허용 상한 이하 심각도만 SUPPRESS합니다.

**읽는 법** — 목록은 「얼마나 진동했나」에 답하며, 목록 칸은 사유 · 진동 정도입니다.

##### 스톰
**무엇인가** — 한 서버에서 짧은 시간에 쏟아지는 알람을 거르는 단계입니다(켜야 동작).

**어떻게 동작하나** — 같은 존·같은 서버에서 60초 안에 발생이 5건을 넘으면 6번째부터 SUPPRESS하고, 처음 5건은 평소대로 판단합니다(기본값이며 설치 설정에 따라 다를 수 있습니다). 해소 알림은 세지 않습니다.

**읽는 법** — 목록은 「얼마나 몰렸나」에 답하며, 목록 칸은 사유 · 몰린 정도입니다. 같은 서버 다발은 스톰, 여러 서버에 걸친 비슷한 알람은 아래 크로스-호스트 상관입니다.

##### 크로스-호스트 상관
**무엇인가** — 여러 서버에서 비슷한 알람이 한꺼번에 날 때 대표 한 건만 남기는 단계입니다(켜야 동작).

**어떻게 동작하나** — 같은 존 안에서 서버가 달라도 알람명·자원 유형·메시지 특징이 비슷한 알람(유사도 0.5 이상)이 2분 안에 이어지면 한 묶음으로 봅니다. 먼저 온 알람이 대표가 되어 평소대로 판단받고, 두 번째부터 SUPPRESS합니다(기본값이며 설치 설정에 따라 다를 수 있습니다). 나중에 대표를 바꾸지 않습니다.

**읽는 법** — 목록은 「어느 대표 알람에 묶였나」에 답하며, 목록 칸은 대표 알람 · 멤버 순번 · 유사도입니다.

##### 계획-무해 주석
**무엇인가** — 계획된 작업으로 생긴 알람을 화면 표시로 낮추는 단계입니다(켜야 동작).

**어떻게 동작하나** — 메시지에 계획 작업이라는 표시가 있고, 해소 표시·상관 묶음·최근 변경 작업 근접 중 하나 이상이 함께 뒷받침하면 DASHBOARD로 낮춥니다. 표시만 있고 뒷받침이 없으면 낮추지 않습니다.

**읽는 법** — 목록은 「무엇이 계획 작업임을 뒷받침했나」에 답하며, 목록 칸은 사유 · 뒷받침한 근거입니다. 이 단계는 SUPPRESS를 만들지 않으므로 확정 건수와 캔슬 건수가 같습니다.

##### 우선순위 매트릭스
**무엇인가** — 앞 단계를 모두 지난 알람의 결과를 정하는 마지막 단계입니다(항상 동작).

**어떻게 동작하나** — 실효 심각도와 자원 중요도로 기본 결과를 정한 뒤, 보조 신호로 한 단계만 조정합니다. 중요도를 알 수 없으면 「보통」입니다.

| 실효 심각도 | 중요도 높음 | 중요도 보통 | 중요도 낮음 |
|---|---|---|---|
| 경고(2) | PAGE | TICKET | DASHBOARD |
| 주의(1) | TICKET | DASHBOARD | DASHBOARD |

올리는 신호(통보 정책 「통보」, AI가 본 비일상, 피드백 의견 「액션 필요」, 최근 변경 근접)가 하나라도 있으면 한 단계 올리고, 없고 내리는 신호만 있으면 한 단계 내립니다.

**읽는 법** — 목록은 「산식이 어떻게 흘렀나」에 답하며, 목록 칸은 티어 · 매트릭스 산식 · 조정 · 통보 정책 · 일상 패턴 · LLM 액션가능성입니다. 이 단계의 SUPPRESS는 DASHBOARD에서 한 단계 내려간 경우뿐입니다.

##### unknown
**무엇인가** — 어느 단계에서 확정됐는지 분류되지 않은 옛 판단을 모으는 행입니다.

**어떻게 동작하나** — 단계 이름이 기록되지 않았고 사유 문장으로도 단계를 알 수 없는 판단이 기간 안에 있을 때만 맨 아래에 생깁니다. 합계가 수신 알람 수와 맞도록 버리지 않고 모아 둡니다.

**읽는 법** — 목록은 「어느 단계에서 확정됐는지 분류되지 않은 옛 판단」을 보여 주며, 목록 칸은 티어 · 사유입니다. 사유 문장으로 어떤 판단이었는지 짐작하세요.

#### 더 알아보기
결정 추적 창의 항목입니다. 최근 결정 항목, 결정 이력 행, 세부 리스트의 「결정 추적」 버튼을 누르면 오른쪽에서 열립니다. 오른쪽 위 ✕, 바깥 어두운 영역, Esc로 닫습니다.

##### 알람명과 머리 줄
**무엇인가** — 결정 추적 창 맨 위에 크게 적힌 알람명과, 그 아래 「서버 · 알람 ID · 판단 시각」 줄입니다.

**어떻게 동작하나** — 누른 행의 판단 하나를 그대로 보여 줍니다. 같은 알람이 여러 번 판단됐어도 다른 판단을 섞지 않습니다.

**읽는 법** — 알람 ID는 결정 이력 검색창에서도 찾을 수 있으므로, 관리자에게 문의할 때 이 값을 함께 알려 주세요.

##### 판단 결과
**무엇인가** — 판단 요약 표 첫 줄로, PAGE·TICKET·DASHBOARD·SUPPRESS 배지입니다.

**어떻게 동작하나** — 판단 요약 표는 값이 있는 줄만 보이며, 이 줄은 모든 판단에 있습니다.

##### 결정 단계
**무엇인가** — 판단 요약 표에서 판단이 확정된 단계 이름을 적은 줄입니다.

**어떻게 동작하나** — 퍼널의 단계 이름과 같고, 아래 판단 경로에서 「— 여기서 결정」이 붙는 단계와 같습니다.

##### 존
**무엇인가** — 판단 요약 표에서 이 알람을 보낸 모니터링 DB의 식별자를 적은 줄입니다.

**어떻게 동작하나** — 화면 집계는 모든 존을 더하므로, 한 판단이 어느 쪽에서 왔는지는 이 줄로 확인합니다.

##### 자원
**무엇인가** — 판단 요약 표에서 알람이 걸린 자원 이름을 적은 줄입니다.

**어떻게 동작하나** — 기록되지 않았으면 줄이 보이지 않습니다. 값 전체가 토큰·키 같은 모양이면 가림 표시로 나옵니다.

##### 직전 창 재발
**무엇인가** — 판단 요약 표에서, 바로 앞 재통보 간격 동안 같은 알람이 온 횟수를 적은 줄입니다.

**어떻게 동작하나** — 재통보 간격이 지나 다시 판단에 올라간 알람에만 값이 있습니다. 간격 안에 반복된 알람은 판단 없이 횟수만 세어 두었다가 다음 판단에 이 값으로 넘깁니다.

**읽는 법** — 값이 크면 판단은 한 건이지만 그동안 같은 알람이 여러 번 왔다는 뜻입니다.

##### 관련 판단
**무엇인가** — 판단 요약 표에서 이 판단과 짝이 되는 다른 판단을 보여 주는 줄입니다. 크로스-호스트 상관이면 묶인 **대표 판단**, 자가복구면 스스로 복구된 **원 발생 판단**의 알람·서버·시각·결과가 나옵니다.

**어떻게 동작하나** — 관련 판단을 찾지 못하면 비워 두지 않고 까닭을 적습니다.

**이상할 때** — 「대표 판단이 조회 범위(결정 기록 최근 구간) 밖입니다」는 대표 판단이 화면이 읽는 최근 기록보다 오래됐다는 뜻입니다. 「원 발생 판단을 조회 범위(결정 기록 최근 구간)에서 찾지 못했습니다」는 원 발생이 그보다 오래됐거나 원 발생에 판단 기록이 없다는 뜻입니다. 「대표 정보가 기록되지 않은 판단입니다」는 처음부터 대표 정보가 없는 옛 판단이라는 뜻입니다.

##### 판단 경로
**무엇인가** — 판단 순서대로 14단계를 세로로 늘어놓고 이 판단이 어디서 멈췄는지 표시한 그림입니다.

**어떻게 동작하나** — 결정 단계보다 위 단계는 이름만 보이고(점 색으로 통과를 나타냅니다), 결정 단계에는 「— 여기서 결정」과 그 아래 사유 문장, 아래 단계에는 「(단락 — 평가되지 않음)」이 붙습니다.

**읽는 법** — 위 단계가 통과로 표시되는 것은 그 단계에 걸리지 않았다는 뜻일 뿐이며, 꺼져 있어 아예 평가하지 않은 단계도 같은 모양으로 보입니다. 켜짐 여부는 퍼널 단계 행의 (!)에서 확인하세요.

**이상할 때** — 단계 이름이 기록되지 않은 옛 판단이면 어느 단계에서 확정됐는지 알 수 없다는 안내가 먼저 나오고 강조 표시 없이 단계만 보입니다. 화면이 단계 순서를 아직 받지 못했을 때는 집계가 갱신된 뒤 다시 열라는 안내가 나옵니다.

##### 단계 근거
**무엇인가** — 결정 단계가 판단 순간에 본 구체적인 값을 적은 표입니다.

**어떻게 동작하나** — 값이 기록돼 있을 때만 나옵니다. 근거가 없는 단계(심각도3 단락·독립 해소·수집 실패·유지보수·상관)나 옛 판단이면 표 자체가 숨겨집니다.

| 결정 단계 | 나오는 줄 |
|---|---|
| 비운영 알람 | 걸린 비알람 표지 단어 |
| 자가복구 상관 | 발생→해소 소요 · 발생 당시 심각도 |
| 침묵 규칙 | 침묵 규칙 ID · 규칙 매처 · 규칙 만료 시각 |
| 의존성 연쇄 | 연쇄 판정 방식(1홉·다홉) · 근본원인 통보됨 · 근본원인 자원명 |
| 인히비션 | 누른 상위 알람 · 상위 알람 심각도 · 상위 알람 경과 · 판정 창 |
| 플래핑 | 상태 변화율(%) · 진동 상한(%) · 진동 하한(%) · 표본 수 |
| 스톰 | 창 안 발생 수 · 임계 건수 · 판정 창 |
| 계획-무해 주석 | 뒷받침한 근거(해소·상관·변경 근접) |
| 우선순위 매트릭스 | 매트릭스 기본 티어 · 승격 근거 · 강등 근거 |

**읽는 법** — 참·거짓은 「예」·「아니오」로, 초 단위 값은 「3분 20초」처럼, 만료 시각은 이 브라우저 시각으로, 빈 목록은 「(없음)」으로 적습니다. 침묵 규칙을 만든 계정은 사용자 화면에 나오지 않습니다.

##### 신호 스냅샷
**무엇인가** — 판단에 쓰인 신호 16가지를 **판단 순간의 값 그대로** 보여 주는 표입니다. 아래 16개 항목이 그 줄입니다.

**어떻게 동작하나** — 나중에 설정이나 상황이 바뀌어도 이 값은 바뀌지 않습니다. 줄마다 한국어 이름, 그 아래 작은 영문 이름, 짧은 설명이 있고 오른쪽에 값이 있습니다. 참·거짓 값은 영문(true·false) 그대로 나옵니다.

**읽는 법** — 신호는 판단에 쓰였다는 뜻이지, 그 신호가 결과를 정했다는 뜻은 아닙니다. 결과를 정한 것은 판단 경로에서 「여기서 결정」이 붙은 단계 하나입니다. 예를 들어 스톰 탐지가 참이어도 그보다 앞선 인히비션에서 결정됐다면 스톰은 결과에 영향을 주지 않았습니다.

**이상할 때** — 값이 「—」이면 그 신호를 모으지 못했거나, 기능이 꺼져 있었거나, 해당 사항이 없었던 것입니다(예: AI가 심각도를 올리지 않은 경우).

##### 수신 심각도
**무엇인가** — 모니터링 시스템이 보낸 원래 심각도입니다.

**어떻게 동작하나** — 0 해소 · 1 주의 · 2 경고 · 3 심각의 숫자로 적습니다. 글자로 온 심각도도 이 숫자로 바꾸며, 알아볼 수 없는 값은 2로 봅니다.

**읽는 법** — 0이면 이 판단은 해소 알림에 대한 것입니다.

##### AI 상향 등급
**무엇인가** — AI가 메시지를 읽고 매긴 심각도입니다.

**어떻게 동작하나** — 관리자가 켠 경우에만 만들어지며, 수신 심각도보다 높을 때만 기록됩니다. 낮추는 제안과 해소 알림에 대한 제안은 쓰지 않습니다.

**읽는 법** — 값이 있으면 목록의 심각도 칸에 「실효 3 (수신 2 → AI 3 상향)」처럼 나옵니다. 「—」이면 기능이 꺼졌거나, 올리지 않았거나, 해소 알림입니다.

##### 실효 심각도
**무엇인가** — 판단에 실제로 쓴 심각도로, 수신 심각도와 AI 상향 등급 중 큰 쪽입니다. 해소 알림은 늘 수신 심각도(0)입니다.

**어떻게 동작하나** — 3이면 심각도3 단락에서 곧바로 PAGE로 끝납니다. 침묵 규칙의 심각도 상한과 비교하는 값도 이것입니다.

**읽는 법** — 우선순위 매트릭스 표의 세로(심각도) 쪽에 들어가는 값입니다.

##### 중요도
**무엇인가** — 알람이 걸린 자원의 중요도(높음·보통·낮음)입니다.

**어떻게 동작하나** — 모니터링 시스템의 중요도 값을 세 단계로 바꾼 것이며, 알 수 없거나 가져오지 못하면 「보통」으로 봅니다.

**읽는 법** — 우선순위 매트릭스 표의 가로(중요도) 쪽에 들어가는 값입니다. 같은 경고라도 이 값에 따라 PAGE·TICKET·DASHBOARD가 갈립니다.

##### 유지보수
**무엇인가** — 판단 순간 자원이 유지보수 모드였는지를 나타내는 값입니다.

**어떻게 동작하나** — 모니터링 시스템이 알려 준 값을 그대로 씁니다. 참이면 유지보수 단계에서 SUPPRESS됩니다(심각 알람과 수집 실패 알람은 그보다 먼저 결정).

**읽는 법** — 유지보수 중인데 알람이 왔다면 판단 경로에서 결정 단계가 유지보수보다 앞인지 보세요.

##### 부모 가용 상태
**무엇인가** — 이 자원이 기대는 상위 자원의 상태 코드입니다.

**어떻게 동작하나** — 0이면 정상, 그 밖의 숫자는 비정상입니다. 의존성 연쇄 단계가 이 값을 보고 연쇄 여부를 판단합니다.

**읽는 법** — 「—」이면 상위 상태를 모른다는 뜻이고, 이때 의존성 연쇄 단계는 억제하지 않고 넘어갑니다.

##### 발생 패턴
**무엇인가** — 이력으로 본 이 알람의 반복 형태입니다.

**어떻게 동작하나** — 첫 발생·주기적·급증·산발적 가운데 하나로 적습니다.

**읽는 법** — 목록의 일상 패턴 칸에 AI의 일상 반복 의견과 함께 나옵니다. 「주기적」인데 결과가 높게 나왔다면 다른 올리는 신호가 있었는지 보세요.

##### 일상 반복
**무엇인가** — AI가 이 알람을 평소 반복되는 것으로 봤는지를 나타내는 값입니다.

**어떻게 동작하나** — 참이면 한 단계 내릴 근거(억제 허용 상한 이하일 때만), 거짓이면 한 단계 올릴 근거가 됩니다.

**읽는 법** — 「—」이면 판단하지 못한 것입니다. 올리는 근거가 하나라도 있으면 내릴 근거는 무시됩니다.

##### 통보 정책
**무엇인가** — 모니터링 시스템 쪽에 설정된 이 알람의 통보 설정입니다.

**어떻게 동작하나** — notify면 한 단계 올릴 근거입니다. 규칙에는 suppress면 한 단계 내리는 조항도 있지만, 지금은 모니터링 시스템에서 이 값을 만들지 않아 내릴 근거로 쓰이는 일이 없습니다.

**읽는 법** — 목록의 통보 정책 칸에는 「통보(notify)」로 나오고, 값이 없으면 「—」입니다.

##### 플래핑 탐지
**무엇인가** — 이 알람이 발생·해소를 반복하며 진동한다고 봤는지를 나타내는 값입니다.

**어떻게 동작하나** — 플래핑 단계가 켜져 있을 때 만들어지며, 참이고 심각도가 억제 허용 상한 이하이면 플래핑 단계에서 SUPPRESS됩니다.

**읽는 법** — 꺼져 있으면 「—」입니다.

##### 자가복구 짝
**무엇인가** — 이 해소 알림이 자가복구 창 안의 같은 알람 발생과 짝지어졌는지를 나타내는 값입니다.

**어떻게 동작하나** — 해소 알림에서만 의미가 있으며, 참이면 자가복구 상관 단계에서 끝납니다.

**읽는 법** — 해소 알림인데 거짓이면 독립 해소 단계에서 처리됩니다.

##### 스톰 탐지
**무엇인가** — 같은 서버에서 짧은 시간에 발생이 몰렸다고 봤는지를 나타내는 값입니다.

**어떻게 동작하나** — 스톰 단계가 켜져 있을 때 창 안 발생 수가 임계를 넘으면 참이 됩니다.

**읽는 법** — 참이어도 앞 단계에서 이미 결정됐다면 결과에 영향을 주지 않았습니다.

##### LLM 액션가능성
**무엇인가** — 운영자 피드백을 참고한 AI 의견입니다.

**어떻게 동작하나** — 관리자가 켠 경우에만 만들어지며, actionable이면 한 단계 올릴 근거, noise면 한 단계 내릴 근거(억제 허용 상한 이하일 때만)입니다. 꺼져 있으면 「—」입니다.

**읽는 법** — 목록 칸에는 「액션 필요」 또는 「노이즈」로 나옵니다.

##### 다홉 연쇄
**무엇인가** — 여러 단계 위 조상 자원이 비정상인지를 나타내는 값입니다.

**어떻게 동작하나** — 의존성 연쇄를 여러 단계 위까지 보는 방식이 켜져 있을 때만 만들어집니다.

**읽는 법** — 참이면 아래 근본원인 자원이 함께 기록되며, 그 자원이 이미 통보됐는지에 따라 SUPPRESS 또는 DASHBOARD가 됩니다.

##### 근본원인 자원
**무엇인가** — 다홉 연쇄에서 찾은 근본원인 자원입니다.

**어떻게 동작하나** — 다홉 연쇄가 참일 때만 값이 있습니다.

**읽는 법** — 같은 근본원인으로 묶인 알람이 많다면 그 자원의 장애를 먼저 보세요.

##### 크로스-호스트 상관
**무엇인가** — 여러 서버 알람 묶음에서 대표가 아닌 쪽으로 판정됐는지를 나타내는 값입니다.

**어떻게 동작하나** — 크로스-호스트 상관 단계가 켜져 있을 때 만들어지며, 참이면 그 단계에서 SUPPRESS됩니다(심각 알람은 앞에서 PAGE로 끝남).

**읽는 법** — 참이면 판단 요약의 관련 판단에서 묶인 대표 판단을 확인하세요.

### U-45
::: what
알람 거르기(노이즈 게이트)는 **미리 정한 규칙**으로 판단합니다. [[AI(LLM)|AI 분석]]는 알람을 요약하고 "평소와 같은 알람인지" 같은 참고 의견을 낼 뿐, 걸러낼지 말지는 규칙이 정합니다. 학습된 머신러닝 모델은 쓰지 않습니다.

규칙은 아래 순서로 적용되고, **먼저 걸린 규칙이 결과가 됩니다.**

| 순서 | 규칙 | 결과 |
|---|---|---|
| 1 | 같은 존·같은 서버·같은 알람·같은 자원이 정해진 시간(기본 4시간) 안에 [[다시 오면|재발 거르기]] | 다시 알리지 않고 횟수만 기록 |
| 2 | 주의처럼 [[최소 심각도]](기본 경고)보다 낮은 알람이면 | 판단 전에 버림, 통보·기록 없음 |
| 3 | **[[심각|2. 심각도3 단락]]** 알람이면 | **항상 즉시 통보([[PAGE|PAGE — 즉시 통보]])** — 아래 규칙을 거치지 않습니다. [[AI 분석]]이 실패해도 원문 알람으로 판단해 통보합니다 |
| 4 | [[해소 알람|4. 독립 해소]]이면([[발생 뒤 금방 스스로 복구된 경우|3. 자가복구 상관]] 포함) | 그 해소 알림은 [[통보하지 않고 기록|SUPPRESS — 기록만]] — 앞서 온 발생 알람의 결과는 바뀌지 않습니다 |
| 5 | [[부가 정보를 못 가져왔으면|5. 수집 실패 보수화]] | {{PAGE — 즉시 통보}} (주의 이상 PAGE) |
| 6 | 서버가 [[유지보수|6. 유지보수]] 중이거나 관리자가 건 [[침묵 규칙|7. 침묵 규칙]]에 걸리면 | {{SUPPRESS — 기록만}} (통보하지 않고 기록) |
| 7 | [[상위 장비 장애로 생긴 연쇄 알람|8. 의존성 연쇄]], [[짧은 시간에 몰린 알람|11. 스톰]], [[켜졌다 꺼졌다를 반복하는 알람|10. 플래핑]] | 대표만 알리거나 보류(관리자가 켠 경우). [[계획 작업 표시|13. 계획-무해 주석]]에 근거가 겹치면 [[DASHBOARD|DASHBOARD — 화면에만]](관리자가 켠 경우) |
| 8 | 위에 걸리지 않으면 **[[심각도 × 서버 중요도|14. 우선순위 매트릭스]]** 표로 기본 판단 | [[PAGE|PAGE — 즉시 통보]]·[[TICKET|TICKET — 확인 대기]]·[[DASHBOARD|DASHBOARD — 화면에만]] 중 하나 |
| 9 | [[보조 신호|15. 보조 신호 조정]](모니터링 시스템의 통보 정책, AI 의견, 운영자 피드백, 최근 변경 작업)로 조정 | **최대 한 단계** 올리거나 내림. 올릴 이유가 하나라도 있으면 내리지 않습니다 |

::: how
1. **노이즈 관제**를 열고 **결정 이력**에서 궁금한 알람 행을 누르세요.
2. **결정 추적**의 **판단 경로**에서 어느 단계에서 결과가 정해졌는지 봅니다.
3. **신호 스냅샷**에서 판단 순간의 값(실효 심각도, 중요도, 일상 반복, 통보 정책, LLM 액션가능성 등)을 봅니다.
4. [[9번 조정|15. 보조 신호 조정]]이 있었다면 사유에 「승격:」 또는 「강등:」 뒤에 이유가 적혀 있습니다.

- **이렇게 되는 알람**: 실효 심각도가 심각(3)인 알람, 부가 정보를 가져오지 못한 주의 이상 알람, 표에서 「경고 × 중요도 높음」 칸에 든 알람, TICKET 칸에서 올리는 신호를 받아 한 단계 올라간 알람입니다.
- **어떻게 처리되나요**: 관리자가 정한 통보 채널로 곧바로 보냅니다. 기본 채널은 업무 메신저 쪽지 하나입니다. 메신저 연결이 설정되지 않은 설치에서는 보내지 않고 넘어갑니다. 사건 추적 기능이 켜진 설치에서는 사건이 하나 열리고, 화면 알람 카드가 **확인** 버튼과 함께 뜹니다. 사건 추적이 꺼져 있으면 쪽지로만 받습니다.
- **읽는 법**: 재통보 간격 동안 같은 알람이 한 번이라도 반복됐다면, 간격이 지나 다시 온 쪽지에 「재발생 이력」 문단이 붙어 그 간격 동안 몇 번 왔는지(처음 통보 포함) 알려 줍니다. 간격 안의 반복은 쪽지가 다시 오지 않습니다.
- **주의**: 화면 표시 범위를 「긴급만」으로 두면 PAGE 카드만 보입니다.

##### TICKET — 확인 대기
- **무엇인가요**: 바로 부를 만큼 급하지는 않지만 누군가 확인해야 하는 알람입니다.
- **이렇게 되는 알람**: 표에서 「경고 × 중요도 보통」, 「주의 × 중요도 높음」 칸에 든 알람입니다. DASHBOARD 칸에서 올리는 신호로 한 단계 올라가거나, PAGE 칸에서 내리는 신호로 한 단계 내려가도 TICKET이 됩니다.
- **어떻게 처리되나요**: 쪽지를 보내지 않습니다. 대신 요약 목록에 한 줄 쌓이고, 화면 알람 카드로 알립니다. 카드에는 **확인** 버튼이 없습니다. 화면 카드가 실제로 뜨는지는 설치 설정에 따라 다릅니다.
- **주의**: 쌓인 TICKET은 관리자가 요약 발송을 켰을 때(기본 꺼짐)만 하루 한 번(기본 오전 9시) 요약 한 통으로 옵니다. 꺼져 있으면 화면 카드나 노이즈 관제의 결정 이력에서 직접 확인하세요. 화면 표시 범위가 「통보 대상」이나 「전체」여야 카드가 보입니다.

##### DASHBOARD — 화면에만
- **무엇인가요**: 알고만 있으면 되는 알람입니다. 누구도 부르지 않습니다.
- **이렇게 되는 알람**: 표에서 「경고 × 중요도 낮음」, 「주의 × 중요도 보통·낮음」 칸에 든 알람입니다. 관리자가 화면 표시로 정한 독립 해소 알림, 상위 장비 장애의 근본원인이 아직 통보되지 않은 연쇄 알람, 계획 작업 표시에 근거가 겹친 알람, TICKET 칸에서 한 단계 내려간 알람도 DASHBOARD입니다.
- **어떻게 처리되나요**: 쪽지도 요약 목록도 없이 화면 알람 카드로만 알립니다. 화면 카드가 실제로 뜨는지는 설치 설정에 따라 다릅니다.
- **주의**: 화면 표시 범위가 기본값 「전체」일 때만 보입니다. 「통보 대상」이나 「긴급만」으로 좁히면 화면에는 뜨지 않지만 결정 기록에는 그대로 남습니다.

##### SUPPRESS — 기록만
- **무엇인가요**: 통보하지 않아도 된다고 판단한 알람입니다. 지우는 것이 아니라 알리지 않는 것입니다.
- **이렇게 되는 알람**: 비운영 알람, 자가복구, 독립 해소(기본), 유지보수, 침묵 규칙, 의존성 연쇄, 인히비션, 플래핑, 스톰, 크로스-호스트 상관 단계에 걸린 알람입니다. 표만으로는 SUPPRESS가 나오지 않으며, DASHBOARD 칸에서 내리는 신호로 한 단계 내려간 경우에만 표에서 SUPPRESS가 됩니다.
- **어떻게 처리되나요**: 쪽지, 요약 목록, 화면 카드가 모두 없습니다. 판단 이유와 당시 신호 값이 결정 기록에만 남습니다. 관리자가 억제 알람 표시를 켠 설치에서는 관리자만 「억제 포함(감사)」 표시 범위로 화면에서 볼 수 있습니다.
- **읽는 법**: 노이즈 관제 결정 이력에서 티어를 SUPPRESS로 골라 조회하고, 행을 눌러 결정 추적에서 어느 단계가 걸렀는지 보세요.
- **주의**: 심각 알람은 비운영 알람으로 판정된 경우 말고는 SUPPRESS가 되지 않습니다.

#### 이렇게 동작합니다
알람 한 건은 받기부터 기록까지 아래 순서로 지나갑니다. 규칙 판단(「단계별로 자세히」) 앞에서 끝나는 단계가 있어, 그 알람은 결정 기록에 남지 않습니다.

##### 받기와 정리
- **무엇을 하나요**: 모니터링 시스템이 보낸 알람을 수신부가 받아 대기열에 넣고, 처리기가 한 건씩 꺼내 읽습니다.
- **심각도**: 「해제·주의·경고·심각」 같은 글자로 와도 0~3 숫자로 바꿉니다. 알아볼 수 없는 값은 버리지 않고 「경고(2)」로 보고 계속 처리합니다. 심각도 0이 해소 알림입니다.
- **서버 이름**: 호스트명만 온 알람은 모니터링 시스템에 등록된 서버 이름과 IP로 맞춥니다. 이후 모든 단계와 화면이 이 등록 이름을 씁니다. 이름 조회가 실패해도 알람은 버리지 않습니다.

##### 재발 거르기
- **무엇을 보나요**: 존·서버·알람명·자원이 모두 같은 알람이 재통보 간격(기본 4시간) 안에 다시 왔는지 봅니다.
- **걸리면**: 판단하지 않고 반복 횟수만 셉니다. 쪽지도 화면 카드도 결정 기록도 없습니다.
- **간격을 재는 법**: 그 알람이 마지막으로 이 거르기를 통과한 시각부터 잽니다. 반복해서 와도 간격이 늘어나지 않습니다. 간격이 지나 다시 판단에 올라가면 앞 간격 동안의 반복 횟수를 함께 넘깁니다.
- **예외**: 해소 알림은 앞선 발생과 짝을 찾아야 하므로 이 거르기를 거치지 않습니다. 심각 알람 전용 간격은 관리자가 따로 정할 수 있습니다(기본은 같은 4시간).

##### 최소 심각도
- **무엇을 보나요**: 심각도가 1 이상이면서 정해진 최소 심각도보다 낮은지 봅니다.
- **걸리면**: 여기서 버립니다. 판단도 기록도 없고, 노이즈 관제 숫자에도 들어가지 않습니다.
- **기본값**: 최소 심각도는 「경고(2)」라서, 기본 설정에서는 「주의」 알람이 모두 여기서 끝납니다(설치 설정에 따라 다를 수 있습니다).
- **예외**: 해소(0)와 심각(3)은 절대 버리지 않습니다.

##### 모양 살피기
- **무엇을 하나요**: 규칙 판단에서 쓸 표시를 미리 만들어 둡니다.
- **항상 보는 것**: 해소 알림이면 앞선 발생과 짝이 맞는지(자가복구) 봅니다.
- **관리자가 켠 것만 보는 것**: 인히비션, 플래핑, 스톰, 크로스-호스트 상관입니다. 꺼진 것은 표시를 만들지 않으므로 뒤 판단에서도 걸리지 않습니다.
- **주의**: 재발 거르기에서 끝난 반복은 여기까지 오지 않아, 플래핑·스톰·상관 계산에 들어가지 않습니다.

##### 부가 정보 모으기
- **무엇을 하나요**: 모니터링 시스템에서 자원 중요도, 유지보수 모드, 알람별 통보 정책을 가져옵니다. 관련 기능이 켜져 있으면 상위 자원 상태와 최근 변경 작업도 가져옵니다.
- **실패하면**: 이 정보 없이 판단을 이어 가되, 규칙 판단의 「수집 실패 보수화」 단계에서 주의 이상 알람을 PAGE로 확정합니다. 모르면 부르는 쪽을 택한 것입니다.

##### AI 분석
- **무엇을 하나요**: AI가 요약·추정 원인·권고 조치를 쓰고, 이 알람이 평소 반복되는 것인지 의견을 냅니다. 관리자가 켜 두면 메시지를 읽어 심각도를 **올리자는** 제안과, 운영자 피드백을 참고한 「액션 필요/노이즈」 의견도 냅니다.
- **판단과의 관계**: AI 의견은 다음 규칙 판단에서 신호로만 쓰입니다. 걸러낼지 말지는 규칙이 정합니다.
- **오류가 나면**: AI 의견 없이 원문 알람으로 규칙 판단을 계속합니다. 통보 요약에는 「AI 분석에 실패해 원문 알람으로 판단했습니다」가 나오고, 결정 추적의 단계 근거에 「AI 분석 실패 — 원문 알람으로 판단」이 남습니다. 심각 알람은 그대로 즉시 통보됩니다.

- **무엇을 하나요**: 규칙 판단이 정한 결과대로 처리합니다. 결과별 처리는 「항목별 설명」의 네 항목에 있습니다.
- **기록**: 결과가 무엇이든 판단 한 건을 결정 기록에 남깁니다. 노이즈 관제 화면이 이 기록을 보여 줍니다.
- **알람 거르기가 꺼진 설치**: 네 결과가 만들어지지 않습니다. 같은 알람 번호가 5분 안에 다시 오면 한 번만 처리하고, 최소 심각도 미만을 버린 뒤, 남은 알람을 모두 통보 채널로 보냅니다. 이때는 해소 알림도 최소 심각도 미만이라 버려집니다.

##### 8. 의존성 연쇄
- **무엇을 보나요**: 이 자원이 기대는 상위 장비·서비스의 상태입니다.
- **조건과 결과**: 기본 방식은 바로 위 한 단계만 보며, 상위가 비정상이면 SUPPRESS입니다. 여러 단계 위까지 보는 방식이 켜져 있으면, 근본원인 자원이 이미 통보됐을 때 SUPPRESS, 아직 통보되지 않았으면 DASHBOARD입니다.
- **켜기**: 관리자가 켜야 동작합니다.
- **예외**: 상위 상태를 모르면 억제하지 않고 다음 단계로 넘깁니다.

##### 9. 인히비션
- **무엇을 보나요**: 같은 존·같은 서버에서 최근에 난 다른 알람입니다.
- **조건**: **이름이 다른** 알람이 더 높은 심각도로 판정 창(기본 5분) 안에 발생해 있습니다.
- **결과**: 지금 알람을 SUPPRESS합니다.
- **켜기**: 관리자가 켜야 동작합니다.
- **예외**: 같은 이름의 알람은 자기 자신을 누르지 않습니다.

##### 10. 플래핑
- **무엇을 보나요**: 같은 알람의 최근 상태(발생·해소)를 최대 21번까지 기억해, 상태가 바뀐 비율을 최근 변화일수록 무겁게 쳐서 계산한 값입니다.
- **조건**: 상태가 5번 이상 쌓였고 비율이 20% 이상이 되면 진동 중으로 보고, 5% 이하로 내려가야 풀립니다(기본값). 진동 중이면서 심각도가 억제 허용 상한 이하입니다.
- **결과**: SUPPRESS.
- **켜기**: 관리자가 켜야 동작합니다.
- **예외**: 재발 거르기에서 끝난 반복은 계산에 들어가지 않습니다. 재통보 간격이 길수록 진동을 알아채기 어렵습니다.

##### 11. 스톰
- **무엇을 보나요**: 같은 존·같은 서버에서 60초 안에 난 발생 건수입니다.
- **조건**: 5건을 **넘었습니다**(이번 건 포함, 기본값).
- **결과**: 6번째부터 SUPPRESS. 처음 5건은 평소대로 판단받습니다.
- **켜기**: 관리자가 켜야 동작합니다.
- **예외**: 해소 알림은 세지 않습니다. 심각 알람은 이 단계보다 앞에서 PAGE로 끝납니다.

##### 12. 크로스-호스트 상관
- **무엇을 보나요**: 같은 존 안에서 **서버가 달라도** 알람명·자원 유형·메시지 특징 글자가 비슷한 알람입니다. 서버 이름은 비교에 넣지 않습니다.
- **조건**: 비슷한 정도가 0.5 이상인 알람이 2분 안에 이어져 한 묶음이 됩니다(기본값).
- **결과**: 먼저 온 알람이 대표가 되어 평소대로 판단받고, 두 번째부터 SUPPRESS합니다.
- **켜기**: 관리자가 켜야 동작합니다.
- **예외**: 나중에 대표를 바꾸지 않고, 존을 넘어서 묶지 않습니다.

##### 13. 계획-무해 주석
- **무엇을 보나요**: 메시지 안의 계획 작업 표시와, 그것을 뒷받침하는 근거입니다.
- **조건**: 계획 작업 표시가 있고, 해소 표시·상관 묶음·최근 변경 작업 근접 중 **하나 이상**이 함께 있습니다.
- **결과**: DASHBOARD. SUPPRESS까지 내리지는 않습니다.
- **켜기**: 관리자가 켜야 동작합니다.
- **예외**: 계획 작업 표시만 있고 뒷받침이 없으면 낮추지 않고 다음 단계로 갑니다.

##### 14. 우선순위 매트릭스
- **무엇을 보나요**: 실효 심각도와 자원 중요도입니다. 중요도는 모니터링 시스템의 중요도 코드를 높음·보통·낮음으로 바꾼 값이며, 알 수 없는 코드는 「보통」입니다.
- **결과**: 아래 표의 칸이 기본 결과입니다. 이어서 「15. 보조 신호 조정」을 거칩니다.

| 실효 심각도 | 중요도 높음 | 중요도 보통 | 중요도 낮음 |
|---|---|---|---|
| 경고(2) | PAGE | TICKET | DASHBOARD |
| 주의(1) | TICKET | DASHBOARD | DASHBOARD |

- **켜기**: 항상 동작합니다.
- **예외**: 관리자가 중요도 구분을 설정하지 않은 설치에서는 모든 알람이 「보통」이라, 표만으로는 PAGE가 나오지 않고 올리는 신호를 받아야 PAGE가 됩니다.

##### 15. 보조 신호 조정
- **무엇을 보나요**: 매트릭스 결과에 붙는 올리는 신호와 내리는 신호입니다.

| 올리는 신호 | 내리는 신호 |
|---|---|
| 모니터링 시스템 통보 정책이 「통보」 | 모니터링 시스템 통보 정책이 「비통보」(지금은 이 값이 만들어지지 않아 실제로는 쓰이지 않음) |
| AI가 평소와 다른 알람으로 봄 | AI가 일상 반복 알람으로 봄(억제 허용 상한 이하일 때만) |
| 피드백을 참고한 AI 의견이 「액션 필요」(켜진 경우) | 피드백을 참고한 AI 의견이 「노이즈」(켜진 경우 · 억제 허용 상한 이하일 때만) |
| 최근 변경 작업과 시간이 가까움(켜진 경우) | — |

- **결과**: 올리는 신호가 하나라도 있으면 한 단계 올리고 내리는 신호는 모두 무시합니다. 올리는 신호 없이 내리는 신호만 있으면 한 단계 내립니다. PAGE보다 위, SUPPRESS보다 아래로는 가지 않습니다.
- **읽는 법**: 사유 문장에 「매트릭스(…) → 기본 결과 · 승격: … → 최종 결과」 형태로 이 흐름이 그대로 남습니다.

|---|---|
| 심각 알람이 처음 온다 | PAGE. 유지보수 중이거나 침묵 규칙에 맞아도 PAGE입니다. 비운영 알람 거르기가 켜져 있고 안내 문구로 판정되면 SUPPRESS입니다. AI 분석이 실패해도 원문 알람으로 판단해 PAGE로 통보합니다. |

| 심각도 값을 알아볼 수 없다 | 「경고(2)」로 보고 판단합니다. |
| 모니터링 시스템에서 부가 정보를 못 가져왔다 | 주의 이상이면 PAGE입니다. |

| 여러 서버에서 같은 종류 알람이 한꺼번에 난다 | 상관이 켜져 있으면 같은 존 안에서 처음 한 건만 평소대로 판단하고 나머지는 SUPPRESS입니다. 심각 알람은 묶여도 각각 PAGE입니다. |
| 한 서버에서 알람이 쏟아진다 | 스톰이 켜져 있으면 60초 안 처음 5건까지만 평소대로 판단하고 그 뒤는 SUPPRESS입니다. 심각 알람은 몇 번째든 PAGE입니다. |
| TICKET 알람을 나중에 모아 받고 싶다 | 관리자에게 TICKET 요약 발송을 켜 달라고 요청하세요. 켜지면 하루 한 번 요약이 옵니다. 그 전에는 결정 이력에서 티어를 TICKET으로 골라 조회하세요. |

#### 자주 묻는 질문
궁금한 질문을 열어 보세요.

##### 걸러진 알람은 어디서 다시 보나요?
노이즈 관제의 결정 이력에서 티어를 SUPPRESS로 고르고 조회하세요. 다만 재발 거르기와 최소 심각도에서 끝난 알람은 판단이 없어 거기에도 나오지 않습니다([U-44](#u-44)).

##### 유지보수 중인 서버인데 왜 알람이 왔나요?
실효 심각도가 3이었거나, 모니터링 시스템에서 부가 정보를 가져오지 못해 유지보수 여부를 모른 채 판단했기 때문입니다. 두 판단 모두 유지보수보다 먼저라서 유지보수 모드여도 PAGE가 됩니다. 결정 추적의 판단 경로에서 「심각도3 단락」이나 「수집 실패 보수화」에 「여기서 결정」이 붙어 있는지 확인하세요.

##### 같은 알람인데 어떤 때는 PAGE, 어떤 때는 TICKET인 까닭은요?
판단 순간의 신호가 달랐기 때문입니다. 두 판단의 결정 추적을 열어 신호 스냅샷의 실효 심각도·중요도·통보 정책·일상 반복 값을 나란히 비교하세요. 값이 다른 줄이 결과를 가른 신호입니다.

##### TICKET 알람은 언제 모아서 오나요?
관리자가 요약 발송을 켰다면 매일 정해진 시각(기본 오전 9시)에 알람 종류별 건수 목록 한 통으로 옵니다. 한 번 받은 항목은 다시 오지 않습니다. 기본은 꺼져 있어 오지 않으며, 그때는 화면 표시 범위를 「통보 대상」 이상으로 두고 화면 카드로 보거나 결정 이력에서 TICKET을 골라 조회하세요.

##### 화면에 알람 카드가 하나도 안 뜹니다.
먼저 화면 머리의 알림 수신이 켜져 있는지, 표시 범위가 너무 좁지 않은지 보세요. 둘 다 맞는데도 안 뜨면 설치에서 화면 중계나 사건 추적이 꺼져 있을 수 있습니다. 이때도 쪽지와 결정 기록은 정상이니 관리자에게 설정을 확인해 달라고 하세요.

##### 「노이즈」 피드백을 여러 번 누르면 더 세게 걸러지나요?
아닙니다. 피드백 반영 기능이 켜져 있을 때만, 피드백은 **알람명이 정확히 같은** 다음 알람의 AI 의견에 참고 예시로 들어갑니다. 자원 이름과 발생 패턴이 같은 피드백을 먼저, 그다음 최신 것을 골라 최대 3건만 씁니다(기본값). 여러 번 누르면 예시 칸을 더 차지할 수는 있지만, 결과는 여전히 한 단계까지만 바뀝니다. 올리는 신호가 하나라도 있으면 그 회차에는 반영되지 않습니다.

## 부록

자주 묻는 질문, 화면에 뜨는 오류 메시지와 대응, 이 매뉴얼에 나오는 용어를 모았습니다.

#### 자주 묻는 질문

**무엇부터 물어보면 좋을까요?**
서버 목록부터 조회해 보세요. 예: 「전체 서버의 호스트명, OS종류, 벤더를 조회해줘」. 질문을 잘 쓰는 요령은 [U-19](#u-19)에 있습니다.

**「상위 N대」는 어떻게 묻나요?**
기준 기간, 지표, 정렬 방향, 개수를 한 문장에 담으세요. 예: 「2026년 6월 메모리 사용률 평균이 높은 순서로 상위 3대 서버를 보여줘」. 사용률(%)이나 코어 수처럼 숫자로 저장된 항목을 기준으로 삼으세요. 메모리·디스크 용량처럼 단위가 붙어 저장된 값으로 정렬하면 순서가 틀릴 수 있습니다([U-19](#u-19)).

**앞 질문의 결과에 이어서 물을 수 있나요?**
네. 같은 대화에서 「그 서버들의 ~」처럼 물으면 됩니다. 예: 「2026년 6월 CPU 사용률 평균이 높은 상위 3대 서버를 알려줘」 다음에 「그 서버들의 제조사와 OS 종류」. 자세한 내용은 [U-34](#u-34)를 보세요.

**결과를 Excel로 받고 싶어요.**
모든 조회 결과 아래에 **CSV 다운로드** 버튼이 있습니다. CSV는 Excel에서 바로 열립니다([U-22](#u-22)). 「전체 서버 목록을 엑셀로 만들어줘」처럼 양식 없이 요청하면 Excel 파일은 만들어지지 않습니다. 정해진 모양의 파일이 필요하면 양식을 첨부하세요([6장](#ch-6)).

**데이터를 고치거나 지울 수 있나요?**
아니요. 이 시스템은 조회만 합니다. 「서버 테이블 전부 삭제해줘」 같은 요청은 실행하지 않습니다([U-19](#u-19)).

**「가동률」을 물었더니 원하는 답이 나오지 않아요.**
가동률은 모니터링 데이터에 집계되지 않는 지표입니다. 답에 함께 나오는 대체 질문을 그대로 보내 보세요([U-19](#u-19)).

**우리 팀에서 쓰는 말로 물어도 되나요?**
유사어를 등록하면 됩니다. 예: 「hostname에 '장비이름' 유사 단어를 추가해줘」. 등록한 말은 모든 사용자에게 적용되니 확실한 것만 등록하세요([U-37](#u-37)).

**비밀번호를 바꾸고 싶어요.**
사용자 화면에는 비밀번호 변경 기능이 없습니다. 관리자에게 비밀번호 초기화를 요청하세요. 관리자가 임시 비밀번호를 발급해 전달합니다.

**비밀번호를 여러 번 틀려 계정이 잠겼어요.**
기본 설정에서는 30분이 지나면 다시 로그인할 수 있습니다(설치 설정에 따라 다름). 급하면 관리자에게 잠금 해제를 요청하세요([U-03](#u-03)).

**원하는 DB가 조회 대상에 없어요.**
조회할 수 있는 DB는 관리자가 정합니다. 권한이 없는 DB는 선택지에 나오지 않으니 관리자에게 권한을 요청하세요([U-24](#u-24)).

#### 오류 메시지와 대응

화면에 나오는 문구를 그대로 적었습니다. 괄호 안의 숫자(N)는 설치 설정에 따라 다릅니다.

**로그인 화면**

| 표시 문구 | 뜻 | 대응 |
|---|---|---|
| ID 또는 비밀번호가 올바르지 않습니다. | ID가 없거나 비밀번호가 틀렸습니다. | 입력값을 확인하고 다시 입력하세요. |
| 로그인 N회 실패로 계정이 잠겼습니다. | 비밀번호를 연속으로 틀려 계정이 잠겼습니다(기본 5회). | 잠금 시간이 지난 뒤 다시 로그인하거나 관리자에게 해제를 요청하세요. |
| 계정이 잠겼습니다. N분 후 다시 시도하세요. | 잠긴 계정으로 로그인을 시도했습니다(기본 30분). | 표시된 시간이 지난 뒤 다시 로그인하세요. |
| 비활성 계정입니다. | 관리자가 계정을 사용 중지했습니다. | 관리자에게 문의하세요. |
| 로그인에 실패했습니다. | 서버가 이유를 알려 주지 않은 실패입니다. | 잠시 후 다시 시도하고, 계속되면 관리자에게 알리세요. |

**로그인이 만료됐을 때**

- 화면을 열거나 새로고침했을 때 로그인이 만료되어 있으면 **안내 없이 로그인 화면으로 이동**합니다. 다시 로그인하세요.
- 질문을 보내는 중에 만료되면 답 말풍선에 「⚠ 토큰이 만료되었습니다.」와 응답 코드 401이 나옵니다. 이때는 **다시 시도**를 눌러도 같은 오류가 납니다. 화면을 새로고침해 다시 로그인한 뒤 질문을 다시 보내세요.
- 내려받기 버튼(CSV·결과 파일·매핑 보고서·원본 파일 카드)이나 **수정된 보고서 업로드**를 누를 때 만료돼 있으면 로그인 화면으로 이동합니다. 다시 로그인해도 예전 답의 내려받기 버튼은 다시 그려지지 않으니 질문을 다시 보내세요.

**내려받기**

| 표시 문구 | 뜻 | 대응 |
|---|---|---|
| 이 결과는 질의한 사용자만 받을 수 있습니다. | 다른 사람이 한 질문의 결과·CSV·결과 파일·매핑 보고서입니다. | 질문한 본인이 받거나 같은 질문을 직접 보내세요. |
| 원본 첨부 파일은 올린 사용자만 받을 수 있습니다. | 다른 사람이 올린 원본 양식입니다(관리자 계정도 같습니다). | 올린 본인이 받으세요. |

**DB 연결 경고 배너**

대화 영역 위에 뜨는 배너입니다. 30초마다 상태를 다시 확인하고, 정상이 되면 저절로 사라집니다([U-07](#u-07)).

| 표시 문구 | 뜻 | 대응 |
|---|---|---|
| 일부 DB 연결 불가: (DB 이름). 쿼리 결과가 불완전할 수 있습니다. | 적힌 DB에만 연결할 수 없습니다. 상태 배지는 WARNING입니다. | 다른 DB에 대한 질문은 정상입니다. 적힌 DB가 필요한 질문은 미루고 관리자에게 알리세요. |
| 모든 DB 서버에 연결할 수 없습니다. MCP 서버 상태를 확인하세요. | 어떤 DB에도 연결할 수 없습니다. 상태 배지는 OFFLINE입니다. | 조회가 되지 않습니다. 관리자에게 알리세요. |
| DB 서버(MCP Server)에 연결할 수 없습니다. 쿼리 실행이 불가능합니다. MCP 서버 상태를 확인하세요. | DB 하나만 쓰는 설치에서 그 DB에 연결할 수 없습니다. 상태 배지는 DB OFFLINE입니다. | 관리자에게 알리세요. |
| API 서버에 연결할 수 없습니다. 서버가 실행 중인지 확인하세요. | 이 화면이 서버와 통신하지 못했습니다. | 잠시 후 새로고침하고, 계속되면 관리자에게 알리세요. |

**질문 처리 중 오류**

| 표시 문구 | 뜻 | 대응 |
|---|---|---|
| 조회할 수 있는 DB가 없습니다. 관리자에게 DB 접근 권한을 요청하세요 (관리자 페이지 「사용자 관리」 탭에서 부여합니다). | 질문이 가리킨 DB가 모두 내 조회 권한 밖입니다(권한이 없는 계정 포함). 조회는 하지 않았습니다. | 권한 있는 존으로 바꿔 묻거나 관리자에게 「조회 가능 DB」 지정을 요청하세요([U-24](#u-24)). |
| 선택하신 DB는 조회 권한이 없습니다. 관리자에게 권한을 요청하거나 선택을 바꿔 주세요. | 조회 대상 칩으로 고른 DB가 권한 밖입니다. | 칩에서 다른 DB를 고르거나 관리자에게 권한을 요청하세요. |
| ⚠ 처리 시간이 초과되었습니다. 질의를 단순화해주세요. | 첫 답(표 또는 첫 글자)이 나오기 전에 처리 시간 상한을 넘었습니다. 말풍선에 「상한 N초 · 경과 …」와 멈춘 단계가 함께 나올 수 있습니다. 조회까지는 끝냈던 질문이면 이 오류 대신 **조회 결과 표**가 나옵니다(아래 참조). | 기간·서버·항목을 줄여 다시 물으세요. 같은 질문을 한 번 더 해 보려면 **다시 시도**를 누르세요([U-16](#u-16)). |
| 답 아래 「답변 생성이 N초 동안 멈춰 여기서 끊었습니다」 | 첫 답이 나온 뒤 답이 N초 동안 더 오지 않아 끊었습니다. 끊기기 전까지 받은 답은 그대로 남고 질의 이력에도 기록됩니다. | 받은 부분으로 충분하지 않으면 **다시 시도**를 누르세요. |
| 답 아래 「답변 전달이 전체 상한 N초(…)를 넘어 여기서 끊었습니다」 | 답은 계속 오고 있었지만 전체 시간 상한을 넘었습니다. 받은 답은 그대로 남습니다. | 답이 길게 나오는 질문은 기간·항목을 나눠 물으세요. |
| ⚠ 서버와의 통신에 실패했습니다: (사유) | 답을 받는 도중 연결이 끊겼습니다. | **다시 시도**를 누르세요. 계속되면 DB 연결 경고 배너가 떠 있는지 확인하세요. |
| ⚠ 처리 중 오류가 발생했습니다. | 서버가 질문을 처리하지 못했습니다. | **다시 시도**를 누르고, 계속되면 질문을 바꿔 보세요. |
| ⏹ 응답이 중단되었습니다 | 내가 **■**(응답 중단)을 눌러 멈췄습니다. 오류가 아닙니다. | 다시 보내려면 ↑ 키로 질문을 불러오세요([U-13](#u-13)). |
| 처리 중인 질의가 끝난 뒤 다시 시도해 주세요. | 다른 질문을 처리하는 중에 **다시 시도**를 눌렀습니다. | 진행 중인 답이 끝난 뒤 누르세요. |

**다시 시도**는 자동으로 실행되지 않습니다. 누를 때만 같은 질문을 다시 보냅니다.

#### 용어집

| 용어 | 뜻 |
|---|---|
| 존 | 데이터를 조회하고 알람을 받는 지역 단위입니다. 예: 은행존, 공동존. 어떤 존의 알람을 받을지는 관리자가 정합니다([U-09](#u-09)). |
| 존 그룹 | 존을 묶은 상위 구분입니다. 여러 존을 조회할 때 조회 순서와 선택 범위를 정합니다. 관리자가 존 그룹 상호배타를 켠 환경에서는 한 번에 한 그룹 안에서만 존을 고를 수 있습니다([U-25](#u-25)). |
| 조회 대상 | 이 대화가 조회하는 DB입니다. 입력줄 위 칩에 표시됩니다([U-24](#u-24)). |
| 승계 | 한 번 조회한 대상을 다음 질문에서도 그대로 쓰는 것입니다. 칩의 **×**로 풀 수 있습니다([U-24](#u-24)). |
| 역질문 | 질문만으로 정할 수 없는 것(존, 양식 항목 등)을 시스템이 되묻는 것입니다([U-25](#u-25), [U-29](#u-29)). |
| 유사어 | 같은 뜻으로 쓰는 다른 말입니다. 등록하면 그 말로 물어도 알아듣습니다([U-37](#u-37)). |
| 심각도 | 알람의 심한 정도입니다. 3=심각, 2=경고입니다. |
| 노이즈 게이트 | 받은 알람을 미리 정한 규칙으로 걸러, 통보할지와 어떻게 통보할지 판단하는 기능입니다([U-45](#u-45)). |
| 티어 | 노이즈 게이트의 판단 결과입니다. PAGE(즉시 통보) · TICKET(즉시 호출 없이 대기열·기록으로) · DASHBOARD(통보 없이 화면에만) · SUPPRESS(통보하지 않고 기록만) 네 가지입니다([U-44](#u-44)). |
| 억제 | 알람을 통보하지 않고 기록만 남기는 판단(SUPPRESS)입니다. 삭제가 아니며 결정 추적에서 이유를 볼 수 있습니다. 심각 알람은 억제되지 않습니다(비운영 알람 예외 — [U-45](#u-45)). |
| 억제율 | 받은 알람 중 억제(SUPPRESS)된 비율입니다. |
| 침묵 | 관리자가 기간을 정해 특정 서버·알람·자원의 통보를 멈추는 규칙입니다. 기록은 남고, 심각 알람은 침묵되지 않습니다. |
| 결정 추적 | 알람 하나가 왜 그렇게 판단됐는지 판단 경로와 당시 신호 값을 보여 주는 화면입니다([U-44](#u-44)). |
