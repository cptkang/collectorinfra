## 1. 결론

### 1.1 한 줄

**매뉴얼 두 권을 `src/static/manual/`의 자기완결 HTML로 만든다. 캡처는 모의 백엔드 위에서 playwright 스크립트로 결정적으로 다시 찍을 수 있게 하고, 기능 목록 manifest와 가드 테스트로 "모든 기능"을 기계적으로 보장한다.** 진입은 메인 화면 헤더의 두 링크다. 「사용자 매뉴얼」은 항상 보이고, 「관리자 매뉴얼」은 기존 Admin 링크와 같은 조건일 때만 보인다.

### 1.3 설계 요지 다섯

1. **매뉴얼은 정적 자산이다.** 새 백엔드 로직은 없다. 추가하는 서버 코드는 `/manual/user`·`/manual/admin` FileResponse 라우트 2개뿐이다(`src/api/server.py:693-721`의 기존 HTML 라우트와 같은 패턴).
2. **캡처는 사람이 아니라 스크립트가 찍는다.** UI가 바뀌면 매뉴얼이 낡는다. 사람이 찍은 캡처는 다시 찍을 수 없어서 곧 거짓말이 된다. `scripts/manual/capture.py` 하나로 전 캡처를 재생성한다.
3. **캡처 환경은 모의 LLM + 로컬 샌드박스다.** 실 LLM 0, 과금 0, 운영 데이터 0. 선례는 `tests/e2e/conftest.py`의 `MockGraph`(18980 포트)와 `scripts/scenario/mockserver.py`다. 캡처에 운영 호스트명·IP·시크릿이 들어가면 안 되므로 이 선택은 보안 요건이기도 하다.
4. **사용자 매뉴얼은 화면 설명이 아니라 사례로 가르친다.** 사용자가 실제로 입력할 프롬프트와 그 결과를 먼저 보여주고, 버튼 설명은 그 뒤에 둔다. 결과 샘플은 지어내지 않고 샌드박스에서 실제로 실행해 뜬 응답을 쓴다(§4.9).
5. **"모든 기능"은 문장이 아니라 목록으로 약속한다.** manifest가 없으면 누락을 알 방법이 없다(`plans/85`의 "헤더 상태 표기를 믿었다가…"와 같은 구조).

### 2.2 화면과 권한

역할은 `user`·`admin` 두 가지뿐이다(`src/domain/user.py:17-21`). 화면 문구의 「운영자」는 admin 권한 또는 break-glass 운영자 토큰(`/admin/login`이 발급, `type=admin`)을 뜻한다(`src/api/dependencies.py:188-215`).

| URL | 파일 | 누가 | 매뉴얼 |
|---|---|---|---|
| `/` | `index.html` + `js/app.js` | 사용자 | 사용자 |
| `/login` · `/register` | `login.html` · `register.html` | 누구나 | 사용자 |
| `/noise` | `noise.html` + `js/noise.js` | 로그인 사용자(읽기 전용 · D-245) | 사용자 |
| `/admin/login` | `admin/login.html` | break-glass 운영자 | 관리자 |
| `/admin` | `admin/dashboard.html` + `js/admin.js` · `js/admin-db-structure.js` | admin | 관리자 |
| `/static/admin/noise.html` | `admin/noise.html` + `js/noise.js` | admin | 관리자 |
| `/docs` | Swagger UI | 누구나 | 관리자(부록) |

**서버 쪽 HTML 인증은 없다.** 모든 화면은 JS가 토큰을 검사하고 리다이렉트한다(`app.js:116-176` · `admin.js:12-49` · `noise.js:26-41`). `/static`은 인증 없는 `StaticFiles` 마운트다(`server.py:726-732`). 따라서 `src/static/manual/*.html`은 **로그인 없이 열린다** → G-2.

### 2.3 진입 링크 자리

`index.html:64-71`의 헤더 nav에는 「노이즈 관제」(`#noiseConsoleLink`)와 「Admin」(`#adminEntryLink`, 기본 `display:none`)이 있다. 둘 다 `target="_blank" rel="noopener" class="btn btn-secondary"` 패턴을 쓴다. Admin 링크는 `app.js:146-152`에서 `userInfo.role === "admin" || !data.auth_enabled`일 때 `inline-flex`로 바뀐다. **관리자 매뉴얼 링크는 이 판정을 그대로 재사용한다**(판정 로직을 복제하지 않는다).

### 4.2 HTML 형식

- **외부 의존 0**: 폐쇄망 배포이므로 CDN·웹폰트 URL을 쓰지 않는다. 폰트는 `src/static/fonts/PretendardVariable.woff2`·`D2Coding.woff2`를 상대 경로로 쓴다.
- **레이아웃**: 좌측 고정 목차(장·절 앵커) + 본문. 폭이 좁으면 목차를 상단 접이식으로 바꾼다.
- **테마**: `js/theme.js`를 재사용해 사용자가 고른 라이트/다크를 따른다.
- **인쇄**: `@media print`에서 목차를 숨기고, 절마다 페이지를 나누고, 이미지 최대 폭을 지정한다 → 브라우저 「PDF로 저장」으로 배포본을 만들 수 있다.
- **캡처 표시**: `<figure>` + `<figcaption>`(「그림 3-2. 처리 현황 패널」). 클릭하면 원본 크기로 본다(라이트박스). `loading="lazy"`.
- **상호 링크**: 관리자 매뉴얼 → 사용자 매뉴얼(사용자 기능은 중복 서술하지 않는다). 매뉴얼 → 화면 링크(`/`·`/admin`)는 새 탭으로 연다.
- **판 정보**: 머리에 「기준 커밋 · 캡처 일자」를 박는다. `capture.py`가 채운다.

### 4.3 절 템플릿 (R2 「자세한 설명」의 정의)

각 기능 절은 다음 5칸을 채운다. **빈 칸이 있으면 가드가 실패한다**(§4.6).

1. **무엇** — 한두 문장. 이 기능이 해결하는 일
2. **어떻게** — 번호 단계. 단계마다 누르는 요소를 화면 표기 그대로(「선택한 존으로 조회」) 적는다
3. **화면 요소** — 캡처 + 콜아웃 번호 표(① 스코프 칩 ② ▾ 선택 ③ × 해제)
4. **주의·제약** — 권한, 기본 off 기능, 크기 제한, 알려진 한계(예: 알람 표시 레벨은 브라우저마다 따로 저장된다 — D-178 주의 ①)
5. **관련** — 다른 절 링크
6. **사례**(사용자 매뉴얼만 · R7) — §4.9의 사례 블록. 프롬프트로 쓰는 기능은 **이 칸이 절의 첫머리에 온다**(무엇 → 사례 → 어떻게 순서). 순수 UI 항목(테마·로그아웃 등)은 `n/a`와 사유를 manifest에 적는다

**문체**: 사용자 매뉴얼은 「~하세요」 안내체, 관리자 매뉴얼은 「~한다」 평서체다(G-5). 내부 설계 어휘(노드명·D 번호·계획서 번호)는 사용자 매뉴얼에 쓰지 않는다. 관리자 매뉴얼에서는 근거로 괄호 인용만 한다.

### 4.5 캡처 스크립트

- `python -m scripts.manual.capture [--only U-25] [--theme light|dark]` — manifest를 돌며 캡처 ID마다 「단계 → 대기 조건 → 콜아웃 주입 → 스크린샷(전체/요소 clip)」을 실행한다.
- **콜아웃**: manifest의 `callouts: [{n: 1, selector: "#dbScopeChip"}, …]`에 따라 번호 배지를 DOM에 absolute로 붙인 뒤 찍는다. 셀렉터가 없으면 **실패로 끝낸다**(조용히 건너뛰지 않는다).
- **출력**: PNG → 로컬에서 `pngquant`류 무손실·준무손실 축소(가능하면). 이미지당 목표 ≤200KB · 총량 ≤15MB(G-1).
- **실행 순서**: 사용자 → 관리자. 관리자 캡처는 admin 토큰으로 `localStorage`를 주입해서 로그인 화면을 건너뛴다(로그인 화면 캡처 1장은 별도).
- **설치**: `pip install -e ".[e2e]"`로 루트 venv에 playwright를 넣거나, 캡처 전용 `uvx --with playwright`로 실행한다(루트 venv를 오염시키지 않는 쪽 — W0에서 결정). 브라우저는 캐시 `chromium-1208`을 쓰고, 버전이 맞지 않으면 다운로드 전에 멈추고 보고한다.

### 4.6 "모든 기능" 가드 — manifest + 테스트

`scripts/manual/features.yaml` 항목 형식:

```yaml
- id: U-24
  manual: user
  title: 조회 대상 스코프 칩
  section: user.html#u-24          # 매뉴얼 절 앵커

  captures:
    - id: U-24-scope-chip
      page: /
      steps: [...]
      callouts: [{n: 1, selector: "#dbScopeChip"}, {n: 2, selector: "#dbScopePick"}]
  no_ui: false                     # 채팅 명령·API 전용이면 true (캡처 0 허용)
```

`tests/test_manual/test_manual_coverage.py`(playwright·LLM 불필요 — 순수 파일 검사라 본 스위트에 편입한다):

1. manifest의 모든 `id`에 대해 매뉴얼 HTML에 `id="u-24"` 절이 있고, §4.3의 5칸 마커(`data-slot="what|how|ui|caution|related"`)가 비어 있지 않다
2. `no_ui: false`이면 캡처가 1장 이상이고, `<img src>`가 실존 파일을 가리킨다
3. `ui_anchors`의 id·레이블 문자열이 `ui_files`에 실존한다(grep) — **UI에서 요소가 사라지면 매뉴얼이 낡았다는 신호**다
4. **역방향 감시**: `index.html`·`dashboard.html`·`noise.html`·`admin/noise.html`의 `<button>`·탭(`data-view`·`data-tab`) id 중 어느 manifest 항목에도 속하지 않은 것을 나열하고, 예외 목록(`features.yaml`의 `ignore:` — 사유 필수)에 없으면 실패한다. **새 버튼이 생겼는데 매뉴얼이 없는 상태를 막는다.**
5. 매뉴얼 HTML에 외부 URL(`http://`·`https://`) 리소스 참조가 0건이다(폐쇄망)
6. **사례 가드(R7)**: 사용자 manifest 항목 중 `case: n/a`가 아닌 것은 사례 블록이 1건 이상이다. 블록의 「입력」은 `samples/<case_id>.json`의 질의와 같고, 「결과」 표는 샘플 파일 결과 행의 앞부분과 일치하며, `sample_reviewed: true`다

> 4번의 범위는 버튼·탭 id로 한정한다. JS가 동적으로 만드는 요소(알람 카드 버튼 등)는 manifest가 레이블 문자열로 잡고, 역방향 감시 대상에서는 뺀다. 과잉 탐지로 가드가 무시되는 것보다 좁고 확실한 편이 낫다.

### 4.9 프롬프트 사례와 결과 샘플 (R7)

#### 4.9.1 사례 블록 형식

```
┌ 사례 3-2. 특정 지역 서버의 CPU 사용률 상위 목록 ───────────────────────┐
│ 입력      김포 서버 CPU 사용률 상위 10건 보여줘                           │
│ 결과      (요약 1~2문장 — 응답 원문 발췌)                                  │
│           | 호스트명 | CPU 평균(%) | … |   ← 상위 3~5행 + 「… 외 N행」      │
│           [결과 화면 캡처 1장 — 대표 사례만]                                │
│ 포인트    위치(「김포」)를 넣으면 조회 존이 좁혀진다.                        │
│           빼면 존 선택 역질문이 뜬다(→ 5장)                                  │
│ 바꿔 보기 「지난주」 「메모리」 「하위 10건」                                │
└──────────────────────────────────────────────────────────┘
```

- **입력**: 사용자가 그대로 복사해 쓸 수 있는 문장이다. 「복사」 버튼을 둔다. 입력창에 넣어 주는 링크는 두지 않는다(매뉴얼은 메인 화면과 다른 탭이다).
- **결과 샘플은 간단히**: 응답 요약 1~2문장 + 표 상위 3~5행(검색·복사가 되도록 텍스트 표) + 대표 사례만 캡처 1장. 양식 채우기 사례는 「채우기 전 / 채운 뒤」 양식 미리보기 2장이다.
- **포인트**: 이 문장의 어느 부분이 결과를 바꾸는지 설명한다. 「자세한 설명」 요건은 주로 이 칸이 채운다.
- **바꿔 보기**: 같은 기능의 변형 프롬프트 2~4개. 결과 샘플은 달지 않는다(분량 관리).
- **잘 안 되는 예**(선택): 시나리오 R2·R3·R4군(오용·실수·착각)에서 가져온 대조 사례다. 「이렇게 물으면 → 이런 안내가 나온다 → 이렇게 고쳐 묻는다」로 쓴다. 사용자가 가장 자주 막히는 지점이라 매뉴얼 가치가 크다.

#### 4.9.3 결과 샘플을 어디서 얻나

**지어낸 결과는 싣지 않는다.** 샘플이 실제 응답 모양과 다르면 사용자가 자기 결과를 오류로 오해한다.

| 방법 | 설명 | 판정 |
|---|---|---|
| **① 샌드박스 실 실행 → 고정(권고)** | 로컬 docker 샌드박스(`polestar` PG · `testdata/pg/init`) + **로컬 MLX 두 평면**으로 사례 프롬프트를 실제 파이프라인에 흘리고, 응답(`final_response`·결과 행·SQL·산출 파일)을 `scripts/manual/samples/<case_id>.json`으로 떠 둔다. 캡처용 모의 앱은 이 파일을 재생한다(§4.4 모의 그래프가 질의 문구에 따라 샘플 파일로 분기) | 실제 모양 그대로 · 캡처는 여전히 결정적·무과금 · **D-240: 두 평면이 `mlx`면 사용자 승인 없이 실행한다.** 실행 전 `python -m scripts.bench --show-env`로 두 평면이 `mlx`로 해석되는지 확인하고, 하나라도 과금 평면이면 실행하지 않는다 |
| ② 모의 응답 수작업 | `MockGraph`에 손으로 응답을 적는다 | 빠르지만 실제와 어긋난다 — **사례 샘플에는 쓰지 않는다.** 역질문·오류 같은 제어 화면에만 쓴다 |
| ③ 운영(폐쇄망) 실행 결과 | 내부망 FabriX로 실행 | 운영 호스트·IP가 들어가 **매뉴얼에 실을 수 없다** — 쓰지 않는다 |

- **샌드박스 한계**: 시나리오 대부분이 `env: closed`(운영 DB 3종 전제)다. 존 선택 역질문(F군)처럼 **존이 여럿 있어야 나오는 화면**은 샌드박스 단일 DB로 재현되지 않을 수 있다. W1.5에서 사례별 재현 여부를 표로 남긴다. 재현되지 않는 것은 ②로 제어 화면만 만들고, 본문에 「화면 예시」라고 표기한다(G-6).
- **MLX 결과 품질**: 로컬 MLX 9B급 모델은 운영 모델보다 응답 문장이 거칠 수 있다. 샘플이 틀렸으면(행 수·SQL 오류) **싣지 않고 프롬프트를 바꾸거나 다시 실행한다.** 샘플마다 사람이 정답 여부를 한 번 확인하고 manifest에 `sample_reviewed: true`를 남긴다.
- **마스킹**: 샌드박스 데이터는 합성이지만, 샘플 파일에 `.env` 값·토큰·내부 경로가 섞이지 않았는지 가드 테스트가 검사한다(§4.7과 같은 패턴 검사).
- **재생성**: `python -m scripts.manual.samples --run`(MLX 실 실행 · 몇십 분) / 기본은 `--check`(샘플 파일과 manifest 대조만). 캡처는 샘플 파일만 읽으므로 **캡처 재생성에는 LLM이 필요 없다.**

### 10.3 샘플 검토 — 제품 결함 관찰 (고치지 않고 보고)

> **★ 보안 — 기준 경로(2단)가 사용자별 DB 인가(D-232)를 우회한다.** 조회 가능 DB 가 빈 목록(`{}` = 전체 차단)인 사례 계정이 2단에서는 샌드박스를 조회했고, 같은 계정·같은 서버 구성의 3단은 「조회할 수 있는 DB가 없습니다」로 거절했다(2026-09-23 · `Q-SQL` 녹화). 원인: 인가는 `src/graph.py` 의 `authorized_router` 로 **3단 `semantic_router` 노드 경계에만** 배선돼 있고, 2단 `run_data_query_pipeline`(`src/orchestration/subagents.py`)은 `allowed_db_ids` 를 전달만 하고 거르지 않는다. D-251 로 기준 경로가 2단이 됐으므로 운영 전환(`ENABLE_DEEPAGENTS_PACKAGE=false`) 전에 막아야 한다. 이번 작업 범위 밖이라 고치지 않았다. **2026-09-23 병행 세션(D-251 담당)이 코드로 확인하고 수정을 맡았다**(1·2단이 공유하는 `subagents.classify_dbs`·`run_data_query_pipeline` 가 활성 DB 전체를 대상으로 삼는다).


사례 샘플을 샌드박스 독립 SQL 로 대조했다(판정은 `fixtures/samples/*.json` 의 `review`). 틀린 답은 매뉴얼에 싣지 않고 문장을 바꿔 재녹화했다. 로컬 MLX(9B) 결과이므로 운영 모델에서 재현되는지는 **측정하지 않았다**.
