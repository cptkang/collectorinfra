## 0. 요약

**(1) 요구** — ① 제니퍼 조회의 주 식별자는 **인스턴스 이름**이다 ② 인스턴스 이름으로 물으면 제니퍼 API로 **전체 인스턴스 목록**을 읽어 관련 인스턴스를 찾고 조회한다
③ **업무명**으로 물으면 폴스타(SMS)나 제니퍼 정보로 인스턴스 이름을 찾아낸 뒤 조회한다.

**(2) 지금과 이 계획 뒤**

| 사용자가 이렇게 물으면 | 지금(실측 §2) | 이 계획 뒤 |
|---|---|---|
| 「WAS_ORD01 응답시간」(정확한 인스턴스 이름) | 파서가 `hostname` 칸에 넣고, 게이트웨이 정합 규칙 `exact`(인스턴스명 = 값)에 **우연히** 맞아 조회된다(A-3·A-4) | 인스턴스 이름 검색으로 **명시적으로** 처리하고 해석 근거를 고지한다 |
| 「ord was 응답시간」(부분 이름 · 대소문자·구분자 차이) | `exact`·`prefix`(「값_」·「값-」로 시작) 규칙뿐이라 대부분 `instance_unresolved` | 정규화·접두·포함 단계 검색 → 상한 안이면 모두 조회 + 고지, 넘으면 후보 제시 |
| 「이미지 업무 WAS 응답시간」(업무명) | 업무명은 식별자 추출 규칙 밖이다. 뽑히지 않으면 대상이 비어 **첫 홉이 인스턴스 목록 앞 10개를 임의로 조회**한다(A-1). 뽑혀도 hostname으로 넘어가 `instance_unresolved` | 업무명 해석(수동 매핑 · 제니퍼 도메인·업무 정의·인스턴스 설명 · **폴스타 등록명·비고**) → 인스턴스 이름 → 조회 |
| **(v1.2)** 「도메인 아이디가 1130인 인스턴스 리스트를 보여줘」(도메인 ID) | **전 도메인 인스턴스 목록**이 답변 LLM에 넘어가고, LLM이 눈대중으로 골라 다른 도메인 인스턴스가 섞인다(사용자 보고 2026-10-06 · A-11·A-12) | 게이트웨이가 `domain_id`로 걸러 **그 도메인 인스턴스만** 돌려준다 · 없는 도메인이면 「도메인 목록에 없음 + 있는 도메인」 고지(N-7·M-7) |

**(3) 한 줄 설계** — 분해 LLM은 대상 **텍스트와 종류(인스턴스·업무)만** 뽑고, 해석은 결정적 코드가 한다. 인스턴스 이름·제니퍼 쪽 업무 해석은 **게이트웨이**(정합 한 곳 — D-274 ⑤),
폴스타(SMS) 업무명 조회는 **본체의 폴스타 소유 간선**(새 간선 E6)이 맡는다. 해석 결과(인스턴스 이름 + 소스)로 기존 보기 도구를 부른다. 사용자가 대상을 말했는데 못 찾으면 **임의 인스턴스를 조회하지 않고** 「찾지 못함 + 비슷한 이름」을 답한다.

## 1. 요구 해석

| # | 요구 | 해석 |
|---|---|---|
| R-1 | 대부분 인스턴스 이름으로 조회 | 제니퍼 조회의 기본 식별자를 hostname에서 **인스턴스 이름**으로 옮긴다. hostname은 폴스타 결과와 합칠 때의 결합 키로 남는다 |
| R-2 | 전체 인스턴스 목록에서 관련 인스턴스 찾기 | 게이트웨이 인벤토리(모든 제니퍼 소스 × 도메인의 `/api/instance` — J8 캐시)를 검색한다. 「관련」 = 정확 > 정규화 > 접두 > 포함 단계 일치. 유사(오탈자)는 **제안만** |
| R-3 | 업무명 → SMS 조회 또는 제니퍼 정보 조회 → 인스턴스 이름 → 조회 | 근거 여러 개를 쓴다: 폴스타 등록명·비고(SMS) · 제니퍼 도메인 이름 · 제니퍼 업무(Business) 정의 · 제니퍼 인스턴스 이름·설명 · 수동 매핑 |

**가정(틀리면 알려 주세요 — Q-1)**: 「SMS」 = **폴스타**다. 저장소 문서가 폴스타를 「폴스타(SMS)」로 부른다(`plans/55` 머리 · `docs/aiops_benchmark/ml_rca_literature.md:6`).
자산관리(ITAM) 스키마의 「업무」는 문서 이름(「업무룰리모델…」 — `testdata/itam/schema.yaml:6`)이라 서버 업무명의 출처가 아니다.

**주 소비 경로** = 본체 채팅(2단 기준 경로의 `apm_query`). `sre_agent`는 도구 인자 확장으로 같은 해석을 쓸 수 있게 문구만 바꾼다. `noise_gate`는 알람이 hostname을 가지므로 대상이 아니다.

- **업무 정의에는 인스턴스 목록이 없다**(`Business` 스키마 — 업무는 규칙으로 정의한다). 제니퍼만으로 업무 → 인스턴스를 얻으려면 트랜잭션·액티브 서비스의 `businessId`로 **관측 역추적**을 해야 한다. 이 방식은 최근 처리한 인스턴스만 잡는다(한가한 인스턴스 누락).
- 로컬 녹화본 지표 카탈로그(`apm_gateway/testdata/jennifer/recorded/local-docker/GET_api_metrics__ok.json`)에 `business` 지표 29종이 있다 — 5.7.0.1에도 업무 층이 있다.
- 제니퍼 도메인은 「에이전트 묶음(서비스·업무 단위)」이다(`docs/31_jennifer_integration_guide.md:147`). 운영 도메인 이름이 업무명인지는 모른다(J0-O).
- 로컬 Docker 제니퍼는 라이선스가 없어(`plans/87` §0.12) 인스턴스·업무·트랜잭션 **실데이터를 볼 수 없다**. 모양은 스펙 합성 픽스처로 시험하고 J0-L-b·J0-O에서 확인한다.

## 4. 설계

### 4.1 흐름

```
사용자 질의
 ├─ 분해 LLM: apm_query task { views, targets: [{text, kind: instance·business·auto}] }   ← APM 활성일 때만 렌더(G-6)
 └─ 입력 파서: filter_conditions hostname(종전 그대로)

apm_query (LLM 0)
 1) 대상 텍스트 모으기 = task.targets ∪ 파서 식별자 ∪ 선행 대상
 2) 텍스트마다 해석
    kind = instance 또는 auto → 게이트웨이 apm_instance_map(query=텍스트)            [인스턴스 이름 검색 — N-1]
    kind = business, 또는 auto인데 인스턴스 0건 →
        게이트웨이 apm_instance_map(business=텍스트)                                  [제니퍼 쪽 업무 해석 — N-2]
      ∥ 폴스타 업무명 조회(간선 E6: 등록명·비고 → hostname) → 게이트웨이 apm_instance_map(hostname=…)
      → 합치기·근거 표기(G-3)
 3) 판정(G-4)
    0건         → 조회하지 않는다 · 「찾지 못함」 + 비슷한 이름 ≤3 (첫 홉 임의 선정 금지 — A-1 수정)
    1 ~ 상한    → 모두 조회 · 해석 고지 1줄
    상한 초과   → 조회하지 않는다 · 후보 목록 + 좁혀 달라는 안내
    〔구현 부기 2026-10-06 — D-296 ④가 D-290 ⑤를 개정: 상한 없이 1건 이상이면 전부 조회 · 「상한 초과」 분기 없음〕
 4) 조회 = 기존 보기 도구를 instance_name(+source_id)으로 호출(N-3)
 대상 텍스트가 하나도 없을 때만 종전 첫 홉(목록 보기)
```

### 4.2 게이트웨이 (`apm_gateway/` — 인스턴스·제니퍼 쪽 업무 해석 한 곳 · D-274 ⑤)

| # | 내용 |

## 6. 수용 기준

- **인스턴스 이름**: 정확 · 대소문자 · 구분자 차이 · 접두 · 포함 각 단계를 단언한다. 앞 단계 결과가 있으면 뒤 단계를 채택하지 않는다. 여러 소스에 같은 이름이면 소스를 표기한다. 유사 이름은 제안만 하고 조회하지 않는다. hostName이 빈 인스턴스도 이름으로 조회된다.
- **업무명**: B0~B3 각 근거 단독·조합 · 폴스타 E6(등록명·비고 · 방언 2종 · DB 권한 밖 DB 조회 0) · 근거 표기 · 0건·상한 초과 처리(〔구현 부기: 상한 초과 분기 없음 — D-296 ④〕).
- **A-1**: 명시 대상 해석이 0건이면 보기 도구 호출 0(검색 호출만) · 「찾지 못함」 고지. 대상 텍스트가 없으면 종전 첫 홉 그대로.
- **프롬프트**: APM 비활성 배포의 렌더 바이트 불변(`plans/125` §15.1 렌더 지문 방식) · 활성 APM 절은 삽입만.
- **(v1.2) 도메인 ID**: `domain_id`를 주면 결과 행의 `domain_id`가 **전부** 그 값이다(목록·hostname 정합 두 경로) · 없는 도메인은 행 0 + 「도메인 목록에 없음(있는 도메인 …)」 고지(침묵 0건 금지) · 형식 밖 값은 게이트웨이 `invalid_argument` / 본체는 버리고 고지 · 미지정이면 종전 결과와 같다 · 분해 프롬프트의 APM 비활성 렌더 바이트 불변.
- **통제**: 허용목록 17(〔구현 부기: 36 → 37〕) · 거부 규칙 불변 · `/api/business` 밖 business 경로 거부 · 도구 수 ≤8(D-195 — 〔구현 부기: D-299 ③으로 숫자 상한 폐지 · 새 도구 0은 유지〕) · 경계 불변식(import 0) · `overfit_check`·`arch_check` 신규 유입 0.

## 7. 다른 계획과의 경계
