## 1. 왜 "상태 표기"만으로는 답이 되지 않는가

`plans/INDEX.md`는 계획서 앞부분 40줄의 `**상태**:` 표기를 기계적으로 옮긴다. 이 방식은
**표기 자체가 낡는 것을 잡지 못한다.** 실제로 이번 대조에서 표기와 코드가 어긋난 사례를 4건 찾았다.

## 2. 조사 방법 — 재현 명령

두 축을 교차했다. **표기 축 단독으로는 §1의 4건을 놓치고, 코드 축 단독으로는 "무엇을 만들려 했는지"를 모른다.**

**축 1 — 표기 수집(전건 기계 추출)**

```bash
cd /Users/cptkang/AIOps/collectorinfra
for f in plans/*.md; do
  s=$(head -40 "$f" | grep -oE '\*\*상태\*\*[^|]*|^상태[:：][^|]*' | head -1 | tr '\n' ' ' | cut -c1-120)
  printf "%-60s | %s\n" "$(basename $f)" "${s:-(미표기)}"
done
```

**축 2 — 코드 실측(핵심 산출물 존재 확인)**

```bash
# Plan 50·51 — RCA/증거수집 엔진
grep -rln "root_cause\|rca_" --include="*.py" src noise_gate sre_agent      # → 0건
# Plan 54 — 노이즈 대시보드
grep -rln "noise.*dashboard" --include="*.py" --include="*.html" src noise_gate  # → 0건(목업 HTML만)
# Plan 56 — Langfuse
grep -rl "langfuse" --include="*.py" --include="*.toml" .                    # → 0건
# Plan 77 — 유사어 제안 큐
grep -rln "synonym_proposal\|proposal_queue" --include="*.py" --include="*.tsx" .  # → 0건
# Plan 68 — 설정 카탈로그(반증 사례)
ls src/api/settings_catalog.py                                               # → 실재
# Plan 46 — 알람 수신부(반증 사례)
ls noise_gate/alarm_server/                                                  # → 7개 파일
```

**축 3 — 태스크 진행률(체크박스 집계)** — `tasks/` 아래 todo 파일이 있는 계획에 한해

```bash
grep -c "^- \[x\]" tasks/todo-70.md   # 73
grep -c "^- \[ \]" tasks/todo-70.md   # 10
awk '/^### /{sec=$0} /^- \[ \]/{print sec" || "$0}' tasks/todo-70.md   # 미완 항목 소속 절까지
```

> **주의(D-161 ② 4항)**: 본 문서는 **어떤 경로의 폐기도 제안하지 않는다.** 폐기 제안은 4항 실측
> (①`.env` 운영 실제값 ②실 설치·서빙 상태 ③`git log` 최종 수정일 ④역방향 import)이 필수인데,
> 인벤토리 목적의 존재 확인 grep은 그 요건을 충족하지 않는다. §8의 중복 판정도 **"판정하라"는 제기**이지
> 판정 결과가 아니다.

## 10. 이 문서의 한계와 갱신 규칙

### 10.1 한계

1. **존재 확인 grep은 완성도를 측정하지 않는다.** "코드 0건"은 확실하지만, 코드가 있다고 해서
   계획서의 수용 기준을 충족한다는 뜻은 아니다. B범주의 판정은 **계획서 자신의 상태 기록에 의존**했다.
2. **`main` 브랜치 상태를 보지 않았다.** 전부 현 브랜치(`multiintent`) 기준이다.
3. **`plans/sre-agent/` 7건은 개별 판정하지 않았다** — Plan 66이 그 잔여를 R1~R16으로 흡수해
   장부화하고 있어 이중 집계를 피했다.
4. **`multiturn_plan.md`·`schemacache_plan.md`·`xls_plan.md`·`README.md`** 는 번호 없는 초기 문서라
   판정 대상에서 제외했다.
5. **폐기 제안이 아니다.** §8.1의 중복 제기는 D-161 4항 실측을 거치지 않은 관찰이다.

### 10.2 갱신 규칙

- 본 문서는 **스냅샷**이다. 계획이 랜딩할 때마다 갱신하는 문서가 아니라, **주기적으로 §2 명령을
  재실행해 다시 만드는** 문서다. 상시 정본은 각 계획서의 본문 표와 `tasks/todo-*.md`다.
- 갱신 시 **§2의 세 축을 모두 다시 돌린다.** 표기 축만 돌리면 §1의 어긋남을 놓친다.
- 본 문서는 **D-번호를 소유하지 않는다.** 여기 나열된 항목이 실제로 착수될 때 해당 계획서가
  자기 예약분을 등재한다. 예약 번호(D-038·D-039·D-163 등)는 **작성 시점 값이므로 착수 시 재확인**한다
  — 「채번 이력」 표에 등재되지 않은 예약은 효력이 없다(D-161 부기).
