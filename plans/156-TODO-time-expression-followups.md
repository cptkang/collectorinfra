## 0. 요약

plans/159는 「분 단위 기간」을 해석기에 넣었다. 그 과정에서 같은 해석기에 **그 계획 밖의 결함 11건**이 확인됐다. 이 계획은 전건을 현행 실측하고(§1), 영향 순서로 묶는다.

**우선순위 = 실측된 영향 순**: (A) **조용한 오해석**(사용자가 말한 시각·수·단위를 고지 없이 버리거나 바꿔 다른 기간을 조회) > (B) **불필요한 되묻기·비대칭** > (C) **도구·문구 틈**.

| 군 | 항목 | 한 줄 현상(기준 10:37) |
|---|---|---|
| **A 조용한 오해석** | 1 시각 시작점 | 「오늘 14시부터」 = 하루 전체(00:00~). **시각 표현 전반이 하루로 뭉개진다**(§1.1) |
| | 2 한자어·확장 고유어 수사 | 「삼십 분」·「삼십 일」·「이십 시간」·「열다섯 시간」 = 흔적에도 안 걸려 **지난달 기본 기간**으로 간다 |
| | 7 「1시간 반쯤」 | 「쯤」이 붙으면 「반」을 버리고 1시간 |
| | 8 영문 `min` | 「최근 30 min」 = 기본 기간(`hours`·`minutes`는 인식하는데 `min`만 빠짐) |
| | 9 슬롯 단위 미대조 | 「최근 30 min」 + 슬롯 `unit=hour` = **30시간**을 `accepted` |
| | 5 시·일 빈도 어휘 | 「최근 3시간 이상 걸린」·「최근 3시간마다」·「최근 3일 간격」 = 3시간·3일 기간(분은 159에서 막았다) |
| **B 불필요한 되묻기·비대칭** | 3 사건 시 롤링 | 「최근 3시간 알람」이 직전 정시(10:00)에서 끝나 10:00~10:37이 빠진다 |
| | 4 「N시간 전」 | 되묻기 — 「N분 전」은 해석(비대칭) |
| | 6 자릿수 | 「최근 10000~10080분」이 `N_MAX` 이하인데 되묻기(인식기 4자리) |
| **C 문구·도구** | 10 「이번 분」 | D-328 ⑧ 본문 「되묻는다」 ≠ 실측(기본값 + 고지) — 부기 ⓐ와 정합 |
| | 11 도구 틈 | `prompt_render_diff.py`가 `input_parser` 프롬프트를 비교하지 않는다 |

**결정이 필요한 것은 8건(G-1~G-8)** — 시각 시작점의 범위·의미(G-1·G-2), 사건 롤링 개정(G-3), 한자어 수사 범위(G-4), 시·일 빈도 어휘(G-5), 「N시간 전」(G-6), 「이번 분」 처리(G-7), 플래그(G-8). 나머지(6·7·8·9·11)는 결정 충돌이 없는 결함 교정이라 게이트 없이 진행한다(근거 §4).

## 1. 문제 / 현행 실측

### 1.1 실측 표 (2026-10-13 10:37 KST · 작업 트리 기준 · `resolve_query_time(…)`)

표기: `M`=성능 통계(`metric`), `E`=사건(`event`·알람). `기본값` = `source=default`·`default_period` 고지(M 지난달 09-01~10-01 · E 기간 조건 없음).

**① 시각 시작점**

| 질의 | clarify | M | E | 판정 |
|---|---|---|---|---|
| 오늘 14시부터 알람 / CPU | 없음 | 10-13 00:00~10:00 | 10-13 00:00~10:37 (`event_to_now`) | **시각 무시 · 하루 전체.** 14시는 기준 시각보다 **미래**인데 되묻지도 않는다 |
| 어제 10시 30분부터 알람 | 없음 | 10-12 00:00~10-13 00:00 | 같음 | 시각·분 무시 · 어제 하루 |
| 10시 30분부터 알람 | `unresolved` | — | — | 되묻기(159 G-5 (b)로 의도) |
| 어제 10시 알람 | 없음 | 10-12 하루 | 같음 | 시각 무시 |
| 오늘 오전 9시 알람 | 없음 | 10-13 00:00~10:00 | 00:00~10:37 | 시각 무시 |
| **오늘 9시부터 10시까지 알람** | 없음 | 10-13 00:00~10:00 | 00:00~10:37 | **범위 시각 둘 다 무시** |
| 2026년 9월 15일 10시 30분부터 | 없음 | 09-15 하루 | 같음 | 시각·분 무시(159 §9 ① 확인) |
| 9월 15일 14시 알람 | 없음 | 09-15 하루(`year_inferred`) | 같음 | 시각 무시 |

- **새로 발견**: 159 §9 ①은 「오늘 14시부터」·「10시 30분부터」만 적었으나 **「N시」가 붙은 모든 절대·상대 날짜 표현이 하루로 뭉개진다**(범위형 「9시부터 10시까지」 포함). 시각 토큰은 `_TRACE_RE`에도 인식 규칙에도 없다(`시(?!간|스템|설|리즈|즌)`는 **숫자 직전 단위**일 때만 — `time_expr.py:572`).
- 슬롯 스키마: `PartialDate`는 이미 `hour`를 갖는다(`time_spec.py:163-166` · `_PARTIAL_KEYS` `time_expr.py` 741 부근) — **`minute`만 없다.** 단 절대 명세에 `hour`가 들어왔을 때 `resolve`가 시 정밀 구간을 만드는지(아니면 일 단위로 자르는지)는 W0에서 `time_spec.resolve` absolute 분기를 읽어 확정한다(미확인).

**② 한자어·확장 고유어 수사**

| 질의 | clarify | M | 판정 |
|---|---|---|---|
| 최근 세 시간 알람 | 없음 | 07:00~10:00 | 정상(고유어 한~열두·스물네 지원) |
| 세 시간 알람 (접두 없음) | `unresolved` | — | 맨 「N시간」과 대칭(흔적) — 정상 |
| 최근 삼십 분 / 삼십 분 동안 | 없음 | **기본값(지난달)** | 흔적에도 안 걸려 **침묵 기본값** |
| 지난 이십 일 / 최근 삼 일 | 없음 | 기본값 | 같음 |
| 최근 이십 시간 · 이십사 시간 | 없음 | 기본값 | 같음 |
| 최근 열다섯 시간 · 스무 시간 | 없음 | 기본값 | 고유어도 `열한·열두·스물네`만 있고 열세 이상 대부분 누락 |
| 세 분 대기 | 없음 | 기본값 | **정상** — 「세 분」은 사람 수라 기간이 아니어야 한다(기간 해석 금지 유지) |

- 원인: `_KO_NUMERALS`(`time_expr.py:72-75`)는 고유어 14개뿐이고 한자어 수사(이십·삼십·…)가 없다. `_TRACE_RE`의 수사 분기(`:575`)도 `_KO_NUM`을 쓰므로 같은 틈을 공유한다. 159 W4 MLX 확인에서 「삼십 분 동안」이 슬롯 null·흔적 없음 → 기본값으로 간 것을 기록해 두었다(159 §9).

**③ 사건 주체 시 단위 롤링 정시 절단**

| 질의 | M | E | 비교 |
|---|---|---|---|
| 최근 3시간 알람 | 07:00~**10:00** | 07:00~**10:00** | E는 10:00~10:37 사건이 빠진다 |
| 최근 30분 알람 | 09:00~10:00 (+`minute_widened_to_hour`) | **10:07~10:37** | 분 단위 E는 기준 시각까지(D-328 ②) — **분은 되고 시는 절단** |

- D-328 ⑥(G-4)이 「발견만 기록 · D-291 사건 정책 개정 사안」으로 미뤘다. APM 경로는 `plan_window`가 롤링 끝을 이미 보정한다(159 §4.4) — **알람 이력 경로(`ctime` 리터럴)만 절단이 남는다.**

**⑨ 슬롯 `unit` ↔ 원문 스팬 단위 미대조**

| 원문 | 슬롯 | 결과 |
|---|---|---|
| 최근 30 min 알람 | `last·n=30·unit=hour·span="30 min"` | `slot_status=accepted` · **M·E 모두 10-12 04:00~10-13 10:00(30시간)** |
| 최근 30 min 알람 | `last·n=30·unit=minute·span="30 min"` | 정상(09:00~10:00 확장 / E 10:07~10:37) |
| 삼십 분 동안 응답시간 | `last·n=30·unit=minute·span="삼십 분 동안"` | 정상 — **슬롯이 한자어 수사의 현재 유일한 구제 경로** |

| 질의 | 결과 |

### 1.2 실측에서 새로 확인된 것 (159 §9에 없던 것)

## 4. 설계 (권고안 기준 — 게이트 확정 시 조정)

### 4.1 인식기 결함 교정 (게이트 없음 — 6·7·8·9·2의 인식 부분)

- **자릿수(6)**: `_NUM`의 `\d{1,4}` → `\d{1,5}`. 상한은 `TimeSpec.__post_init__`의 `N_MAX` 검사(`time_spec.py:228`)가 지킨다. 연도 4자리 오탐(`2026년`)은 단위가 `년`뿐이라 `last 2026년`은 `N_MAX["year"]=10` 초과로 되묻기 — W0에서 `20260101` 같은 8자리 연속 숫자가 `(?<![\d.])` 가드로 안전한지 확인.
- **「반쯤」(7)**: `_HALF_END`(`:276`)의 허용 후행에 `쯤|정도|가량|여`를 더한다. 「반영·반기·반복」 차단은 유지. `_MINUTE_PART`와 `_MINUTE_TAIL_RE`가 한 `_HALF_END`를 공유하므로 변경 1곳.
- **영문 단위(8)**: `_UNIT`에 `mins?|hrs?`·`min`(단독 약어 — 영문자 경계 `(?![A-Za-z])`) 추가, `_unit_of` 정규화. 「minimum·minute·minor」 오인식은 단어 경계로 막는다.
- **슬롯 단위 대조(9)**: `_check_span_values` 옆에 `_check_span_unit(unit, span)` — 스팬에서 `_UNIT`·한자어 단위를 정규화해 **슬롯 `unit`과 하나라도 일치하지 않으면** 거절(`unit_mismatch_span`)하고 `slot_status=rejected`로 흐르게 한다(→ 규칙이 잡았으면 규칙, 못 잡았으면 흔적/기본값). 스팬에 단위어가 없으면(「지난 한 달」 등 비수치) 검사하지 않는다. 주는 일×7, 연은 월×12로 환산되므로 대조 표에 환산 허용(`week↔day` · `year↔month`)을 둔다 — 기존 `n` 대조(`derived`)와 같은 방식.
- **수사(2) — G-4 (a) 기준**: `_KO_NUMERALS`에 고유어를 채우고, 한자어는 별도 `_SINO_NUMERALS` 사전(십 단위 이상만)으로 둔다. 파서는 `이십`=20 · `이십오`=25 · `삼십`=30 · `백이십`=120을 계산한다(자릿수 문법 1개 함수). 기간 규칙(`_b_last_n`)·흔적(`_TRACE_RE` 수사 분기)·슬롯 `n` 대조(`_span_numbers` `:716`)가 한 사전을 본다(사본 금지 · D-131). 단위 제한: 고유어는 기존 `_KO_NUM_UNITS`(월·주·시간) 유지, 한자어는 **분·시간·일·주·개월**(년은 「이십 년」 허용 여부를 W1 사례 표에서 확정). **「세 분」 보호**: 고유어 + 분은 `_KO_NUM_UNITS` 밖이라 불변 — 한자어 + 분(「삼십 분」)만 기간이다.

### 4.2 시각 시작점 (G-1·G-2 (a))

- **슬롯 스키마**: `_PARTIAL_KEYS`에 `minute` 추가, `PartialDate.minute`(0~59 · `hour` 없으면 `partial_date_gap`). `_check_span_values`의 `(month, day, hour)` 대조에 `minute` 추가. `SLOT_KEYS` 변경 없음(`start`/`end` 내부 키만).
- **인식 규칙**: 날짜 토큰(`오늘·어제·그제·M월 D일·YYYY년…`) 뒤 (선택 `오전|오후|새벽|아침|저녁|밤`) + `H시(\s*M분)?` + (`부터`|`이후`|`에서`~`까지`|`~`)를 **한 명세로 묶는다**. 시각 단독(날짜 토큰 없는 「14시부터」「10시 30분부터」)은 오늘로 본다. 오전/오후는 12시간제 환산표 1개 함수. 159의 `_after_clock`·`_CLOCK_BEFORE_RE`(시각 뒤 분 제외)는 이 규칙이 먼저 소유하므로 **`분`이 시각 일부로 소비돼 기간 오인 가드가 자연히 필요 없어진다** — 단 규칙이 거부한 경우(예: 분 값 60 이상)에는 가드를 남긴다.
- **해석(`time_spec.resolve`)**: absolute·hour(+minute) 시작점 → 사건 `[시작, 끝 또는 기준)` · 통계 시 경계 확장(시작 내림 · 끝 올림은 직전 정시 이하로 제한). 시작이 기준 시각 이후면 `future_explicit` 되묻기. 시각 뒤 분이 통계 확장되면 `minute_widened_to_hour` 재사용(신규 코드 0).
- **프롬프트**: 슬롯 설명에 `minute` 키와 예시 1줄 추가(§4.5).
- W0 미확인 사항 2건: ① absolute + `hour` 명세의 현행 `resolve` 분기(시 정밀 구간을 이미 지원하는지) ② `_policy_cap`(`time_spec.py` 591 부근)·`display_grain` 상호작용.

### 4.3 사건 롤링 끝 (G-3 (a))

- `time_spec.resolve`: `last`·`hour`(rolling)에서 `subject == "event"`면 끝 = `floor_min(anchor)`, 시작 = 끝 − N시간(분 단위 분기 `_resolve_minute`와 같은 형태로 합치되 `_UNIT_GRAIN` 영향은 통계에 한정). 통계는 현행 정시 유지.
- 소비처: 알람 `alarm_ts_bounds`·`validators.check_time_conditions`(159 W3에서 분 경계 비교 확인됨) — 변경 0 예상. APM `plan_window` 롤링 보정(`:555-560`)은 끝이 정시가 아니면 걸리지 않으므로 변경 0 예상(W0 확인). **동작 고정 테스트 개정 대상**: `tests/test_domain/test_time_spec.py`·`test_query_time.py`의 사건 시 롤링 기대값(`07:00~10:00` → `07:37~10:37`).

### 4.4 비대칭 해소 (G-5·G-6 (a))

- **빈도 어휘**: `_MIN_NOT_PERIOD_WORDS` 이름을 `_NOT_PERIOD_WORDS`로 일반화하고 `_UNIT` 전 단위에 `(?!…)`를 건다 — 이미 `_NOT_PERIOD_AFTER`(`:564`)·`_MIN_PERIOD`가 둘로 갈라진 구조라 **하나로 합치는 것이 설계 목표**(사본 금지). 「최근 3일 간격」의 `최근` 접두 우선 문제는 같은 합치기로 해소.
- **「N시간 전」**: `_b_minute_ago`(`:318`)를 `_b_unit_ago`로 일반화해 `minute`·`hour`를 받는다. `resolve`: `ago·hour` → 사건 `[anchor−N시간, anchor)`(분 정밀) · 통계 `[직전 정시−N시간, 직전 정시)`. 현행 `ago`의 `time_spec` 분기(`:652-` 부근)와 D-328 ② 「N분 전」 읽기 동일 — 고지 코드 신설 없음. `ago·day` 이상은 되묻기 유지.

### 4.5 슬롯 프롬프트 · 도구 · 문구

- `src/prompts/input_parser.py:185` 부근 `INPUT_PARSER_TIME_SLOT_SECTION`: `minute` 키 설명 · 시각 예시 1줄 · `N시간 전` 예시. 바이트가 바뀐다.
- **도구(11)**: `scripts/prompt_render_diff.py`에 `--prompts <base_sha>` 모드 신설 — `git show <sha>:src/prompts/*.py`와 작업 트리를 AST로 읽어 **모듈 수준 대문자 문자열 상수**별 일치/변경/신설을 표로 낸다(159 W2 수동 절차의 도구화 · 신규 의존 0). 기본 모드(폴스타 템플릿 diff)는 불변. `--ci`가 바뀐 상수에 사유 표(`_BLOCK_REASONS` 방식)를 요구하지는 않는다 — 목록 보고만(범위 최소).
- **문구(10)**: G-7 (a)면 D-328 ⑧ 본문을 부기 ⓐ에 맞춘다(결정 개정 1행 — D-328는 신규 결정이 아니라 **기존 파일 정정**) · 159 §8의 같은 문구도 변경 이력에 정오 1줄.

## 7. 위험

- **「분」·「시」·「일」·「이」 계열 오인식**(G-4 한 글자 한자어 수사): 「이 일」「오 분」「사 일」「이 시간」 등. 권고는 한 글자 한자어를 기간으로 읽지 않는다 — 사례 표 행으로 고정하고 W1에서 골드(122)·복합 질의 말뭉치에 대한 오탐 전수(`grep` 말뭉치 + 152 시나리오 135턴 재실행)를 한다.
- **시각 규칙의 오탐**: 「14시 장애」(사건 시각 언급인지 조회 시작점인지)·「9시 이후 생성된」(속성 필터)·「14시 30분 알람」(시점 단독). G-1 (a)에서도 **시점 단독(「14시 30분 알람」)은 `[14:30, 14:31)`로 읽을지 해당 시(`[14:00, 15:00)`)로 읽을지**가 열려 있다 — W2 사례 표에서 확정하고 필요하면 게이트를 추가한다(권고: 해당 시 구간 + 고지). 날짜 속성 필터 가드(`_is_deadline_filter` · EoS 규칙)와 같은 방식으로 「이후·이전」 속성 필터를 제외한다.
- **통계 확장의 기대 불일치**: 시각 시작점이 분 포함이면 통계는 시 경계로 넓어진다 — 159와 같은 의무 고지를 쓴다.
- **G-3 개정의 파급**: 사건 롤링 끝이 바뀌면 122 골드·벤치·매뉴얼 표의 「최근 3시간」 구간 표기가 바뀐다 — W0 grep으로 전수, 골드는 기대값 교체 + 근거 주석.
- **G-5 (a) 확대의 사용자 체감**: 「최근 3시간 이상 걸린 거래」가 종전 3시간 → 기본 경로로 가면 응답이 달라진다(올바른 방향이지만 눈에 보이는 변화) — 매뉴얼 주의 1줄.
- **슬롯 `unit` 대조의 과거부 (9)**: 대조 표가 너무 엄격하면 정상 슬롯(「이번 주」 `unit=week` 등 스팬에 숫자·단위어가 없는 경우)을 거부한다 — 스팬에 단위어가 없으면 검사하지 않는 규칙으로 막고 122 골드로 검증.
- **프롬프트 바이트 변화**: 슬롯 섹션 변경 → LLM 분포 영향. W5 도구로 의도된 상수만 바뀌었음을 확인하고 MLX 1회.
- **159 미커밋 의존**: 이 계획의 모든 실측은 159 작업 트리 기준이다. 159가 되돌려지거나 SHA가 바뀌면 W0 재대조가 필수다.
