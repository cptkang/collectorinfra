## 0. 요약

목표는 **제니퍼가 제공하는 읽기 데이터를 빠짐없이 조회하고, 여러 대상·기간·소스를 조합하여 분석하며, 채팅·조사·알람의 각 진입 경로에서 활용하는 것**이다. API를 허용목록에 넣거나 예문 43건을 통과하는 것만으로 완료하지 않는다.

- 전체 읽기 API → 선택 인자 → 반환 필드 → 도구 → 채팅 보기 → 소비 경로 → 테스트의 대응표를 만든다. 누락은 구현 잔여로 남기고 승인된 제외 사유 없이 범위를 줄이지 않는다.
- 기간·대상·건수에 더해 **복수 보기 3개 제한도 제거**한다. 요청한 대상·보기·지표는 전부 수행하며 동시 실행 수·속도 제어는 작업을 나누는 수단이다.
- 장시간·대용량 처리 기반을 먼저 만든 뒤 상한을 제거한다. 요약·상위 행은 화면 표현이고 전체 결과는 파일로 제공한다.
- 관리·상세 조회도 조사에 필요한 근거로 제공한다. 도구 개수를 8개·9개에 고정하지 않고 기능별로 묶는다. 조회 권한·필드 마스킹은 모든 진입 경로에 적용한다.
- 기존 예문에는 순수 채팅 외 알람(F-11·F-12), 조사 위임(F-13), 복합 질의(F-14)가 있다. 각각의 실제 경로로 검증하며 **121 연동 전에는 전체 완료로 선언하지 않는다**.

현재 43사례의 상태는 `docs/33`이 정본이다(✅10·◐8·조사 전용5·허용됐지만 도구 없음6·허용 확정 구현 전13·현재 불가1). 이 개정으로 구현 상태를 올리지 않는다.

권고 실행 순서: **W0 전수 대응표·재현 → W0-B 대용량 실행 기반 → W1 상한 제거·결함 교정 → W2 기존 API 전면 활용 → W3 복수 대상·전체 범위 → W4 업무 / W5 거래 심층 → W6 비교·연계 분석 → W7 관리·상세 및 조사 활용 → W8 전수 통합 검증**. W9 문서·매뉴얼·선택 검증은 매 Wave, W10 실응답 검증은 외부 전제가 풀리는 대로 한다.

## 4. 설계

### 4.1 전체 기능 대응표(COV)

W0에서 `spec/CAPABILITY-MAP-134.md`와 `spec/SPEC-apm-question-coverage.md`를 작성한다(스펙 산출물은 `spec/`에만). 원천 버전·경로·메서드별 행을 만들고 필드·인자별 하위 행은 같은 파일 안의 평면 표로 관리한다.

| 필수 열 | 계약 |
|---|---|
| capability_id · 원천 | 안정적인 기능 ID, 스펙/매뉴얼 버전·위치, GET 경로, 중복 표현의 대표 경로 |
| 인자·필드 | 필수/선택 키·형식·허용값·기본값·단위·해상도·응답 필드. 비밀 제거/마스킹/전체 파일 전용 필드는 처분 사유를 기록 |
| 배선 | 어댑터 → 게이트웨이 도구/인자 → 채팅 보기/선택지 → 채팅·조사·알람 소비처. 경로별 적용 여부와 사유 |
| 검증·잔여 | 질문 ID(없으면 추가), 계약 테스트 ID, 실제 API 호출 단언, 기대 집계, 합성/녹화본 구분, 담당 Wave·소유 계획·미확인 항목 |

완료 조건은 데이터 제공 GET 경로와 지원 인자·필드의 미처분 누락 0이다. 카탈로그의 모든 enum 조합을 전수 실행하는 대신 각 옵션의 전달 테스트와 경계·대표 조합 테스트를 둔다. 카탈로그 기반 유효 값 전체를 선택 가능하게 하고 임의 축소 enum을 만들지 않는다.

`/api/metrics`는 내부 검증만이 아니라 **`apm.metrics` 보기**로 공개한다. domain·instance·business·application·sql·externalCall 전체 카탈로그와 소스별 차이·단위를 돌려준다. 지표 이름은 카탈로그로 검증하고 LLM은 그 안에서 선택한다. 도메인·업무 지표에도 동일 계약을 적용한다.

### 4.2 도구·보기·조건 전달

- 기존 8개 도구를 호환성의 출발점으로 삼되 **8개/9개 고정 상한은 폐지**한다(D-299 — D-195 ①의 APM 도구 수 제한 개정). 성능·런타임·트랜잭션·이벤트·설정·계정 등 기능별 응집성으로 묶고 선택 정확도를 측정한다. API마다 무조건 도구를 하나씩 만들지는 않는다.
- 보기 수 역시 24개에 고정하지 않는다. 기존 7개 + app/sql/external 통계·changes·service·ranking·fleet_events·business·profile·trace·event_rules·process·jennifer_server·loaded_classes·environment·users·active_detail·**metrics**를 출발 목록(25개)으로 삼고 COV 누락에 맞춰 보강한다.
- `ViewSpec`은 도구·고정 인자·허용 선택지·필수 대상/참조·민감 필드 정책을 선언한다. `view_args`에 카탈로그 지표·필터·정렬·개수·해상도·기간·검색어·계정 ID 등 원천에서 지원하는 선택 인자를 실을 수 있어야 한다. 자유 URL·임의 API 경로는 받지 않는다(D-122 취지 유지).
- LLM은 의도와 유효한 기능/선택지를 고르고 코드가 타입·범위·필수값을 검증한다. 알 수 없는 값은 버린 뒤 다른 조회로 성공 처리하지 말고 미해결 조건을 고지하거나 되묻는다.
- 선택한 보기가 없거나 요청 영역을 덮지 못하면 카탈로그를 이용한 **선택 재시도 최대 1회**, 이후 필요한 선택만 질문하거나 미해결로 끝낸다. 명시한 환경변수·SQL 등의 요청을 응답시간/목록으로 바꾸지 않는다. 명시 기능 없는 일반 현황 질문의 기본 보기는 유지한다. 소스를 단어로 고르는 코드는 추가하지 않는다(D-004·D-295).
- 선택 재시도는 필요한 APM task에만 추가 호출하며 기존 ‘추가 LLM 0’ 권고는 D-299로 대체한다. 재시도 횟수·지연·미해결률을 측정한다. 비활성 배포 렌더는 그대로이고 활성 배포의 카탈로그·선택 정책 변경을 지문에 반영한다.

**대용량 소유·전달 경계**: 게이트웨이는 원천 API 청크 수집·마스킹·분석·스풀을 소유하고 본체는 사용자 작업 상태·인가·진행 UI·다운로드 전달을 소유한다. 패키지 간 import·공유 로컬 경로에 의존하지 않는다. ### 4.6 조사·알람 연계

- 조사에서도 환경변수/JVM 속성·이벤트 룰·실행 중 요청 상세 등 필요한 읽기 근거를 사용한다. `apm_config` 전체 제외와 민감 보기 일괄 비노출 권고는 폐기한다. 호출 주체의 소스 권한·필드 마스킹을 적용하며 채팅 위임은 사용자 권한을 승계하고 자동 알람 조사는 명시된 서비스 권한을 사용한다. 사용자 목록을 모든 조사에 선조회하는 것은 아니다.
- F-13 2단 조사 위임은 121 소유지만 134 전체 완료의 **필수 연동 조건**이다. 134는 확장 도구·참조·권한·부분 실패 계약과 통합 테스트를 소유한다.
- 알람 F-11 영향 판정과 F-12 폴러 수신의 기존 동작을 보존한다. 조회 버퍼 추가로 발행 최소 레벨·멱등·해소 정책이 변하지 않는지 검증한다.
- 기존 소비자의 기본 인자 의미는 유지하되 D-296이 폐지한 건수·길이 상한에 따른 결과 증가는 의도된 변경이다. ‘결과 바이트 동일’ 수용 기준은 적용하지 않는다.

**검증 방식(2026-10-06 개정 · D-240 부기 — 사용자 *"MLX는 속도가 느리다 MLX로 검증하는것은 최소한으로 검증하는 방식으로 계획이 작성되어야 한다."*)**: ① **기본 검증 = 가짜 LLM · 목 API · 실프로세스 종단**(게이트웨이 실프로세스 ↔ 실제 MCP SSE ↔ 본체 2단 노드 — 호출 경로와 최종 데이터까지 · 포트·PID 소유 확인 · 합성/녹화본 구분 보고). ② **로컬 MLX = 바뀐 프롬프트·선택 경로의 최소 스모크** — 바뀐 부분마다 대표 문항 소수 · 1회 실행 · 골드 전수 재측정·반복 금지. Wave 계획에 문항 수와 예상 소요를 적는다(9B 분해 1문항 ≈ 4초 · 선택 재시도 +1~9초 — W5~W7 실측). 두 평면 `mlx` 루프백 · 외부 차단 가드 유지(D-240). ③ **보기 선택 정확도·재선택률·미해결률·지연 = 내부망 FabriX 측정**(사용자 실행) — MLX로 줄여 재지 못한 것은 「내부망 FabriX 측정 잔여」로 보고한다. 필수 골드의 무관한 기본 보기 대체 0 요구는 그대로다. ④ **회귀 = D-303 모듈 단위 회귀**(사용자 지시 2026-10-06 · 피어 세션 등재 · 근거 `plans/136`): 바꾼 테스트 파일 + 바꾼 모듈을 직접 import하는 테스트(함수 안 import·`patch("src.x.y")` 문자열 포함) + 바꾼 비Python 파일 경로를 적은 테스트 + 바꾼 독립 패키지(`apm_gateway`·`sre_agent`·`mcp_server`) 테스트 전체 · 정적 게이트(`arch_check --ci`·`overfit_check --ci`)는 매번 · 실패가 나면 그 실패 ID만 세션 시작 커밋 worktree에서 재대조 · **전체 회귀는 사용자가 요청할 때만**(Wave 종료·커밋 전에도 자동 실행하지 않는다) · 보고에 회귀 범위(「모듈 단위 · 전체 미실행」 등)를 적는다.

## 6. 수용 기준

1. COV의 전체 데이터 GET·인자·필드 누락 0. 필드 보호·외부 제약은 사유와 테스트가 있다. API가 허용돼도 호출부·사용자 기능이 없으면 미완이다.
2. 43사례와 추가 기능 골드가 **각자의 진입 경로**로 통과한다. F-13 연동 완료 전 전체 완료 불가. 실응답 미검증은 완료 보고에 별도 잔여로 표시한다.
3. 여러 호스트/인스턴스/업무/소스·4개 이상 보기를 포함한 전체 요청이 잘리지 않는다. 사용자 필터·N·해상도 보존, 전체 행·중첩 필드·원문 파일 확인.
4. 장기 작업이 MCP 10초·일반 채팅 120초 제한 때문에 끊기지 않는다. 작업 상태·부분 결과·취소·정체·재기동·소유자 검증과 전체 파일 정리까지 통과한다. 접수 메시지는 데이터 완료가 아니다.
5. 비교·집계·순위 결과를 수치 오라클로 검증한다. 원시 관측의 누락·해상도·시계 차이를 숨기지 않는다. 폴러 버퍼의 불완전 구간은 API로 보충한다.
6. 채팅·조사·알람별 권한이 실제 실행 경계에 전달된다. 자격증명 카나리아가 도구·LLM 입력·답변·전체 파일·로그·감사 어디에도 없다. 일반 설정 조회는 제공한다. 개인정보 원값은 G-11 확정 전 제공하지 않는다.
7. 원시 API/쓰기 도구 비노출, 허용목록·사본 일치, GET 이외·token·리다이렉트 거부 유지. 비활성 렌더 불변, 활성 변경 지문 기록. 기존 알람 의미 회귀 없음.
8. 코드 구현 시 `arch_check --ci`·`overfit_check --ci`, 게이트웨이 경계 테스트, 관련 ruff/mypy, **D-303 모듈 단위 회귀**(본체 바꾼 모듈의 직접 import 테스트 · 게이트웨이·조사 패키지 테스트 전체 — 전체 회귀는 사용자 요청 시만) 통과. D-255 매뉴얼 원천·필요 캡처·빌드·`tests/test_manual` 동반. 이 v1.2 개정은 문서 작업이라 제품 매뉴얼은 구현 Wave에서 반영한다.
