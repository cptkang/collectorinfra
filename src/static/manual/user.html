    U-01이 시스템으로 할 수 있는 일

    무엇을 하나

    이 시스템은 인프라 관측 데이터를 자연어로 조회하는 도구입니다. 할 수 있는 일은 크게 네 가지입니다.

    할 수 있는 일 예 설명 장
    서버 구성·성능·알람 조회 「2026년 6월 메모리 사용률 평균 상위 3대」 3장
    양식(Excel·Word) 채우기 서버 목록 양식을 올리고 「채워줘」 6장
    실시간 알람 받기 알람 카드에서 바로 조회 9장
    알람이 왜 걸러졌는지 보기 노이즈 관제 화면 10장

    조회만 합니다. 데이터를 바꾸거나 지우는 요청은 실행하지 않습니다.

    사용 방법

    1. 로그인하면 질의응답 화면이 열립니다.
    2. 아래 입력창에 궁금한 것을 한국어로 적고 Enter를 누르세요.
    3. 답이 표로 나오면 그대로 읽거나 CSV로 내려받습니다.

    화면 요소

    1. 1예시 질문 버튼 — 누르면 입력창에 예시 문장이 채워집니다(U-17).
    2. 2「❓ 사용법」 — 지금 조회할 수 있는 데이터를 안내받습니다(U-18).
    3. 3입력창 — 여기에 질문을 적습니다.

    주의·제약

    • 답은 조회 시점에 수집된 데이터를 기준으로 합니다. 성능 통계는 시간·일·월 단위로 모아 둔 값이라 「지금 이 순간」 값과 다를 수 있습니다.
    • 조회할 수 있는 DB는 관리자가 정해 줍니다. 원하는 데이터가 나오지 않으면 관리자에게 권한을 확인하세요.

    U-02회원가입

    무엇을 하나

    처음 쓰는 분은 계정을 직접 만듭니다.

    사용 방법

    1. 로그인 화면 아래의 회원가입을 누르세요.
    2. 사용자 ID, 이름, 비밀번호, 부서를 입력하세요.
      • 사용자 ID: 영문·숫자·밑줄(_)로 3~50자
      • 비밀번호: 8자 이상. 확인란에 한 번 더 입력합니다.
    3. 가입하기를 누르면 로그인 화면으로 돌아갑니다.

    화면 요소

    1. 1사용자 ID
    2. 2이름 — 화면 오른쪽 위에 표시되는 이름입니다.
    3. 3비밀번호(확인 포함)
    4. 4부서
    5. 5가입하기

    주의·제약

    • 가입만으로는 조회할 수 있는 DB가 없을 수 있습니다. 설치 설정에 따라 기본 권한이 없으면 관리자가 「조회 가능 DB」를 지정해 줘야 합니다.
    • 비밀번호를 잊으면 관리자에게 초기화를 요청하세요. 화면에서 직접 바꾸는 기능은 없습니다.

    U-25존 선택 역질문

    무엇을 하나

    존(은행존·공동존)을 적지 않고 전체를 묻는 대량 조회는, 어느 존을 조회할지 먼저 되묻습니다. 여러 존을 한 번에 조회하면 오래 걸리고 결과가 섞이기 때문입니다.

    사용 방법

    1. 예: 「ㅇㅇ존 서버 CPU 사용률」처럼 존을 정하지 않고 보내면, 답 말풍선에 존 선택 상자가 나옵니다(조회는 아직 하지 않습니다).
    2. 조회할 존을 체크하세요. 여러 개를 고르면 존마다 차례로 조회합니다.
    3. 선택한 존으로 조회를 누르세요.
    4. 존과 상관없이 전체를 보려면 건너뛰고 전체 조회를 누르세요.

    화면 요소

    1. 1존 선택 상자
    2. 2선택한 존으로 조회

    질문에 따라 건너뛰고 전체 조회 버튼이 함께 나올 수 있습니다(존을 고르지 않고 전체를 조회).

    주의·제약

    • 기본 설정에서는 은행존과 공동존을 함께 고를 수 있습니다. 관리자가 존 그룹 상호배타(ZONE_GROUP_EXCLUSIVE)를 켠 환경에서는 한 그룹(은행존 또는 공동존) 안에서만 고를 수 있으니, 둘 다 필요하면 따로 두 번 물으세요.
    • 질문에 「김포」, 「여의도」, 「은행존」처럼 위치를 적으면 되묻지 않고 바로 조회합니다.
    • 선택지에는 내 계정이 조회할 수 있는 DB가 속한 존만 나옵니다. 원하는 존이 없으면 관리자에게 권한을 요청하세요.
    • 이 사례 화면은 테스트 환경에서 찍었습니다. 선택지는 설치 환경의 존 구성에 따라 다릅니다.

    U-45알람이 걸러지는 원리

    무엇을 하나

    알람 거르기(노이즈 게이트)는 미리 정한 규칙으로 판단합니다. AI(LLM)는 알람을 요약하고 "평소와 같은 알람인지" 같은 참고 의견을 낼 뿐, 걸러낼지 말지는 규칙이 정합니다. 학습된 머신러닝 모델은 쓰지 않습니다.

    규칙은 아래 순서로 적용되고, 먼저 걸린 규칙이 결과가 됩니다.

    순서 규칙 결과
    1 같은 서버·같은 알람·같은 자원이 정해진 시간(기본 4시간) 안에 다시 오면 다시 알리지 않고 횟수만 기록
    2 심각 알람이면 항상 즉시 통보(PAGE) — 아래 규칙을 거치지 않습니다
    3 해소 알람이거나, 발생 뒤 금방 스스로 복구됐으면 통보하지 않고 기록
    4 서버가 유지보수 중이거나 관리자가 건 침묵 규칙에 걸리면 통보하지 않고 기록
    5 상위 장비 장애로 생긴 연쇄 알람, 짧은 시간에 몰린 알람, 켜졌다 꺼졌다를 반복하는 알람 대표만 알리거나 보류(관리자가 켠 경우)
    6 위에 걸리지 않으면 심각도 × 서버 중요도 표로 기본 판단 PAGE·TICKET·DASHBOARD 중 하나
    7 보조 신호(모니터링 시스템의 통보 정책, AI 의견, 운영자 피드백, 최근 변경 작업)로 조정 최대 한 단계 올리거나 내림. 올릴 이유가 하나라도 있으면 내리지 않습니다

    사용 방법

    1. 노이즈 관제를 열고 결정 이력에서 궁금한 알람 행을 누르세요.
    2. 결정 추적의 판단 경로에서 어느 단계에서 결과가 정해졌는지 봅니다.
    3. 신호 스냅샷에서 판단 순간의 값(실효 심각도, 중요도, 일상 반복, 통보 정책, LLM 액션가능성 등)을 봅니다.
    4. 7번 조정이 있었다면 사유에 「승격:」 또는 「강등:」 뒤에 이유가 적혀 있습니다.

    화면 요소

    화면 캡처가 없습니다. U-44의 결정 추적 그림을 보세요.

    주의·제약

    • 심각 알람은 침묵 규칙이나 피드백으로 걸러지지 않습니다. 예외는 하나뿐입니다 — 관리자가 비운영 알람 필터를 켠 환경에서, 알람 표시 없이 승인·안내 문구만 있는 메시지는 심각도와 관계없이 기록만 남깁니다.
    • 걸러진 알람도 지워지지 않습니다. 판단 이유와 함께 기록에 남습니다.
    • 5번과 7번의 일부는 관리자가 켜야 동작합니다. 그래서 환경마다 걸러지는 양이 다를 수 있습니다.
    • 노이즈 피드백은 그 알람을 바로 막지 않습니다. 같은 이름의 다음 알람을 판단할 때 참고 예시로 쓰이고, 그것도 최대 한 단계만 내립니다.

    자주 묻는 질문

    무엇부터 물어보면 좋을까요? 서버 목록부터 조회해 보세요. 예: 「전체 서버의 호스트명, OS종류, 벤더를 조회해줘」. 질문을 잘 쓰는 요령은 U-19에 있습니다.

    「상위 N대」는 어떻게 묻나요? 기준 기간, 지표, 정렬 방향, 개수를 한 문장에 담으세요. 예: 「2026년 6월 메모리 사용률 평균이 높은 순서로 상위 3대 서버를 보여줘」. 사용률(%)이나 코어 수처럼 숫자로 저장된 항목을 기준으로 삼으세요. 메모리·디스크 용량처럼 단위가 붙어 저장된 값으로 정렬하면 순서가 틀릴 수 있습니다(U-19).

    앞 질문의 결과에 이어서 물을 수 있나요? 네. 같은 대화에서 「그 서버들의 ~」처럼 물으면 됩니다. 예: 「2026년 6월 CPU 사용률 평균이 높은 상위 3대 서버를 알려줘」 다음에 「그 서버들의 제조사와 OS 종류」. 자세한 내용은 U-34를 보세요.

    결과를 Excel로 받고 싶어요. 모든 조회 결과 아래에 CSV 다운로드 버튼이 있습니다. CSV는 Excel에서 바로 열립니다(U-22). 「전체 서버 목록을 엑셀로 만들어줘」처럼 양식 없이 요청하면 Excel 파일은 만들어지지 않습니다. 정해진 모양의 파일이 필요하면 양식을 첨부하세요(6장).

    데이터를 고치거나 지울 수 있나요? 아니요. 이 시스템은 조회만 합니다. 「서버 테이블 전부 삭제해줘」 같은 요청은 실행하지 않습니다(U-19).

    「가동률」을 물었더니 원하는 답이 나오지 않아요. 가동률은 모니터링 데이터에 집계되지 않는 지표입니다. 답에 함께 나오는 대체 질문을 그대로 보내 보세요(U-19).

    우리 팀에서 쓰는 말로 물어도 되나요? 유사어를 등록하면 됩니다. 예: 「hostname에 '장비이름' 유사 단어를 추가해줘」. 등록한 말은 모든 사용자에게 적용되니 확실한 것만 등록하세요(U-37).

    비밀번호를 바꾸고 싶어요. 사용자 화면에는 비밀번호 변경 기능이 없습니다. 관리자에게 비밀번호 초기화를 요청하세요. 관리자가 임시 비밀번호를 발급해 전달합니다.

    비밀번호를 여러 번 틀려 계정이 잠겼어요. 기본 설정에서는 30분이 지나면 다시 로그인할 수 있습니다(설치 설정에 따라 다름). 급하면 관리자에게 잠금 해제를 요청하세요(U-03).

    원하는 DB가 조회 대상에 없어요. 조회할 수 있는 DB는 관리자가 정합니다. 권한이 없는 DB는 선택지에 나오지 않으니 관리자에게 권한을 요청하세요(U-24).

    용어 뜻
    존 데이터를 조회하고 알람을 받는 지역 단위입니다. 예: 은행존, 공동존. 어떤 존의 알람을 받을지는 관리자가 정합니다(U-09).
    존 그룹 존을 묶은 상위 구분입니다. 여러 존을 조회할 때 조회 순서와 선택 범위를 정합니다. 관리자가 존 그룹 상호배타를 켠 환경에서는 한 번에 한 그룹 안에서만 존을 고를 수 있습니다(U-25).
    조회 대상 이 대화가 조회하는 DB입니다. 입력줄 위 칩에 표시됩니다(U-24).
    승계 한 번 조회한 대상을 다음 질문에서도 그대로 쓰는 것입니다. 칩의 ×로 풀 수 있습니다(U-24).
    역질문 질문만으로 정할 수 없는 것(존, 양식 항목 등)을 시스템이 되묻는 것입니다(U-25, U-29).
    유사어 같은 뜻으로 쓰는 다른 말입니다. 등록하면 그 말로 물어도 알아듣습니다(U-37).
    심각도 알람의 심한 정도입니다. 3=심각, 2=경고입니다.
    노이즈 게이트 받은 알람을 미리 정한 규칙으로 걸러, 통보할지와 어떻게 통보할지 판단하는 기능입니다(U-45).
    티어 노이즈 게이트의 판단 결과입니다. PAGE(즉시 통보) · TICKET(즉시 호출 없이 대기열·기록으로) · DASHBOARD(통보 없이 화면에만) · SUPPRESS(통보하지 않고 기록만) 네 가지입니다(U-44).
    억제 알람을 통보하지 않고 기록만 남기는 판단(SUPPRESS)입니다. 삭제가 아니며 결정 추적에서 이유를 볼 수 있습니다. 심각 알람은 억제되지 않습니다(비운영 알람 예외 — U-45).
    억제율 받은 알람 중 억제(SUPPRESS)된 비율입니다.
    침묵 관리자가 기간을 정해 특정 서버·알람·자원의 통보를 멈추는 규칙입니다. 기록은 남고, 심각 알람은 침묵되지 않습니다.
    결정 추적 알람 하나가 왜 그렇게 판단됐는지 판단 경로와 당시 신호 값을 보여 주는 화면입니다(U-44).
