## 의존 그래프

```
[A1 저장소]──→[A2 기록]──→[A5 목록·검색·삭제]──→[A6 검증]
     │                          ↑
     └──→[A3 마크업]──→[A4 뷰전환]┘

[B1 라우트 주입]──→[B2 노드 제거·CLI 이설]──→[B3 관리자 표기]──→[B4 검증]

두 사슬은 서로 닿지 않는다 — 파일 교집합 0.
```

**A2는 A1 뒤**여야 한다(저장 함수가 있어야 부른다). **A5는 A3·A4 뒤**여야 한다(그릴 컨테이너와
전환 경로가 있어야 한다). **B2는 B1과 같은 커밋**이어야 한다 — 사이가 벌어지면 그 구간에
파일 이중 기록이 남는다.

## 슬라이스 순서

수직 슬라이스로 자른다. 각 슬라이스 끝에서 화면이 동작하거나 테스트가 돈다.

| 슬라이스 | 내용 | 끝에서 확인되는 것 |
|---|---|---|
| **S1** | A1 + A2 | 질의를 보내면 localStorage에 쌓인다(DevTools로 확인 가능) |
| **S2** | A3 + A4 | 세 번째 탭이 보이고 전환된다(빈 뷰) |
| **S3** | A5 | 목록·검색·재사용·삭제가 동작한다 |
| **S4** | B1 + B2 | 질의 1건 = 파일 1건 + DB 1행, CLI도 1건 |
| **S5** | B3 | 관리자 감사 탭에 인증 상태 표기 |
| **S6** | 테스트 + 캐시 버스팅 + 문서 | 계약 고정 · 신규 실패 0 · D-183 등재 |

S1~S3(트랙 A)만 랜딩해도 사용자 요청은 충족된다 — S4~S5는 운영자 측 보강이다.

## 위험과 완화

| 위험 | 완화 |
|---|---|
| `setActiveView` 일반화가 알람 탭 동작을 깨뜨린다 | `test_ui_alarm_view.py` 9건을 매 슬라이스 후 돌린다. 스크롤 복원 분기는 `else`가 아니라 **`view === "chat"`** 조건으로 명시(지금 `else`면 이력 탭 진입 시 복원이 돈다) |
| 파일 이중 기록이 한 커밋 구간에 남는다 | B1·B2를 **한 슬라이스(S4)** 로 묶는다 |
| CLI 감사 상실 | S4의 수용 기준에 CLI 경로를 포함하고 테스트로 고정 |
| localStorage 예외로 질의 전송이 막힌다 | 모든 저장소 접근을 try/catch로 감싸고, 실패 시 목록만 비운다(테스트 8) |
| 모바일에서 탭 3개가 넘친다 | S2 끝에서 headless Chrome 414px 렌더로 실측 후 판단 |
| 정적 자산 캐시로 변경이 안 보인다 | S6에서 `?v=` 증가(직전 D-182 후속에서 실제로 겪은 문제) |

## 병렬 가능성

트랙 A(S1~S3)와 트랙 B(S4~S5)는 파일 교집합이 없어 병렬 가능하다. 단일 작업자는 **A 먼저**
진행한다 — 사용자 요청의 본체이고, B는 없어도 A의 수용 기준이 성립한다.
