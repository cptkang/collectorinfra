# 구현 계획 — WU-D2 (라우터 intent/DB 2단 분리)

명세: `SPEC-router-two-stage.md` · 상세: `plans/79` 트랙 B · 착수 판정: `plans/80` §5.2 이월 축

## 0. 이 작업의 성격

**보류 해제 착수다.** `plans/79` 트랙 B는 라우터 평면 이동 뒤로 이월돼 있었고(D-170 후속),
사용자 지시로 해제했다. 따라서 계획의 1순위는 *빨리 만드는 것*이 아니라
**끄면 아무 일도 없는 상태로 만드는 것**이다 — 미검증 항목 4건(M-1~M-4)이 남기 때문이다.

## 1. 컴포넌트와 의존

```
T1 프롬프트 절 추출 (바이트 동일 고정)
      └─ T2 1단·2단 템플릿 신설
              ├─ T3 스키마 (IntentDecision · DatabaseSelection)
              │      └─ T5 2단 분류 경로
              └─ T4 RouterConfig (플래그 · 기본 off)
                     └─ T5
                            └─ T6 신뢰도 2축 · 조기 차단
                                   └─ T7 회귀·불변식 고정
```

**순차 필수**: T1 → T2 → {T3, T4} → T5 → T6 → T7
**T1이 먼저인 이유**: 절 추출이 기존 렌더를 바꾸면 그 위의 모든 것이 오염된다.
바이트 동일을 **먼저** 고정하고 그 위에 얹는다.

## 2. 구현 순서와 이유

| # | 작업 | 왜 이 자리인가 |
|---|---|---|
| 1 | **T1** 절 추출 + 골든 고정 | 사본 금지(D-053)를 지키면서 기존 경로를 건드리지 않는 유일한 방법. **가장 회귀 위험이 큰 단계**라 먼저 하고 즉시 고정한다 |
| 2 | **T2** 1단·2단 템플릿 | 추출된 상수를 조립. 새 텍스트는 **최소**로 — 출력 형식 지시만 새로 쓴다 |
| 3 | **T3** 스키마 | 2단 경로의 타입 계약. 기존 `RouterDatabase` 재사용 |
| 4 | **T4** `RouterConfig` | 79 §6.2가 이미 선언한 이름을 그대로 쓴다(`ROUTER_` 접두) |
| 5 | **T5** 2단 분류 경로 | 위 넷이 있어야 조립된다. **플래그 off면 기존 함수가 그대로 실행** |
| 6 | **T6** 신뢰도 2축·조기 차단 | 경로가 선 뒤에 얹는다. 교체점(`ROUTER_CONFIDENCE_SOURCE`)을 한 곳에 |
| 7 | **T7** 회귀·불변식 | 멀티 DB 축소 0·플래그 off 비트동일을 마지막에 전수 고정 |

## 3. 리스크와 완화

| 리스크 | 실체 | 완화 |
|---|---|---|
| **R-1 ★ 프롬프트 렌더 변형** | 절 추출 중 공백·개행 하나가 달라지면 **S-1 기준선이 조용히 오염**된다 | **골든 문자열 바이트 비교**를 T1에서 즉시 고정. 실패하면 되돌린다 |
| **R-2 멀티 DB 축소** | 79 §1.1 불변식 위배 = 회귀 | 2단계 출력 스키마를 **기존 `databases` 그대로** 유지. mock으로 다중 선택 단언 |
| **R-3 D-004 위반** | 2단계를 결정적 규칙으로 만들고 싶은 유혹 | **2단계도 LLM**임을 테스트로 고정(위치 힌트 import 부재 단언) |
| **R-4 근거 없는 임계 추가** | 자기보고 조기 차단 임계는 S-3와 같은 문제 | **기본 off + 근거 부재 주석**. 임계 미설정 시 차단하지 않는다 |
| **R-5 미검증 채택** | 구조가 서면 "켜도 되겠지"로 흐른다 | SPEC 「미검증으로 남는 것」을 코드 주석·플래그 설명에 **박아 둔다** |
| **R-6 과금** | 2단 = 호출 2회 | mock 전용. `RUN_E2E` 설정하지 않는다(D-127) |
