## D-261. 감사 로그 결함 ① — 로그인 이벤트 이름 통일 · 연속 실패 경보 배선 · 관리 작업 감사 · 쿼리 실행 DB 기록 (사용자 지시 2026-09-27 · `plans/116` §11.8.3 ① · D-027 이행 보완 · D-183 경계 유지)

- **결정일**: 2026-09-27 | **상태**: 확정·구현(④는 아래 **사용자 확인 필요**)
- **결함**: 로그인·로그아웃이 `login`·`logout`으로 기록돼 필터(`user_login`)로 0건 · 연속 실패 경보 판정이 부르지 않는 `log_login` 안에만 있고, 잠그는 실패는 423을 먼저 던져 `login_fail`도 남지 않음 · 사용자 관리 변경·감사 정리가 서버 로그에만 남음 · `query_execution`이 감사 DB에 0건이라 성공률 카드·쿼리 실행 필터·대량 조회 경보가 비어 있음.
- **결정**: ① 기록 이름은 `AuditEvent`(D-027의 `user_login`·`user_logout`)로 통일하고, 옛 `login`·`logout` 행은 **감사 행을 고치지 않고 조회가 함께 찾는다**(`domain/audit.LEGACY_EVENT_ALIASES` → 저장소 `event_type = ANY(...)`) — 보관 기간이 지나면 별칭을 없앤다. ② 연속 실패 경보는 계정 잠금 카운터(`login_fail_count` — 성공·해제로 0)로 판정한다(DB의 최근 `login_fail` N건은 「연속」이 아니다). 잠그는 실패도 `login_fail`(`locked`)로 남긴다. ③ 사용자 관리 변경과 수동 감사 정리는 `admin_action`(`action`·`target_user_id`·`changes{before,after}`)으로 남긴다 — 비밀번호 값·거절된 변경은 남기지 않는다. 관리자 화면 필터에 「관리 작업」 추가(`admin.js?v=10`). ④ `query_execution`은 노드 공용 감사 함수(`audit_logger.log_query_execution`)에서 **DB에만 한 행 더** 쓴다(JSONL 1줄 유지 · 복제 대상은 DB 감사가 구성된 `AuditService`가 약한 참조로 등록 · 요청 ID·IP는 감사 미들웨어 컨텍스트). 라우트에는 넣지 않는다(재시도·DB별 기록 손실, JSONL 이중 기록). `data_access`는 `query_execution`과 정보가 겹쳐 기록하지 않는다.
- **사용자 확인 필요(④)**: SQL 1건마다 감사 DB INSERT를 한 번 기다린다 — 앱 DB가 느리면 조회 지연이 실행 건마다 생긴다(D-183 `user_request`와 같은 위험). 받아들이기 어려우면 `audit_logger.py`의 복제 호출 한 줄로 되돌린다.
- **대안(기각)**: 감사 행 UPDATE 마이그레이션(사후 변조로 보임) · 필터 값을 `login`으로(D-027과 어긋남) · DB 누적 판정 그대로 배선(누적 오경보) · 라우트에서 `log_query_execution`.
- **검증**: 신규 26건(`tests/test_api/test_audit_login_events.py`·`test_admin_user_mgmt_audit.py`·`tests/test_security/test_audit_event_alias_filter.py`·`test_query_execution_db_audit.py` — 수정 전 실패 확인). 도움말 `audit.yaml` 연속 실패 문구 교정.
- **잔여**: 서버 자동 감사 정리·break-glass `/admin/login`·없는 ID/잠긴 계정 로그인 시도는 감사에 남지 않는다 · 필터 「데이터 접근」은 늘 0건(선택지 제거 권장) · 호출부 없는 `_check_login_failure_alert` 정리 필요.

- **부기(2026-09-27 · ④ 사용자 확인 해소 — 「권고대로 진행하라」)**: 쿼리 실행의 DB 복제를 조회 경로에서 떼어 **백그라운드 태스크**로 쓴다 — `log_query_execution`은 JSONL 1줄을 쓴 뒤 `_schedule_query_execution_mirror`로 태스크만 띄우고 돌아온다(요청 ID·IP는 띄우는 시점에 감사 미들웨어 컨텍스트에서 읽음). 태스크는 `mirror_query_execution`(DB 행 + 대량 조회 경보)을 5초(`_DB_MIRROR_TIMEOUT_S`)로 감싸고 시간 초과·실패는 경고 로그만 남긴다(DB 행 누락 · JSONL 유지 — D-183). 참조는 `_pending_mirrors`로 보관(GC 방지)하고, 서버 종료 시 `auth_pool.close()` 앞에서 `wait_pending_db_mirrors()`로 마친다(`src/api/server.py`). 대안(기각): 동기 대기 유지(앱 DB 지연이 SQL마다) · 큐·스레드 워커 · 시간 제한 설정 키 신설. 검증: `tests/test_security/test_query_execution_db_audit.py` 재현 3건(수정 전 시간 초과 실패)+실패 무해 1건. 잔여: 동시 복제 수 상한 없음(인증 풀 max 5 경합 가능).
