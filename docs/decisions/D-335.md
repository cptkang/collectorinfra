- **배경**: `plans/160`의 값 해석은 결과 안 위치·의미까지만 말하고 정상/위험 판정·원인 추정을 금지했다(D-327 ④). 판정 기준(임계)은 본체에 없고 APM 게이트웨이가 소유하며(D-274 ⑤), 원인 추정은 추가 신호 조회가 필요하다. 둘 다 LLM에 맡기면 근거 없는 답을 지어낸다.
- **결정**:
  ① **판정은 게이트웨이가 결정적으로 한다**(G-1) — 게이트웨이 domain에 `judge_row_values`, 읽기 전용 MCP 도구 `apm_judge_values(rows)`를 신설한다. 본체는 결과 행의 **수치 칼럼만** 보내고 결과를 표시만 한다. 본체에 APM 지표 키·임계 리터럴을 두지 않는다. 판정 경로의 LLM 호출 0.
  ② **어휘·단계**(G-2) — 「기준 초과(주의/위험)」·「기준 이내」·「판정 기준 없음」. 주의/위험은 **그 신호 종류의 기존 수준**(WARNING/CRITICAL)을 그대로 쓰고 새 임계·단계를 만들지 않는다. 「정상」 어휘는 쓰지 않는다. 판정마다 「참고용」·기준값·기준 출처(`was_signatures.yaml · 잠정`)·「단일 시점 비교」를 붙이고, 같은 호스트의 게이트웨이 지속 신호(`was_signals`)가 있으면 먼저 보인다.
  ③ **평소 범위(1차)**(G-3) — APM 지표는 「평소 범위 없음(원천 없음)」으로 고지만 한다. D-110 baseline은 폴스타 CPU·메모리 전용이며, APM baseline은 이력 창 상한 확인 뒤 후속.
  ④ **원인 조사 = `sre_diagnose` 위임**(G-4) — 알람 없는 진단 입력을 재사용하고 sre_agent 계약은 바꾸지 않는다. 질문은 코드 템플릿(사용자 자유 텍스트 없음). 본체는 접수만 하고 기다리지 않는다.
  ⑤ **권한**(G-5) — `authorize_host_investigation` 그대로(기본 `HOST_AUTHZ_MODE=admin_only` · D-170 R-9 「조회 권한 ≠ 조사 권한」). 불가 사용자에겐 버튼 비활성 + 사유, API는 403 + 감사.
  ⑥ **비용 상한**(G-6 · D-325 ⑩의 제외 사유 해소) — 사용자별 진행 중 1건 · 시간당 3건(설정) · 같은 `(query_id, table, row)` 재접수는 기존 조사 id 반환 · sre_agent dispatcher 상한 유지 · 운영 `hourly_budget` 설정 권고.
  ⑦ **저장·인가**(G-7) — `InvestigationStore`에 `kind=diagnosis`와 선택 필드 `owner_sub`·`query_id`·`subject`를 더한다. 조회는 **소유자 또는 관리자**(알람 존 판정 미사용 — 알람 없는 레코드는 그 함수에서 403).
  ⑧ **조사 카드**(G-8) — 접수 후 팝오버를 닫고 답 말풍선 아래 카드로 진행→완료를 보인다(15초 재조회 · 상한 도달 문구). 결과는 「가설 · 참고용」. 대화를 다시 열면 `query_id`로 카드를 복원한다.
  ⑨ **범위**(G-9) — 폴스타 서버 지표 판정(`cmm_alarm_def_c_con` 임계 · 운영 DB2 구조 확인)은 후속 계획.
  ⑩ **지연 poll 공용화**(G-10) — `alarm.py`의 지연 poll·잠금·종결 기록을 공용 모듈로 동작 불변 추출해 알람·결과 조사 라우트가 함께 쓴다.
  ⑪ **플래그** — `cfg.result_viz.judgment_enabled`·`investigate_enabled` 기본 off(D-162 · 둘 다 `explain_enabled` 필요). 게이트웨이 도구는 플래그 없음(읽기 전용 순수 계산 · 호출처가 플래그 뒤) — 단 LLM 질의 계획에 노출하지 않는다.
- **근거**: 임계 소유·판정 정의는 게이트웨이 한 곳(D-274 ⑤) · 운영 보정값도 없는 잠정 임계 위에 단계를 지어내지 않는다 · sre_agent에 알람 없는 진단 입력이 이미 있다 · 조사 권한 정책은 `host_authz.py` 한 곳.
