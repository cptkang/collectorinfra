- **결정**:
  ① **성능 = 정확도** — 구조 판정 5축(소스·보기·대상·구간·인자)으로 판정한다. 지연은 기록만 한다(판정·목표선 없음). 값 대조는 하지 않는다(살아 있는 데이터) — 빈 결과 판별만 같은 인자 직접 재호출로 한다.
  ② **시나리오 = API 전수 생성** — `spec/CAPABILITY-MAP-134.md` 표 A(허용 경로)·표 B(선택 인자)마다 그것을 호출하게 만드는 사용자 프롬프트(`testdata/apm_bench/scenarios.yaml`). 앞 턴 결과가 필요한 API는 멀티턴. 기대값은 레지스트리 보기·인자 대응에서 결정적으로 뽑는다. 운영 이름은 자리표. 개발 70 · 홀드아웃 30(경로마다 양쪽 최소 1). 응답 필드 단위는 범위 밖.
  ③ **운영 뷰 서버 허용 범위**(개발 뷰 서버 없음) — 버전 5.6.2.18 미만이면 미실행 · 벤치 전용 게이트웨이 초당 2·폴러 끔(운영 게이트웨이 불변) · 1회 실행 · 소스당 3,000호출 예산 · 무거운 등급 최대 5시나리오 맨 마지막 · WAS 접촉 가능 API(실행 중 요청 상세·로드된 클래스·환경변수)는 API당 1회 지정 인스턴스 1개 · 자동 중단(429 1회 · 타임아웃 5% 초과 · `/api/domain` 기준선 대비 지연 3배) · 업무 외 시간. 운영 협의 값이 더 엄격하면 그 값을 따른다.
  ④ **반출 = 근거 묶음** — 실패 턴마다 분해 원출력·정제 변경·재선택·대상 후보·구간·호출·응답과 few-shot 수정 가능 여부·위치를 담아 반출본만으로 고칠 수 있게 한다. few-shot 원문 대신 지문.
  ⑤ **위생** — 이름은 토큰 단위 일관 형식 보존 치환(D-321) + 내부망 검토 일반 단어 허용 목록 · 민감 API 3종은 응답 모양만 · ITAM 벤치 위생·관문 재사용(게이트웨이 import 없음 · D-274).
  ⑥ **개선 수단 = few-shot**(레지스트리 `views[].examples`·보기/인자 설명 · 분해 프롬프트 APM 절·교차 예시 · 보기 재선택 프롬프트) — 개발셋 실패만 보고 고치고 홀드아웃으로 판정 · 벤치 프롬프트 원문 예문 금지(검사기) · 예문 복사(`fewshot_copy`) 분류 · 분해 프롬프트 크기 상한 · 라우팅·4소스 골드 회귀 · 같은 실패가 예문 수정 2회 뒤 잔존하면 결정적 처리로 승격 · few-shot으로 못 고치는 실패(대상·구간·정제·조합)는 코드 교정으로 분리.
  ⑦ **본체 변경** — 기존 `run_capture.emit()` 지점 최대 3곳(미설치 = 즉시 반환 · 비트 동일) · 설치는 벤치 서버 진입에서만(D-301 ⑥ 방식).
