## D-188. 알람 서버 식별 역조회 — hostname → 폴스타 등록 서버명·IP·존 (템플릿 platformName 미지원 대응)
- **결정일**: 2026-08-26 | **상태**: 구현 완료(개발망 테스트 통과) — 폐쇄망 실기 검증 대기
- **배경**: 폴스타 알람 소켓 연계(`KbAlarmSocketLinkageProcessor2$MessageContext`)가 `${platformName}`을 지원하지 않아(SpEL `EL1008E`, 발송 자체 실패) 운영 템플릿이 `"serverName":"${hostname}"`로 바뀌었다(`ipAddress`·`resourceAncestry`·`conditions`도 미지원으로 제외). Plan 46 §6.1의 변수 가정이 실제와 달랐던 두 번째 사례(첫 번째=D-184 severity). 결과: ①웹 UI 헤더가 hostname만 보여 공동존(name ≠ hostname)에서 서버 식별이 어렵고 ②이력·노이즈 컨텍스트의 `SVR.NAME = server_name` 완전 일치(D-035)가 공동존에서 0건이 될 위험. 사용자 요청은 헤더에 등록 서버명·IP·OS 노출.
- **결정**: ①**hostname → `cmm_resource(name, hostname, ipaddress)` 역조회**를 `application/server_identity.attach_server_identity()` 단일 함수로 두고 워커 `_process`(이벤트 구성 직후·dedup/지문/그래프 이전)와 API 라우트(`_attach_server_identity`) **양쪽**에서 호출(경로 대칭). SQL은 `polestar_hostname_resolver.build_server_identity_sql`(hostname 완전 일치·server.Server·DTIME IS NULL·`LIMIT 2`로 모호 판별·D-022 조인 없음·DB2 방언 분기). ②**결정적 승격 규칙**: `server_name`은 템플릿이 hostname을 준 경우(빈 값 또는 hostname과 동일)에만 등록명으로 교체, `ip_address`는 빈 경우만 채움, 같은 hostname의 server.Server 행이 2건 이상이면 둘 다 승격 생략(`ambiguous=True`, UI에 `?` 표시). 승격 덕에 이력 매칭·지문·캐시 키·통보 본문·SSE가 코드 변경 없이 등록명을 쓴다(②의 D-035 위험 해소). ③`AlarmEvent.server_identity: ServerIdentity`(name/hostname/ip/os_type/zone/zone_label/site_label/source/ambiguous) 부착, 존·사이트 라벨은 `config/db_registry.yaml`(zones·locations 배타 표면어) 파생 — DB 조회 실패 시에도 존 라벨은 붙는다(source=event). ④SSE payload(`_tier_sse_payload`·incident 재발행·API publish 2곳)에 `server_identity`·`alarm_time`·`received_at`(부기 2026-08-27 — 워커 경로에 시각이 없어 말풍선에 발생/수신 시각이 전혀 안 보이던 것을 API 경로와 대칭화, `AlarmEvent.received_at` 신설, UI 메타 줄 끝 `MM-DD HH:MM:SS 발생`·60초 이상 지연 시 `(HH:MM:SS 수신)` 병기) 추가, 워크비 본문에 `존:` 라인(식별 정보 있을 때만 — 없으면 비트 동일). ⑤UI 헤더 3줄 재구성: `[심각도] 등록 서버명` / `hostname · IP · OS배지 · 존` / `알람명 · 자원명`(`renderAlarmIdentityHeader`). ⑥Redis 캐시 `alarm:identity:{db_id}:{hostname}`(TTL 기본 1h) + 전체 타임아웃 3s + graceful. `AlarmConfig.server_identity_timeout_seconds/cache_ttl_seconds`(상시 동작 — `_enabled` 플래그는 D-162 §6에 따라 두지 않음, 2026-08-27 정리).
- **근거**: 템플릿 변수로는 불가(실측)하므로 DB가 유일한 출처이며 컬럼이 직접 존재(NAME/HOSTNAME/IPADDRESS). 역조회를 단일 함수로 양 경로에 두어야 E7-c 비대칭 재발이 없다. 승격을 "템플릿이 hostname을 준 경우"로 한정해 향후 폴스타가 별도 서버명을 지원해도 덮어쓰지 않는다. 모호 시 미승격은 오식별(다른 서버 이력 첨부)보다 미표시가 낫다는 보수 원칙.
- **OS(부기 2026-08-27)**: `core_config_prop.OSType`을 식별 SELECT에 **스칼라 서브쿼리(MAX)** 로 얹어 `ServerIdentity.os_type`을 채운다(LEFT JOIN 행 증식으로 모호 판별이 오염되지 않게). 조인 키 `r.resource_conf_id = cc.configuration_id`는 D-022 재검토(2026-07-30)로 확정된 현행 정본 방식(프롬프트 규칙 9·docs/10 검증 쿼리). UI는 값이 있을 때만 Linux/Windows/AIX/HP-UX/Solaris 배지(미매핑은 원문). 같은 날 사용자 검토로 헤더를 `[심각도] 서버 — 알람명 (자원)` 1행 + 메타 1행으로 병합(3행→2행). **범위 밖(후속)**: 은행존(b0)은 알람 미연동·DB2 방언 별건. 워커 경로 SSE에 `history_stats`/`process_snapshot`을 싣는 페이로드 대칭(§5 관찰)은 직렬화기가 `src/api`에 있어 별건.
- **구현**: `noise_gate/application/server_identity.py`(신규)·`noise_gate/domain/alarm.py`(`ServerIdentity`·`AlarmEvent.server_identity`)·`noise_gate/infrastructure/polestar_hostname_resolver.py`(`build_server_identity_sql`·`lookup_identity`)·`noise_gate/application/alarm_worker.py`(`_build_identity_resolver`·`_process` 부착)·`src/api/routes/alarm.py`(`_attach_server_identity`·`_identity_dict`·publish 2곳)·`noise_gate/application/nodes/alarm_notifier.py`(`_identity_dict`·payload 2곳·본문 존 라인)·`src/config.py`·`.env.example`·`src/static/js/app.js`(`renderAlarmIdentityHeader`·`renderOsBadge`)·`src/static/css/style.css`·`noise_gate/tests/test_server_identity.py`(신규 33건)·`tests/test_api/test_settings_catalog.py`(277→280).
- **주의**: 지문(`compute_fingerprint`)이 server_name을 쓰므로 DB 장애로 역조회가 간헐 실패하면 같은 알람의 지문이 hostname/등록명 사이에서 흔들려 dedup·상관이 그 창에서 끊길 수 있다 — 캐시(1h)가 완화하며, 장애가 길면 이력 조회도 같이 죽는 상황이라 허용. 은행존 등록명(`AAA (AAA업무 AP서버)`)은 그대로 표시된다. 폐쇄망 확인: 워커 로그 `서버 식별 역조회: … → name=…`, UI 헤더 1행에 등록명·2행에 hostname/IP/사이트, 공동존 알람의 `history_stats`가 다시 채워지는지, grep 심볼 `attach_server_identity`(worker·route)·`build_server_identity_sql`·`renderAlarmIdentityHeader`.
