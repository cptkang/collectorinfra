## D-363. 솔루션 간 호스트 이름 매칭 — 정규형 일치(L0) 공용화 · `hostname(업무명)` 꼬리 제거 · `-`·`_` 무시 · LIKE는 후보 전용

- **결정일**: 2026-11-03 | **상태**: 확정 · 구현(`plans/211` W1~W5 · 플래그 기본 off · 잔여 W0 폐쇄망 확인) | **번호**: 원 D-360 — 2026-11-04 `origin/main` 병합 시 재부여(main이 D-360~D-362를 먼저 사용)
- **배경**: 사용자 요청(2026-11-03) *"apm, sms, itam의 hostname은 like로 비교가 되어야 한다. 3가지 솔루션들 간의 이름이 약간씩 다를 수가 있다. 이 문제를 해결하기 위한 방안을 검토하라."* 실측(`plans/211` §2): 호스트 이름 비교 규칙이 6곳에 따로 있고 서로 다르다 — HolmesGPT·플레이북이 쓰는 `mcp_server` 앵커 조회는 대소문자 구분 정확 일치, 게이트웨이는 소문자·짧은 이름, D-224 값 판정은 `web01(업무)`를 키로 인정하지 않으며, ITAM 프로필에는 `entity_keys`가 없다. 단순 `LIKE '%x%'`는 `web01`이 `web010`에 걸리고 `_`가 와일드카드라 오진(D-188)을 낸다.
- **결정**: 사용자 확정 *"1,2는 권고대로 하고 3은 하나의 경우는 hostname + (업무명) 으로 쓰는 경우가 있다."*
  ① **LIKE는 후보 전용**(Q1) — LIKE·토큰 넓힘 결과는 사람이 확정하기 전에는 자동으로 쓰지 않는다(D-348 ② 유지).
  ② **정규형 일치(L0)는 자동** — 공백 제거 → 첫 `(` 뒤 업무명 꼬리 제거 → 소문자 → (IP는 정규 표기) → 레이블별 `-`·`_` 제거(Q2·Q3). 둘 다 FQDN이면 전체 비교(D-224 ㉰ 유지), 그 밖은 첫 레이블 비교. 대상이 **정확히 1건일 때만** 자동이고 2건 이상이면 모호로 후보 표시(D-224 ④).
  ③ **정규형 정본은 `src/domain/host_names.py`** — `mcp_server`·`apm_gateway`는 import 0(D-139·D-274)이라 사본을 두고 같은 테스트 벡터(`plans/211` §5)로 동등성을 단언한다.
  ④ **SQL은 세 엔진 공통 함수**(`LOWER`·`TRIM`·`REPLACE`·`LIKE '접두%'`)로 조립하고, 입력 정규형이 `[a-z0-9.]` 밖이면 조립하지 않는다(와일드카드 차단).
  ⑤ ITAM 서버 원장에 `entity_keys`(호스트명 compare `canonical` · IP)를 선언해 D-224 키 브리지를 ITAM에도 적용한다.
  ⑥ 패키지별 플래그 기본 off = 현행 비트 동일.
  ⑦ **범위 밖**: text2sql LLM 생성 SQL의 `ILIKE '%x%'`(이름 일부 검색 기능) · ITAM 확정 연결 저장소 · 꼬리 업무명의 D-290 근거 활용.
- **근거**: 사용자 확정 · `plans/211` §2 실측 · D-188(오진이 미표시보다 나쁘다) · D-224 ㉰·④.
- **구현**: `plans/211` W1~W5 — 본체 `src/domain/host_names.py`(정규형·일치·SQL 조건)·`entity_key`·소재 조회·폴스타 어댑터·`key_bridge`(LIKE 와일드카드 이스케이프·매니페스트 `compare: canonical`) · `noise_gate` 후보 등급(정규형 일치) · `mcp_server/host_canonical.py`(사본) · `apm_gateway/domain/host_canonical.py`(사본) — 사본 동등성은 공통 벡터 테스트. 플래그 `HOST_CANONICAL_MATCH_ENABLED`(본체·mcp_server) · `APM_HOST_CANONICAL_MATCH_ENABLED`(apm_gateway) 모두 기본 false = 현행 비트 동일.
- **주의**: 컬럼에 함수를 씌우면 인덱스를 못 탄다 — W0에서 행 수 확인. 정규형 충돌(서로 다른 서버가 같은 키)은 W0 SQL로 시스템별로 센다. **부기 1(2026-11-03)** — 사용자 *"폴스타에 있다. 괄호를 쓴다."* → 업무명 꼬리는 폴스타 값에만 있고 반각 괄호다. 괄호 꼬리 SQL 분기는 폴스타 SQL에만 두고 ITAM SQL에는 두지 않는다(Python 정규화는 전 경로 공통 유지). 칸(등록명/호스트명)은 W0에서 확인하며, 앵커·소재 조회는 두 칸을 모두 비교한다.
- **부기 2(2026-11-04 · 사용자 결정)** — ① 가드 「안 A」: 정규형 SQL의 `REPLACE(…)`가 금지 키워드에 걸려, 함수형 `REPLACE(`만 키워드 대조에서 뺐다(`REPLACE INTO` 차단 유지 — D-003 부기 2026-11-04). ② ITAM 「안 A」: `config/db_profiles/itam.yaml`에 손으로 블록을 쓰지 않고 빌더 경로(`scripts/itam_bench/build_assets.py` → `entity_keys_asset(host_compare="canonical")`)로만 낸다(D-311 ③ · D-316 ②) — 다른 DB의 생성기 출력은 `casefold` 그대로. ITAM `entity_keys`는 P1 반출 뒤 빌더 재실행으로 생긴다.
