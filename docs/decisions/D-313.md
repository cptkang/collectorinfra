## D-313. `plans/134` W6 잔여 구현 결정 — **APM 창 = 요청 단위 시간 해석(`time_resolution.event`)·「하루 넘게 지난 기간」 거부 폐지 · 두 구간 비교 채팅 배선(`apm.period_compare` — 구간 규칙 결정적) · 기간 순위(`apm_fleet` ranking 기간 모드 · 시 단위 통계 전부 수집 뒤 정렬) · 서버 미지정 = 현재 부하(TPS) 상위 N대(기본 20)만 조회 + 의무·중립 고지** (팀 리드 지시 — 134 W6 잔여 · ④는 2026-10-07 사용자 결정 「서버 미지정 질의는 상위 N대만 조회 + 안내」 · D-309·D-310 이행)

- **결정일**: 2026-10-07 | **상태**: **확정(구현 · 작업 트리 · 커밋 없음)** — W8 · W10 잔여 | **번호**: 색인 최댓값 D-312 + 1(등재 직전 `ls docs/decisions/` 재확인 — D-311·D-312는 병행 세션 선점)
- **배경**: W6 잔여 3건(M-7 · A-1 채팅 · A-4 기간 순위)의 선행(`plans/122` ⑥ D-309 · W3 `apm_fleet` D-310)이 충족됐다. 또 W3(D-310 ③)가 첫 홉 절단을 걷어 서버를 지정하지 않은 보기 질의가 제니퍼 WAS 전부를 조회한다 — 운영 약 350도메인에서 수십 분이 걸릴 수 있어 사용자가 ④를 정했다.
- **결정**:
  ① **창 = `QueryTime.from_state(time_resolution).event`**(M-7 · D-309 ③ · 해석기 사본 0 — D-131): 기간 없음(unbounded)·`present` = 도구 기본(현재값) · 기간 = 반개구간 `[start, end)` → `reference_time`(끝 — 기준 시각과 1분 안이면 null)·`lookback_minutes`. 기준 시각은 `qt.anchor_at`(KST aware). `time_resolution`이 없을 때만 ISO `time_range`(종전 · aware `now`면 KST 부여). **「하루 넘게 지난 기간」 거부 폐지**(`_OUT_OF_WINDOW_AFTER` 삭제). range 보기에서 해석이 롤링(「최근 3시간」)이고 끝이 기준 시각의 정시 내림이면 창을 `(기준 시각 − 길이, 기준 시각)`으로 민다(지난 정시에서 끝나 최근 최대 59분을 잃던 것 — V6-2). hourly 보기는 해석 그대로. 기간을 줬는데 0행이면 「요청 기간에 행이 없습니다 — 보존 기간은 확인 전(W10)」(보존 만료 단정 금지).
  ② **해상도**: 사용자 지정(`interval_minute`)이 이긴다(장기간이어도 바꾸지 않음). 미지정이면 레지스트리 `view_args.interval_minute.verified_values`(실측 허용값)에서 점 288개 이하가 되는 가장 작은 값을 `WindowPlan.args`에 두고 고지 — **현재 선언 0**(허용값 W10)이라 고르지 않고 「허용값 미실측」만 고지한다. 창·해상도는 보기 단위라 배치 1호출이 유지된다.
  ③ **두 구간 비교(A-1)**: 보기 `apm.period_compare`(게이트웨이 `apm_period_compare` · 보기 28 → 29). 구간은 코드가 정한다(`plan_compare_window`): 기간 2개 = 이른 쪽 기준·늦은 쪽 비교(진행 중이면 기준도 같은 경과로 자름) · 기간 1개 **진행 중**(to_date 또는 끝 > 기준 시각) = 비교 시작~정시 내림, 기준 = 한 단위 앞의 같은 경과(앞 단위가 더 짧으면 앞 단위 전체 — 비교와 겹치지 않음) · **롤링**(「최근 N단위」 N ≥ 2 · rolling) = 그 구간이 비교, 바로 앞 같은 길이가 기준(끝은 정시 — 게이트웨이 시 경계 확장으로 겹치지 않게) · **지난 기간**(N = 1 「지난주」·「어제」·「최근 한 달」) = 기준, 바로 뒤 같은 길이(지금까지 — 잘리면 기준도 같은 경과) · 기간 0개·3개 이상 = 되묻기 · 경과 0 = 전용 되묻기 문구. 가중 평균·기준 0 = N/A·누락 구간 0 채움 금지는 게이트웨이 계산을 그대로 옮긴다.
  ④ **기간 순위(A-4)**: `apm.ranking` 창 `current` → `range`. 게이트웨이 `apm_fleet(mode=ranking)`에 `reference_time`·`lookback_minutes`가 오면 범위 안 (소스, 도메인)의 인벤토리 인스턴스 **전부**를 인스턴스마다 시 단위 애플리케이션 통계 1호출(응답에 인스턴스 칸이 없어 묶어 부를 수 없음 — 실측)로 모은 **뒤** 정렬(`expect_calls` = 인스턴스 수 · 작업 승격). 기간 지표 = `response_time_avg_ms`(호출 수 가중) · `tps`(구간 호출 ÷ 초 — 실시간 tps와 정의 다름 고지) · 기간 전용 `calls`·`failures`·`failure_rate`(0~1)·`max_response_time_ms`(레지스트리 enum 34 = 게이트웨이 `ALL_RANKING_METRICS` — 본체 사본은 드리프트 테스트로 고정). 기간 전용 지표 + 기간 없음 = 그 보기만 되묻기(호출 0 · 기본 지표로 대체하지 않음). 기간으로 계산 못 하는 지표(heap 등) + 기간 = 현재값 순위 + 고지(`window_mode="current"`). 통계 행 없는 인스턴스는 순위 밖(0으로 채우지 않음). 부분 실패 = 잠정 순위 + 누락 도메인·인스턴스·소스 표시(의무 `apm_partial_sources`). 기간 인자가 없으면 실시간 순위 바이트 동일(`window_mode` 칸 없음). 샘플 상위 N을 「전체 순위」로 부르지 않는다.
  ⑤ **서버 미지정 = 부하 상위 N대(2026-10-07 사용자 결정 · D-310 ③ 개정)**: 대상 필수 보기에 대상(대상 텍스트·식별자·선행 결과·직전 대상)이 없으면 첫 홉을 인스턴스 목록 대신 `apm_fleet(mode=ranking, metric=tps, order=desc, n=N)`(실시간 · 기간 인자 없음)으로 부르고 상위 N개만 대상으로 쓴다. N = `CompositeConfig.apm_untargeted_top_n`(env `COMPOSITE_APM_UNTARGETED_TOP_N` · 기본 **20** · 잘못된 값은 warning 후 20). 대상은 (호스트, 소스) 단위로 싣고, 같은 호스트의 다른 도메인 인스턴스까지 조회되면 고지가 실제 조회 인스턴스 수를 말한다. 고지: 「대상 서버 미지정 — 전체 인스턴스 M개 중 현재 부하(TPS) 상위 N개(호스트 H대)만 조회했습니다 · 특정 서버(또는 업무)를 지정하면 …」 = 새 kind **`apm_untargeted_scope`(의무 · 중립 · task)** — 의도된 범위 제한이라 실패 등급(partial)이 아니다. M ≤ N이면 전부 + 비의무 범위 줄. **조용히 전체로 넓히지 않는다**: 순위 실패·부를 대상 0 = 인스턴스 목록 앞 N개 + 「부하 순이 아닙니다」(의무 `apm_partial_sources`) · 잠정 순위·결과 파일 읽기 실패도 `apm_partial_sources`. 분해가 그 보기(`full` 선언 보기)에 `full=true`를 냈으면 전부 조회(종전 W3 경로) + 고지. 사용자가 서버·업무·서비스를 지정한 경로는 종전대로 전부. 첫 홉 호출도 본체 감사 `commands`에 싣는다(V6-8).
- **근거**:
  - 「부하 순서」 = 실시간 TPS(`apm_fleet` ranking — W3 D-310 ⑤): 한 번의 (소스, 도메인)당 실시간 1호출로 전 인스턴스를 모은 뒤 정렬하므로 표본이 아니라 그 시점의 전수 순위다. 처리량(TPS)이 「부하」의 가장 직접적인 정의이고, 응답시간 등 보기 지표로 고르면 「느린 서버만 본 응답시간」처럼 결과가 편향된다. 기간 질의도 현재 부하로 고른다(기간 순위는 인스턴스마다 통계 1호출이라 첫 홉 비용이 대상 조회 비용과 같아짐 — 대안 (c)).
  - N = 20: 응답시간 목표(복합 질의 < 30초 — CLAUDE.md)와 게이트웨이 호출 속도(G-12 잠정 5회/초)에서 대상 20개 × 보기 1호출 ≈ 4초 + 첫 홉 — 보기 2~3개를 함께 골라도 목표 안이다. 운영 350도메인 전체(인스턴스 수백~천여 개)는 같은 모델로 수 분~수십 분이다. 한 화면에서 읽을 수 있는 표 길이(20행)와도 맞는다. 값은 설정으로 바꾼다.
  - 독립 검증(실프로세스 게이트웨이 ↔ MCP SSE ↔ 본체 2단 · 가짜 LLM · 목 Open API) E1~E5 성립 · 본체 인자 ↔ 게이트웨이 실 입력 스키마 101건 위반 0 · 감사 지적 V6-1~V6-8(Major 3: 비교 구간 겹침 · 최근 N시간 정시 절단 · 롤링 비교 의미)을 같은 작업에서 교정.
- **대안(기각)**: (a) 서버 미지정 = 전부(W3 현행) — 운영 규모에서 수십 분 · 사용자 결정으로 폐기 (b) 인스턴스 목록 앞 N개 — 부하와 무관한 표본을 순위처럼 보이게 함(폴백에만 쓰고 그 사실을 고지) (c) 기간 질의의 첫 홉을 기간 순위(통계)로 — 인스턴스 수만큼 호출해 절감 효과가 없음 (d) 도메인 단위 부하(`/api/realtime/domain`)로 도메인을 먼저 고름 — 같은 도메인의 한가한 인스턴스가 섞여 N대 선택이 부정확 (e) 상위 N 고지를 `apm_partial_sources`(partial)로 — 실패가 아닌 의도된 범위 제한을 실패 등급으로 셈(벤치 등급 왜곡) (f) A-1 롤링 비교를 「바로 뒤 구간」 규칙으로 — 「최근 7일 비교」가 10시간끼리 비교됨(V6-4).
- **주의**:
  - `full`은 원래 「행 수 상한 없이」인데 ④에서 「무대상이면 인스턴스 전부」로도 읽힌다 — 한 인자 두 뜻(사용자 확인 대기).
  - 기본값 20은 「신규 설정 기본 off = 현행 동작」 원칙의 예외다(근거: 사용자 결정 2026-10-07 · config 주석).
  - 「최근 하루 비교」·「최근 한 달 비교」(N = 1)는 지난 기간 규칙을 따른다 — 롤링으로 볼지는 미결.
  - 기간 순위는 인스턴스마다 직렬 호출이라 대상 수백 개면 수십~수백 초(작업 승격으로 마감은 지킴 · 실 속도 W10). 대상은 현재 인벤토리 기준이라 기간 중 사라진 인스턴스는 빠진다(고지).
  - ISO `time_range`는 남는다 — APM 폴백(`_legacy_bounds`) · 121 `time_window` · SQL 경로 폴백 다수가 아직 읽는다(D-309 주의 ③ 부기).
  - 측정 못 한 것: 실 제니퍼 시 단위 통계 행 모양·`instance_id` 단일 지정 응답 · `interval_minute` 허용값 · 운영 속도 · 실 입력 파서·LLM 슬롯이 섞인 해석 경로 · MLX 9B가 「web01 지난달 응답시간 추세」에 서비스 추세 보기를 고른 1건(1회 관측 — 선택 정확도는 내부망 FabriX).
