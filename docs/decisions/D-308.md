- **배경**: ITAM 내부망 1회차(run `20261006-152938` · FabriX/vllm)에서 ITAM 단일 DB 12턴이 전부 SQL 0건으로 끝났다. 승인된 조회 대상 테이블(`allowed_tables`) 99개가 단일 경로 강제 보충(`plans/114` P-4①)으로 매 질의 프롬프트에 전부 실려 FabriX 입력 한도(95,232)를 넘었고(보고 96,858), 단일 경로에는 백엔드 오류 감지가 없어 오류 문구의 `from orchestrator`가 「존재하지 않는 테이블 참조」로 오표면화했다(`plans/139` §2). 테이블 이름은 코드형(`tcdms…`)이고 테이블 의미·관계·기본키 표시가 0이라, 현행 선택 프롬프트(테이블명 + 컬럼 15개)로는 현행·수집 적재·수집 이력 3종 쌍둥이 테이블을 가릴 근거가 없다.
- **결정**(사용자 지시 *"테이블에 따라 해당 테이블에서 관리하는 정보를 먼저 정의하여 관리하고 LLM을 통해 사용자의 프롬프트에 맞는 조회대상 테이블을 선별하고 해당 테이블을 통해 쿼리를 생성하는 방식으로 동작해야 한다."* · 인터뷰 G-1~G-7 · 상한):
  ① **정의 자산** — 프로필 키 `table_definitions`(테이블당 `manages` 필수 · `kind`·`key_columns`·`related`·`notes`·`origin`). 「DB 구조」 탭에서 초안(가져오기·테이블 주석·LLM 묶음 초안) → 결정적 검증 → 테이블 단위 승인 · 버전·되돌리기. 사람 값(`manual`)은 재생성에서 보존한다. 값(표본·코드값)은 정의에 넣지 않는다. 질의 경로는 읽기만 한다(D-227).
  ② **적용 범위(G-1)** — **정의가 승인된 DB만**(현재 ITAM). 정의가 없는 DB(폴스타 4종)는 현행(조회 대상 필터 + 강제 보충) 비트 동일.
  ③ **선별** — 후보 = 스키마 ∩ `allowed_tables`. LLM이 정의 목록을 보고 고르고, 결정적 후처리(실존·후보 교집합 · 선별 테이블을 잇는 중간 테이블 보완 · 상한)를 거친다. **정의 모드에서는 강제 보충(`plans/114` P-4①)·Q-5 생략·EAV 보충을 하지 않는다.** 상한은 **8개**(설정 `cfg.text2sql.schema_table_select_max`).
  ④ **선별 실패(G-2)** — 질문 단어를 정의·컬럼 이름과 맞춰 상위 8개로 대체(로그·상태 표지) → 그것도 0개면 SQL을 만들지 않고 찾는 대상을 되묻는 안내로 끝낸다. 후보 전체 반환은 하지 않는다.
  ⑤ **경로 대칭(G-3)** — 여러 DB를 함께 조회하는 멀티 경로도 같은 선별 함수를 쓴다(멀티 질의당 정의 보유 DB마다 LLM 1회 추가). 선별 테이블의 정의 블록(「테이블 용도」)도 단일·멀티 같은 자리에 싣는다.
  ⑥ **단일 경로 예산 사다리(G-4)** — 시스템 + 사용자 프롬프트를 추정해 90K 초과 시 ①유사어·설명 ②표본 제거 ③호출 없이 명시 실패. 예산 안이면 바이트 무변경.
  ⑦ **백엔드 오류 감지 단일 대칭** — 멀티의 마커 판정을 공용 함수로 옮겨 단일 검증·선별 호출에서도 쓴다. 감지되면 재생성 0회 · 종결 사유 `backend_limit`.
  ⑧ **벤치 설명 출처(G-5)** — 벤치 카탈로그는 서버와 같은 순서(Redis → 파일)로 설명을 읽는다. 스키마 재저장 때 파일 설명이 유실되는 것이 재현되면 `PersistentSchemaCache.save()`가 부가 필드를 보존하도록 고친다.
  ⑨ **사용률 정본(G-6)** — 「자산관리에서 지난주 CPU 사용률 추이」에 ITAM 수집 이력(`기준년월일`·`CPU사용률`)으로 답하면 **오답**이다. 사용률의 정본은 관측 DB(폴스타)이고, 기대 응답은 「자산관리에는 사용률 추이가 없다 — 관측에서 조회할지」 안내다. 라우팅 교정은 `plans/132`(소스 선별) 소관으로 넘기고, ITAM-114 시나리오 기대값은 유지한다.
  ⑩ **반출 유래 시드(G-7)** — `testdata/itam_bench/closed/itam_schema.json`(108테이블·1,988컬럼 이름·타입)과 `table_definitions.yaml`(관리 정보 초안)을 **git으로 추적한다**. 데이터 값·반출 원본(`results/`)은 저장소에 넣지 않는다. 정의 가져오기 테스트는 이 실제 모양을 써도 된다.
