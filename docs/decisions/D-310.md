## D-310. `plans/134` W3·W4 구현 결정 — **다건 대상 = 게이트웨이 배치 `targets`(한 호출 = 작업 1개 · 대상별 하위 봉투) · 보기 3개·대상 10개 절단 제거 · 첫 홉 = 인스턴스 전부 · 전 대상 순위·이벤트 `apm_fleet`(전체 수집 뒤 정렬 · 실패 있으면 잠정) · 조회용 이벤트 버퍼(확정 구간만 재사용) · 서비스 `apm_service_status`·업무 `apm_business`·도메인/업무 시계열(지표 미지정 = 게이트웨이 기본 지표) · 이름 전부 미해결 = 넓히지 않음 · 소스 지목 `sources` · 보기 22 → 28 · 허용목록 37 → 41** (사용자 지시 *"134번 계획을 구현하라."* · 팀 리드 경유 · 사용자 확정 착수 순서 ① `plans/122` ⑥ → ② `plans/130` → ③ W3·W4(D-300 부기 2026-10-04) 준수 · D-296·D-299·D-290 이행)

- **결정일**: 2026-10-06 | **상태**: **확정(구현 · 작업 트리 · 커밋 없음)** — W6 잔여(M-7·A-1 채팅·A-4) · W8 · W10 잔여 | **번호**: 색인 최댓값 D-309 + 1(등재 직전 `ls docs/decisions/` 재확인)
- **배경**: 134 W3(N-9~N-11 · M-5)·W4(N-12)는 130 대상 해석이 선행이었다(130 구현 완료 · 사용자 커밋 `9cc8c6b`·`8f9b1c4`·`bac814c`). 130 팀 지적: 업무명 하나가 인스턴스 수십 개로 풀리면 본체가 대상마다 따로 불러 D-296의 「오래 걸리면 진행 안내」(M-10)가 그 경로에 붙지 않는다. 대상 없는 질문은 인스턴스 목록 앞 10대만 조회했고(C-13), 보기는 3개에서 잘렸다(C-11).
- **결정**:
  ① **다건 대상 = 배치 1호출**: 게이트웨이의 `hostname`을 받는 데이터 도구 17종에 `targets: [{hostname?, instance_name?, instance_id?(받는 7도구만), source_id?}]`(개수 상한 없음 · 항목 `hostname`·`instance_name` 200자 이하 · 모르는 키·형식 밖·빈 목록·최상위 대상 인자와 함께 = `invalid_argument` · HTTP 0회). 한 호출 = 작업 1개이고 항목마다 기존 도구 코어를 부른다 — 하위 봉투(`batch[i]`)는 단건 호출과 같은 칸·같은 값이고 행에는 `target_index`. 예상·진행은 배치 전체(첫 하위 계획 × N에서 시작 · 차이만 신고 — 이중 계산 0). 일부 실패 = `partial` + 대상별 사유 · 전부 실패 = 오류 봉투 + `batch` · 최상위 `limits` = 실패 줄 + 하위 `[한계]` 합집합 · 감사 대상 `targets(N)`. `apm_metrics`의 `targets`는 instance 시계열에서만. **본체는 한 보기의 대상이 2개 이상일 때만 배치**로 부르고(1개면 종전 호출 모양 바이트 동일 — `bac814c` 대비 본체 인자 8사례·게이트웨이 접근 기록 10호출 대조), `batch[i]`로 대상별 가상 호출을 복원해 집계·판정·출처·실패를 종전처럼 대상별로 남긴다. 배치가 마감 안에 끝나지 않으면 작업 1건 접수 답(예상·진행 — G-13: 재승인 질문 없음). 결과 파일로 간 행은 대상별 표지로 구별한다(행 0 · 건수 양수 모순 없음).
  ② **절단 제거**(D-296 ④ · D-299 ②): `MAX_VIEWS = 3` 삭제(분해 지시 「1~2개」 → 「필요한 보기를 모두」) · APM 경로 hostname 대상의 `max_targets` 절단 삭제(폴스타 공유 설정 `composite.max_targets`는 그대로). → `plans/125` A-6 ②(다건 hostname) 이행.
  ③ **첫 홉 정리**(기존 12개 보기): 대상 필수 보기에 대상이 없을 때만 인스턴스 목록을 먼저 부르고 **절단 없이 전부** 대상으로 쓴다(호스트 정합 인스턴스 = hostname 대상 · 호스트 없는 인스턴스 = `{instance_name, source_id, instance_id}` · 목록이 인라인 상한을 넘으면 결과 파일을 청크로 끝까지 읽는다 · 읽기 실패면 「전체」라고 쓰지 않고 의무 `apm_partial_sources`). 범위 고지 「대상 서버 미지정 — 전체 인스턴스 N개(호스트 H대) 조회」(비의무 · 0개면 생략). 대상 텍스트가 있었으면 첫 홉 없음(D-290 ⑥) · 명시 hostname 정합 실패는 그 대상의 실패로 끝 · 전 대상 보기·이름 보기·지표 목록에는 첫 홉 없음.
  ④ **서비스·업무**(N-9·N-12): `apm_service_status`(`/api/realtime/domain` — 이름 없음 = 소스당 1호출 전 도메인 · 이름 = 도메인 이름 단계 검색) · `apm_business`(`mode` current·list — 업무 정의 이름 단계 검색 · 한 이름에 여럿 = 전부 조회 + `[한계]` 이름 목록 · 되묻지 않음) · `apm_metrics(series, scope=domain|business)`. 단계 검색은 130 `search_instances`의 판정을 이름 단위 공용 함수(`name_tier`·`search_names`·`suggest_names`)로 뽑아 인스턴스·도메인·업무가 같이 쓴다(사본 0 · 130 테스트 무변경 통과). **이름을 줬는데 하나도 못 찾으면 데이터 API 0회 · 행 0 · 전체로 넓히지 않음** + `apm_unresolved_condition` + 후보 ≤3(자동 채택 안 함). 시계열 지표 미지정 = 게이트웨이 기본 지표(`response_time_avg_ms`·`service_count`·`service_err_count` — 카탈로그에 있는 것만 · `[한계]`) · 모르는 지표 일부 = 빼고 조회 + 고지 · 전부 모름 = 기본 지표 + 고지(`partial`) — W2 `apm_runtime_health` 규칙과 같은 계열(선택 조건 무효가 보기 전체를 실패시키지 않음). 기본 지표는 게이트웨이 어댑터가 정한다(레지스트리는 벤더 중립 어휘만 · D-274 ③). instance 시계열 동작은 불변.
  ⑤ **전 대상 순위·이벤트 `apm_fleet`**(N-10 · A-4 원자료): ranking = 범위 안 전 (source, domain)의 `/api/realtime/instance`를 모은 **뒤** 정렬(식별 `(source_id, domain_id, instance_id)` · 지표 = 실시간 수치 칸 중립 이름 30종 `RANKING_METRICS` = 레지스트리 enum · 값 없음은 순위 밖으로 센다) · 실패한 도메인·소스가 있으면 `provisional` + `[한계]` → 본체 `**판정·집계**` 블록에 「잠정 순위 — 조회 실패 도메인 k곳 제외」 + 의무 `apm_partial_sources`. events = 버퍼가 확정한 구간은 버퍼, 나머지는 도메인마다 API 1회(빈 구간을 감싸는 한 구간) · 레벨 거르기는 받은 뒤 같은 코드로(API에 `level`을 넘기지 않음 — 버퍼 행과 API 행이 같게) · 중복 제거는 버퍼↔API 겹침에만 · 실패 도메인은 0건이 아니라 「확인하지 못함」. 서비스로 좁힘(`service`)은 ④의 해석기를 쓴다. 본체는 전 대상 보기 task의 `instance` 종류가 아닌 대상 텍스트를 `service`로 옮기고, 사용자가 말한 서버로는 좁히지 않았다는 사실을 의무 고지한다(조용히 버리지 않음).
  ⑥ **조회용 이벤트 버퍼**(N-11): 게이트웨이 프로세스 메모리. 폴러가 도메인을 받은 직후 **레벨 필터 전** 전 이벤트를 `apm_events` 행과 같은 마스킹으로 기록하고, 응답 모양을 알아볼 때만 `[cursor, end − 60초]`를 확정 구간으로 둔다. 보관 `APM_EVENT_BUFFER_MINUTES`(60)·최대 `APM_EVENT_BUFFER_MAX_EVENTS`(200,000)은 메모리 한도이지 조회 범위 상한이 아니다(밖은 API) · 밀어낸 만큼 확정 구간을 당김 · 만료 키 sweep · 실패·백오프·중지·재기동 = 미확정 → API. 기록은 원자적(예외 시 불변식 유지). **알람 발행(최소 레벨·멱등·XADD 페이로드)은 버퍼 유무와 바이트 동일**(검증 독립 재현 4경우). 상태는 `gateway_health.poller.event_buffer`.
  ⑦ **보기·대상 표현**: 보기 22 → **28**(`apm.service`·`apm.service_trend`·`apm.ranking`·`apm.fleet_events`·`apm.business`·`apm.business_trend` · 새 영역 없음) · `ViewSpec.target: named` + `target_arg`(service·business — 이번 task 대상 텍스트 중 `instance` 종류 밖을 목록으로 싣고, 없으면 전체 1회). **소스 지목 `sources`**: 분해 task 칸(활성 + 레지스트리 소스 2개 이상일 때만 렌더 · 골격 키 포함) → 레지스트리 id로 검증 → 그 task의 모든 게이트웨이 호출(해석 검색·첫 홉·배치 포함)에 `source_ids` · 모르는 id = 빼고 고지 · 전부 무효 = 게이트웨이를 열지 않고 되묻기(전 소스로 넓히지 않음) · 소스 표 없는 배포 = 쓰지 않고 비의무 고지.
  ⑧ **허용목록 37 → 41**: `/api/realtime/domain`·`/api/dbmetrics/domain`·`/api/realtime/business`·`/api/dbmetrics/business`(D-290 ④ 개정 · D-296 ① 이행) · `time_pattern`·`.xml`·끝 `/`·비GET·`token` 거부 유지(HTTP 0회).
  ⑨ **조사 활용**(D-299 ③): `sre_agent` 조사 순서 ⑥에 `apm_fleet`(events는 사건 앵커 인자 · ranking은 지금 값)·`apm_service_status`·`apm_business`·`targets` 한 줄(앵커 도구 목록은 불변).
  ⑩ **작업 기록의 대상 원문**: 승격된 배치 작업의 `result_meta.batch[].target`에는 사용자가 가리킨 hostname·인스턴스 이름·소스 id가 남는다 — 비밀 값이 아니고 단건 작업 기록의 `instance_resolution`과 같은 종류이며, 작업 소유자 확인·보관 기간(D-262)을 따른다. 감사·작업 목록에는 `targets(N)` 요약만 나간다. 유지한다.
- **근거**: D-296 ④(자체 상한 없음 · 긴 것은 작업) · D-299 ②④(복수 조회·전수 순위·장기 작업) · D-290 ⑥ · D-274 ⑤(정합·판정·집계·기본 지표는 게이트웨이) · D-287 · G-13. 실측: 독립 검증(실프로세스 게이트웨이 ↔ MCP SSE ↔ 본체 2단 · 가짜 LLM · 목 Open API 2소스) E1~E8 성립 · 정적 계약 대조 336사례(본체 실제 인자 403호출 — 모르는 키·빠진 필수·형 불일치 0) · 적대 58건 · 자격증명 카나리아 배치 경로 0 · 검증 Major 3(V34-1 시계열 지표 · V34-2 첫 홉 인라인 절단 · V34-4 전 대상 보기의 대상 침묵 폐기)·리뷰 Major 1(R34-1 결과 파일 대상 표지)을 같은 작업에서 교정.
- **대안**: (a) 대상별 호출 유지 + 본체 예상 고지 — 작업이 아니라 120초 마감에 끊기고 진행이 없다 → 기각 (b) 대상 전부를 한 정합 결과로 합쳐 1호출 — 대상별 집계·판정이 섞인다 → 기각 (c) 첫 홉 절단 유지 — D-296 ④ 위반 → 기각 (d) 레지스트리에 벤더 지표 이름 기본값 — D-274 ③ 위반 → 기각 (e) 시계열 모르는 지표 = `invalid_argument` — 흔한 질문 모양이 실패(V34-1 · MLX 실측 `responseTime`) → 기각.
