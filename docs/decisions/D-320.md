## D-320. 지문 dedup 심각도 상승 우회 — 같은 지문이 재통보 간격 안에 더 높은 심각도로 오면 버리지 않고 판정한다(전 경로 · 기본 on — 신규 플래그 기본 off 원칙의 예외) (`plans/144` Q-4 · 사용자 확정 2026-10-07)

- **결정일**: 2026-10-07 | **상태**: 확정(구현 · 커밋 없음) | **번호**: 2026-10-07 D-318로 등재 → 2026-10-08 원격 병합에서 원격 D-318(`is_routine` 승격 제거)·D-319와 겹쳐 **D-320으로 재부여**
- **배경**: `plans/144` W1 검증에서 verifier가 기존(폴스타 포함) 경로의 결함을 실측했다 — 워커 지문 dedup(`_is_duplicate_fingerprint` · 기본 4h · `last_notified` 고정창)은 심각도와 무관하게 같은 지문을 버리므로, 같은 지문의 심각도 2가 통보된 뒤 4시간 안에 온 심각도 3이 게이트에 닿지 못한다. D-048 「심각도3 절대 PAGE」의 빈틈이다. 제니퍼 정책 경로에는 W1 교정으로 같은 우회가 이미 있다(`_apm_sent_severity`). 사용자 지시(2026-10-07): *"기존 폴스타 경로에도 「심각도 상승 시 dedup 건너뜀」을 별도 결정으로 넣는다. … 플래그 기본값을 어떻게 둘지 CLAUDE.md 「신규 플래그 기본 off」 원칙과 대조해 정하고, 예외로 할 경우 근거를 config 주석과 결정문에 적어라."*
- **결정**:
  ① 지문 레코드에 마지막 통보 심각도를 기록하고, 재통보 간격 안이라도 **들어온 심각도 > 기록 심각도**면 중복으로 보지 않는다(비중복 경로 그대로 — 레코드 리셋 · 새 심각도 기록 · info 로그 1줄). 같거나 낮은 심각도의 반복은 종전대로 버린다 → 창당 추가 통과는 최대 2회(1→2→3). 해소(0)는 원래 dedup 대상 밖이다.
  ② 플래그 `NOISE_DEDUP_SEVERITY_RISE_BYPASS`(`NoiseGateConfig.dedup_severity_rise_bypass`) **기본 True**. false면 종전 동작과 비트 동일(레코드에 심각도 키도 두지 않는다). 심각도 키가 없는 구 레코드는 우회하지 않는다.
  ③ 제니퍼 정책 경로 전용 우회(`plans/144` W1)는 그대로 둔다 — 전역 플래그를 꺼도 정책 경로 보장은 남는다. 둘이 함께 켜져도 정책 경로가 먼저 레코드를 지우므로 이중 우회·로그 중복이 없다(테스트 고정).
- **기본 on 예외 근거**(CLAUDE.md 「신규 기능 플래그는 기본 off = 현행 동작과 비트 동일 · 예외는 근거와 함께 config 주석에」): 이 플래그는 새 기능이 아니라 확정 결정(D-048 「심각도3 절대 PAGE」)과 dedup 자신의 독스트링(「최초 발생 sev3는 항상 PAGE」)이 약속한 동작을 복구하는 결함 교정이다. 기본 off는 알려진 재현율 결함(심각 장애 미통보)을 운영에 그대로 두는 선택이라 D-048.4(재현율 우선)와 충돌한다. 비용은 상한이 있다(지문·창당 최대 2회 추가 판정). off 스위치는 회귀 확인·긴급 원복용으로 남긴다. 근거는 `src/config.py` 해당 필드 주석에도 적었다.
- **구현**: `noise_gate/application/alarm_worker.py`(`_is_duplicate_fingerprint` · `_dedup_severity_rises` · `_dedup_meta` — 반환 재발 메타에는 심각도 키를 싣지 않아 recurrence 모양 불변 · `_apm_dedup_active` 정합) · `src/config.py` · `src/api/settings_catalog.py`(「기본 동작」 구획) · `config/settings_help/noise_gate_core.yaml` · `.env.example` · 카탈로그 총수 단언 · 테스트 `noise_gate/tests/test_plan144_wave_a.py`.
- **주의**: 경량 설정(SimpleNamespace) 테스트는 플래그가 없어 off로 해석된다 — 기존 dedup 테스트의 기대값은 바뀌지 않는다. 운영 기본값(on)에서 같은 지문 sev2→sev3는 2건이 게이트에 닿는다(`test_plan144_apm_policy.py::...test_sev3_escalation_off_and_polestar_unchanged`는 경량 설정 = off 전제).
