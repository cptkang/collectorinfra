## D-243. 미연동 환경의 알람 통보·조사는 **traceback 없이 한 줄 경고로 생략한다** — worKB 미설정이면 발송하지 않고 · 조사 서비스는 사전 도달성 확인 (사용자 지시 2026-09-21)

- **결정일**: 2026-09-21 | **상태**: 확정 (구현 완료) | **번호**: 등재 직전 실측 2026-09-21 — `## D-` 헤더 최댓값 **D-242** · 「변경 이력」 표 최댓값 **D-242** · 「채번 이력」 표 예약에 243 없음 → **D-243**
- **배경**: 폐쇄망 Windows 호스트 로그(2026-09-21 17:07 · `alarm_id=15633882`) — ①`NOISE_INVESTIGATION_SERVICE_URL=http://10.37.26.71:9098/sse`로 SSE 연결 → `httpx.ConnectTimeout`(mcp `sse_client` 기본 5초) → ExceptionGroup traceback 전문(통보는 graceful 진행) ②`WORKB_BASE_URL` 미설정 → `_send_workb`의 `ValueError` → `logger.exception` traceback. 둘 다 설정 문제다 — `sre_agent`는 `127.0.0.1` 고정 바인드인데 원격 IP로 접속했고, `.env.example`의 `WORKB_BASE_URL=`(빈 값)이 그대로 남았다. 사용자 지시: *".env에 워크비가 없으면 발송안하도록 코드를 구현하라. sre_agent가 없는지 사전에 확인하여 간단한 워닝만 나오도록 수정하라."*
- **결정**:
  - ①**worKB 미설정은 장애가 아니라 설정 상태다** — `_send_workb`가 `WorkbNotConfiguredError`(`ValueError` 하위 · 직접 호출 계약 유지)를 올리고, 발송 루프가 이를 따로 받아 `notifications_sent["workb"]=False` + 한 줄 WARNING(`worKB 미설정(WORKB_BASE_URL 없음) — 발송 생략: alarm_id=…`)으로 끝낸다. 다른 채널은 그대로 발송한다. 후속 브리핑·L3 후속은 본 통보가 실제로 나간 경우에만 돌므로 따라서 생략된다. 판정 키는 `WORKB_BASE_URL` 하나다
  - ②**조사 서비스 사전 도달성 확인** — `SreAgentClient.unreachable_reason()`: URL의 host:port에 **TCP 연결만** 시도(상한 2초 · happy eyeballs 0.25초)하고, 미가용 판정은 **30초 재사용**한다(클래스 상수). 트리거 노드가 인가 게이트 뒤 · 가용성 SQL 조회(Plan 81) 앞에서 호출하고, 미가용이면 한 줄 WARNING(`조사 서비스 미가용 — 조사 생략(통보는 진행): alarm_id=… 사유=…`) + 감사 `status="down"` 후 `{}`를 반환한다. 즉시·후속(3-E) 두 모드 공통. 확인 메서드가 없는 클라이언트 대역은 확인을 건너뛴다
  - ③사전 확인을 **통과한 뒤**의 연결 실패(포트는 열렸으나 MCP가 아님 · 인증 401 등)는 종전대로 traceback을 남긴다 — 서비스 부재가 아니라 이상 신호이기 때문이다
- **근거**: 사용자 지시. 침묵 폴백 금지는 유지된다 — 알람마다 한 줄 경고 · 감사 `down` · `notifications_sent=False`로 남는다. 지연도 줄어든다: 서비스 부재 시 알람당 5초 대기 → 첫 확인 최대 2초, 이후 30초간 즉시(실측 2026-09-21 맥: 패킷을 버리는 주소 2.00s → 재사용 0.0ms · 닫힌 localhost 포트 0.01s · `127.0.0.1` 전용 리스너에 `localhost` URL 0.011s 도달)
- **대안(기각)**: worKB 사용 여부 플래그 신설(키만 늘 뿐 `base_url`이 없으면 어차피 못 보낸다) · 발송 루프에서 `cfg.workb.base_url` 직접 검사(기존 테스트 대역 `SimpleNamespace()`에 속성이 없어 판정이 흔들린다 — 검사는 `_send_workb` 한 곳에 둔다) · 기동 시 1회만 확인(나중에 뜬 서비스를 재기동 전까지 못 쓴다) · 확인 상한·재사용 창의 설정화(요청 범위 밖)
- **구현**: `noise_gate/application/nodes/alarm_notifier.py`(`WorkbNotConfiguredError` · 발송 루프 분기) · `noise_gate/infrastructure/sre_agent_client.py`(`unreachable_reason` · `PROBE_TIMEOUT`·`UNREACHABLE_COOLDOWN`) · `noise_gate/application/nodes/investigation_trigger.py`(사전 확인 분기) · 테스트 `noise_gate/tests/test_unconfigured_notify_skip.py`(7건 — 실제 루프백 소켓 포함)
- **주의**: ①**증상(로그·지연)만 다룬다** — 폐쇄망 호스트에서 조사가 실제로 돌려면 `NOISE_INVESTIGATION_SERVICE_URL=http://localhost:9098/sse`(같은 서버)로 바꿔야 한다. `sre_agent`는 `127.0.0.1` 고정 바인드라 원격 IP로는 서비스가 떠 있어도 닿지 않는다(`docs/26` §1.3) ②사전 확인은 TCP 직결이다 — `HTTP_PROXY` 경유로만 닿는 배치라면 오판한다(조사 서비스는 같은 서버 전제라 현 배치에는 해당 없음) ③Windows의 `::1` 거절 재시도 지연은 happy eyeballs로 막았지만 **Windows 실측은 아직 없다**
