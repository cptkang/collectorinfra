## D-332. 프로젝트 스킬 2종 신설 — `refactoring`(동작 불변 구조 리팩터) · `secure-coding`(시큐어 코딩)

- **결정일**: 2026-10-14 | **상태**: 확정 · 구현 완료(커밋 없음)(사용자 지시 *"분석한 내용을 확인하고 참고 문헌 및 논문등을 참고하여 리펙토링 및 시큐어 코딩 스킬을 생성하라."*)

  ② `.claude/skills/secure-coding/` — `SKILL.md`(영역 A DB 읽기 전용·SQL / B 인증·인가 / C 오류 처리 / D 설정·시크릿·외부 연결 / E 로그·PII / F LLM 특화 + 절차·금지) · `references/standards.md`(OWASP ASVS v5.0.0·Top 10:2025·LLM Top 10 2025·CWE·RFC 8725/7519·NIST SSDF·DB 벤더 문서·논문) · `scripts/secure_scan.py`(ast 기반 검토 후보 스캐너 R1~R6).

- **구현**: 위 파일. 두 스크립트는 `ruff check` 통과(line-length 100). 제품 코드 변경 0.
- **주의**: ① 스캐너 결과는 검토 후보다 — 오탐(도메인 예외 메시지 `apm_jobs.py:51-55`·`result_viz.py`, HTTPException 재전달 `query.py:3618`, DRM 사유 `query.py:3500`)을 고치려고 코드를 바꾸지 않는다. ② `smell_metrics.py --getattr`는 D-331 ② 린트가 생기면 그 스크립트를 정본으로 쓴다. ③ 스캔에서 `src/clients/fabrix_kbgenai.py`(4곳)·`fabrix_retrieval.py:272`의 무조건 `verify=False`가 잡혔다 — 아래 부기대로 결함이 아니다.

- **부기(2026-10-14 · 사용자 확정 *"사내망에서는 TLS가 필요없는데?"*)**: 사내망 구간(FabriX·폴스타 REST 등)은 TLS를 요구하지 않는다. 해당 클라이언트의 `verify=False`는 의도된 설정이며 `plans/163`에 넣지 않는다. `secure-coding` 스킬 D절과 `secure_scan.py` 머리에 반영했다. 사내망 밖 연결(과금 외부 API 등)의 TLS 검증 해제는 여전히 하지 않는다.
