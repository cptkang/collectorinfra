## D-248. 질의응답 스레드를 **서버 앱 DB에 턴 단위로 남기고, 질의 이력 사이드바의 "대화"에서 다시 불러와 이어서 질의한다** · Admin·노이즈 관제는 새 탭 (사용자 지시 2026-09-22 · D-183 G-1 부분 개정)

- **결정일**: 2026-09-22 | **상태**: 확정 (구현 완료) | **번호**: `## D-` 헤더 최댓값 **D-247** · 「변경 이력」 표 최댓값 **D-247** · 안내 라인 "다음 D-248" 대조 → **D-248**(2026-09-22 실측, 등재 직전 재grep)
- **배경(사용자 지시)**: *"사용자화면에서 admin 화면으로 전환했다가 다시 사용자화면으로 돌아가면 기존에 동작했던 질의응답 내용이 모두 사라져 있다. 유지되도록 수정하라."* 실측 원인: Admin 링크가 **같은 탭 이동**(`href="/admin"`)이고 채팅은 **DOM에만** 있어 페이지가 내려가면 사라진다(thread_id도 메모리 전용). 세 안(탭 저장소 스냅샷 · 서버 체크포인트 재조회 · 새 탭)과 새로고침 처리를 물었고, 사용자 답: *"기본 3번으로 진행하고 질의 응답 스레드를 별도로 DB에 저장하여 질의 이력에서 볼 수 있도록 개선하라."* · 새로고침은 **새 대화 유지**(권장안).
- **결정**:
  - **① 새 탭** — 사용자 화면의 Admin·노이즈 관제 링크에 `target="_blank" rel="noopener"`. 원래 탭이 내려가지 않으므로 질의응답 화면이 그대로 남는다.
  - **② 저장 위치는 앱 DB의 `query_thread_turns` 한 테이블**(감사 로그와 같은 `auth_pool` — `auth_db_url` 또는 `db_connection_string`). 기동 시 `ensure_tables()`가 멱등 DDL을 실행한다. **체크포인트를 재조회하지 않는 이유**: `/conversation/{thread_id}`가 읽는 `state.messages`에는 노드 12곳이 넣는 중간 `AIMessage`가 섞이고 SQL·행 수·스코프가 없다. 풀이 없으면 기능이 꺼지고 목록이 사유(`no_store`)를 보여 준다.
  - **③ 소유 키 — D-183 G-1 부분 개정**: 로그인 사용자는 `user:{sub}`(기기를 바꿔도 같은 목록), 익명(`AUTH_ENABLED` 미설정 운영)은 `anon:{X-Client-Id}`다. `X-Client-Id`는 브라우저가 `crypto.getRandomValues`로 만든 32hex(localStorage `query_client_id`)이고 `getAuthHeaders()`가 모든 요청에 싣는다. `crypto.randomUUID`는 보안 컨텍스트 전용이라 내부망 http에서 없어서 쓰지 않았다. **식별자가 없거나 형식이 틀리면 기록·조회 모두 하지 않는다**(`no_owner` — 섞이는 것보다 비는 편이 낫다). G-1이 서버 저장을 기각한 근거(전원 `anonymous` 한 명으로 뭉침)는 이렇게 푼다. **G-2(질의 목록은 질의문+시각만, 브라우저)는 그대로**이며 사이드바 "질의" 모드로 남았다.
  - **④ 기록 지점은 진입점 4곳의 모든 정상 종료**다 — 반환 7곳 `turn.response(QueryResponse(...))`, SSE 7곳 `StreamingResponse(turn.stream(gen()))`. D-183 감사 이설과 같은 대칭 원칙이고, AST 테스트가 네 함수의 모든 반환·스트림을 검사한다. **완결된 턴만** 남긴다(done 이벤트·QueryResponse). 실패·중단 턴은 답이 없어 남기지 않는다. 역질문·승인 대기 턴은 `status`(`clarification`·`awaiting_approval`)로 구분된다. thread_id가 없는 응답(파일 경로 첫 턴 역질문)은 이어 붙일 대화가 없어 남기지 않는다.
  - **⑤ `done`을 내보내기 전에 기록한다** — 래퍼가 `done` 청크 직전에 `add_turn`을 await한다(상한 3초, 실패는 `WARNING` 후 응답 계속). 그래서 클라이언트가 done 직후 목록을 다시 받아도 방금 턴이 들어 있다.
  - **⑥ 상한**: 소유자당 **200 스레드**(D-183 `HISTORY_MAX` 전례). 삽입과 같은 트랜잭션에서 초과분을 지운다.
  - **⑦ 화면**: 사이드바에 **대화/질의 전환**(기본 대화)을 둔다. 대화를 누르면 채팅 화면을 비우고 턴을 다시 그린 뒤 `currentThreadId`와 스코프 칩을 그 대화에 맞춰 **이어서 질의**할 수 있다. 칩은 마지막으로 비어 있지 않은 `db_scope`를 쓴다(D-205 거울 규칙 — 역질문 턴은 직전 값 유지). 검색은 대화 안의 모든 질의문을 본다. **다운로드·CSV 링크는 다시 그리지 않는다** — 원본은 인메모리 `_results_store`에만 있어 지난 대화에서는 대개 사라졌다. 삭제는 목록(기록)에서만 지우고 체크포인트는 남는다. 스레드 ID 갱신은 `setCurrentThread` 한 곳을 지나며(완료 지점 5곳), 이때 목록을 다시 받는다.
  - **⑧ 새로고침은 새 대화**(D-205 전제 유지). 지난 대화는 목록에서 다시 연다.
- **부수 교정(기존 결함 · 이 작업의 브라우저 실측이 발견)**: `var HISTORY_PANEL_KEY`가 초기화 `setupViewTabs()`(IIFE 528행)보다 **뒤**(3950행대)에 선언돼 있어 초기화 시점 값이 `undefined`였다. 그 결과 D-183 개정의 **"편 상태는 브라우저가 기억한다"가 동작하지 않아** 늘 접힌 채로 시작했고, 저장값이 "펼침"이면 **새로고침 뒤 첫 클릭이 패널을 열지 못했다**. 정적 테스트는 선언 문자열만 대조해 통과하고 있었다. 선언을 상단 State 구역으로 옮기고 순서 테스트를 추가했다(HEAD에서 실패 · 수정본에서 통과). 대화 기능의 동선(사이드바 열기) 한가운데라 함께 고쳤다.
- **대안(기각)**: 탭 저장소 스냅샷(사용자 미선택 · 응답·SQL이 브라우저 저장소에 남는다) · 체크포인트 재조회(중간 메시지 혼입 · 메타 부재) · 클라이언트가 턴을 POST(웹 UI 밖 호출은 빠지고 기록 지점이 클라이언트 5곳으로 흩어진다) · 익명 전원 한 목록(G-1).
- **주의**: ①브라우저 식별자는 **인증이 아니라 추측 불가 값에 기댄 구분**이다(인증을 켜면 user_id로 바뀌고, 익명 시절 대화는 새 소유 키에서 보이지 않는다). ②localStorage를 지우면 식별자가 새로 생겨 그 브라우저에서 이전 대화가 안 보인다(서버에는 남는다). ③보존 기간 기반 정리는 없고 개수 상한만 있다. ④admin 대시보드의 "사용자 화면" 링크는 같은 탭 이동 그대로다 — 새 탭으로 연 관리자 탭에서 누르면 그 탭에 새 사용자 화면이 뜬다(원래 탭은 유지).
