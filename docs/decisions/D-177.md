## D-177. 알람 피드백·ack 루프 신뢰성 — **쓰기 경로에도 존 RBAC · 철회는 tombstone**

- **결정일**: 2026-08-28 | **상태**: 확정 (구현 완료 · `plans/83` 트랙 A · `SPEC-alarm-feedback-loop.md`) | **번호**: 등재 최댓값 D-175 → 예약 D-176(`plans/82`) 다음 **D-177**
- **배경(실측 · `docs/28` 작성 중 발견)**: 운영자 가이드를 쓰려고 피드백 경로를 전수 실측하다 **읽기·쓰기 경로의 인가 비대칭**이 드러났다 — SSE 스트림은 `alarm_zones_for_user`로 구독자 존을 거르는데(`alarm.py:938`), **피드백·ack에는 같은 판정이 없어** 알람명만 알면 다른 존 알람에 라벨을 남기고 사건을 확인 처리할 수 있었다. 함께 발견된 것: 저장 `pattern`(LLM 산출)과 조회 `pattern`(결정적 `pre_classification`)의 원천 불일치, 작성자 미기록(ack는 `acked_by`가 있는데 피드백엔 없다), 철회 수단 부재, `find_similar`의 전체 파일 동기 스캔 + 회전 부재.
- **결정**:
  - **쓰기 경로에 읽기 경로와 동일한 존 판정을 적용한다.** 공용 `_assert_zone_access`가 SSE `_visible`과 같은 규약을 쓴다 — 존 없음 403, 전 존 통과, **db_id 미상은 차단하지 않는다**(판정 불가 ≠ 거부 · 하위호환). ack는 `IncidentStore.get_db_id`(포트 신설)로 대상 존을 조회하며, 조회 실패·미보유 구현체는 통과시킨다.
  - **철회는 tombstone append**(파일 재작성 금지). 원본 레코드는 감사 추적용으로 남고 `find_similar`·`summarize` 후보에서만 빠진다. append-only 감사 원칙(D-048.4)과 동시 쓰기 안전을 함께 지키는 유일한 방법이다.
  - **작성자(`labeled_by`)는 감사 전용** — few-shot 프롬프트 렌더에 싣지 않는다. 작성자 이름이 LLM 판단에 개입할 이유가 없다(테스트로 고정).
  - **피드백 저장 키의 원천을 결정적 값으로 통일**한다. `AlarmAnalysisResult.pre_classification`을 신설해 SSE payload **4곳**(`_tier_sse_payload`·`_incident_open_payload`·analyze·analyze-raw)에 대칭 주입하고, UI가 그 값을 되돌려 보낸다. LLM 산출 `pattern_type`은 표시용으로만 남긴다.
  - **조회 창 = 회전 상한**(`NOISE_FEEDBACK_STORE_MAX_LINES=20000`). 창 안에서는 전체 스캔과 결과가 동일하고(등가성 테스트로 고정), 초과 시 오래된 절반이 `.1`로 밀린다. hot path 조회는 `asyncio.to_thread`로 감싸 이벤트 루프를 막지 않는다.
  - **버튼 가용성은 서버가 알려준다**(`GET /alarm/capabilities` · 불리언·정수만). 종전에는 기능이 꺼져 있어도 버튼이 그려지고 누르면 503이 떠 원인을 알 수 없었다.
  - **라벨 상충은 보여주되 판정하지 않는다**(`GET /alarm/feedback/summary` + 관리자 `알람 피드백` 탭). 다수결·가중 합의는 D-035 경계 재검토가 선행돼야 하는 별건이다.
- **게이트 확정(사용자 2026-08-28)**: **G-3 note 입력란 신설**(200자 · 민감정보 금지 안내 상시 노출) · **G-5 철회 = tombstone**.
- **구현**: `noise_gate/infrastructure/feedback_store.py`(`labeled_by`·`record_retract`·`summarize`·`_read_window`·`_rotate_if_needed` · **표준 라이브러리 유지**) · `noise_gate/domain/incident_store.py`+`incident_repository.py`(`get_db_id`) · `noise_gate/domain/alarm.py`(`pre_classification`) · `noise_gate/application/nodes/alarm_analyzer.py`(사전분류 단일 산출 · `to_thread`) · `alarm_notifier.py`(payload 2곳) · `src/api/routes/alarm.py`(`_assert_zone_access`·capabilities·retract·summary) · `src/static/js/app.js`·`admin.js`·`dashboard.html`·`style.css` · `src/config.py`(`feedback_store_max_lines`).
- **주의**: ①`db_id`를 싣지 않는 기존 클라이언트는 **존 무판정으로 통과**한다 — 판정 강제 전환은 UI 배포 안정화 뒤 별도 스위치로 한다. ②회전이 일어난 뒤에는 오래된 라벨이 조회 창에서 빠진다(설계상 의도 · 회전 전까지는 전체와 동일). ③`note`는 프롬프트로 그대로 전달되므로 민감정보 금지 안내가 UI에 고정 노출된다.
