  실측(`plans/102` §1): 시스템 선택은 LLM 분류 1회뿐이고 검증 코드가 없다 · 빈 분류·LLM 실패는 **첫 활성 DB로 침묵 폴백**(`subagents.py:174` · 3단은 `semantic_router.py:250,338`) · 레지스트리 능력 축(`capability_providers()`)은 운영 소비처 0건 · ★서버 식별 키 판정이 **컬럼명 목록**(`is_server_identity_col`)이라 자산 DB `sevrHostName`·`iPCtnt`가 인정되지 않아 **자산→폴스타 체인이 `prior_no_identity`로 차단**(실행 확인)되고 IP는 스코프 키 후보에 아예 없다 · 소재 탐색(`host_discovery`)은 폴스타 존 축·호스트명 완전 일치만 있다.
- **결정**:
  ① **답변 영역(capability) 소유** — 정본 시스템은 필요한 정보 종류로 정하고 **레지스트리 데이터로 선언**한다. LLM은 답변 영역을 말하고, 코드가 그 영역의 정본 시스템을 판정한다. 소유 검증의 입력은 **LLM 구조화 출력뿐**이다 — 질의 원문 키워드 분류 금지(D-004 유지). 검증 지점은 2곳(3단 라우터 노드 / 분해 task)이고, 단일 DB 시스템은 `db_ids`를 고정하며 다중 존 시스템은 DB 집합 제한만 한다(존 한정을 깨뜨리지 않는다).
  ② **값 기반 식별 키 판정** — 서버 키는 컬럼명이 아니라 **값**(호스트명·FQDN·IPv4·IPv6)으로 판정하고 RFC 4343(대소문자 비구분)·RFC 5952(IPv6 정규 표기)로 정규화한다. **컬럼명 판정(D-100)은 폐기가 아니라 보조 신호로 남긴다.** 구현 시 계획 대비 조정 3: ㉮컬럼 판정 단위는 값 타입이 아니라 **키 계열**(`hostname`=hostname·fqdn / `ip`=ipv4·ipv6) — 한 컬럼에 단축명과 FQDN이 섞이는 것이 정상이다 ㉯단일 레이블은 **2자 이상**만(`Y`/`N`·`N/A`가 호스트명 컬럼으로 판정되던 것 차단) ㉰`possible` 등급은 **FQDN ↔ 단일 레이블**에만 준다(양쪽이 FQDN이면 도메인이 다른 별개 호스트다).
  ③ **키 브리지 매니페스트** — 시스템 간 키 대응은 공용 코드가 아니라 **DB별 프로필 `entity_keys`**(대상 컬럼·우선순위·다중값·행 다중도)에 둔다(D-089 · D-053). 양방향이 **같은 계약**이며 대상 컬럼은 코드가 확정한다 — 종전의 LLM 위임 문구(*"또는 동등한 식별 컬럼"*)를 없앤다.
  ④ **매칭 등급 노출** — `link`/`possible`/`non_link`/`ambiguous`로 판정해 경과 노트로 보인다. **모호 일치(`ambiguous`)는 결과에 넣지 않는다**(추측 금지). 매칭 보고 합계 = 선행 키 수(침묵 0).
  ⑤ **식별자 소재 프로브** — `host_discovery` 판정을 **(시스템, 존) 축**으로 일반화하고 **"미발견"과 "확인 못 함"을 분리**한다. 발동은 조건부(두 시스템이 다 필요 · 소유 시스템에서 미발견 · 소유 모호)이고, LLM 추가 호출 0 · 시스템(폴스타는 인가 존)당 고정 조회 1회다. **itam은 존이 없어 시스템 1회 조회**다(G-4).
  ⑥ **하네스 계약** — 계약 차원마다 계산적 센서 1개(D1~D8)를 두고 변이 스위트로 **그 차원의 센서만** 실패함을 고정한다. 플래그 3종 `CROSS_SYSTEM_KEY_BRIDGE_ENABLED`·`CROSS_SYSTEM_PROBE_ENABLED`·`ROUTER_CAPABILITY_OWNERSHIP_ENABLED`는 **기본 off = 현행 비트 동일**이다.
  ⑦ **소유·판정 주체는 사다리 3단**(v2 · D-225 연동) — 계약은 3단 `semantic_router`가 소유·판정하고 1단 `deep_agent`는 **같은 함수를 부르는 부가 경로**다(1단 전용 판정 로직 신설 금지). 3단 교차 체인 진입은 원문 표지 문자열이 아니라 **라우터 구조화 출력 `chain`**으로 판정한다(D-004).
  ⑧ **빈 분류·LLM 실패 폴백을 응답에 표기**한다 — 첫 활성 DB 폴백은 없애지 않되 `routing_fallback` 노트로 드러낸다(침묵 금지).
