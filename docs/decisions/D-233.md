## D-233. 원격 조사 프로파일의 bash 제거 — **중앙 호스트 셸은 조사 근거가 아니다 · `core` 허용목록은 읽기 전용이 아니었다** (SREAgent D-004·plans/sre-agent/06 §6 전제 갱신)

- **결정일**: 2026-09-21 | **상태**: 확정 · 구현 완료 (사용자 승인 후 착수 — *"1번은 진행"*) | **번호**: 등재 직전 재실측 — `## D-` 헤더 최댓값 D-231 · 「변경 이력」 최댓값 D-231 · 「채번 이력」 예약 최댓값 D-232(`plans/104` C-4) → **D-233**
- **배경**: D-229 검증에서 원격 조사 프로파일(`remote_vm_profile()`)의 bash가 `builtin_allowlist="core"`로 켜져 있고, 그 목록이 **읽기 전용이 아님**을 실측했다(LLM 0회·명령 실행 0): `echo x > f` · `grep … >> f` · `sort -o f` · `uniq in out`이 검증을 **통과**한다. 리다이렉트는 prefix 허용목록으로 막을 수 없다 — `bashlex` 세그먼트가 명령 이름으로 시작하므로 `echo`가 허용되면 `echo … > 파일`도 허용된다. 또 `core`에는 `kubectl` 읽기 13종이 들어 있어 k8s가 아닌 환경에서 무의미하고, 2026-09-17 실 조사에서 9B 모델이 **40 step 중 35를 `kubectl get pods` 반복**에 소진했다.
- **결정**: `remote_vm_profile()`의 bash를 **`{"enabled": False}`로 끈다**(종전 `{"enabled": True, "config": {"allow": [], "builtin_allowlist": "core"}}`). 플래그를 두지 않는다 — 조사 도구 표면은 프로파일이 정본이다(D-229 ①).
- **왜 축소가 아니라 제거인가(대안 비교)**:
  ① **`builtin_allowlist: "none"` + 읽기 전용 유틸 allow** — 허용한 prefix가 무엇이든 리다이렉트 쓰기가 다시 열린다(`jq . f > out`). 요구(쓰기 형태를 검증 단계에서 거부)를 만족할 수 없다.
  ② **`none` + `allow: []`(도구는 두되 전부 승인 필요)** — 실행은 막히지만 도구가 표면에 남아 LLM이 계속 시도한다(관측된 실패 모드가 그대로).
  ③ **deny 목록으로 쓰기 형태 차단** — deny도 prefix 매칭이라 리다이렉트를 표현할 수 없고 `sort --output=`류를 놓친다.
  ④ **제거(채택)** — 요구를 전부 만족하고 표면도 줄인다.
- **"유지할 읽기 전용 텍스트 유틸"이 없다는 실측**: ①`tool_results_dir`를 넘기는 코드가 0건이라 holmes가 도구 결과를 디스크로 흘리지 않는다 → 자동 추가되는 `cat/head/tail/wc/jq <저장경로>` 허용 prefix는 **죽은 경로**이고 `_has_bash_for_file_access`도 이 배치에선 의미가 없다. ②MCP 도구 출력은 파일이 아니라 대화에만 있다 → bash로 가공할 대상 자체가 없다. ③2026-09-17 실 조사의 bash 호출 42회는 `kubectl` 38 · `hostname` 3 · `psql` 시도 1(허용목록 밖 → 승인 필요 → 비대화형에서 미실행)로 **조사 데이터 가공 0건**.
- **기존 결정과의 관계**: SREAgent **D-004**(VM 진단 대상·읽기 전용 프로파일)와 `plans/sre-agent/02` §8(*"어느 배치든 변경 명령은 toolset에 물리적으로 존재하지 않게 한다"*)의 **취지를 강화**한다 — 리다이렉트 쓰기라는 구멍을 닫는다. `plans/sre-agent/06` §6 표의 *"bash 확장 안 함(내장 core 텍스트 유틸만)"*은 **전제가 갱신됐다**: 그 표현은 `core`가 텍스트 유틸만이라는 전제였으나 실제로는 kubectl 13종 + 쓰기 가능 형태를 포함한다(시점 문서라 원문은 보존하고 본 결정이 정본). **D-119**(PromQL은 `mcp_server` 경유)·**D-125**·**D-123**은 영향 없음 — 원격 데이터 경로는 처음부터 MCP뿐이다.
- **로컬 프로파일은 범위 밖**: `vm_profile()`·`middleware_profile()`(로컬 배치 L3 — SREAgent D-004 소관)은 **그대로 둔다**. 다만 같은 리다이렉트 쓰기 구멍이 있다(예: `uptime > /tmp/x`) — 사용자 보고 사항이며 이번 변경 대상이 아니다. 변경 명령(`kill`·`rm`·`systemctl restart`·`dmesg -C`)이 허용목록 밖이라 비대화형에서 미실행인 것은 회귀 테스트로 고정했다.
- **검증(2026-09-21 · LLM 0회 · 명령 실행 0)**: `sre_agent/tests` **419 passed·3 skipped → 422 passed·3 skipped**(신규 3 — 런타임 도구 목록에 `bash`·`read_image_file` 없음 · `core` 목록이 쓰기 4형태와 `kubectl get`을 허용했음을 고정(제거 근거·holmes 상향 감지) · 로컬 프로파일의 변경 명령 승인 필요 유지). 수정 전 코드에서 5건 실패 확인 · `arch_check --ci` 위반 0 · 루트 `overfit_check --ci` 신규 유입 0.
