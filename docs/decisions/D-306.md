## D-306. 집계 결과 표의 NULL 묶음 기준을 「(값 없음)」으로 표시 — **화면 결과 표에만(저장 결과·CSV·양식 채우기·후속 질의 값 불변) · 레지스트리 DB 항목 `label_null_group_keys`(기본 false · ITAM만 true) · 묶음 기준은 실행 SQL의 SELECT 목록으로 판정(집계 함수 아닌 항목) · 단일 DB 집계만** (사용자 확정 2026-10-06 — 적용 범위 *"권장안대로 (가)안 채택"* · 문구 *"권장안대로 (값 없음) 채택"* · `plans/137` §9 W13)

- **결정일**: 2026-10-06 | **상태**: 확정 · 구현 완료 — 폐쇄망 재검증 대기
- **배경**: D-305 반영 뒤 폐쇄망 재검증(사용자 전달)에서 「자산분류별 자산 수」·「부점별 취득금액 상위」 표 가운데에 이름 없는 빈 줄이 끼어 오류처럼 보였다. 정합성 쿼리로 확인한 결과 데이터·정렬은 정상이었다 — 전체 3,843 = 2,386 + 1,419 + 38, 빈 줄은 빈 문자열이 아니라 **NULL**(분류 1,419건 · 부점명 1,616건), 금액은 decimal. 정렬 기준은 건수·금액이라 NULL 묶음도 제 크기 순서에 온다(`NULLS LAST`와 무관 — 집계 값은 NULL이 아니다). 문제는 표시뿐이었다.
- **결정**:
  ① **적용 위치 = 화면 결과 표 렌더 직전**(`output_generator._render_result_table`) — 표시용 사본만 바꾼다. 실행 결과(`query_results`)·정리 행(`organized_data.rows`)은 NULL 그대로라 CSV·Excel/Word 양식 채우기(D-147 공란 규칙)·다음 단계 범위(`prior_rows`)·후속 질의 엔티티·멀티 DB 병합 정렬·요약 수치 점검·전 행 null 강등이 종전과 같다.
  ② **범위 = 레지스트리 `label_null_group_keys: true` DB**(사용자 확정 (가) — ITAM만). 「한글 식별자 허용」과 뜻이 달라 별도 항목으로 둔다. 멀티 DB 병합 표는 끈다(행마다 출처가 다름).
  ③ **묶음 기준 판정 = 실행 SQL**(`group_key_columns`) — 최상위 `SELECT … FROM` 목록에서 집계 함수(COUNT·SUM·AVG·MIN·MAX 등)가 아닌 항목의 결과 이름(별칭 · `t.col 별칭` · 단순 컬럼). `GROUP BY`가 없거나 최상위가 `WITH`이거나 `*`가 있거나 집계 항목이 없으면 적용하지 않는다(보수). 값 형식으로 가르지 않는 이유: 코드값(`'31'`)이 숫자처럼 보인다.
  ④ **행 조건** — 묶음 기준 칸이 NULL이고 같은 행의 집계 값이 있을 때만. 문구는 「(값 없음)」(사용자 확정).
- **근거**: 사용자 결정. 실측 — 폐쇄망 정합성 쿼리 결과(위 배경) · 출력 경로 전수 조사(표 칸 렌더 `partial_result._cell` None→빈칸 · CSV `query.py` DictWriter · 양식 `excel_writer`/`word_writer` · `prior_rows`·`previous_entities`·`result_merger` NULL 처리).
- **구현**: `src/routing/registry.py`(`DBEntry.label_null_group_keys` · `null_group_label_enabled`) · `config/db_registry.yaml`(ITAM `true`) · `src/nodes/output_generator.py`(`NULL_GROUP_LABEL` · `group_key_columns` · `_null_group_key_columns` · `_label_null_group_keys`) · 매뉴얼 U-20 주의 1줄 · 테스트 `tests/test_nodes/test_plan137_hangul_identifier_policy.py`.
- **주의**: ① LLM 요약 입력은 NULL(`null`) 그대로라 요약 문장이 「분류 없음」 등 다른 표현을 쓸 수 있다(수치는 같다). ② 시간 상한 부분 결과 표(`render_partial_text`)·진행 패널 미리보기는 빈칸 그대로다. ③ 별칭 없는 계산식 묶음 기준은 이름을 알 수 없어 표시되지 않는다.
- **대안(기각)**: 실행 결과 값 자체를 바꿈(CSV·양식·후속 질의·병합 정렬 오염) · NULL 묶음을 맨 뒤로(상위 N 순위 왜곡) · 결과에서 제외(합계와 표 불일치) · 전 DB 적용(폴스타 비고려 원칙 — (나) 미채택) · 「한글 식별자 허용」 설정 재사용(뜻이 다름).
- **관련**: D-100 · D-147 · D-251 · D-255 · D-297 · D-305 · `plans/137`
- **부기(2026-10-06 · 게이트 교정)**: 첫 구현(`a8da41b`)은 폐쇄망 재검증에서 라벨이 한 번도 붙지 않았다 — 게이트가 `active_db_id`·`generated_sql`만 읽었는데, 2단·1단 최종 응답은 `result_aggregator._build_output_state`가 허용목록으로 만든 state로 `output_generator`를 불러 두 키가 없다. 게이트를 **`executed_sqls`(`[{db_id, sql}]` — 실제 실행 SQL) 우선**으로 고쳤다(1건이면 그 DB·SQL · 여러 건이면 멀티 DB라 미적용 · 없으면 종전 키 — 그래프 3·4단). 테스트는 `_build_output_state`를 통과한 state로 검증한다. 결정 내용(①~④)은 그대로다. 실수 기록 `docs/18_known_mistakes.md` 2026-10-06.
