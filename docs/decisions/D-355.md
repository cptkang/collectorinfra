## D-355. 제니퍼 K8s 파드 알람의 노드 서버 연결 — 웹 세션 `hostAddress` · 노드 IP 정확 일치 1건 자동 연결(D-348 예외) · 파드 미확정 시 설정 매핑 대체 금지(`plans/196` §5.2 순서 변경 · 파드 한정) (사용자 확정 2026-10-29 · `plans/202` §5 Q1~Q5)

- **결정일**: 2026-10-29 | **상태**: 확정 · 구현(2026-10-29 · `plans/202` W1~W4 · 커밋 없음 · 플래그 기본 off · 폐쇄망 검증 대기) | **번호**: 원 D-352 → **D-355 재부여**(2026-10-30 · origin/main `36ce5f1` 병합 시 — 원격 「조사 결과 표시 3단」이 D-352·`plans/199`를 먼저 푸시해 미푸시인 이쪽을 옮겼다. 계획서도 `plans/199` → `plans/202` · 테스트 `test_plan199_*` → `test_plan202_*`) · 2026-10-29 예약(색인 예약 행) → 같은 날 본문 등재 · 등재 직전 `ls docs/decisions/` 최댓값 D-351
- **배경**: 제니퍼 파드 인스턴스는 `hostName`=파드명 · `ipAddress`=파드 IP(10.139)뿐이라 폴스타 서버(노드 · 10.136으로 등록)와 이름·IP 모두 맞지 않는다. 연결이 없으면 sre_agent가 설정 매핑(b0 → polestar_b0)으로 대체해, 실제 노드가 CM-GP인 B0 제니퍼 알람의 폴스타 단계가 전부 0건이 된다(침묵 오답). 노드 IP 출처 실측(2026-10-29): Open API·환경변수·알람 원문·뷰서버 extension `InstanceData` 모두 없음 · K8s API·에이전트 description 주입 불가 · 폴스타 `tunl0` 블록 매칭은 클러스터 간 파드 대역 중복으로 기각 · **웹 내부 API `GET /agent/upgrade/list?sid=`의 `hostAddress`가 유일**(웹 세션 전용 — 토큰·무인증 모두 `/login` 리다이렉트 · 조회 권한 계정으로 조회 가능).
- **결정**:
  ① **출처 = 웹 세션**: `apm_gateway`가 소스별 **전용 조회 권한 웹 계정**으로 로그인해 **알람이 난 도메인만** `/agent/upgrade/list`를 조회하고 `(source_id, sid)` 단위로 캐시한다(전체 주기 조회 없음 · TTL·재조회 최소 간격). 허용 목록은 Open API 목록과 분리한 코드 상수(로그인 POST · 목록 GET 1종). 응답은 허용 칸(`instId`·`sid`·`hostName`·`ip`·`hostAddress`·`status`·`statusMsg`·`lastLiveTime`)만 남기고 파싱 직후 나머지(`jmx` 자격증명 포함)를 버린다. 자격증명은 게이트웨이에만(D-274 ③ 유지). 결과는 `alarm:raw` `apm.host_address`·`apm.host_address_status`로 싣는다(플래그 off = 키 없음 · 현행 비트 동일).
  ② **Q1 — 자동 연결(D-348 예외)**: 파드(`hostAddress ≠ ip`)의 노드 IP가 폴스타 전 존에서 **서로 다른 서버 정확히 1대**와 일치하면 사람 확인 없이 연결한다(`meta.hints.polestar_link` `basis: node_address`). 근거 문장에 노드 주소와 「알람 시점 · 자동」을 항상 표시한다. 노드 연결은 **저장하지 않는다**(알람마다 판정). 0대·2대 이상·일부 존 확인 못 함은 연결하지 않는다(**일부 존 확인 못 함 + 나머지 존 1대 일치는 부기 2로 연결로 변경**).
  ③ **Q2 — 노드 주소 우선**: 같은 알람에 저장된 확정 연결(D-348)이 있어도 노드 주소 연결을 쓴다. 둘이 다르면 근거에 둘 다 적는다.
  ④ **Q3 — 파드 미확정 시 설정 매핑 대체 금지**: 파드로 판정됐는데 노드를 정하지 못하면 `SRE_PLAYBOOK_POLESTAR_SOURCE_MAP`으로 대체하지 않고 사유(노드 IP 폴스타 미등록 · 여러 서버 일치 · 노드 주소 조회 실패 · 일부 존 확인 못 함)를 밝힌다 — `plans/196` §5.2 「unresolved는 설정 매핑을 이기지 않는다」를 **파드 한정**으로 바꾼다. 파드 여부를 모르면(노드 주소 없음) 종전 순서. 파드는 「서버 선택 대기」 UI를 열지 않는다(사람 선택이 다음 파드에 무효).
  ⑤ **Q4 — VM 제외**: `hostAddress = ip`(VM)에는 적용하지 않는다 — 기존 이름·IP 후보 + 확정 연결(D-348) 그대로.
  ⑥ **Q5 — 운영**: 소스별 전용 조회 권한 계정 발급 완료 · b0 = `https` · cm_prd·cm_stg = `http` — **평문 전송 위험 수용**(사용자 확정). b0는 사설 인증서·CA 미보유라 인증서 검증을 끄는 소스별 설정(`JENNIFER_<ID>_WEB_TLS_VERIFY=false`)을 둔다(같은 등급 위험으로 수용 · 2026-10-29 실측). 사람 계정 공유 금지(중복 로그인 충돌).
  ⑦ **구현 전 검토 반영(2026-10-29 · 사용자 승인)**: 파드 판정은 게이트웨이가 **같은 웹 목록 행의 `ip`·`hostAddress`**로 하여 `apm.pod`로 싣는다(인벤토리 `ipAddress` 비교 금지 · 판정 불가면 키 없음 = 현행 — VM 회귀 방지) · 조회 실패 중에는 기억한 도메인 종류가 `pod`일 때만 `pod` · 알람 경로는 캐시 60초 초과 시 재조회하고 **`stale`은 자동 연결하지 않는다** · 우선순위 노드 linked → 저장 확정 연결 → 파드 미확정 사유 · 노드 연결은 `host_link_enabled`와 **독립**(게이트웨이 키가 있을 때만 작동) · sre_agent 사전 수집 경로도 노드 linked를 쓴다.
- **근거**: 노드 주소는 이름 유사 추정이 아니라 제니퍼가 기록한 실행 노드 사실이고 1건 정확 일치만 쓴다(D-188 정확 일치 자동 승격과 같은 등급). 파드명은 재기동마다 바뀌어 사람 확정이 누적되지 않는다. 틀린 존 0건은 「확인 못 함」보다 나쁘다(D-348 원칙 「다른 서버 이력을 근거로 붙이는 오진이 미표시보다 나쁘다」와 같은 방향).
- **주의**: 비공개 웹 내부 API 의존 — 제니퍼 업그레이드 시 재실측(형태 검증 실패는 `error`로 노출 · 침묵 폴백 금지) · 로그인 실패 연속 3회 → 30분 정지(계정 잠금 방지) · 쿠키·비밀번호는 메모리에만·로그 가림 · 뷰서버 부하(도메인 1건 ≤ 83KB·≤ 0.7s 실측). 크로스소스 사건 키(`plans/144`)에 노드 주소를 쓰는 것은 과묶음 위험(D-349)으로 범위 밖.
