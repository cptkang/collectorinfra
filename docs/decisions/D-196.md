- **결정**:
  1. **퍼널의 근거는 `stage` 필드**(사용자 확정 G-2). `NotificationDecision.stage` 신설 + 결정 지점 16곳에 닫힌 집합 라벨(14종) + `STAGE_ORDER`(순서 정본은 판정 코드와 같은 파일). reason 문자열 역추정도 가능했지만 **사유 문구를 고치면 퍼널이 조용히 깨진다**. 구 레코드는 `stage_from_reason` 폴백으로 흡수하고, 매핑 실패는 `unknown` 단계에 모아 **버리지 않는다**(합계 항등식이 깨지면 퍼널이 거짓말을 한다). 라벨은 관측 전용 — tier·reason·priority·signals는 **비트 동일**.
  2. **퍼널 항등식**: 모든 결정은 정확히 한 단계에서 종결되므로 `Σ stages[].terminated == raw`. `cut`은 그중 **통보되지 않은 것**(SUPPRESS·DASHBOARD)만 센 별도 지표다 — DASHBOARD를 캔슬로 세는 이유는 "통보되지 않았다"가 퍼널의 축이기 때문.
  3. **침묵(Silence)은 도메인이 판정한다**. 워커가 bool을 넘기는 `flapping`·`storm` 패턴을 따르려 했으나 — 규칙의 심각도 상한은 **실효 심각도**(AI 보강 반영 후)와 대조돼야 하고 그 값은 `decide_notification` 안에서만 안다. 워커는 **활성 규칙 목록**만 넘기고(TTL 캐시 10초) 매칭은 `noise_gate/domain/silence.py` 순수 함수가 한다(같은 domain 계층 import). 단계 위치는 **유지보수 다음·의존성 앞** — 시스템이 알려준 사실이 운영자 의도보다 앞선 사유로 남아야 감사가 정확하다.
  4. **침묵 안전 가드는 전부 서버 강제**: 심각도3 불가침(게이트 단락이 앞선다 + 매처 상한 검사) · **전 매처 공백 규칙 금지**(전체 침묵 — API 400 + 도메인 `matches()` False 이중) · 만료 필수(최대 7일) · 글롭 1종만(정규식 금지 — 의도보다 넓게 걸리는 사고 차단) · **기본 off**(`NOISE_GATE_SILENCE_ENABLED=false`면 워커가 규칙을 조회조차 하지 않아 판정 비트 동일). 저장은 append-only JSONL + 해제 tombstone(`FeedbackStore` 전례) — 누가 언제 무엇을 조용히 시켰는지가 규칙보다 오래 남는다.
  5. **관제 스트림의 인가는 따로 판정**한다. EventSource가 헤더를 못 실으므로 쿠키 우선·쿼리 토큰 폴백(`resolve_stream_user` 전례)이되, **사용자 토큰으로는 열 수 없다** — 이 스트림에는 존 RBAC를 우회한 전 존 억제 내역이 흐른다.
  6. **테마는 기존 체계 정합**(사용자 확정 G-4 · D-180). 시안은 다크 고정이었으나 티어 토큰 4종(`--tier-page`·`--tier-ticket`·`--tier-dash`·`--tier-suppress`)을 라이트/다크 양쪽에 정의했다. SUPPRESS만 회색조인 것은 의도다 — 녹색을 주면 운영자가 "안전하다"로 읽는다.
