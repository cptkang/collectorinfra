## D-240. 실 LLM 테스트는 로컬 MLX로 진행한다 — **두 평면 `mlx`(루프백)는 승인 없이 · pytest `RUN_LOCAL_LLM=1`은 외부 차단 가드를 유지 · 과금 외부 API는 건별 승인 유지** (D-127 ①③ 개정 · D-222 후속 · 사용자 지시 2026-09-21)

- **결정일**: 2026-09-21 | **상태**: 확정 (구현 완료) | **번호**: 등재 직전 실측 2026-09-21 — `## D-` 헤더 최댓값 **D-239** · 「변경 이력」 표 최댓값 **D-239** · 「채번 이력」 표 예약에 240 없음(표 최댓값 D-232) → **D-240**
- **배경**: 사용자 지시 *"api 금지 제약은 mlx를 기반으로 테스트를 진행하도록 정의하여 제약을 수정하라."* D-127은 과금 외부 API 호출을 건별 승인으로 묶으면서 `RUN_E2E=1` 설정 자체를 승인 행위로 정의했다. 그 결과 에이전트 작업 지시가 "실 LLM 호출 · `RUN_E2E=1` · 실 재실행 금지"로 굳어, 비과금인 로컬 MLX(D-222)로도 실 LLM 테스트를 돌리지 못했다. pytest 쪽은 구조적으로 막혀 있었다 — `live_llm` 테스트를 켜는 수단이 `RUN_E2E=1` 하나뿐이고, 그것이 전역 외부 접속 가드까지 끈다(`tests/conftest.py`). 두 평면이 `mlx` 여도 Gemini 전용 live 테스트가 있으면 과금이 날 수 있는 구조라, 승인 없이 켤 안전한 수단이 없었다.
- **결정**: ①**실 LLM이 필요한 테스트·스모크·검증의 기본 경로는 로컬 MLX다.** 워커·오케스트레이터 두 평면이 모두 `mlx`(127.0.0.1 루프백 `mlx_lm.server`)로 해석되면 비과금이므로(D-222 ②③) **사용자 승인 없이** 에이전트가 실행한다. 실행 전에 설정 해석 출력(`python -m scripts.bench --show-env` · `--preflight`)으로 두 평면을 확인하고, 하나라도 과금 평면이면 실행하지 않는다 ②**pytest 로컬 LLM 모드 `RUN_LOCAL_LLM=1`** — `live_llm` 테스트를 돌리되 **외부(공인 IP) 접속 차단 가드는 그대로 둔다.** 로컬 LLM은 루프백이라 통과하고, 과금 외부 API는 connect 이전에 차단돼 실패로 드러난다(침묵 과금 불가). 결정은 `tests/conftest.py` `_test_modes()` 한 곳이다 — `RUN_LOCAL_LLM=1` → (가드 on · live 실행), `RUN_E2E=1` → (가드 off · live 실행), 둘 다 없음 → (가드 on · live skip). 값은 `"1"` 만 켠다. 컬럼 커버리지 이중 모드 fixture도 같은 판정(`LIVE_LLM`)을 쓴다 ③**D-127 ①③ 개정** — 건별 승인의 대상은 **과금 외부 API** 호출과 **가드를 끄는 `RUN_E2E=1`** 이다. 로컬 MLX 실행과 `RUN_LOCAL_LLM=1` 은 승인 대상이 아니다. 키 존재 게이팅 금지(D-127 ②)와 비용 감사(④)는 그대로다 ④하네스 진입점은 바꾸지 않았다 — 시나리오 `--run`·벤치 `--mode run` 은 D-216·D-222 판정(`preflight.external_planes`)으로 두 평면이 비과금이면 이미 승인·`RUN_E2E` 없이 돈다
- **근거**: 가드를 유지한 채 live 테스트를 켜는 것이 규칙(사람 판단)이 아니라 **코드 게이트로 안전을 보장**하는 유일한 형태다(D-127 ② "수동 스크립트도 코드 게이트로 강제"와 같은 원칙). `RUN_E2E=1` 을 "mlx 면 승인 없이 써도 된다"로 풀면 가드가 꺼져, `noise_gate/tests/test_agentic_enricher_gemini_live.py` 같은 Gemini 전용 테스트나 설정 오해석이 곧바로 과금이 된다. 새 변수로 분리한 이유: `RUN_E2E` 를 소비하는 곳이 conftest 밖에 10곳 이상이고(`tests/e2e/conftest.py`는 값이 있기만 하면 playwright 를 임포트한다 — 루트 venv 미설치), 값 하나를 덧씌우면 그 게이트들의 의미가 함께 바뀐다. Gemini 전용 live 테스트는 자기 게이트(`RUN_E2E == "1"` + 키)를 가져 로컬 모드에서 건너뛰어진다
- **대안(기각)**: `RUN_E2E=1` 을 두 평면 `mlx` 일 때 승인 없이 허용(가드가 꺼진다 — 과금 방어가 사람의 확인 하나로 준다) · `RUN_E2E=mlx` 값 추가(10여 곳의 `RUN_E2E` 소비처 의미가 바뀌고 `tests/e2e` 가 playwright 임포트로 수집 실패) · conftest 가 `.env` 를 읽어 `mlx` 면 가드 자동 유지(설정 해석 결과에 따라 게이트가 암묵적으로 바뀐다 — 명시 옵트인 원칙 위반) · 제약 문구만 고치기(pytest 는 여전히 안전하게 켤 수단이 없다)
- **구현**: `tests/conftest.py`(`_test_modes` · `GUARD_EXTERNAL`·`LIVE_LLM` · 가드 설치·`live_llm` skip·`column_coverage_llm` 이 이 판정을 쓴다 · 차단·skip 문구에 로컬 모드 안내) · `tests/test_network_guard.py`(`test_test_modes` 5건 — 기본·로컬·외부·둘 다·오타값) · `CLAUDE.md`(개발 명령의 테스트 안내 · Known Mistakes 「과금 외부 API 승인 게이트」 개정)
- **검증**: `RUN_LOCAL_LLM=1 pytest tests/test_network_guard.py` 18 passed(가드가 설치돼 공인 IP·Gemini 호스트명 차단 단언이 통과) · `live_llm` 테스트(`tests/test_pipeline.py::TestHappyPath::test_full_pipeline_end_to_end`)가 기본 모드에서 SKIPPED, 로컬 모드에서 skip 없이 실행 대상(`--setup-plan`)임을 실측. 본 작업의 실 LLM 호출 0회
- **주의**: ①`RUN_E2E=1` 하드 게이트만 아는 스크립트(`scripts/eval_routing.py` 등)에는 로컬 모드가 없다 — 여전히 건별 승인 대상이다(편입은 별건) ②가드는 **pytest 프로세스 안**의 접속만 막는다 — 서버를 자식 프로세스로 띄우는 하네스(시나리오·벤치)는 가드가 아니라 `external_planes` 판정으로 막는다(D-222) ③가드는 사설 대역을 허용한다 — 내부망 프로바이더(FabriX·vLLM)도 로컬 모드에서 통과한다. 둘 다 비과금 집합이다(D-222) ④MLX 결과는 로직 확인용이다 — 성능(지연) 결론은 내부망 결과로만 낸다(`plans/109` 가이드 MLX 절). 공유 MLX 서버(8080)는 동시 사용 시 OOM 위험이 있어 자기가 띄우지 않은 서버는 종료하지 않는다

- **부기(2026-09-21 · 사용자 결정 ⑤ — `eval_routing.py` 로컬 MLX 모드)**: 주의 ①의 「`RUN_E2E=1` 전용 스크립트에는 로컬 모드가 없다」를 `scripts/eval_routing.py` 에 대해 해소했다. 워커·오케스트레이터 **두 평면이 모두 `mlx` 이고 둘 다 루프백**이면 `RUN_E2E` 없이 돈다(`local_mlx_mode` → `_require_optin`). 과금 판정은 D-222 정본 `scripts.scenario.preflight.external_planes` 를 그대로 쓰고, 그 위에 `mlx`·루프백을 **더 좁게** 요구한다 — 내부망 FabriX·vLLM 은 비과금이지만 이 모드의 대상이 아니라 종전대로 `RUN_E2E=1` 이다. 설정을 못 읽거나 한 평면이라도 과금·비루프백이면 열지 않는다. 다른 `RUN_E2E=1` 전용 스크립트는 그대로다. 검증: `tests/test_routing_eval/test_eval_routing_harness.py` `TestLocalMlxGate` 8건(두 평면 mlx 루프백 통과 · `mlx`+`gemini`·`gemini`+`mlx`·`fabrix`+`vllm`·`mlx`+`vllm` 거부 · 원격 MLX 거부 · 게이트 거부/통과). **실 실행 0회**(공유 MLX 8080 사용 중)
