## D-330. 노이즈 게이트 PAGE = 「새 사건의 첫 알림」 — 마지막 관문 PAGE 필요성 재판정(`page_review`) · 수집 실패 sev3만 PAGE · 리마인더 24h · 강등 목적지 TICKET · 분석 로그 비식별 (D-035·D-048 부분 개정 · `plans/162`)

- **결정일**: 2026-10-14 | **상태**: 확정 · 구현 완료(W0~W3 · 2026-10-14 · 커밋 없음 · 플래그 기본 off) · 효력은 내부망에서 `NOISE_PAGE_REVIEW_MODE=enforce`·`NOISE_COLLECTION_FAILED_PAGE_SEV3_ONLY=true`를 켤 때(W4)
- **배경**: 노이즈 관제 24시간 PAGE 약 170건(사용자 보고 2026-10-14 · 목표 10~20). D-318 뒤에도 PAGE가 줄지 않았다. 코드 실측: 심각도3은 step 3에서 모든 억제·묶음 단계보다 먼저 PAGE로 끝나고, 지문 dedup이 4h 고정창이라 미해소 알람이 하루 최대 6회 PAGE되며, dedup 상태가 워커 메모리에만 있어 재기동 때 초기화되고, 신호 수집 실패면 심각도 1 이상이 전부 PAGE다. 사용자 지시: *"권고에 맞게 정리하고 …"*(권고안 그대로 확정).
- **결정**:
  ① **PAGE는 「사람이 지금 새로 움직여야 하는 사건의 첫 알림」이다.** 기존 판정이 PAGE인 건만 마지막 관문 `page_review`(결정적 규칙 · LLM 미사용)를 거친다. 열린 사건의 반복(R1) · 같은 호스트 진행 중 사건(R2) · 다수 호스트 동시 발생의 대표 외(R3)는 TICKET으로 내린다. **D-035·D-048 「심각도3 절대 PAGE」를 「심각도3 새 사건은 억제·강등 없이 PAGE · 같은 사건의 반복·동반 알림은 TICKET으로 묶는다(억제 아님)」로 고친다.**
  ② 보존 규칙(강등보다 우선): 새 사건의 첫 PAGE · 심각도 상승 · 앱 영향 fatal · **미해소 리마인더 24h** · 운영자 지정 항상 PAGE.
  ③ **신호 수집 실패 시 PAGE는 심각도3만**이다. 그 밖은 중요도 보통으로 매트릭스를 탄다(D-048 「실패 시 보수적 PAGE」 개정). 수집 실패율 메타경보를 더한다.
  ④ **강등 목적지는 TICKET**(일배치 요약 + 화면 실시간) · 첫 PAGE에 묶인 알림 수를 표시한다. 억제≠삭제(D-048.4)는 그대로 — 강등 건도 감사 기록이 남는다.
  ⑤ 켜는 순서 off → shadow → enforce(`NOISE_PAGE_REVIEW_MODE` 기본 off = 비트 동일). 내부망 shadow 24h에서 「했을 PAGE」 ≤ 20 · 놓친 사건 0이면 enforce.
  ⑥ **분석 로그(W0 `page_audit`) 비식별** — 허용 목록 방식(정한 필드만 내보냄) · IP·호스트명·서버명·자원명·alarm_id·로그 원문·AI 서술은 버리거나 실행 단위 무작위 키 HMAC 가명(대응표 없음 · D-321 전례) · 출력 전수 누출 검사에 걸리면 아무것도 쓰지 않는다 · 운영 Redis는 읽기 명령만.
- **미결(W0 결과 뒤)**: 만성 알람 강등(R6 · G-2) · LLM·이상탐지만으로 오른 sev3를 단락에서 빼는지(R5 · G-5).
- **대안(기각)**: dedup 창만 늘리기(해소 뒤 진짜 재발까지 버림 — 현행 dedup은 해소 때 지워지지 않는다) · LLM에 PAGE 필요 여부 질의(D-048 결정적 판단 · D-318 사고와 같은 위험) · PAGE 일일 예산 초과분 억제(중요 장애가 순서 때문에 묻힘).
- **구현**(2026-10-14 · `plans/162` W0~W3): W0 `noise_gate/scripts/page_audit.py`·`page_audit_sanitize.py`(⑥ — 허용 목록·값 단위 허용 목록·실행 단위 HMAC 가명·NFKC/Cf 제거 뒤 전수 누출 검사·원자적 쓰기 0600·Redis `xrange`/`xinfo_groups`/`xpending` 래퍼 · R1~R3 what-if는 도메인 `review_page` 호출) · W1 `noise_gate/domain/page_review.py`(`review_page`·`PageRegistry`) + 단계 `page_review`(`STAGE_ORDER` 맨 뒤 · `notification_gate_node`에서 `store.record` 앞) · 설정 `NOISE_PAGE_REVIEW_MODE`(off|shadow|enforce, 기본 off)·`_HOST_WINDOW_MINUTES` 30·`_FANOUT_WINDOW_MINUTES` 10·`_FANOUT_PAGE_MAX` 1·`_REMINDER_HOURS` 24·`_REOPEN_QUIET_MINUTES` 30·`_ALWAYS_PAGE_CSV` · W2 ③ `NOISE_COLLECTION_FAILED_PAGE_SEV3_ONLY`(기본 off)·`NOISE_META_ALERT_COLLECTION_FAILED_RATIO`(기본 0 = 끔 · `meta_alerts` type `collection_failed_ratio`) · W3 관제 KPI(재판정 후 PAGE·shadow 「했을 PAGE」)·퍼널 `page_review` 행·드로어 근거(대표 PAGE 링크·묶인 알림 수)·매뉴얼·`docs/28` §4-C.
