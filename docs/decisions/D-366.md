## D-366. 심층 조사 회복력 — Harmony 파싱 오류 1회 재시도 · 심층 실패 조사 재분석 합류 제외 · 생략 경로 진단

- **결정일**: 2026-11-04
- **상태**: 확정 · 구현 완료(2026-11-04 · `plans/213` W1~W3 · 브랜치 `sre_improvement` · 폐쇄망 검증 대기) · **재부여**: 원 D-363/`plans/211` — 원격 `main`(8608c8ee)이 D-363·`plans/211`을 호스트 이름 매칭에 먼저 사용
- **결정**:
  ① **Harmony 파싱 오류 재시도**: holmes `DefaultLLM.completion` 경계(가장 안쪽)에서 예외 메시지에 Harmony 파싱 실패 표지(`expecting start token`)가 있는 litellm 오류만 **같은 요청 그대로 1회** 재시도한다. temperature 등 요청은 바꾸지 않는다(사용자 결정 — 같은 서버 재요청 정상 반환 실측). 첫 시도 경과가 `LLM_HARMONY_RETRY_SKIP_AFTER_S`(기본 45초)를 넘으면 재시도하지 않는다. 조사 루프·단계 소견·종합 모두 대상. 플래그 `LLM_HARMONY_RETRY_MAX`(기본 1 · 0 = off) — **기본 on 예외**(표지 오류일 때만 동작 · 그 밖 비트 동일 · D-213·D-343 선례) · 만료일 2027-05-04.
  ② **재분석·추가 조사 합류 예외**: 저장된 브리핑의 심층 섹션 상태가 `failed`·`timeout`·`skipped`면 조사 상태가 `done`이어도 합류하지 않고 새 조사를 접수한다(다시 분석 · 추가 조사 양쪽). `incomplete`는 제외. 키가 잘려 판정할 수 없으면 종전대로 합류. 플래그 없음 — D-341 ㉔(G-31)의 「실패는 다시 요청 가능」 의도 복원(부기).
  ③ **생략 경로 진단**: 형식 불일치 판정에 종류(`markup`·`call_syntax`·`bare_json`)를 붙이고, 한계 문구를 종류와 실행된 도구 건수로 3종 중 고른다(도구 1건 이상이면 「파서보다 모델 응답 문제」 — 파서 정상을 단정하지 않음). 플레이북 심층 생략에도 원문 앞 200자 warning을 남기고, 감사에 가산 키 `deep_dive_display`·`deep_dive_malformed`(주 경로는 `answer_malformed_kind`)를 더한다. 기존 키(`deep_dive_status`·`answer_malformed`)의 의미·값과 생략 판정 기준은 바꾸지 않는다.
- **근거**: 폐쇄망 보고(2026-11-03~04) — ⓐ 도구 호출이 전부 `native`인 조사가 「vLLM 파서 확인」 안내로 생략돼 파서 오진·모델 교체 검토로 이어졌고, 심층 경로에는 원문 증거가 없었다(`dispatcher:2040`) ⓑ gpt-oss-120b 교체 후 `Unexpected token … expecting start token 200006`(Harmony `<|start|>`) 400 한 번으로 심층 조사 실패 — holmes 0.36.0 `completion`은 재시도가 없다(실측) ⓒ 심층만 실패한 플레이북 조사는 `done`(`dispatcher:2272`)이라 10분 합류 창(`alarm.py:2720`)에 걸려 「다시 분석」이 돌지 않았다.
- **구현**: ① `sre_agent/sre_agent/infrastructure/harmony_retry_guard.py`(`HARMONY_PARSE_ERROR_MARKER` · `install_harmony_retry_guard` — 사슬 C8 → D-213 → 본 가드 → 원본 · `diagnosis.py`가 D-213보다 먼저 설치) · `settings.py` `llm_harmony_retry_max`(1 · 0이면 미설치)·`llm_harmony_retry_skip_after_s`(45.0 · 첫 시도 시작부터 누적) · `sre_agent/.env.example` ② `src/api/routes/alarm.py` `_deep_dive_retryable`·`_DEEP_DIVE_RETRYABLE` — 키 경로 `briefing["deep_dive"]["status"]`(clip 후보 모두 보존 · 키 빠지면 종전 합류) · 다시 분석·추가 조사 재접수 양쪽(추가 조사는 kind `diagnosis`라 현 런타임 판정은 늘 False) ③ `domain/answer_markup.py` `classify_tool_call_markup`·`malformed_limitation` · 디스패처 심층 생략 warning 「심층 조사 답변에 도구 호출 형식 불일치」·감사 `deep_dive_display`/`deep_dive_malformed`/`answer_malformed_kind`. 문서 `docs/26` §5.6.3 뒤 단락(①)·§5.6.6 결과 표(③) · 매뉴얼 user U-64(②)·admin 형식 불일치(③). 상세 `plans/213` §7·§8.
- **주의**: ① 재시도는 근본 조치가 아니다 — 재실패가 잦으면 엔드포인트 vLLM·openai-harmony 버전 문제로 운영자에게 요청한다(재시도 로그로 판정). 공유 엔드포인트 사용량이 늘 수 있다. 표지 문자열이 vLLM 버전에 따라 바뀌면 재시도가 조용히 멈춘다(실패해도 종전 동작). ② 재분석은 플레이북 수집 전체를 다시 돈다(「심층만 다시」는 범위 밖). ③ 원문 앞부분 로그는 주 경로와 같은 취급(서버 밖 반출 없음 · D-339 가림 경유). ④ (구현 실측) ②의 `skipped`에는 심층 mode off·고정 알려진 오류·트리거 미충족도 들어가 그런 배치에서는 끝난 플레이북 조사의 10분 합류 창이 사실상 사라진다(진행 중 합류·사용자별 상한 유지) — 사유별 세분은 후속 결정 후보. ⑤ ① 재시도 직전 취소(D-347) 확인은 없다(후속 후보).
