## D-228. 수동 프로필 없는 DB의 LLM 유사어 전역 전파 차단 — **질의 경로에서 자동 생성된 유사어는 DB별 캐시에만 둔다** (plans/95 v11 · D-011 부분 개정)

- **결정일**: 2026-09-17 | **상태**: 확정 · 구현 완료 → **2026-09-17 D-227로 가드 소멸**(질의 경로 지연 LLM 생성 자체 삭제 · B-8 ②) · ④는 G-11 (b)로 처분 | **번호**: 등재 직전 재실측 — `## D-` 헤더 최댓값 D-222 · 「변경 이력」 최댓값 D-222 · 「채번 이력」 예약 최댓값 D-227 · `D-228` 선점 0(plans·docs grep) → **D-228**
- **배경**: `plans/95` v10 로컬 활성화 검증에서 수동 프로필이 없는 `itam`에 질의 1건을 보내자 LLM이 만든 컬럼 유사어 9건이 `synonyms:global`에 컬럼명 키로 들어갔다(출처 `llm` · `sWSportEndYmd`→"클라이언트종료일" 같은 오역 포함 · D-214 ⑤ T4 관찰). 전역 사전은 DB에 귀속되지 않아 한 DB의 검증 안 된 LLM 산출물이 다른 DB의 매핑·프롬프트 재료로 번진다. 처리안 A(활성 유지·itam 질의 금지)·B(활성화 되돌림)·C를 사용자에게 올렸고, 사용자 결정 원문 *"C로 진행하라. mlx 서버는 그대로 둬라."* — C = *"수동 구조 정보(수동 프로필)가 없는 DB에 대해, LLM이 만든 유사어가 전역 사전(`synonyms:global`)에 쓰이지 못하게 코드로 막은 뒤 itam을 다시 활성화한다."*
- **결정**:
  ① **쓰기 지점의 결정적 가드** — `SchemaCacheManager.get_schema_or_fetch`의 캐시 미스 자동 생성(`DescriptionGenerator.generate_for_db` → `save_descriptions` → `save_synonyms`) 직후 전역 병합 `sync_global_synonyms(db_id)`를 **`_has_manual_profile(db_id)`가 참일 때만** 부른다. 판정 = `config/db_profiles/{db_id}.yaml`의 `source: manual`(schema_analyzer `_load_manual_profile`과 같은 기준 · 같은 계층 로더 `catalog_builder.load_structure_profile` 재사용 · `source: auto`는 수동 아님). 거짓이면 WARNING 1줄 `LLM 유사어 전역 전파 차단: db_id=<db_id>, columns=<n> (수동 프로필 없음 — DB별 캐시에만 저장)`. 프롬프트·LLM 출력 교정으로 풀지 않는다.
  ② **DB별 캐시는 막지 않는다** — `schema:{db_id}:descriptions`·`:synonyms`는 종전대로 저장돼 그 DB 질의에는 쓰인다.
  ③ **사용자 명시 경로는 불변**(**D-227 부기**: 이 중 `cache_management`의 생성·무효화 6종은 인증 켜짐 시 관리자 전용으로 바뀌었다) — 관리 명령(`src/nodes/cache_management.py` 설명 생성 뒤 `sync_global_synonyms` `:428`·`:473` · 전역 유사어 생성·재사용 `:536`·`:592` · 등록 `:1043`·`:1111`·`:1229`) · 사용자 선택 등록 `src/nodes/synonym_registrar.py:149` · 시드·파일 로더 `src/schema_cache/synonym_loader.py`(`config/global_synonyms.yaml` 자동 로드 `schema_analyzer.py:1206-1220` 포함) · 관리자 API·CLI · 양식 매핑 사용자 피드백 `document/field_mapper.py` `apply_mapping_feedback_to_redis`(`:1952`). 가드를 `sync_global_synonyms` 안에 두지 않은 이유가 이것이다(관리 명령 경로까지 바뀐다).
  ④ **보류(사용자 결정 대기)** → **처분(D-227 · G-11 (b) 사용자 확정)**: 구조 정보(프로필·승인 버전) 없는 DB의 양식 LLM 매핑·유사어 발견은 전역 대신 그 DB의 유사어 캐시에 `llm` 출처로 등록한다(EAV 매핑은 등록 0 + 로그) — 양식 업로드의 LLM 매핑 자동 등록 `document/field_mapper.py` `_register_llm_mappings_to_redis`(호출 `:424` → 전역 쓰기 `:1427`)·`_register_llm_synonym_discoveries_to_redis`(호출 `:1063` → `:1118`·`:1133`)도 자동 LLM 산출물의 전역 쓰기이고 대상 `db_id`가 수동 프로필 없는 DB일 수 있다. 그러나 컬럼 경로가 **전역에만** 쓰므로(`redis_cache`가 없을 때만 DB별 폴백) 막으면 그 DB의 양식 매핑 학습이 통째로 사라진다 — "차단"과 "DB별 등록으로 전환" 중 선택은 C가 정하지 않은 설계 선택이라 구현하지 않았다.
  ⑤ **비트 동일** — 현행 프로필 4종(`polestar_b0`·`polestar_cm_gp`·`polestar_cm_yd`·`polestar`)은 모두 `source: manual`이라 동작 불변. 활성 DB 중 수동 프로필이 없는 DB는 `itam`뿐이다(등록·비활성 `cloud_portal`·`itsm`은 활성화하면 같은 규칙을 받는다). 플래그 없음.
  ⑥ `plans/104`(D-227 — 질의 경로 구조 분석을 관리자 기능으로 이관)가 들어오면 지연 자동 생성 경로 자체가 바뀌므로 이 가드를 재평가한다(코드 주석 명기). **후속(2026-09-17 · plans/104 v3 B-8)**: 승인본이 생기면 조건을 「수동 프로필 또는 승인본」으로 넓히고, 질의 경로 지연 LLM 생성 제거(104 B-6)와 같은 결정 안에서 가드를 없앤다. ④의 양식 매핑 자동 등록 처분은 104 G-11(기본 (a) 차단)로 이관.
