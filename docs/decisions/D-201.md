## D-201. "이번 달" 성능 통계 = cmm_metric_stat_d 당월 1일~어제 집계

- **결정일**: 2026-09-07 | **상태**: 확정 (구현 완료 · 폐쇄망 검증 대기) | **번호**: 원 채번 **D-198** → **2026-09-09 `test_update` 병합 시 D-201 재부여**(「채번 이력」 표 참조)
- **결정**: "이번 달"/"이번달"/"당월" 명시 성능 통계 질의는 `cmm_metric_stat_m`(직전월까지만 집계 — C-06 실측)이 아니라 **`cmm_metric_stat_d`를 당월 1일~어제 범위로 집계**해 답한다(사용자 제안 채택). 3존 프로필의 시간 분기 규칙 교체(방언별 BETWEEN 예시 포함, 종전 "이번 달 명시 시 현재 월 stat_m" 규칙 폐기). **매월 1일은 범위가 비어 0행** — h(시간)로 강하하지 않고 기존 빈 결과/전행 null 안내 폴백을 정답으로 한다(사용자 확정: 하루 미만 집계는 월 통계로서 대표성 없음, stat_h는 보관도 짧음).
- **근거**: stat_d 보관 기간 폐쇄망 실측(2026-09-07) — 롤링 1년(min=오늘-1년, max=어제)이라 당월 1일~어제가 항상 보관 범위 내. 일별 max의 MAX=월중 최대 정확, 일별 avg의 AVG=월중 평균 근사(일 단위 균등 가중).
- **구현**: ①3존 `config/db_profiles/*.yaml` 월 분기 규칙 교체 ②진행월 값이 확정 통계로 읽히지 않도록 결정적 각주 `_append_current_month_partial_note`(output_generator — 조회 기간 끝=당월 + 지표어 + 숫자 값 존재 시 "당월 1일~어제 일간 통계 집계 기준" 명시, 알람 질의 제외) ③**검증기 결정적 안전망**(4차 실측에서 stat_m 당월 생성 재현 → 주의① 승격 즉시 구현): `check_current_month_stat_table`(폴스타 어댑터 validators, D-089 격리) — 기간 해석이 정확히 (당월,당월)인 질의가 `cmm_metric_stat_m`을 참조하면 반려 + stat_d 재생성 힌트. `validator_checks(user_query=…)` 옵션 인자로 주입(미지정 시 종전 목록 그대로 — 하위 호환), 단일(query_validator)·멀티(full validation)·초안 도구(tools/validation) 3 소비처 대칭.
- **주의**: ①(해소 — 구현 ③으로 승격 완료) ②폼필 결정적 조립 경로는 본 결정 범위 밖(기준월 관례=지난달 끝, H-12) — "이번 달 기준으로 채워줘" 요구가 실측되면 별도 확장 ③프로필 프롬프트 바이트 변경이므로 완결 월 질의(C-01·C-02) 회귀 확인 1회 필요 ④멀티 경로 안전망은 `TEXT2SQL_MULTI_FULL_VALIDATION` ON에서만 발동(간이 검증 경로는 어댑터 훅 미소비 — 종전 구조 그대로).
