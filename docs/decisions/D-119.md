### D-119 전제 라벨(nodename) 규약 실측 — Docker Prometheus (2026-08-06 · R-D 부분)

- **결론: 서버측 `{nodename="…"}` 조립의 전제가 픽스처에서 성립함을 실측 확인.** 단 **대상은 Docker 픽스처(9190)이며 운영 Prometheus가 아니다** — 운영 인프라 소유·라벨 표준화 협의(P0-3)와 R-D 최종 확정은 그대로 잔여.
- **실측치(Prometheus 2.53.0)**: ① **nodename 커버리지 1404/1404 = 100%** — `nodename` 없는 시계열 0건. 스크레이프 설정의 `static_configs.labels`로 **수집 시점 주입**하므로 job(node·mock) 무관하게 전 메트릭이 보유 → 고수준 도구가 임의 지표에 `{nodename=…}`을 붙여도 빈 결과가 되지 않는다. ② **보존 15d**, 스크레이프 간격 5s, 타깃 2종 모두 `up`. ③ **인증 없음** — 무인증 쿼리 HTTP 200(운영은 `PROMETHEUS_AUTH_HEADER` 전제이므로 픽스처와 다름). ④ 미존재 hostname(`nodename="no-such-host"`) → `status=success`·빈 배열로 **graceful**(오류 아님).
- **라벨 충돌 실측(주의)**: node_exporter가 `node_uname_info`에 자기 `nodename`(실 uname)을 실어 보내는데, 스크레이프 타깃 라벨과 이름이 겹쳐 **Prometheus가 노출 측 라벨을 `exported_nodename`으로 밀어낸다**(honor_labels 미사용 기본 동작). 결과적으로 **타깃 라벨이 이기므로 D-119 조립은 안전**하다. 다만 `exported_nodename` 값 목록에 **컨테이너 ID `efc0cb8b934d`가 남아 있다** — 2026-07-28 14:49 단일 시점의 `node_uname_info` 잔재(D-126 target-vm 승격 이전 수집분)로 현재 활성 시계열은 0건이나 **15d 보존 창 안이라 조회는 된다**. 소비 측이 `nodename` 대신 `exported_nodename`을 쓰면 서버명이 아닌 컨테이너 ID에 매칭될 수 있다 → **조립·검증은 반드시 `nodename`을 쓴다**(코드는 이미 그러함).
- **운영 편입 시 체크리스트(P0-3에 인계)**: ① 운영 스크레이프가 `nodename`을 폴스타 `server_name`과 동일 값으로 주입하는지(픽스처는 `static_configs.labels`로 정렬) ② exporter 자체 라벨과의 충돌 시 `exported_*` 승격 정책 ③ 보존기간·인증 헤더 ④ 미존재 호스트 graceful 여부.

### D-119 부기 — 운영 Prometheus 라벨 실측 · ③ 앵커 개정 (2026-10-20 · 구현 완료 · 폐쇄망 검증 대기)

- **전제(사용자 확정 2026-10-20)**: ⓐ Prometheus는 **공동존(`polestar_cm_gp`·`polestar_cm_yd`) 전용**이며 그중 **관제를 요청한 서버만** 등록돼 있다 — 폴스타 등록 서버의 부분집합이다. ⓑ **은행존(`polestar_b0`)은 Prometheus를 쓰지 않는다.** ⓒ 폴스타 등록 서버명(공동존은 VMware VM name)으로는 조회할 수 없다 — Prometheus의 `name`은 비교하기 어려운 값이고, VM name에 대응하는 `resources`는 OS 업그레이드 등으로 VM을 교체하면 **이전 VM name으로 남는다**(`up{resources,hostname,node_ip}` 실패 · `up{hostname,node_ip}` 성공 사례 다수).
- **운영 실측(폐쇄망 · `/api/v1/query`)**: ① 타깃 라벨은 `name`·`center`·`company`·`desc`·`endpoint`·`grade`·`ha`·`hostname`(OS 호스트명)·`instance`(`node_ip:port`)·`job`·`namespace`·`node_ip`(OS IP)·`os`·`port`·`project`·`project_kr`·`resources`·`service`·`service_type`·`type="node"` — **`nodename` 라벨 없음** → 현행 `{nodename="…"}` 조립(③)은 운영에서 **전건 빈 결과**(G-6 실현). ② 커버리지 `up{type="node"}` **1229** · `hostname!=""` **1204** · `node_ip!=""` **1204**(98.0%) — 25 시리즈는 `hostname` 공백. ③ `hostname` **유일하지 않음** — 물리 호스트명이 들어간 그룹 8개(2~5건씩) · 동일값 중복 4쌍(2건씩) · 공백 25. ④ 메트릭 이름은 표준 node_exporter(`node_*`) — 도구 `metric` 인자 계약은 그대로 둔다.
- **개정(③)**: 서버측 결정적 조립(LLM 라벨 미취급)은 유지하고 **앵커 라벨만 바꾼다.**
  1. **앵커 = 폴스타 `hostname`·`ipaddress` ↔ Prometheus `hostname`·`node_ip`.** 폴스타 서버명·`resources`·`name`은 앵커로 쓰지 않는다(ⓒ).
  2. **앵커 값 해석은 서버가 한다** — 도구 인자(source·서버 식별자)로 폴스타 자원 행을 조회해 `hostname`·`ipaddress`를 얻는다. LLM이 IP·라벨을 고르지 않는다.
  3. **조립 사다리(AND 고정 금지)**: `{hostname="h",node_ip="ip"}` → 0건이면 `{node_ip="ip"}` → 0건이면 `{hostname="h"}`. **어느 단이든 서로 다른 `instance`가 2개 이상이면 합치지 않고 「모호」 사유로 반환**한다(③ hostname 비유일 대응).
  4. **사유를 명시해 반환한다(침묵 빈 결과 금지)**: 응답에 `matched_by`(성립 단)·`tried`(시도 셀렉터)를 싣는다. 전 단 0건이면 `reason="prometheus_not_monitored"`(관제 미등록 — ⓐ)로 반환해, LLM이 0건을 「정상·0」으로 서술하지 못하게 하고 폴스타 지표(`polestar_metric_trend`)로 대체하도록 안내한다.
  5. **은행존은 호출 전에 차단한다** — source가 `polestar_b0`이면 HTTP 없이 `reason="prometheus_unsupported_zone"`을 반환한다(ⓑ). 적용 존은 하드코딩하지 않고 설정으로 둔다.
  6. **설정 기본값은 현행과 동일하게 둔다** — 앵커 라벨 목록 기본 `["nodename"]`(픽스처 호환). 운영은 `config.toml`에 `hostname`·`node_ip`를 명시한다. 픽스처(`testdata/prometheus`)에도 `hostname`·`node_ip` 타깃 라벨을 추가해 두 규약을 모두 검증한다.
- **범위 밖(수용)**: `hostname`·`node_ip`가 비어 있는 25 시리즈는 앵커로 찾을 수 없다(`instance`만 남음) — 조회 불가로 둔다.
- **잔여 → 해소(같은 날 실측)**: ① `count by (node_ip)(up{type="node"}) > 1` → `{}` 25 한 건(공백 25)뿐 — **비어 있지 않은 `node_ip`는 유일**하므로 사다리 2단(`{node_ip}`)이 주력 대체 단이다. ② 폴스타 `hostname`과 Prometheus `hostname`은 **같은 값**(둘 다 OS 호스트명 · 일부 FQDN도 양쪽이 같다) — **정규화 없이 완전 일치**로 비교한다. ③ 구현 계획서 = **`plans/189`**(설정 키 · 앵커 해석 SQL · 사다리 · 반환 계약 · `metric_source.py` · 조사 지침 · 픽스처 · 문서). 남은 것은 구현뿐이다(189 게이트 전건 확정).
- **구현 계약 확정(2026-10-20 · 사용자 · `plans/189` §6)**: ⓖ1 고수준 PromQL 도구에 **선택 인자 `source`(db_id)를 추가**한다 — MCP 공개 시그니처 변경. 지정하면 그 source에서만 앵커를 해석하고, 생략하면 Prometheus 적용 source 전체에서 찾는다. ⓖ3 앵커 해석 결과는 **캐시하지 않는다** — 호출마다 폴스타를 조회해 VM 교체를 즉시 반영한다. ⓖ2 **A안 확정** — 폴스타 해석 0행이면 Prometheus를 부르지 않고 `reason="polestar_not_found"`(물리 호스트명 아래 VM 1대처럼 「모호」 판정으로 못 거르는 오귀속 차단). 폴스타 **조회 오류**일 때만 `{hostname="x"}` 단독(모호 판정 유지)으로 강등하고 `matched_by="hostname_unverified"`·`anchor=null`·경고를 싣는다 — 0건이면 `anchor_unresolved`. 운영 뒤 감사 로그의 `polestar_not_found` 빈도로 재판정한다.
- **관련**: D-035(결정적 가드) · D-120(실데이터 조사 LLM은 사내 백엔드) · D-271(공동존 김포·여의도 구분) · `docs/27` §3.5·§6·§8 G-6.
