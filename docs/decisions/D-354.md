## D-354. 사용자 담당 업무(`duty_areas`) — 권한이 아니라 중점 · 숨김 없음 · 선택사항 · 서버 저장 · 어휘 정본 `config/duty_areas.yaml` (사용자 지시 2026-10-30 · `plans/201`)

- **결정일**: 2026-10-30 | **상태**: 확정(방향 · Q1~Q6 2026-10-30 확정) · 계획(`plans/201` · 코드 0) | **번호**: 원 D-353 → **D-354 재부여**(2026-10-30 · origin/main `36ce5f1` 병합 시 — 원격 「장애 조사 실행 병렬화」가 D-353·`plans/200`을 먼저 푸시해 미푸시인 이쪽을 옮겼다. 계획서도 `plans/200` → `plans/201`)
- **배경**: 현장 피드백 — 담당자들이 접속해도 "이걸로 장애 판단·조치를 어떻게 해야 할지, 어떻게 활용해야 할지 모르겠다". 사용자 속성은 인가 3축(`allowed_db_ids`·`allowed_sources`·`alarm_zones`)과 자유 텍스트 `department`뿐이고 화면·예시 질문·조사 결과가 담당과 무관하게 같다. 인프라운영 조직은 영역별 팀(OS/서버·WAS/미들웨어·스토리지·백업·네트워크·DB)으로 나뉘고, b0는 영역별 은행 담당자가, cm은 은행·통합MSP 담당자가 섞여 확인해 R&R을 시스템이 정확히 나누기 어렵다.
- **결정**:
  ① **담당 업무는 사용자 속성 `duty_areas: list[str] | None`**이다. `role`(user/admin)에 끼워 넣지 않는다(D-082 「역할 리스트 일반화」 기각 전례 · `alarm_zones`와 같은 별도 리스트). 여러 개 선택 가능.
  ② **권한이 아니다.** 인가 판정(DB·소스·존·조사 인가)에 쓰지 않는다. 데이터·알람·조사를 **숨기지 않고** 순서·강조·기본 문구만 바꾼다(재현율 우선 D-048 정합).
  ③ **선택사항이다.** 미지정(`None`/빈 목록)과 플래그 off는 현행 비트 동일이다 — 미지정 사용자는 이 기능의 이점도 받지 않는다(사용자 확인). 단 조사 결과 영역별 판정표(`plans/201` W4)는 담당과 무관하게 보이는 것을 권고한다(Q4).
  ④ **첫 영역은 3개** — `server_os`(서버/OS) · `was_mw`(WAS/미들웨어) · `db`(DB). 네트워크·스토리지·백업은 데이터가 서버 측 단면뿐이거나 없어 데이터 편입과 함께 연다.
  ⑤ **어휘 정본은 `config/duty_areas.yaml` 하나**다. 프론트는 서버가 내려준 메타만 읽고 사본을 두지 않는다. sre_agent가 쓰는 영역 코드는 계약으로 보고 루트 테스트가 두 YAML을 파일로 대조한다(양방향 import 0 · D-139).
  ⑥ **서버(앱 DB `auth_users.duty_areas`)에 저장한다.** 가입·관리자·본인(Q1) 세 경로로 지정하고 변경은 감사 로그 대상이다. D-178(표시 선호는 localStorage)의 예외가 아니라 다른 축이다 — 담당은 관리자가 지정하고 기기 간에 유지돼야 하는 사용자 속성이고, 「내 담당 먼저」 정렬 토글 같은 표시 선호는 D-178대로 브라우저에 둔다.
  ⑦ **R&R(서버·영역별 책임 주체)은 이 시스템이 정의하지 않는다.** 담당은 "내가 중점적으로 보는 영역"일 뿐 "이 서버를 누가 맡나"가 아니다. 책임 주체 표시·통보 라우팅은 ITAM·폴스타 원천 실측 뒤 별도 계획.
  ⑧ 담당에 따라 바뀌는 문구·판정·인계 문구는 **결정적 조립**이며 새 LLM 호출을 만들지 않는다. 추천·예시 질의는 검증 근거(`verified_by`)가 있는 형태만 싣는다(D-192 · D-341 ⑪).
- **근거**: 권한으로 쓰면 R&R이 섞인 cm에서 누락이 생기고 오지정이 곧 장애 미인지가 된다. 중점(정렬·강조)으로만 쓰면 오지정의 피해가 순서 변화에 그친다. 3개로 시작하면 보여 줄 데이터가 있는 영역만 연다(DB도 DB 서버 자원·앱이 본 SQL로 최소 콘텐츠가 있다).
- **구현**: 미착수 — `plans/201` W1(필드·지정 경로) → W2(예시 질의) → W3(알람 강조) → W4(조사 영역별 판정 `duty_view`) → W5(조치 지원). 플래그 전부 기본 off.
- **주의**: ①인가 모듈이 `duty_areas`를 읽기 시작하면 이 결정 위반이다(W1 grep 단언으로 고정). ②영역 판정 근거가 없으면 「정상」이 아니라 「미확인(사유)」. ③DB 내부 지표는 미수집 — DB 영역 문구·매뉴얼에 명시.
- **대안(기각)**: 담당 = 권한 필터(누락 위험) · R&R 정본 테이블 신설(실제 조직과 어긋남 · 통보 누락) · localStorage 저장(관리자 지정·기기 간 유지 불가) · 6개 영역 일괄 개시(백업·네트워크·스토리지 빈 화면).
