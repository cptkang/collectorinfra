- **★ 실측이 바꾼 것 3건**:
  - **G6가 맨 앞**: 브리핑 소비자 2곳(`src/nodes/fault_diagnosis.py`·`noise_gate/.../alarm_notifier.py`)이 생산자가 만들지 않는 키(`evidence`·`limitation`)를 기다려 **`[한계]`·`[가설]`·`[중요도]`가 사용자에게 도달하지 않았고** list·dict가 Python repr로 알림에 나갔다(실 함수 호출 재현). 기존 테스트(`test_briefing_six_elements_are_rendered`)가 그 잘못된 키를 정답으로 굳히고 있었다. 이 계약을 먼저 닫지 않으면 뒤 모듈의 산출물도 똑같이 탈락한다.
  - **`stat_date`는 varchar**(h=`YYYYMMDDHH`·d=`YYYYMMDD`·m=`YYYYMM`) — 구간 앵커는 timestamp 산술이 아니라 **granularity 포맷 문자열 비교**여야 한다. `cmm_alarm.ctime`만 timestamp다.
  - **holmes `Tool.invoke`는 LLM 객체를 요구**: `ToolInvokeContext(llm: holmes.core.llm.LLM, max_token_count, tool_call_id)` 필수(0.36.0 실측). 결정적 사전수집을 거기에 묶을 수 없어 계획 A′-3(holmes 경유) 대신 **B′(`mcp` 클라이언트 직접 호출)를 선행 채택**했다 — `mcp` 1.25.0은 `sre_agent/.venv`에 이미 있었고(holmesgpt 전이) `pyproject.toml`에 `mcp<2`를 명시했다(D-181 상한).
- **결정**:
  1. **브리핑 키 계약의 정본은 생산자**(`briefing_builder.build_briefing`)다. 소비자는 공용 렌더러 `noise_gate/domain/investigation_briefing.py::render_briefing_lines`(평문 · 순서 고정 · **모르는 키는 말미에 원 키명으로 렌더** — 침묵 누락 재발 방지) 하나를 쓴다. 소재지 근거: `src → noise_gate.domain`은 확립된 전례(`audit_logger`·`process_query`가 `process_rank`를 씀)이고 역방향은 D-139 위반. `sre_agent`는 루트 venv에서 import되지 않으므로 계약은 **양쪽에 같은 리터럴 키 집합을 둔 대칭 테스트**로 고정한다(`tests/test_briefing_contract.py` ↔ `sre_agent/tests/test_briefing_builder.py`).
  2. **사건 좌표계**: `mcp_server` 조회 도구에 `reference_time`(ISO 8601 · DB 벽시계)·`lookback_minutes`·`baseline_periods` 인자, `polestar_incident_alarms`(구간 내 전 알람 · `CTIME ASC`) 신설, `prom_metric_range`에 `end` 앵커. **미지정 시 생성 SQL은 변경 직전 스냅샷과 문자열 동일**(회귀 0의 검증 형태). 구간 경계는 파이썬이 계산해 리터럴로 넣는다(엔진별 interval 산술을 SQL에 두지 않음). 비 ISO 문자열은 SQL 생성 전에 거부.
  3. **위임 계약**: `sre_diagnose(..., reference_time, lookback_minutes)` · 잡 필드 `reference_time`·`lookback_minutes`·`correlation` · push는 `event.alarmTime` → ISO(기본 120분) · pull은 `src/domain/incident_time.py` **결정적 파서**(`now` 주입 · "어제 14시쯤"=anchor+60분 상한·180분 폭 · 시각 없으면 인자 미전송). 형식 오류는 침묵 폴백이 아니라 `rejected`.
  4. **조사 지침 배선**(G5): `_default_diagnose_fn`이 `build_guidance(settings, job)`를 `system_prompt_additions`로 넘긴다 — 순서 ①`REMOTE_VM_SHELL_NOTE` ②사건 구간(앵커 인자 사용 지시) ③결정적 상관 결과(수치 인용 지시) ④`INVESTIGATION_GUIDANCE_EXTRA`(Plan 51 §6 플레이북 편입점). 종전엔 ①조차 주입되지 않았으므로 ①은 회귀가 아니라 결함 수정이다.
  5. **결정적 사전수집 + 상관은 `sre_agent`에 둔다**(§0.4-b 확정 유지): `domain/correlation.py`(순수 함수 · **벤더 중립** — 테스트로 `polestar`·`cmm_` 0건 고정) · `application/evidence_prefetch.py`(도구 인자·행 해석) · `infrastructure/mcp_tool_client.py`(SSE 1세션 배치 · 호출 단위 격리). dispatcher가 조사 **전에** 돌리고(`prefetch_fn` 주입) 실패는 조사를 막지 않는다(`prefetch_failed` 감사). **플래그 `EVIDENCE_CORRELATION_ENABLED` 기본 off** — off·기준시각 없음이면 호출 자체가 없다.
  6. **브리핑 반영**(§7.2·§9.1): `root_cause_hypotheses[{rank, cause, confidence, evidence, reasoning}]` 신설 — 선행 신호(sustained=high·spike=medium) → 그 외 이상 지표 → LLM 인용 원인(검증 시 medium·아니면 low) 순으로 **결정적으로** 매기고 `reasoning`에 **상관 ≠ 인과**를 명시. 타임라인은 `T-15m 메트릭 …` 상대시각 항목이 앞에, LLM 인용 라인이 뒤에. `notes`는 `limitations`로. 상관이 없으면 빈 목록이라 사용자 출력은 종전과 같다.
