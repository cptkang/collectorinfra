## D-329. 제니퍼 소스 운영 확정 — **`b0`·`cm_prd`·`cm_stg` · `legacy` 폐지(은행 소스 `b0`에 병합) · 소스 `terms` 확정값 · 제니퍼 소스 단어는 D-271 DB 존 용어와 별개** (사용자 확정 2026-10-13 「A안」 — 저장소 제니퍼 소스 구성을 폐쇄망 운영 구성으로 일치)

- **결정일**: 2026-10-13 | **상태**: 확정 · 구현(커밋 없음 · `plans/161`)
- **배경**: D-322 구현 때 레지스트리 `solutions[apm].sources`는 잠정값(`bank`·`common`·`legacy` · 주석 「잠정값 — 운영 확정 필요」)이었다. 폐쇄망은 처음부터 `b0`·`cm_prd`·`cm_stg`를 쓰고 게이트웨이 `apm_gateway/.env` `JENNIFER_SOURCES`도 이 id다. 저장소 `config/db_registry.yaml`을 폐쇄망에 반입하면서 운영 값이 덮여 본체 소스 id와 게이트웨이 소스 id가 어긋났다(`docs/18` 2026-10-13 항목). 저장소를 운영 구성에 맞춰 두면 다음 반입·벤치(`plans/152` W8)에서 어긋남이 생기지 않는다.
- **결정**:
  ① **소스 3개** — 레지스트리 `solutions[apm].sources`:
  ```yaml
      - {id: b0, label: 은행 제니퍼, zone: bankjon,
         terms: ["은행존", "은행", "은행 제니퍼", "레거시", "레거시 제니퍼"]}
      - {id: cm_prd, label: 공동존 운영 제니퍼, zone: gongjon,
         terms: ["공동존 운영", "김포", "운영", "DR", "공동존 운영 제니퍼"]}
      - {id: cm_stg, label: 공동존 개발/스테이징 제니퍼, zone: gongjon,
         terms: ["공동존 개발", "개발", "스테이징", "여의도", "공동존 개발/스테이징 제니퍼"]}
  ```
  ② **`legacy` 폐지** — 레거시 제니퍼는 별도 소스가 아니라 은행 소스 `b0`에 병합한다. 「레거시」·「레거시 제니퍼」는 `b0`의 단어다.
  ③ **소스 간 공유 단어 없음** — 「은행」·「은행존」은 이제 `b0` 하나로 정해진다(종전 bank·legacy 공유 → 되묻기). 「공동존」·「공동」 단독은 어느 소스의 단어도 아니다 — 지목 없음으로 D-322 ③ 되묻기를 따른다. 애매 되묻기는 서로 다른 소스 단어가 둘 이상 걸릴 때(예 「김포랑 여의도」)만 생긴다(D-322 구현 부기 ⑦ 문언 그대로).
  ④ **D-271과 별개** — 제니퍼 소스 `terms`는 폴스타 DB 존 용어(D-271: 「운영」= 김포 · 「개발」「스테이징」「DR」= 여의도)와 독립된 사용자 확정값이다. 「DR」을 `cm_prd`에 둔 것은 사용자 값이며 D-271에 맞춰 고치지 않는다. 매칭의 제외어(「운영체제」 등)는 D-322 ②대로 그대로 쓴다.
  ⑤ **운영 정본 반입 규칙** — 이 값은 폐쇄망 값과 같으므로 저장소 레지스트리를 반입해도 소스 블록은 바뀌지 않는다. 그래도 `config/` 정본은 반입 목록에 넣지 않고 블록 diff로 전달한다(`docs/18` 2026-10-13 방지책).
- **근거**: ① 사용자 확정(2026-10-13 「A안」) ② 게이트웨이 `JENNIFER_SOURCES`와 본체 레지스트리 id가 같아야 소스 지목·정합 점검(D-322 ⑥)·E2 벤치 인벤토리가 동작한다 ③ 운영 구성과 다른 잠정값을 저장소에 두면 반입 때마다 덮어쓰기 사고가 재발한다.
- **구현**: `config/db_registry.yaml` sources 블록 · 실 레지스트리에 의존하는 테스트 · `noise_gate/scripts/mock_polestar_events.py` 제니퍼 소스 id · APM 벤치 소스 시나리오(`testdata/apm_bench/scenarios.yaml` APM-SRC-* · `placeholders.e1.yaml`) · 매뉴얼 제니퍼 소스 절(D-255) · `docs/31`·`spec/SPEC-apm-gateway.md`·`spec/SPEC-apm-noise-gate.md`·`plans/152` 현행 서술. 본체 `src/`는 레지스트리 파생이라 코드 변경 0. `apm_gateway/` 자체 테스트 픽스처의 소스 id는 게이트웨이 설정값이라 바꾸지 않는다(D-274).
- **주의**: ① 「은행」만 말한 질문이 종전엔 되묻기였으나 이제 `b0` 단일 조회다 ② 「공동존 WAS」처럼 공동존만 말하면 되묻는다(운영·개발 구분이 필요) ③ **공동존 알람의 제니퍼 조회가 두 소스로 넓어졌다** — 노이즈 게이트 `app_impact`·크로스소스 상관은 알람 DB의 존으로 소스를 고르므로(`SPEC-apm-noise-gate` §4) 공동존 알람은 `polestar_cm_gp`·`polestar_cm_yd` 구분 없이 `source_ids=["cm_prd","cm_stg"]` 둘 다 묻는다(종전 `common` 하나 · 은행존은 `bank`·`legacy` → `b0` 하나로 좁아짐). DB → 소스 정밀 대응이 필요하면 별도 결정 ④ 소스가 더 늘면 레지스트리 한 행 + 게이트웨이 `.env` 추가(D-322 ⑥)이며 이 결정의 단어 목록도 함께 갱신한다. ⑤ **미결(사용자 결정 대기 · 검증 중요-1)**: 제외 꼬리(`_TERM_EXCLUDED_TAILS` — 운영체제·운영 중·운영팀 등)는 단어 「운영」에만 걸려, 복합 단어 「공동존 운영」은 「공동존 운영체제별 WAS 수」·「공동존 운영팀 WAS」에서도 `cm_prd` 단일로 좁힌다(재현 `tests/test_routing/test_plan161_verify_sources.py` xfail strict 3건) ⑥ **미결(검증 중요-2)**: 「은행존이랑 공동존 WAS 비교」는 「공동존」이 소스 단어가 아니라 `b0` 단일 조회 + 고지(종전 되묻기) — 양 존 의도의 반만 조회한다.
