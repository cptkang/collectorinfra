## D-292. 관리자 「DB 구조」 **DDL 스키마 등록** — **O-2 스키마 수집의 대체 입력 · 붙여넣기·`.sql` 업로드 → 분석(미리보기 · 저장 0) → 등록(잡) · 결정적 해석(LLM 0 · DB 접속 0 · SQL 미실행) · 결과는 MCP 수집과 같은 모양(같은 구조 = 같은 스냅샷 해시) · 대상은 「DB 구조」 목록에 보이는 DB만 · 주석은 미리보기에만** (사용자 지시 2026-10-01 *"DB구조 탭의 기능에서 db 스키마를 붙여 넣기 하거나 \*.sql파일을 업로드하면 분석을 누르면 파싱하여 스키마 수집을 가능하도록 기능을 추가하고 싶다."* · 게이트 3건 권고안 확정 · D-227 ⑨ 부기)

- **결정일**: 2026-10-01 | **상태**: **확정 · 구현 완료**(작업 트리 · 커밋 없음) | **번호**: 등재 직전 3곳 grep — `## D-` 헤더 최댓값 D-291 · 「변경 이력」 D-291 · 「채번 이력」 예약 최댓값 D-288(본문 등재 완료) · 안내 라인 「다음 D-292」 · `plans`·`docs`·`spec`·`tasks`·`CLAUDE.md` 선점 0건 → **D-292**
- **배경**: 현행 O-2(D-227 ⑦)는 MCP `get_full_schema` 1회로 스키마 캐시와 변경 점검 기준선(스냅샷)을 함께 만든다 — 설명 초안(O-4)·구조 분석(O-6)은 이 두 저장물을 읽는다. DDL만 있는 경우(MCP 수집 전 사전 등록 · 정의서로 받은 스키마)를 위한 입력이 없었다. D-227 ⑨는 「신규 DB 구조 조사는 사용자에게 묻지 않는다 — MCP로 수집」이다 — 이 결정은 관리자가 고르는 **대체 입력**을 더할 뿐 묻는 흐름을 만들지 않으므로 ⑨를 개정하지 않고 부기한다.
- **게이트 확정값(2026-10-01 · 사용자 응답 — 세 건 모두 권고안)**: G-1 대상 = **「DB 구조」 목록에 보이는 DB만**(MCP 소스 ∪ 레지스트리 ∪ `ACTIVE_DB_IDS` · 새 db_id 생성 없음) · G-2 저장 = **분석은 미리보기만, 「스키마 등록」을 눌러야 저장** · G-3 주석(`COMMENT ON`·MariaDB `COMMENT`) = **스키마만 등록하고 주석은 미리보기에 표시만**(설명 초안으로 만들지 않음).
- **결정**:
  ① **같은 자리·같은 모양** — 등록은 O-2와 같은 저장 함수(`_save_schema_and_snapshot`)로 스키마 캐시 · 기준선 스냅샷 · 등록 상태 `schema`에 쓴다. 해석 결과는 `SchemaInfo`(MCP `get_full_schema`와 같은 모델)이고, 테이블 키·타입 표기를 MCP 서버의 엔진별 조회 결과에 맞춘다 — PG `public`이면 bare·그 밖 `schema.table` · MariaDB 기본 database(레지스트리 `db_schema`)면 bare · DB2 항상 bare · 타입은 `information_schema.data_type`/`SYSCAT.TYPENAME` 표기(길이·정밀도 제외) · 인용 없는 식별자는 PG 소문자·DB2 대문자·MariaDB 그대로 · PK 컬럼 NOT NULL · DB2 인용 식별자 뒤 공백 제거(db2look 8자 채움). **같은 구조면 MCP 수집과 스냅샷 해시가 같아** DDL 기준선 뒤 MCP 변경 점검에 가짜 차이가 없다(세 엔진 테스트로 단언).
  ② **결정적 해석 · SQL 미실행** — 자체 토크나이저(주석·문자열·PG 달러 인용·MariaDB `DELIMITER`·DB2 `--#SET TERMINATOR`)로 문장을 나누고 `CREATE TABLE`(열 목록 있는 것) · `ALTER TABLE … ADD`(PK·FK·컬럼) · `COMMENT ON`만 읽는다. 그 밖의 문장은 종류별 건수만 보이고, 읽지 못한 정의·참조는 경고로 남긴다(조용히 버리지 않음 · 경고 200건 상한). 컬럼 없는 테이블은 경고와 함께 뺀다(캐시 저장이 그 한 개로 전체를 거부하므로). `sqlglot`은 DB2 방언이 없어 쓰지 않았다(신규 의존성 0 · `sqlparse`도 미사용).
  ③ **미리보기와 같은 것만 저장** — 등록 요청은 미리보기의 `snapshot_hash`를 싣고, 서버가 다시 해석해 다르면 잡을 만들지 않고 422. 등록은 관리자 잡(`ddl_import` · 소스별 락 · 202)으로 돌리며 잡 파라미터·감사 기록에 DDL 본문을 싣지 않는다(길이·테이블 수·해시만). 해석 경고가 있으면 등록 상태를 `warning`으로 남긴다.
  ④ **미리보기가 바뀔 것을 보인다** — 현재 기준선 대비 차이(`diff_snapshots`)와 출처(MCP/DDL)를 보이고, 기준선에 있는데 DDL에 없는 테이블(캐시에서 빠지고 설명·유사어가 정리됨)과 소스 엔진과 다른 방언 선택을 맨 위 경고로 낸다. 기준선 기록에 `origin: ddl`을 남기고(MCP 수집 기록은 종전 모양 그대로 · 상세 요약은 표기 없으면 `mcp`) 화면 요약에 출처를 보인다.
  ⑤ **API·화면** — `POST /admin/db-structure/{source}/ddl/preview`(200 · 저장 0) · `POST …/ddl/import`(202 잡) · 본문 상한 500만 자 · 전부 `require_admin_user` + `ADMIN_ACTION` 감사. 화면은 O-2 행 「DDL로 등록」 + 「DDL로 스키마 등록」 섹션(엔진 선택 · `.sql` 불러오기(UTF-8로 깨지면 EUC-KR 재시도 · 5MB) · 입력란 · 분석 · 스키마 등록). 해석은 스레드에서 돌린다(수 MB가 이벤트 루프를 막지 않게).
- **근거**: ① O-2 뒤 단계(O-4·O-6)를 바꾸지 않고 재사용하려면 같은 저장 자리·같은 모양이어야 한다 ② MCP 표기와 어긋나면 이후 MCP 변경 점검이 모든 컬럼을 「타입 변경」으로 보인다 ③ 저장은 기존 캐시·기준선을 덮고 설명·유사어를 정리하므로 미리보기 확인을 강제한다(이 탭의 초안 → 승인 흐름과 같은 결) ④ 사용자 확정(G-1~G-3).

- **주의**: ① 해석은 DDL에 적힌 것만 안다 — 뷰·파티션 자식(`PARTITION OF`)·`LIKE`·`INHERITS` 상속 컬럼·`ALTER COLUMN … SET NOT NULL`은 반영하지 않는다(경고 또는 건수) ② MariaDB `lower_case_table_names`를 반영하지 않는다 — 인용 없는 이름은 적힌 대로다 ③ PG 교차 스키마 FK는 MCP가 돌려주지 않지만 DDL 해석은 관계로 만든다(그 경우만 MCP 점검과 FK 차이가 날 수 있음) ④ DDL 등록 뒤에도 DB에 실제로 묻는 단계(O-1 연결 확인 · 구조 분석 샘플 실행 검증 · 값 인덱스)는 MCP 연결이 필요하다 ⑤ 주석은 저장하지 않는다(G-3) — 설명 초안으로 쓰려면 별도 결정.
- **대안(기각)**: 새 db_id도 DDL로 생성(G-1 ② — 목록·준비도·등록 상태가 MCP·레지스트리 어디에도 없는 DB를 다뤄야 함) · 분석 즉시 저장(G-2 ② — 잘못 붙인 DDL이 바로 캐시를 덮음) · 주석을 설명 초안으로(G-3 ② — 범위 확대) · `sqlglot` 도입(DB2 방언 없음).
