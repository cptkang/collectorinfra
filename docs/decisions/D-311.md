## D-311. ITAM 자산 외부망 생성 — **반출 로그에 P1 근거(「DB 구조」 탭 결과 읽기 · 벤치 DB 조회 0)를 담고 · 코드값은 코드 컬럼만 형식 보존 치환(대응표 없음 · 외부망 테스트 전용) · 외부망 빌더가 근거 있는 자산만 설정 파일에 직접 커밋 · P1 한글 식별자 단서** (사용자 지시 2026-10-07 *"반출한 데이터를 이용하여 외부망에서 만들 수 있는 것들은 모두 만들고 itam bench 에서 생성하는 로그 정보를 이용하여 외부망에서도 자체적으로 생성할 수 있도록 로그에 담는 정보를 수정하라."* · 인터뷰 G-1~G-4 · `plans/140`)

- **결정일**: 2026-10-07 | **상태**: 확정 · 구현(2026-10-07 — W1~W4 · W5 빌더 경로 · 실 산출 2회차 반출 뒤)
- **배경**: 1회차 반출(`20261006-152938`)에는 이름·타입·NULL·조회 대상만 있고 기본키·행 수·관계·의미·코드값·값 형식이 전부 비어 있다(카탈로그 입력 = 파일 스키마 캐시 · 내부망 P1 미실행). 게다가 P1 코드 컬럼 판정은 라틴 이름 접미사만 봐서 내부망 ITAM 한글 컬럼 1,988개 중 0개를 잡는다(한글 단서로는 371개 — `plans/140` §1.3).
- **결정**:
  ① **반출 근거 출처(G-1)** — 내부망 관리자가 「DB 구조」 탭 자산 자동 생성 1단계(P1 · LLM 0)를 먼저 돌리고, 벤치 카탈로그는 `StructureStore`의 스냅샷·DDL 주석·최신 P1 초안·현행 프로필을 읽는다. 벤치의 DB 조회는 계속 0이다(D-301 ③ 불변). P1 근거가 없으면 파일 스키마 캐시로 내려가고 리포트에 경고한다.
  ② **치환 코드값(G-2 · G-4)** — P1이 코드로 판정한 컬럼과 공통코드 테이블만, 사람 정보·서술형·금액·네트워크 등급을 빼고, run마다 새 비밀키(메모리)로 형식 보존 치환한 값을 6번째 반출 파일 `code_samples.yaml`에 싣는다. 같은 원값은 run 안에서 같은 치환값이고, 치환값은 원 코드 집합과 겹치지 않는다. 대응표는 두지 않는다(되돌릴 수 없음). **치환값은 외부망 쿼리 생성 테스트 자료로만 쓰고 내부망으로 가는 설정 파일에 넣지 않는다.**
  ③ **반입 경로(G-3)** — 외부망 빌더(`python -m scripts.itam_bench --build-assets`)가 `config/db_profiles/itam.yaml`(`allowed_tables`·`table_definitions`·근거 있는 `entity_keys`·`relationships`·`query_rules`) · `config/synonym_seeds/itam.yaml`을 직접 쓰고 커밋한다. 근거(P1 값 형식 비율 · 값 겹침 채택 · 주석) 없는 짐작은 쓰지 않는다 — 예외는 테이블 정의 초안(D-308). 코드값·코드 라벨의 정본은 내부망 P1 승인이며, 반입 뒤 P1을 다시 돌려 그것만 골라 승인한다.
  ④ **P1 한글 식별자 단서** — 코드 후보 이름 단서에 한글 접미(`코드·구분·여부·상태·유형·종류·등급·분류·단계`)를 더하고, 기본키 없는 테이블 쌍은 같은 이름의 식별자형 컬럼을 관계 후보로 삼아 값 겹침·부모 유일성으로 채택한다. 라틴 이름·선언 PK가 있는 DB는 비트 동일.
  ⑤ **로컬 샌드박스** — 직접 커밋으로 `config/db_profiles/itam.yaml`이 내부망본이 된다. 로컬 2테이블 승인본은 `testdata/itam/`에 보존하고, 외부망 테스트는 모의 DB(`testdata/itam_closed_sim/` · 3308 · 생성기만 커밋)로 한다.
- **근거**: 사용자 결정(인터뷰 2026-10-07 G-1~G-4). 실측 — 반출 카탈로그 빈 칸(`plans/140` §1.1) · `schema_inference._CODE_NAME_RE` 라틴 전용 · 예산 400 대 후보 ~790 · 내부망 프로필 `query_guide` 643자 = 저장소 로컬 승인본 길이.
