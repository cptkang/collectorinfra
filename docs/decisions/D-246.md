- **결정**:
  1. **3단 대상 선정(F-1)** — 관련도 필터·정렬 뒤, 소유 검증·존 역질문 게이트 앞에서 `parsed_requirements.target_db_hints`를 1·2단·폼필과 **같은 해소 함수**(`resolve_priority_db_ids`)로 고정한다(`semantic_router._pin_turn_location_hints`). 해소 집합에 존 그룹 DB가 있으면 분류 결과의 다른 존 그룹 DB는 뺀다("공동존 김포" → gp). **존 그룹이 없는 DB는 분류 결과를 그대로 둔다** — 1·2단 `_apply_turn_hint_pinning`의 전량 탈락을 복제하지 않는다(plans/95 W-10 방향). 분류에서 재사용한 항목은 **표지까지 그대로**(1·2단과 같다 — 소유 교정이 직접 지정 항목을 건너뛰므로 새 표지는 교정을 끈다), 채운 항목만 `user_specified=True`. 고정 여부로 존 역질문 후단 게이트를 끄고 `db_scope_source="hint"`를 싣는다(`user_specified_db`는 존 선택 고정과 같은 집합 규칙 — 여럿이면 None). **`ZONE_GROUP_EXCLUSIVE=true`에서 해소가 두 존 그룹에 걸치면 고정하지 않는다**(원문 혼합 지목은 라우트 pre-gate가 먼저 끝내므로 여기 오는 것은 제품명 단독 "폴스타"·부분 별칭 힌트뿐 — 결정적으로 펼치면 D-143 후속3 위반 · 개방이면 1·2단과 같다). 힌트 없음·해소 0건이면 반환이 종전과 같다. 조기 반환 경로(`selected_db_ids`·`mapped_db_ids` 등)는 거치지 않는다.
  2. **플래그 없이 적용 — "신규 플래그 기본 off"(plans/80 §5.4-③)의 명시 예외.** 근거: 새 동작이 아니라 1·2단이 이미 무조건 적용하는 규칙(D-065 보강 · D-084 고정)을 3단에 옮긴 **비대칭 결함 수정**이다. off로 두면 기준 경로(D-225)에 결함이 그대로 남는다. 예외 근거는 config 주석 대신 이 항목과 plans/113 §7.1에 둔다(플래그가 없으므로 주석 자리가 없다).
  3. **D-004 경계** — 라우터 안에서 원문을 새로 스캔하지 않는다. 입력 파서가 만든 사용자 명시 힌트(레지스트리 경계 ① "사용자가 명시한 DB 힌트의 결정적 보강")만 읽고 의도 분류에는 쓰지 않는다. LLM 분류는 그대로 돌며 `sub_query_context`를 공급한다.
  4. **순위 질의 전역 재정렬·재LIMIT(S-1)** — 사다리 전 단의 멀티 DB 합류점 `result_merger`에서, 각 DB가 **실제로 실행한 SQL**(`multi_db_executor`가 `db_executed_sqls`로 새로 기록)의 최외곽 `ORDER BY` 첫 키·방향과 `LIMIT n`/`FETCH FIRST n ROWS ONLY`를 `sqlparse`로 결정적으로 읽는다(LLM 판단 없음 — D-035·D-068). 행 있는 DB가 2곳 이상이고 모두 같은 기준(정렬 키는 `_merge_results` 정규형 대조 — DB2 소문자 alias 흡수)이면 NULL은 뒤로·동률은 레지스트리 DB 선언 순으로 재정렬해 N행으로 자른다. 적용 제외(종전 이어 붙이기): 기준 불일치 · 판독 불가 · UNION 등 · OFFSET · 정렬 키가 결과 칼럼에 없음(한정 이름이 다른 식의 별칭과 겹치는 경우 포함) · 키 값이 수치·날짜가 아님(일반 문자열은 DB collation과 파이썬 순서가 달라 전역 순위를 보장 못 함) · **NULL 선두 절단**(NULL을 앞에 두는 정렬 — PG·DB2 `DESC` 기본 · MariaDB `ASC` 기본 · 명시 `NULLS FIRST` — 로 N행에서 잘린 DB에 NULL 키가 있으면 값 있는 상위 행이 병합에 오지 않았을 수 있다) — 사유를 로그와 응답 존별 건수 줄에 남긴다(침묵 강등 금지). 대상 외(노트 없음): 순위 형태가 아닌 조회(ORDER BY·행 상한 없음 · **기본 안전 상한 `QUERY_DEFAULT_LIMIT` 이상**) · 양식 턴 · **DB·존별 순위 요청 표현**(각각 · 각 존/DB · 존별/DB별 · 존·DB마다 · N개씩 — 전역 한 표로 자르면 요청한 존별 목록이 사라진다. 표면어 결정적 가드이며 라우팅 의도 분류가 아니다 · D-202 조립기 가드와 같은 방식 · 오탐은 종전 동작이라 하방 안전).
  5. **원본 보존(G-4)** — `query_results`(CSV 다운로드·row_count·다음 턴 맥락의 원천)는 **바꾸지 않는다**. 재정렬 결과는 요청 스코프 키 `merged_ranking`으로 싣고 `result_organizer`가 응답용 행(`organized_data.rows`)으로 쓴다. 재시도로 단일 경로 행이 들어오면(출처 태그 없음·행 수 불일치) 쓰지 않는다. **같은 턴 선행 결과 전달**(`prior_rows`·`prior_targets`·순차 경과 판정)은 응답에 보인 전체 상위 N을 쓰도록 `_pack_pipeline_result`가 `rows`에 재정렬 행을 싣는다(세 판독처가 `rows`를 1순위로 읽는다). D-005의 병합 정의(`_source_db` 태깅 + 이어 붙이기)는 개정이 아니라 확장이다.
  6. **응답 미리보기 균형(S-2)** — 멀티 DB이고 재정렬이 적용되지 않은 턴은 20행 미리보기를 DB별로 번갈아 뽑는다(DB마다 1행 이상 · DB 안 순서 유지). 출처 태그는 레지스트리 표시명 「출처」 칼럼으로 싣는다. **존별 건수 1줄**(`[존별 결과]`)은 종전 "일부 존 0행"에서 **멀티 DB 정상 조회 턴 전체**로 넓히고 표시명을 레지스트리에서 읽는다(재정렬 시 전체 기준 상위 N의 존별 분포 · 미적용 시 사유). **단일 DB 프롬프트·응답은 바이트 동일**(HEAD 대조 실측). 잔존 방어: 후속 턴 델타(`create_followup_input`)가 `db_result_summary`·`db_executed_sqls`·`merged_ranking`을 비운다(종전엔 단일 DB 후속 턴에 직전 멀티 DB 요약이 남아 알람 헤드라인·절단 각주에도 섞일 수 있었다) · 이번 응답 행에 출처 태그가 없으면 존별 건수 줄을 싣지 않는다(같은 요청 안 단일 경로 재시도).
