## D-360. 폴스타 식별자 0건 재해소(등록명↔호스트명) · 조사 식별자 라벨 · S4 0건 결손 판정

- **결정일**: 2026-11-03
- **상태**: 확정 · 구현 완료(`plans/209` W1~W3 · 2026-11-03) · 폐쇄망 검증 대기
- **결정**:
  ① **mcp_server 폴스타 도구는 0건일 때만 식별자를 1회 재해소한다** — 등록명 전용 도구 6종(`polestar_alarm_history`·`polestar_incident_alarms`·`polestar_metric_trend`·`polestar_resource_status`·`polestar_topology`·`polestar_change_history`)은 받은 값으로 0행이고 `source`가 있으면 `resolve_polestar_anchor`로 찾아 **정확히 1건**일 때만 그 등록명으로 재조회하고 `server_name_note`를 단다. `polestar_os_config`는 대칭(호스트명으로). 행이 있으면 현행과 비트 동일(추가 조회 0).
  ② 모호(2건 이상)·0건·조회 오류·source 없음은 재조회하지 않고 0건 응답에 `hint`와 사유를 단다(D-188 보수 원칙 · 침묵 폴백 금지). 도구 설명에 「server_name = 폴스타 등록명」/「hostname = OS 호스트명」을 명시한다.
  ③ **sre_agent 조사 질문·지침은 등록명·호스트명·폴스타 source를 라벨과 함께 싣는다** — 값 하나만 이름표 없이 싣지 않는다.
  ④ **S0 뒤 스코프 재작성은 이벤트가 준 등록명을 덮지 않는다** — `polestar_link`가 `linked`가 아니어도, 이벤트의 폴스타 서버명이 이벤트 hostname과 다르면 유지한다. 비었거나 같을 때만 제니퍼 호스트명을 쓰고 그 사실을 근거 사유에 남긴다. D-348 소스 순위·확정 연결 우선은 그대로다.
  ⑤ **지표 판정은 3상태다(이상 / 이상 아님 / 판정 불가)** — 점 0개·기준선 부족·분산 0은 「판정 불가」(`is_anomalous: None`)다. S4는 전 지표 판정 불가·결손이면 `missing`, 일부만이면 이상 없는 나머지로 「정상」을 내지 않고 판단 보류(`verdict=None`)로 둔다. 하류 판독(R-E 등)은 판정 불가를 「이상 없음」이 아니라 결손으로 다룬다.
- **근거**: 폐쇄망 보고(2026-11-03) — 등록명 `cocm-ngcpkd05`/호스트명 `worker1` 서버 조사가 「worker1 정보 없음」으로 끝나고, S4가 값 없이 「정상」으로 표시됐다. 원인 실측: 등록명 전용 도구의 완전 일치·0건 무안내, 질문의 무라벨 단일 식별자(`mcp_service.py:185`), 미연결 스코프의 호스트명 덮어쓰기(`playbook_steps.py:1292-1295`), `metric_finding` 초기값 False(`correlation.py:137-150`). 0건일 때만 재해소하면 정상 경로의 지연·결과가 바뀌지 않아 플래그 없이 결함 교정으로 적용한다.
- **구현**: `plans/209` — W1 `mcp_server/mcp_server/polestar_tools.py`(+헬퍼) · W2 `sre_agent/sre_agent/interface/mcp_service.py`·조사 지침·`application/playbook_steps.py` · W3 `sre_agent/sre_agent/domain/correlation.py`·`application/playbook_steps.py`(`usage_trend`)·`domain/playbook_readings.py`·`domain/step_findings.py` 등.
- **주의**: 재해소는 정확 일치(`NAME = x OR HOSTNAME = x`)만 쓴다 — D-348의 유사 후보는 자동 사용하지 않는다. 결함 교정이라 기능 플래그를 두지 않는다(정상 경로 비트 동일 · 0건·판정 불가 경로만 바뀜).

- **부기 1(2026-11-03 · 구현)**: ⑤의 「판정 불가」 범위를 좁혔다 — ① 사건 구간 점 0개 ② z-score를 못 구하고(기준선 부족, 또는 분산 0인데 최대값이 기준선 평균 초과) 절대 임계도 없으며 초과도 없을 때만 `None`. 절대 임계가 있으면 그 임계로 판정한 현행 결과를 유지하고, 분산 0 기준선에서 최대값 ≤ 평균이면 「이상 없음」이다(유휴 서버 disk_io가 판단 보류로 남발되는 것을 막고, 판정 가능한 경우 현행 유지 원칙을 지킴). 판정 가능 경로의 finding 키는 종전과 같다(`judgeable`·`reason`은 판정 불가일 때만). ④는 폴스타 source가 있는 런에서 S0가 제니퍼 호스트명을 쓰면 `polestar_basis` 끝에 「제니퍼 호스트명으로 조회(host)」를 남긴다(payload source 경로에도 basis 키가 생김 — 의도).
