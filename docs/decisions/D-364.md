## D-364. 노이즈 게이트의 APM 게이트웨이 주소를 채팅과 통합 — `NOISE_APM_MCP_URL` 폐지 · 주소는 `MCP_SOURCE_ENDPOINTS["apm"]` 하나 · 토큰은 `NOISE_APM_MCP_TOKEN` 유지

- **결정일**: 2026-11-04 | **상태**: 확정 · 구현(작업 트리 · 본 결정과 같은 작업)
- **배경**: 사용자가 관리자 「APM·SMS 연계」 탭에서 스캔했더니 APM 인벤토리가 `gateway_unreachable`로 나왔다. 채팅은 같은 게이트웨이를 정상으로 쓰고 있었다. 실측: 본체 안에서 게이트웨이 주소가 두 키로 나뉘어 있다 — 채팅·질의는 `MCP_SOURCE_ENDPOINTS["apm"]`(D-283 ①), 노이즈 게이트(app_impact 승격 · APM·SMS 연계 스캔 · ITAM 생성 요청 · 재분석 `apm_ref` 역조회)는 `NOISE_APM_MCP_URL`(plans/87 J4). D-287 ①은 소비자 셋(채팅 · 노이즈 게이트 · sre_agent)이 각자 주소를 갖는 구조를 그대로 두었다. 사용자 지시 *"이미 apm은 연동되어 있는데 연계 스캔 정보를 따로 설정하면 이중관리가 되어야 한다. 통합하는 것을 고려해라."*
- **결정**: 사용자 선택 — 통합 방식 「NOISE_APM_MCP_URL 폐지」 · 토큰 「주소만 통합」.
  ① **주소 단일화** — 본체의 게이트웨이 주소는 `MCP_SOURCE_ENDPOINTS["apm"]` 하나다. 노이즈 게이트의 네 소비처와 `noise_gate/scripts/probe_apm_host_map.py`가 모두 이 값을 읽는다(`noise_gate/infrastructure/apm_gateway_client.py` `apm_gateway_url`·`build_apm_gateway_client(app_config)`).
  ② **`NOISE_APM_MCP_URL` 폐지** — `NoiseGateConfig.apm_mcp_url` 필드·설정 카탈로그 항목·도움말을 지웠다. 값이 남아 있어도 읽지 않는다. 옛 키만 둔 환경이 조용히 꺼지지 않도록, 본체 기동 때 `.env`나 환경변수에 이 키가 있으면 경고를 남긴다(`src/api/server.py` `_warn_retired_apm_url` · 값은 로그에 싣지 않고 `MCP_SOURCE_ENDPOINTS`의 apm이 설정됐는지만 적는다).
  ③ **토큰은 분리 유지** — 노이즈 게이트는 `NOISE_APM_MCP_TOKEN`을 쓴다. 채팅 토큰(`MCP_SOURCE_TOKENS["apm"]`)으로 대신 채우지 않는다. 게이트웨이가 토큰으로 호출 주체를 가르기 때문이다(D-300 ② · D-302 ④).
  ④ **컴포넌트 관리 주소 파생**(D-345 부기)도 `MCP_SOURCE_ENDPOINTS["apm"]`만 본다. `NOISE_APM_MCP_URL` 폴백은 없앴다.
  ⑤ **범위 밖** — sre_agent의 `APM_MCP_URL`. 별도 프로세스이고 `.env`도 따로라(D-139) 이번에 바꾸지 않는다.
- **근거**: 같은 게이트웨이 하나에 주소 키가 둘이면, 한쪽만 고쳤을 때 기능 하나가 조용히 끊긴다(이번 `gateway_unreachable` 사례). 폴백(빈 값이면 대신 쓰기) 대신 폐지를 고른 것은 사용자 선택이다 — 주소가 하나뿐이어서 어느 값이 쓰이는지 헷갈리지 않는다. 토큰을 나눠 두면 게이트웨이 감사·작업 접근이 채팅(`chat` 주체)과 섞이지 않는다.
- **구현**: `src/config/alarm.py`(필드 삭제) · `noise_gate/infrastructure/apm_gateway_client.py` · `noise_gate/application/{worker_wiring,apm_host_map_scan,apm_host_map_lookup}.py` · `noise_gate/scripts/probe_apm_host_map.py` · `src/infrastructure/component_admin_client.py` · `src/api/server.py` · `src/api/settings_catalog.py` · `config/settings_help/{infrastructure,noise_gate_investigation,component_admin}.yaml` · `.env.example` · `spec/SPEC-apm-noise-gate.md` · `docs/31_jennifer_integration_guide.md` · 관리자 매뉴얼(A-90 설정 표 · 노이즈 게이트 절). 테스트 `tests/test_api/test_d364_apm_gateway_url_unified.py` 외 기존 4개 파일 갱신(설정 카탈로그 항목 수 485 → 484).
- **주의**: 폐쇄망 `.env`에 `NOISE_APM_MCP_URL`만 있고 `MCP_SOURCE_ENDPOINTS`의 apm이 비어 있으면, 배포 뒤 app_impact 승격·연계 스캔이 꺼진다. 기동 경고(「NOISE_APM_MCP_URL은 폐지됐다 … (현재 비어 있음 …)」)를 보고 값을 `MCP_SOURCE_ENDPOINTS`로 옮긴다. 이렇게 옮기면 채팅 WAS 질의도 함께 켜진다(D-283 ① — 코드가 있으면 그 시스템이 활성). 스캐너 사유는 주소가 없으면 `gateway_not_configured`, 연결·인증 실패면 `gateway_unreachable`이다.
