- **결정**:
  ① **대상** — 사용자 화면(`index.html`·`noise.html`·`login.html`·`register.html`) 또는 관리자 화면(`admin/*`)에서 사람이 직접 쓰는 기능을 **새로 만들거나, 기존 기능의 사용법·화면이 달라지는 변경**. 화면 버튼 없이 채팅·API로 쓰는 사용자 기능(manifest `no_ui`)도 포함한다. **제외**: 사용자 접점이 없는 변경(내부 리팩터·성능·벤치·평가 하네스·운영 스크립트·로그).
  ② **같은 작업 단위에서 할 일** — ⓐ `scripts/manual/features.yaml`에 항목 추가(또는 기존 항목 `anchors` 갱신) ⓑ `scripts/manual/content/{user,admin}.md`에 해당 절 5칸(무엇·어떻게·화면·주의·관련) 작성·갱신 — 사용자 절은 사례(`cases`) 또는 `case_na` 사유 ⓒ 화면이 바뀌었으면 `captures.yaml` 갱신 후 `python -m scripts.manual.run_capture --only <캡처ID>`로 재캡처(LLM 0) ⓓ `python -m scripts.manual.build`로 `src/static/manual/*.html` 재생성 ⓔ `pytest tests/test_manual` 통과.
  ③ **완료 보고에 매뉴얼 반영 여부를 적는다.** 반영하지 못한 부분(재캡처 불가 등)은 사유와 잔여로 남긴다 — 조용히 빠뜨리지 않는다.
  ④ **강제 장치는 기존 가드를 쓴다** — `test_reverse_every_button_and_tab_is_documented`가 화면의 `<button id>`·탭 값 중 manifest 미등재를 실패시킨다. 이 가드가 잡지 못하는 것(링크·메뉴 항목·`<button>` 아닌 컨트롤·채팅 명령·API)은 ②를 작업자가 스스로 챙긴다. 가드 대상 확장은 이번 결정에 넣지 않는다.
  ⑤ **재캡처 절차 제약** — 캡처 서버 포트(18981·18982) 점유를 먼저 확인하고, 끝나면 자기가 띄운 PID만 종료한다. 매뉴얼 파일을 다른 세션이 편집 중이면 먼저 통지한다.
