- **결정**:
  ① **toolset 활성 정본 = 넘긴 프로파일 + holmes 내장 기본값** — `DiagnosisAgent.llm`을 `prerequisite_cache=DISABLED`·`enable_all_toolsets_possible=False`로 만든다(홈 캐시 읽기·쓰기 0 · 호스트 CLI 자동 활성 0). 비용: 기본 toolset 선행검사는 config 파싱뿐 — 생성 0.17s 대 0.17s(LLM 0 실측) · MCP는 캐시 모드에서도 매번 검사. 테스트만 캐시를 끄고 운영 경로는 켠 채였던 비대칭을 없앤다.
  ② **LLM 왕복 검증 전용 `no_host_access_profile()`** + 붙은 도구를 **허용목록 `NO_HOST_ACCESS_TOOLS`(`TodoWrite`·`fetch_skill`)로 LLM 호출 전 대조**(스모크 2단계). 차단목록이 아닌 이유: holmes 상향으로 새 기본 toolset이 생겨도 조용히 붙지 않게.
  ③ **토큰 예산 필드 `override_max_content_size`·`override_max_output_token`**(env 이름 = holmes와 동일 · `gt=0` · 기본 None = holmes 동작 비트 동일) — 설정 시 에이전트 인스턴스에 적용(컨텍스트 = `DefaultLLM.max_context_size` · 출력 = 인스턴스 `get_maximum_output_token` 대체 → 요청 `max_tokens`와 압축 예약분이 같은 값) · holmes 프로세스 env보다 우선. 둘은 함께 준다(vLLM은 입력+출력 ≤ `--max-model-len`).
  ④ **e2e 조사 LLM 선택 = `API_BASE` 유무** — 있으면 운영 배선(`MODEL`·`API_BASE`·`API_KEY`·토큰 예산) + 스텁 게이트는 테스트 안에서 더미 통과, 없으면 종전 Gemini 조립(비트 동일). D-127 게이트(파일 전역 `RUN_E2E=1`) 불변. MVP 대장 지문에 실제 모델(`llm.model`) 기록.
  ⑤ **브리핑 인용 판정은 도구 출력 0건이면 거짓**(`_is_cited` 한 곳) — 미완주 안내 *"수집된 근거가 불충분…"*이 마커 `근거`에 걸려 도구 출력 0건인데 원인·타임라인에 가설 표기 없이 실리던 결함(docstring "도구 출력 전무 → 가설" 계약과 일치시킴). e2e 상관 픽스처 `alarmTime`을 계약 형식 `yyyyMMddHHmmss`로 교정(종전 형식은 `reference_time` None → 사전수집 생략 → 구조적 통과 불가) · dispatcher에도 tmp 감사 경로 전달(공용 `sre_agent/.data` 오염 방지).
