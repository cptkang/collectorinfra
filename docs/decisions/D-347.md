## D-347. 알람 조사는 수동 전용(선별 실행)이 기본 · 조사 부하 상한(조사 서비스 대기열·버려진 조사 계상 · 조회 대상 동시 상한 · 본체 증분 조회)

- **결정일**: 2026-10-26 | **상태**: 확정 · 구현 완료(`plans/194` W0~W6 · 커밋 없음 · 내부망 확인 남음 — S7·DB2 timeout·본체 RSS) | **번호**: 등재 직전 `ls docs/decisions/` 최댓값 D-346 확인
- **배경**: 사용자 제기(2026-10-26) *"장애진단이 자동으로 진행되어 서버에 행이 걸리는 이슈가 있다. 선별적으로 진행해야 한다."* 사용자 확정: ① 수동 전용(자동 조사 없음 · 새벽 알람은 통보만) ② 조사 시작 = 알람 존 권한 사용자(현행 「이 알람 분석」 인가·사용자별 상한) · 설정 = 관리자 ③ 행 지점 = 본체 포털·조사 서비스·조회 대상 셋 다. 코드 실측(`plans/194` §1): 자동 조사가 PAGE마다 조사를 띄워 알람 폭주를 조사 폭주로 증폭 · sre_agent는 대기열 상한이 없고 타임아웃된 조사 스레드를 멈추지 못해(슬롯은 반환) 실제 동시 수가 상한을 넘음 · 조사 1건이 조회 대상에 최대 16건 동시 호출(프로세스 전역 상한 없음) · mcp_server 풀 대기·DB2 쿼리에 timeout 없음 · 본체는 조사·판정 저장소를 매 호출 전체 파싱(이벤트 루프 위)하고 허브가 변화 없이도 스트림을 깨움.
- **결정**:
  ① **수동 전용이 기본** — 자동 조사(`NOISE_INVESTIGATION_TRIGGER_ENABLED` · 사건 종합 조사 포함)는 끈다(코드 기본 false 유지 · 운영 `.env` 명시값을 false로). 사용자 요청 조사 `NOISE_INVESTIGATION_MANUAL_ENABLED` 코드 기본 **true**. 「조사 가능」 신호(capabilities `investigation_enabled`)는 자동 또는 수동 중 하나면 참 — 수동 전용에서도 알람 카드·관제·장애 진단의 [조사 시작] 동선이 산다. D-341 ⑦(현행 PAGE 자동 트리거 그대로)을 개정한다 — 자동 트리거는 옵트인으로 남는다.
  ② **조사 서비스 상한** — 대기열 상한(`INVESTIGATION_MAX_QUEUED` 기본 4 · 넘치면 `rejected: queue_full`) · 타임아웃으로 버린 조사 스레드는 실제로 끝날 때까지 동시 슬롯·같은 호스트 키를 붙든다(유예 `INVESTIGATION_ABANDON_GRACE_SECONDS` 120 뒤 강제 반환·감사) · 협조적 중단 · 프로세스 전역 도구 동시 상한(`SRE_TOOL_GLOBAL_CONCURRENCY` 8 · 축별) · 접수 즉시 거부는 접수 응답에 싣는다 · 대기 순번 상시 노출 · 시간당 전역 조사 예산(`INVESTIGATION_HOURLY_BUDGET`) 코드 기본 **20**(사용자 확정 2026-10-26 · 종전 None). 소견·종합 LLM 요청의 timeout 전달은 보류(holmes 0.36에 인자 없음 · `plans/194` R1).
  ③ **조회 대상 보호** — mcp_server 소스별 동시 상한·대기 timeout(기본 = 풀 크기·query_timeout — 정상 부하 무대기) · DB2 쿼리 timeout · apm_gateway 소스별 in-flight 상한(8).
  ④ **본체 조회 비용** — 저장소 tail은 경로 단위 증분(추가 바이트만) · 허브는 변화 있을 때만 스트림을 깨운다.
  ⑤ **넘친 요청은 사유를 보인다** — 접수 응답 `reason_text`(한국어) · 화면 표시(W5). 사용자별 상한(D-335 ⑥ · 진행 1 · 시간당 3)은 유지하되 **실제 접수만 센다** — 조사 서비스 혼잡 거부(대기열 가득 `queue_full` · 서비스 과부하 `service_overloaded` · 같은 서버 진행 중 `host_investigation_in_flight`)를 비롯한 거부 기록은 시간당 건수에 넣지 않는다(사용자 결정 2026-10-26 · D-335 ⑥ 해석 — 「잠시 뒤 다시 요청」 안내를 따르다 조사 0건으로 1시간 막히는 것을 막는다).
  ⑥ **PAGE 통보 안내** — 수동 전용(자동 off ∧ 수동 on)일 때 **PAGE 통보에만** 「자동 조사 꺼짐 — 웹 알람 카드에서 [조사 시작]」 한 줄(웹 주소 설정이 있으면 링크). 그 밖의 통보는 비트 동일(사용자 결정 2026-10-26).
- **근거**: 사용자 확정(①②) · `plans/194` §1 코드 실측(B1~B6 · S1~S7 · T1~T5) · 로컬 재현(§1.4). 신규 상한의 기본값은 D-162 「기본 off = 비트 동일」의 명시 예외 — 현행이 무기한 대기·무제한 누적의 결함이고, 상한 값은 정상 부하에서 동작이 같도록 잡았다(`plans/194` §5). `.env`는 미추적이라 사용자 확정 설정은 코드 기본으로 둔다.
- **구현**: `plans/194` §3 W1~W6(대상 파일은 계획서 머리 「회귀 대상 파일」 · 결과 §8.1·§8.1.1).
- **주의**: ① 운영 `.env`에 `NOISE_INVESTIGATION_TRIGGER_ENABLED=true`가 있으면 코드 기본을 덮는다 — 반드시 false로 고친다(`plans/194` §8) ② 수동 전용에서 PAGE 통보에는 브리핑이 붙지 않는다 — 안내 한 줄(⑥)로 대신한다 ③ 조사 서비스 무응답의 실체(S7 — GIL·소켓)는 내부망 스택 덤프로 확정할 것 ④ 진행 중 목록에 본인 접수 조사가 보이는 것은 `plans/192` W3이 맡는다(완료 · 미커밋) — 남이 먼저 접수한 조사에 합류한 사용자는 목록에 안 나오며(범위 확대 안 함), 합류 응답 화면의 [장애 진단에서 보기]로 연다. ⑤ 증분 tail 캐시는 파싱한 레코드를 프로세스에 상주시킨다(판정 저장소 20000줄 — 로컬 41MB) — 내부망에서 본체 RSS를 확인한다(`plans/194` R12).
