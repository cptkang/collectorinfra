## D-259. 플래핑 판정에 표본 하한(상태 5개)을 둔다 — 재발생 한 번은 플래핑이 아니다 (사용자 지시 2026-09-27 · `plans/116` §11.8.3 ⑫ · D-048.4 정합)

- **결정일**: 2026-09-27 | **상태**: 확정·구현
- **결함**: `flap_percent`가 관측한 전이의 가중합으로 나눠, 상태가 적으면 발생 → 해소 → 재발생 한 번(전이 1~2회)만으로 100%가 됐다. `NOISE_FLAPPING_ENABLED`를 켠 설치에서 정상 재발생 알람이 SUPPRESS됐다. 기존 테스트(`test_alternation_triggers_flapping`)가 이 동작을 정답으로 굳혀 두었다.
- **결정**: 도메인 상수 `MIN_STATES = 5` — `update_flap_state(samples=…)`는 상태가 하한 미만이면 이전 상태와 무관하게 플래핑이 아니다. 워커는 `samples=len(states)`를 넘긴다. 값 5는 Nagios 원식(분모 = 창 전체 20전이)에서 기본 시작 임계 20%에 닿는 최소 전이 4회에서 나왔고, 이 모듈의 식으로 창이 가득 찬 경우(최신 전이 3회 17.7%, 4회 23.4%)도 같다. 설정 키는 두지 않는다(`MAX_STATES`와 같은 도메인 상수 관례 · `plans/109` 설정 축소 방향). 비율 식·임계·근거 기록 필드는 그대로다. 억제를 줄이는 방향이라 재현율 우선(D-048.4)과 정합하고, 플래핑 기본 off라 기본 동작은 그대로다.
- **대안(보류)**: Nagios식 패딩(분모를 창 전체로 고정) — 임계를 올렸을 때의 과대 판정까지 해소하지만 `flap_percent` 값의 의미가 바뀐다.
- **검증**: `noise_gate/tests/test_flapping_gate.py`·`test_flapping.py` — 재현 테스트(수정 전 실패) · 근거·경계 테스트 4건 · 버그를 굳힌 기존 단언 교정.
