## D-179. 설정 UI 경계 — **`.env` 커버리지는 이미 100%, 남은 것은 경계 표시**

- **결정일**: 2026-08-28 | **상태**: 확정 (구현 완료 · `plans/83` 트랙 C · `SPEC-settings-ui-coverage.md`) | **번호**: **D-179**
- **배경(실측 정정)**: *".env 옵션이 관리자 페이지에서 모두 UI로 정의되는가"* 를 `field_index()` 직접 실행으로 확인한 결과 **카탈로그 290필드 · `.env` 139키·`.env.example` 186키 모두 미포함 0건**이었다. D-129(인트로스펙션 SSOT)가 의도대로 동작 중이며, 파일에 없는 config 전용 필드까지 UI에 나온다(290 > 186). **"빠진 옵션"은 없었다.**
- **결정**:
  - **남은 갭은 표시 품질과 경계 표시뿐이다.** ①`SECTION_BY_KEY` 미분류 8키(`NOISE_ANOMALY_METRIC_SOURCE_MAP_CSV`·`NOISE_ANNOTATION_LLM_*`·`NOISE_INVESTIGATION_FOLLOWUP_*`)에 **인접 키와 같은 구획명**을 부여한다(새 구획을 만들지 않는다). ②별도 프로세스 설정(`mcp_server/.env`·`config.toml`·`sre_agent/.env`·`.encenv`)은 설정 탭 하단에 **"이 화면 범위 밖"** 으로 명시한다.
  - **별도 패키지 설정을 본체 UI에서 쓰지 않는다.** 쓰기를 허용하면 본체가 다른 프로세스의 파일 시스템·재기동을 전제하게 되어 D-139(패키지 경계) 를 침식한다. *어디서 관리하는지*를 밝히는 것이 옳은 해법이다.
  - **누락 감지를 테스트로 상시화한다** — `field_index()`의 모든 `NOISE_` 키가 구획을 갖는지 단언하는 테스트가 그물이 된다. 실제로 이 결정과 함께 추가된 `NOISE_SSE_SUPPRESSED_ENABLED`·`NOISE_FEEDBACK_STORE_MAX_LINES`가 이 테스트에 걸려 등재됐다(그물이 작동함을 구현 중 확인).
- **실측 정정(계획 판단 철회)**: 계획서가 지적한 "시크릿 편집 불가 안내가 약하다"는 **틀렸다** — `admin.js:470`이 이미 `🔒 .encenv 관리` 배지와 "`.env` 수정은 반영되지 않습니다" 툴팁을 상시 노출하고 있었다. **추가 작업 없이 충족**으로 종결한다.
- **주의**: `tests/test_api/test_settings_catalog.py`의 **필드·그룹 카운트 단언 2건은 HEAD 시점부터 이미 실패**하고 있었다(클린 worktree 실측: 251/19 기대 vs 262/24 실제). 다른 작업이 config 그룹을 늘리며 카운트를 갱신하지 않은 선재 실패이며, 이 결정은 그 값을 건드리지 않는다(공유 카운터를 자기 델타로 덮어쓰지 않는다).
- **검증**: 섹션 누락 0건 · `.env`/`.env.example` 커버리지 0건 누락을 테스트로 고정 · 신규 실패 0.
- **관련**: D-129(카탈로그 SSOT) · D-135(즉시 반영 확대) · D-139(패키지 경계) · Plan 68.
