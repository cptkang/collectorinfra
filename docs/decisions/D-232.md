## D-232. 사용자별 DB 조회 인가를 질의 경로가 강제한다 — **`AUTH_DEFAULT_ALLOWED_DB_IDS` 실제 적용 · `[]`=조회 불가 통일 · 관리자 전체 허용 · 권한 편집 UI** (plans/104 C-4 · D-026 ②의 미구현 전제 해소)

- **결정일**: 2026-09-21 | **상태**: 확정(사용자 결정 "(a) 범위 확장") · 구현 완료 | **번호**: 2026-09-17 예약(「채번 이력」). 등재 직전 재실측 — `## D-` 헤더 최댓값 D-234 · D-232 선점 0(plans·docs grep) → 예약 번호 사용
- **배경**: `plans/104` C-4 착수 실측에서 **설정 하나를 켜는 문제가 아니었다**. ①`allowed_db_ids`를 읽는 곳은 스코프 칩·범위 선택(`routes/scope.py`·`query.py`)·`host_sweep`·`process_query`·`entity_locator`·`general_inference` 카탈로그뿐이고 **메인 질의 경로(semantic_router → schema_analyzer·multi_db_executor·query_executor)에는 필터가 0건**이었다 — D-026 주의의 *"`allowed_db_ids`는 Plan 41 접근제어 전제"*가 그대로 미구현이었다 ②`[]`의 의미가 갈렸다 — `general_inference.py:99`의 `if allowed:`는 빈 목록을 **전체 허용**으로, 나머지 소비처는 **전체 차단**으로 읽었다 ③관리자 역할 예외 규칙이 없고 **관리자 화면에 DB 권한 편집 UI가 없어**(`PUT /admin/users/{id}/permissions` API만 존재) 권한을 회수만 하고 부여할 수 없었다. 설정만 적용하면 "칩·탐색은 좁아지는데 채팅 질의는 전 DB에 닿는" **부분 차단 + 거짓 안전감**이 된다.
- **결정**:
  ① **세 값의 의미를 한 곳에서 못 박는다**(`src/routing/db_authz.py`) — `None`=전체 허용(기존 사용자·개발 모드 익명·seed admin) · `[]`=**조회 가능 DB 없음** · 목록=활성 DB와의 교집합. `general_inference`의 `if allowed:`를 `if allowed is not None:`으로 교정해 규약을 통일한다.
  ② **강제는 라우터 노드 경계 한 곳**에서 — `graph.py`가 `semantic_router`를 `authorized_router`로 감싸 **모든 반환 경로**에 같은 필터를 건다(본체는 반환 지점이 여러 곳이라 안에서 거르면 빠뜨린다 · 본체 파일은 수정하지 않는다). 단일 DB(`active_db_id`)·멀티 DB(`target_databases`)가 이 결과에서 파생되므로 하위 경로가 자동 대칭이다.
  ③ **인가된 대상이 0이면 사유를 남기고 종결**한다 — `routing_intent="access_denied"` + `final_response`(관리자에게 권한 요청 안내) → `route_after_semantic_router`가 END. 빈 대상으로 파이프라인을 계속 보내 "데이터 없음"처럼 보이게 하지 않는다(침묵 강등 금지).
  ④ **DB를 고르지 않는 의도는 통과** — 캐시 관리·유사어 등록·일반 추론·장애 진단·존 역질문은 필터를 타지 않는다(각자의 인가는 그 경로가 판정 — 채팅 캐시 관리는 D-227 S2).
  ⑤ **관리자 역할은 목록과 무관하게 전체** — 알림 존 RBAC에서 관리자를 전 존으로 보는 D-082와 같은 기준. 권한을 부여·회수하는 주체가 스스로 잠기지 않게 한다.
  ⑥ **신규 가입자의 초기 허용 목록 = `AUTH_DEFAULT_ALLOWED_DB_IDS`**(쉼표 구분 · 빈 값이면 `[]` = 없음). **기존 사용자 레코드는 바꾸지 않는다**(`None` 유지). seed admin(D-069 부트스트랩)·break-glass 운영자 토큰은 `None`이라 영향 없다.
  ⑦ **관리자 화면에 DB 권한 편집 UI** — 「사용자 관리」 표에 「조회 가능 DB」 열(전체 / 없음(관리자 지정 필요) / 목록)과 편집기(활성 DB 체크박스 + 「전체 허용」). 후보 목록은 화면이 이미 받는 `/api/v1/health`의 `db_status_map`을 쓴다(추가 API 없음). 보호 계정(D-083)도 DB 권한은 편집 가능하다 — D-083이 보호하는 것은 역할·상태·삭제다.
  ⑧ 설정은 더 이상 미소비 키가 아니다 — `settings_catalog.UNCONSUMED_KEYS`에서 빼고(20→19) 도움말(`config/settings_help/auth.yaml`)과 준비도 C10 문구를 실제 동작으로 정정한다.
  ⑨ **요청 본문의 DB 선택(`selected_db_ids`)은 요청 경계에서 거른다**(2026-09-21 보강 — 사용자 지시 *"지금 막는다"*) — ②의 래퍼는 **라우터가 고른 대상**만 거른다. 요청이 직접 지정한 선택은 라우터를 우회해(`semantic_router` 우선순위 2.5) 상태에 실리고, 순차 러너의 task 고정(`subagents.run_data_query_pipeline`의 `raw_targets = task.db_ids or zone_selection_db_ids or selected_db_ids`)이 그 DB로 조회를 확정한다 — **3단 기준 경로도 이 부품을 쓴다**(`docs/21` §7). UI 체크박스는 활성 DB만 보여 주지만 API 직접 호출은 임의 db_id를 실을 수 있다(UI 게이트 ≠ 인가). 차단 지점은 `src/api/routes/query.py`의 **네 진입 전부**(`/query`·`/query/stream`·`/query/file`·`/query/file/stream`)이며 상태 조립(`_build_turn_input_state`·`create_initial_state`)보다 **앞**이다. 규칙은 ①과 같다(`None`=전체 허용 · 관리자 전체 · 목록=교집합). 일부만 비인가면 그 db_id만 떨어뜨리고 나머지로 진행하며, **전부 비인가면 조회하지 않고 사유를 응답한다**(`SELECTION_DENIED_MESSAGE` — 침묵 강등 금지). 폼필 답변 턴의 존 복원(`pending_form_fill.db_ids`)도 같은 필터를 지난다 — 체크포인트는 이전 턴의 산물이고 `thread_id`는 요청이 정하므로 권한 회수·타인 스레드 지정으로 비인가 DB가 되살아날 수 있다(전부 걸러지면 선택 없음으로 되돌리고 사유 통보는 ③이 맡는다).
- **근거**: 사용자 확정 *"(a) 범위 확장"*. 대안 (b)(설정만 적용)는 위 ①때문에 거짓 안전감을 만들고, (c)(보류)는 도움말과 코드의 불일치를 남긴다. Known Mistakes *"UI 게이트 ≠ 인가"* · *"침묵적 폴백 금지"*.
- **대안(기각)**: 라우터 본체 안에서 각 반환 경로마다 필터(누락 위험 · 병행 편집 충돌) · 관리자 예외 없이 일괄 적용(권한 부여 주체가 잠긴다) · `[]`를 전체 허용으로 통일(설정의 안전 실패 의미가 사라진다).
- **구현**: 신규 `src/routing/db_authz.py`(`parse_allowed_db_ids`·`authorized_db_ids`·`is_db_access_denied`·`filter_router_result`·`authorized_router`·**`filter_selected_db_ids`**) · `src/graph.py`(래퍼 배선 · `access_denied`→END) · `src/api/routes/query.py`(**`apply_selection_authorization` — 네 진입 경계 + 폼필 존 복원**) · `src/api/routes/user_auth.py`(가입 기본값) · `src/nodes/general_inference.py`(`[]` 의미 교정) · `src/api/settings_catalog.py` · `src/domain/db_readiness.py`(C10) · `config/settings_help/auth.yaml` · `src/static/admin/dashboard.html`·`src/static/js/admin.js`(권한 편집 UI) · 테스트 `tests/test_api/test_plan104_db_authz.py` **51건**(선택 인가 17건 포함 — 순차 러너 task 고정까지 실제로 태우는 3건) · `tests/test_api/test_plan104_admin_permissions_ui.py` 20건.
- **상호작용(존 선택 보존 경로·task 고정)**: 인가 축이 들어오면 **활성 DB만 보고 대상을 되살리는 경로**가 구멍이 된다 — `semantic_router._keep_zoneless_targets`(존 미배정 DB 보존 · plans/102 W-10)는 후보를 `active_db_ids` 기준으로만 고르고, task 격리 입력(`subagents._make_isolated_input`의 `allowed_db_ids`·`zone_selection_db_ids`)도 같은 성격이다. ②의 **노드 경계 필터가 보존 경로를 함께 덮는다**(보존 대상도 라우터 반환값에 실려 나온다 — 회귀 테스트로 고정). **task 고정은 3단에서도 도달한다**(순차 러너가 2단 부품을 재사용 — `docs/21` §7). 그 경로의 입력이 되는 요청 선택값은 ⑨가 요청 경계에서 막으므로 3단은 닫혔다. 남은 잔여는 **1·2단이 각자 활성 DB 목록을 따로 읽는 부분**이며, 그 두 단을 쓰려면 같은 교집합(`[]`=전체 차단 · 관리자 전체 허용)을 격리 입력·계획 수립에도 걸어야 한다(`plans/104` §11.5 U-6).
- **주의**: ①1·2단(`deep_agent`·`intent_orchestration`)은 각자 활성 DB 목록을 따로 읽는다 — 이 결정은 **기준 경로 3단**에 건다(D-225). 그 두 단을 쓰려면 같은 헬퍼를 같은 방식으로 걸어야 한다 ②`AUTH_ENABLED=false` 개발 모드의 익명 사용자는 `allowed_db_ids=None`이라 종전과 같다 ③기존 계정에 소급 적용하려면 관리자 화면에서 개별 지정해야 한다(자동 마이그레이션 없음) ④활성 DB에서 빠진 db_id가 사용자 목록에 남아 있으면 화면이 함께 보여 저장 시 조용히 사라지지 않게 한다
