## D-345. 분리 컴포넌트 설정 — 각 컴포넌트가 자기 설정 관리 API(`/admin/config`)를 소유하고 본체 관리자 UI는 그 API를 프록시한다 (D-179 개정)

- **결정일**: 2026-10-21 | **상태**: 확정 · 구현 진행(`plans/191`) | **번호**: 2026-10-19 예약 행 → 본문 등재(등재 직전 `ls docs/decisions/` 최댓값 D-343 확인)
- **배경**: D-179는 "별도 패키지 설정을 본체 UI에서 쓰지 않는다"로 정했다 — 본체가 다른 프로세스의 파일 시스템·재기동을 전제하면 D-139를 침식하기 때문이다. 2026-10-19 사용자 인터뷰(`plans/191` §0)에서 분리 컴포넌트 5종(`sre_agent`·`apm_gateway`·`mcp_server`·`noise_gate/alarm_server`·`fabrix_proxy`)의 설정도 관리자 화면에서 보고 저장하기로 했다(U-1·U-2·U-3). D-179의 우려(파일 시스템·재기동 전제)는 **본체가 파일을 직접 쓰는 방식**에 해당하고, 컴포넌트가 자기 파일을 스스로 쓰는 API를 소유하면 생기지 않는다.
- **결정**:
  ① **소유**: 각 컴포넌트가 자기 HTTP 앱에 관리 라우트 3종(`GET /admin/config/schema` · `PUT /admin/config` · `GET /admin/config/status`)을 단다. 본체는 HTTP JSON 계약으로만 프록시한다 — import 0(D-139 유지) · 다른 호스트 배치 지원. 계약 정본은 `spec/SPEC-component-config-admin.md`.
  ② **기본 off**: 컴포넌트 관리 토큰이 없으면 라우트를 등록하지 않는다(현행 비트 동일). 본체는 `COMPONENT_ADMIN_ENDPOINTS` 미입력이면 컴포넌트 선택 UI를 그리지 않는다.
  ③ **반영**: 저장 + 재기동 대기 표시만(U-3). 리로드·재기동 버튼은 범위 밖(D-135 확장 아님).
  ④ **게이트 확정(사용자 위임 2026-10-21 — 권고안 채택, W0 실측 보정 포함)**:
   - G-1 관리 토큰은 MCP·서비스 Bearer와 분리한다. 같은 값이면 라우트를 등록하지 않는다.
   - G-2 `sre_agent` CWD가 패키지 루트가 아니면(루트 CWD = 본체 `.env`/`.encenv`를 읽음) 쓰기를 전체 거부하고 사유를 보인다(읽기는 허용).
   - G-3 `mcp_server/config.toml`은 읽기 전용 표시. `.env` env 오버라이드 키만 쓴다. `[[sources]]` 접속 문자열은 노출하지 않는다. **보정**: 데이터 경계 가드 키(`EXPOSE_EXECUTE_SQL`·`POLESTAR_DOMAIN_GUARD`·`EXPOSE_RAW_PROMQL`)와 바인딩 키(`SERVER_HOST`)도 웹 쓰기를 막는다 — 웹으로 경계를 넓히지 않는다(D-003 취지). 같은 이유로 각 컴포넌트의 바인딩 호스트 키는 읽기 전용이다.
   - G-4 `alarm_server`는 CWD `alarm_server.env`가 없으면 쓰기를 거부하고 「전용 파일 생성」을 안내한다. **보정(실측)**: `env_file=["alarm_server.env", ".env"]`는 pydantic-settings에서 **뒤 파일(`.env`)이 이긴다** — 코드 주석의 「전용 파일 우선」과 반대다. 그래서 CWD `.env`에 있는 키는 `override_dotenv`로 쓰기에서 뺀다. 우선순위 자체는 바꾸지 않는다(행동 변경 — 별건).
   - G-5 `apm_gateway` `JENNIFER_SOURCES`(소스 추가·삭제)는 파일 편집 유지. 기존 소스의 비시크릿 키 수정만 웹으로 한다.
   - G-6 `fabrix_proxy`(PoC · `plans/148`)는 포함한다. 운영 미배치면 본체 `COMPONENT_ADMIN_ENDPOINTS`에 넣지 않으면 된다.
   - G-7 관리 라우트는 서비스와 같은 호스트·포트(`alarm_server`만 옵트인 관리 리스너 `ALARM_SERVER_ADMIN_PORT` · 기본 `127.0.0.1`). 원격 배치는 관리 토큰 + 네트워크 ACL을 운영 안내에 적는다.
  ⑤ **OS env 우선 판정**: `apm_gateway`·`mcp_server`의 자체 `.env` 로더는 기존 `os.environ`을 덮지 않고, 기동 후 `os.environ`에는 파일 값도 섞인다. 그래서 로더가 **주입한 키 집합을 기동 시 기록**하고, 주입되지 않은 키를 OS 원천(`override_os`)으로 본다.
  ⑥ **공용 로직은 바이트 동일 사본**(D-339 ② 전례): `config_admin.py`(stdlib + starlette만) — 정본 `sre_agent/sre_agent/interface/config_admin.py`, 사본 4개, 일치는 루트 테스트가 바이트로 단언한다. 컴포넌트마다 다른 것은 어댑터로 주입한다.
- **근거**: 컴포넌트만이 자기 설정 로더·우선순위·쓰기 대상 파일을 정확히 안다(실측: 로더 5종이 모두 다르다 — CWD 기준 pydantic 2 · 패키지 루트 pydantic 1 · 자체 `load_dotenv` 2). 본체가 파일 경로를 추정해 쓰면 "쓰는 파일 ≠ 읽는 파일"이 된다.
- **비용·주의**: 컴포넌트마다 관리 토큰 1개·감사 JSONL 1개가 는다. 시크릿 웹 편집은 계속 막는다(D-129 ②). 정책·플레이북 YAML 편집은 범위 밖이다.
- **관련**: D-179(개정 대상) · D-139 · D-129 · D-135 · D-125 · D-274 · D-339 · D-003 · D-255 · `plans/191`
- **부기(2026-10-21 · W7 검증·감사 반영)**: ① 웹 쓰기에서 막는 「보안 경계 키」를 G-3 가드 3종에서 **전 컴포넌트의 바인딩 호스트·자격증명이 따라가는 URL·보안 가드·파일 경로·프롬프트 주입 경로**로 넓혔다 — URL만 바꿔도 저장된 시크릿이 다른 호스트로 가고(감사 M-2), 경로 키는 임의 파일 읽기·쓰기로 이어진다(M-3). ② 값 sanitize에 `$`·백틱(변수 확장으로 시크릿 노출 — M-1)과 유니코드 제어·줄 구분자(줄 주입 — H-1)를 더했다. ③ `sre_agent`는 litellm import가 `.env`를 `os.environ`에 싣기 때문에 OS 원천 판정을 패키지 import 시점 스냅샷으로 한다. 계약 정본 `spec/SPEC-component-config-admin.md` 갱신.

- **부기(2026-10-21 · 사용자 지시 「3.번은 해결하라」 — alarm_server 설정 파일 우선순위 교정 · 행동 변경)**: G-4 보정에서 별건으로 남긴 순서를 바로잡았다. `AlarmServerConfig.env_file`을 `["alarm_server.env", ".env"]` → **`[".env", "alarm_server.env"]`**로 바꿔(pydantic-settings는 뒤 파일 우선 — 재실측) **전용 파일이 공용 `.env`를 이긴다**. 전용 파일에 없는 키는 `.env`로 보충된다. 우선순위는 `OS env > alarm_server.env > .env > 기본값`이며, 이는 `docs/23` 「`alarm_server.env` = 전용 오버라이드」와 종전 코드 주석의 의도에 맞춘 것이다. 어댑터는 `.env` 키를 더 이상 `override_dotenv`로 막지 않고(`sources[]` `role: "fallback"` · priority 1 < write_target 2), dry-run도 실 로더와 같은 `[.env, 후보]` 순서로 읽는다. **운영 영향**: 두 파일에 같은 `ALARM_SERVER_*` 키를 다른 값으로 둔 배치는 재기동 뒤 전용 파일 값으로 바뀐다 — 배포 전 두 파일의 겹치는 키를 확인한다. 테스트: `noise_gate/tests/test_alarm_server_config_admin.py` `test_dedicated_file_beats_dotenv_in_loader` · `test_dotenv_key_is_writable_and_dedicated_file_wins`(종전 `test_dotenv_key_is_override_dotenv` 대체).

- **부기(2026-10-22 · 사용자 지시 「이미 .env에 있는 정보를 왜 또 등록하냐 — 수정하라」)**: 본체 `COMPONENT_ADMIN_ENDPOINTS`에서 `sre_agent`·`apm_gateway`·`mcp_server` 주소를 다시 적지 않게 했다. `COMPONENT_ADMIN_TOKENS`에 토큰이 있고 명시 주소가 없는 컴포넌트는 기존 서비스 URL의 `scheme://host:port`를 쓴다 — `sre_agent` ← `NOISE_INVESTIGATION_SERVICE_URL` · `apm_gateway` ← `MCP_SOURCE_ENDPOINTS["apm"]`(없으면 `NOISE_APM_MCP_URL`) · `mcp_server` ← `DBHUB_SERVER_URL`(관리 라우트가 서비스와 같은 호스트·포트 — G-7). 명시 주소가 이긴다. `alarm_server`(관리 전용 리스너)·`fabrix_proxy`(본체가 아는 주소 없음)는 여전히 명시한다. **기능 on 판정이 `endpoints` 비어 있음 → 토큰 비어 있음으로 바뀌었다**(토큰 없으면 현행 화면 동일 유지). 관리 토큰은 G-1대로 서비스 Bearer와 분리 유지. 구현 `src/infrastructure/component_admin_client.py` `derive_endpoints`·`resolve_endpoints` · 테스트 `tests/test_api/test_admin_components.py`.
