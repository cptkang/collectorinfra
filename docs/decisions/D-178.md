## D-178. 알람 UI 표시 레벨 — **권한은 서버, 표시 선호는 브라우저**

- **결정일**: 2026-08-28 | **상태**: 확정 (구현 완료 · `plans/83` 트랙 B · `SPEC-alarm-view-level.md`) | **번호**: **D-178**
- **배경**: 알람 수신에 대해 사용자가 고를 수 있는 것은 **on/off 토글 하나**뿐이었다(`app.js:2647`). 서버 필터는 존 RBAC만 있고 티어 필터가 없어, 당직자도 관제도 같은 양을 받았다. 또한 SUPPRESS는 SSE로 발행되지 않아 **오억제 점검이 감사 파일 tail로만** 가능했다(`docs/28` §6.3).
- **결정**:
  - **티어 기준 4단계**(긴급만 `page` / 통보 대상 `ticket` / **전체 `dashboard`(기본)** / 억제 포함 `suppress`). **심각도가 아니라 티어**여야 한다 — 심각도로 거르면 "심각도 1인데 승격돼 PAGE가 된 알람"을 놓쳐 재현율 우선 원칙(D-048)과 어긋난다.
  - **저장은 localStorage**(사용자 확정 G-1). `alarm_receive_enabled` 전례를 따르며 DB 스키마·JWT 클레임을 건드리지 않는다.
  - **★ 그 귀결로 두 축을 분리한다 — 권한은 서버, 선호는 클라이언트.** 서버가 레벨을 모르므로 page/ticket/dashboard 표시는 브라우저가 판단하되, **존과 SUPPRESS 수신은 서버가 판정**한다(`event_visible_to`). 클라이언트 필터는 *이미 받은 것을 안 그릴* 뿐이라, SUPPRESS를 무조건 흘리면 억제 알람 전문이 비관리자 브라우저에 도달한 뒤 가려질 뿐이고 개발자 도구로 그대로 보인다. **이것은 G-1의 예외가 아니라 그 보완이다.**
  - **`tier` 미상 이벤트는 항상 통과**시킨다 — analyze 테스트 경로 payload에는 `tier`가 없어 막으면 테스트 카드가 사라진다(재현율 우선과도 정합).
  - **기본값은 `dashboard`**(사용자 확정 G-2) — 현행과 같은 표시 집합이라 회귀 0이다. 기본을 조용하게 하는 선택(`ticket`)은 기존 사용자에게 알람이 줄어드는 동작 변경으로 체감된다.
  - **SUPPRESS 발행은 옵트인**(`NOISE_SSE_SUPPRESSED_ENABLED=false` 기본). 기본 off면 현행과 비트 동일이며, 켜면 억제율이 높은 환경에서 **가장 큰 트래픽원**이 되므로 점검 기간 한정 사용을 권한다.
  - **비관리자가 `suppress`를 고르면 조용히 강등**한다(G-4). 400 거부는 UX 마찰만 늘린다 — 애초에 선택지를 노출하지 않고, 서버도 보내지 않는다(이중 방어).
- **구현**: `noise_gate/application/nodes/alarm_notifier.py`(`_route_non_page_tier(suppress_sse=)`) · `src/api/routes/alarm.py`(`event_visible_to` 순수 함수 분리 — 로직 미러가 아니라 스트림이 실제로 호출하는 함수를 테스트한다) · `src/static/index.html`·`app.js`(`isTierVisible`·셀렉트) · `src/config.py`·`.env`·`.env.example`.
- **주의**: ①레벨은 브라우저마다 다르다(G-1의 알려진 한계 — 기기 간 동기화 없음). ②`suppress` 선택지는 관리자 **AND** 발행 플래그 on일 때만 노출된다(빈 선택지 방지). ③SSE는 연결 시점 사용자 정보로 권한을 판정하므로 권한 변경은 재연결 후 반영된다.
- **검증**: 스트림 가시성 9건(존 × SUPPRESS × 티어 미상) · SUPPRESS 발행 3건(**기본 off = 발행 0** 고정) · `arch_check --ci` exit 0 · 신규 실패 0.
- **관련**: D-048(4-티어) · D-049(카드 렌더) · Plan 59 §17(존 RBAC) · D-177(capabilities 계약 제공자).
