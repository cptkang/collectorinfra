## D-349. 제니퍼 알람 크로스호스트 상관 — 같은 도메인끼리만 묶고, 대표 외는 SUPPRESS가 아니라 DASHBOARD 상한 (옵트인)

- **결정일**: 2026-10-27 | **상태**: 확정 · 구현(`plans/197` W3 · 플래그 `NOISE_APM_CORRELATION_DOMAIN_SCOPE_ENABLED` 기본 off · 커밋 없음) · **Q2 (a) 권고 적용 · 사용자 확인 전** | **번호**: 등재 직전 `ls docs/decisions/` 최댓값 D-348 확인
- **배경**: 내부망 로그(2026-10-27 17:49)에서 제니퍼 심각도 2 알람 3건이 step 7.5 「크로스-호스트 상관 — 클러스터 대표 외 억제」로 SUPPRESS됐다. 상관 스코프가 `event.db_id`(= `jennifer_<소스>`)뿐이고, `SERVICE_EXCEPTION`처럼 흔한 유형은 `apmdomain` 토큰 하나가 달라도 Jaccard 4/6≈0.67 ≥ 임계 0.5라 **서로 다른 업무 앱 장애가 한 군집**이 된다. `plans/144` §4.4의 의도는 「같은 도메인의 여러 인스턴스」였고, D-317은 크로스소스 강등을 「SUPPRESS 없음 · DASHBOARD 상한」으로 정했다.
- **결정**:
  ① 플래그 on이면 제니퍼 이벤트(`is_apm_source`)의 상관 스코프를 `db_id|domain`(`raw.apm.domain_id`를 `correlation_extra`와 같은 원자 토큰으로 정규화)으로 나눈다. 도메인이 없으면 현행 `db_id` 스코프. 제니퍼 정책 경로(`NOISE_APM_NOISE_POLICY_ENABLED`) on/off와 무관.
  ② 플래그 on이면 step 7.5에서 제니퍼 군집 대표 외는 SUPPRESS가 아니라 **DASHBOARD 상한** — 매트릭스 결과가 DASHBOARD보다 높을 때만 DASHBOARD로 낮추고(`capped_from` 근거), 이미 DASHBOARD 이하면 통과(None — 티어를 올리지 않음 · step 7.6 패턴).
  ③ 폴스타 알람·심각도 3 단락·플래그 off는 비트 동일. D-109 B-6(존 경계)은 그대로 — 도메인 스코프는 존 안을 더 좁힐 뿐이다.
- **근거**: `plans/144` §4.4 의도 · D-317 원칙(SUPPRESS 없음 · DASHBOARD 상한) · 코드 계산(위 Jaccard). 운영 억제 건수·대표 등급 분포는 W0 측정 대기.
