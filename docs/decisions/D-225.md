## D-225. 실행 경로 기준 전환 — **사다리 3단 `semantic_router` 기준 · `deep_agent` 부가 경로 · 2단 배선 기본 off** (plans/102 v2 · D-037·D-161·D-162·D-221 ⑤·D-222 부기 2 ② 개정)

- **결정일**: 2026-09-17 (본문 등재 2026-09-21) | **상태**: **개정됨(→D-251 · 2026-09-23)** — ①「기준 경로 = 3단」·④「2단 미입력 = off」는 **D-251로 전면 개정**(기준 = 2단 `intent_orchestration` · 3단은 비교 arm). ② 1단 부가 경로는 유지. 아래 본문은 이력으로 보존한다 | 종전 상태: **확정**(사용자 지시) — **코드 기준 전환 완료**(L-1~L-4). 운영 `.env` 전환(L-5)은 `plans/103` P5 + 사용자 확인 뒤 대기 | **번호**: 2026-09-17 예약. 등재 직전 재실측(2026-09-21) — `## D-` 헤더 최댓값 D-231 · D-225 헤더 0건 · 「변경 이력」·「채번 이력」에 예약 행만 → **예약 번호 사용**
- **배경**: 사용자 지시 원문 *"기본은 시멘틱 라우터를 사용한다. 모든 동작은 시멘틱 라우터에서 동작되어야 한다. deepagents는 부가적으로 사용할 예정이라. 기본 동작은 시멘틱 라우팅을 통해 진행되어야 한다. 이 기준에 맞게 계획을 업데이트하라."*
  실측(`plans/102` §1.6): 운영 `.env`는 1단 확정(세 플래그 모두 true) · 정본 판정 `ladder.py`의 `is_canonical`이 `DEEP_AGENT` 고정 · 2단 tri-state 미입력 + 멀티 DB면 자동 on · ★3단 순차 러너는 구조 승인 HITL 코드 기본 on이라 **운영 설정으로 진입하지 않았다**(`plans/104`가 해소) · `process_query`·`host_inspect`·`host_discovery`는 3단 도달 경로가 없다.
- **결정**:
  ① **기준 경로 = 사다리 3단 `semantic_router`.** 신규 기능의 수용 기준은 3단 확정 기동에서 판정한다. `docs/21`의 "1 정본 + 3 폴백" 서술과 `ladder.py` 정본 판정을 3단 기준으로 바꾼다(`LadderTier.is_canonical` → `SEMANTIC_ROUTER`).
  ② **`deep_agent`(1단)는 부가 경로 — 폐기 대상이 아니다.** D-161 ①(승격-폐기 동반)의 **명시 예외**다: 사용자가 부가 사용 예정을 밝혔다. 1단 확정은 강등 경고가 아니라 **opt-in 기록(INFO)**이다(`LadderTier.is_optin`). 부가 사용 형태는 `plans/102` G-9 (a) — 프로세스 단위 opt-in(빌드 타임 배타 유지).
  ③ **2단 `intent_orchestration` 배선은 기본 off, 모듈은 유지** — 3단 순차 러너가 부품(`_llm_decompose`·`agent_orchestrator`·`subagents`·`result_aggregator`)을 함수로 재사용하므로 모듈 의존 방향은 불변이다(`docs/21` §7).
  ④ **코드 기본값으로 고정** — `enable_intent_orchestration` **미입력은 항상 off**(`resolved_by=code_default`)로 바꿔 tri-state 미입력 + 멀티 DB가 2단으로 자동 확정되는 것을 막는다. `enable_semantic_routing` 미입력은 종전대로 `ACTIVE_DB_IDS` 등록 여부로 자동 결정한다. **운영 `.env` 전환은 3단 기능 동등성(`plans/103` · D-226) 완료 뒤**다 — 3단 미도달 기능을 둔 채 운영을 먼저 바꾸면 그 기능이 퇴행한다.
  ⑤ **강등 사유 어휘 재정의 · `flag_off` 폐기**(D-221 ⑤·D-222 부기 2 ② 개정) — 종전 `flag_off`는 "1단 플래그 off"를 뜻했는데 **1단 off가 기준 상태가 됐으므로 그 자체로는 사유가 아니다**. 어휘는 `none`(기준 경로 확정 또는 1단 opt-in 확정)·`intent_flag_on`(2단 확정 — 운영자 선택)·`semantic_routing_off`(4단 확정)·`orchestrator_unavailable`·`package_missing`(1단 opt-in 실패)이다. 기동 로그 첫 줄 형식(`tier=… degraded_reason=… resolved_by=…`)과 필드명은 **판독 도구 호환을 위해 유지**한다. 1단 opt-in 실패 집합 `OPTIN_FAILURE_REASONS`는 시나리오 러너의 `UNINTENDED_DEGRADATION`과 **같아야 하며 동기 테스트로 고정**한다. **2026-09-17 이전 run 기록·로그의 `flag_off`는 종전 어휘다** — 새 어휘로 소급 해석하지 않는다.
  ⑥ **정본 전제 소비처 재정의** — 시나리오 사전 점검(`scripts/scenario/preflight.py` `_check_ladder`)·리포트(`report.py`)·D-221 ⑤ 경고의 기준 단을 3단으로 바꾸고 1단은 안내로 표기한다. `scripts/eval_text2sql.py`에 `--path semantic_router`를 추가한다 — **기본값은 `orchestration` 그대로다**(그 경로는 단일 DB 파이프라인을 직접 구동해 사다리 단에 중립이므로, 기본값을 바꾸면 기존 골드셋 측정치와의 비교가 끊긴다).
  ⑦ **기능 배치 원칙** — 새 판정·조립 로직은 **3단이 부르는 공통 함수**에 두고 1단은 같은 함수를 호출한다. **1단 전용 판정 로직 신설 금지**(동등성은 같은 함수 호출 grep으로 확인한다).
- **행동 변화(명시)**: `ENABLE_INTENT_ORCHESTRATION`을 **명시하지 않은** 환경에서 멀티 DB가 등록되면 종전에는 2단이 자동 확정됐으나 이제 3단으로 확정된다. 세 플래그를 모두 명시한 운영 `.env`는 **무영향**(1단 유지)이다.
