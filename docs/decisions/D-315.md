## D-315. 포탈 기능 질의응답 — **채팅에서 포탈(이 시스템)의 기능·화면 용어·사용 방법을 물으면 사용자·관리자 매뉴얼을 근거로 답한다 · 매뉴얼 빌드 산출 색인(`src/static/manual/help_index.json`) + 프로세스 안 BM25 · 서술 LLM 1회 + 입력 예·매뉴얼 링크는 코드 부착 · 2단 조건부 처리기 `portal_help` + 명시 명령 단락(별칭은 레지스트리) · 분해 LLM 오배정 되돌림(D-004 부기 변경) · 1단 도구 노출 · 기본 on(신규 플래그 기본 off 원칙의 예외)** (사용자 확정 2026-10-13 · 팀 리드 경유 · `plans/142`)

- **결정일**: 2026-10-13 | **상태**: 확정 · 구현(2026-10-14 main 병합 · 매뉴얼 번호 U-57→U-61 · A-74→A-76 — main 선점) — 폐쇄망 확인(FabriX 서술 · 운영 `.env` 사다리 단) 잔여 | **번호**: 2026-10-07 색인 예약 행 → 본문 등재
- **배경**: 「itam db에 유사어를 등록하려고 한다. 어떻게 해야 되냐?」·「노이즈 캔슬링의 '수신 알람'은 무엇인지 설명하라.」 같은 포탈 기능 질문을 맡을 담당이 없었다. W0 실측(로컬 MLX): 2단은 각각 `cache_management`(+ 입력 분석 LLM의 등록 신호가 `field_mapper` 가드를 통과해 등록 흐름 진입)·`general_inference`로 갔고, 1단은 「수신 알람」을 도구 없이 직답하며 노이즈 캔슬링 **헤드셋** 기능으로 지어냈다.
- **결정**:
  ① **근거 = 매뉴얼 두 권만**(G-1 (a)). `scripts/manual/build.py`가 HTML과 함께 절·항목 청크 색인을 만든다(같은 원천·같은 커밋 · 사본 원천 금지 — D-131). 동기화 가드(`tests/test_manual/test_help_index.py`)가 「색인 = 현재 원천으로 다시 만든 결과」를 요구한다. 사례 입력 원문은 게재 판정(ok·partly) 사례만 싣는다(D-252 ⑤).
  ② **검색 = 프로세스 안 어휘 BM25**(G-3 (a) · 한글 2글자 + 영문·숫자 · 항목명·절 제목 ×3 · 장 제목 ×2 · `features.yaml` 절 `aliases`로 질의 확장 · 따옴표 화면 용어 정확 일치 최우선). 외부 검색 플랫폼·벡터 DB 0. 상수(k 4 · 예산 6,000자 · 최소 점수 0.3)는 모듈 상수.
  ③ **답 = 고정 단계**: 근거 0건이면 LLM 0회 결정적 안내(D-284 ⑧과 같은 계약) · 근거 있으면 answer 프로파일(D-194) 서술 1회 · **입력 예(사례 원문·형식 문장)와 「매뉴얼에서 보기」 링크는 코드가 붙인다**(G-9 (a) — LLM이 입력 예를 만들지 않는다).
  ④ **역할 필터**(G-2 (a)): 일반 사용자는 사용자 매뉴얼만 · 관리자 매뉴얼에만 근거가 있으면 내용 없이 「관리자 기능입니다(관리자 매뉴얼 A-NN 「제목」)」 결정적 안내 · 관리자는 두 권. 관리자 매뉴얼 HTML은 무인증 공개(D-252 ①)라 보안 장치가 아니라 안내 정확도 장치다.
  ⑤ **배선 — 2단 조건부 처리기 `portal_help`**(D-251 기준 경로 · `doc_query`와 같은 결합): 활성 = `PORTAL_HELP_ENABLED` ∧ 색인 성립(부재·손상이면 비활성 + 기동 로그 1줄). 활성일 때만 분해 프롬프트에 담당 1줄 + 절(대조 예 4쌍) — 비활성이면 바이트 불변.
  ⑥ **명시 명령 단락 ③.9**(G-4): 레지스트리 `solutions[portal].aliases`(「포탈 매뉴얼」「사용자 매뉴얼」「관리자 매뉴얼」「AIOps 포탈」「포탈 도움말」 — 맨 「매뉴얼」 제외) + 지목 조사 + 설명·검색 동사면 분해 LLM 없이 `portal_help` 단일 task. D-307과 **같은 판정 함수**(`doc_command.parse_designated_command`)를 쓴다. 남은 질의에 데이터 요청 표지가 있으면 보류(종전 분해). 포탈 항목은 `data_source: false`라 명시 소스 고정·소스 기억·소스 칩·관리자 소스 권한 목록·`allowed_sources` 인가에 오르지 않는다.
  ⑦ **분해 LLM 오배정 되돌림**(G-5 (b) — **D-004 부기(D-307 「질문 내용어로 소스를 정하지 않는다」) 변경 · 사용자 승인**): 좁은 결정적 판정(`portal_redirect_match` — 색인 항목명·절 제목·별칭(공백 제외 3자 이상)의 낱말 전부 포함 ∧ 설명·방법 의문 표지 ∧ 데이터 요청 표지 없음 ∧ 그 용어 절이 검색 1위·점수 ≥ 0.5)이 성립할 때만 ⓐ 2단 분해 출구에서 **단일 task**의 `general_inference`·`cache_management`를 `portal_help`로 ⓑ 1·2단 수렴점 `subagents.run_general_inference`(1단 `general_answer` 도구 포함)에서 매뉴얼 답으로 위임한다. ③.8 사용법 단락 질의·고정 안내(`direct_response`)·플래그 off는 대상이 아니다. 반대 방향 가드: 분해 LLM이 낸 `portal_help` task에 데이터 요청 표지(단일 task = sub_query 또는 원문 · 다중 task = sub_query)가 있으면 `data_query`로 되돌리고 기존 알람 교정이 `alarm_query`로 마저 바꾼다(W5 실측 오탐 「오늘 수신 알람 몇 건이야」).
  ⑧ **1단 도구 노출**(G-8 (b) — D-038 대칭): 활성일 때만 `answer_portal_help` 도구 1종 + 오케스트레이터 지시 1줄(포탈 기능·화면 용어 질문은 직접 답하지 말고 도구 호출). 활성 판정은 기동 시 1회 값이라 턴마다 도구 목록이 흔들리지 않는다(78 P14). D-251의 「1단 조건부 처리기 비노출」 선례에 대한 이 처리기 한정 예외다.
  ⑨ **기본 on**(G-7 (b) — 「신규 플래그 기본 off」 원칙의 예외 · 사용자 확정): 근거는 `src/config.py` `PortalHelpConfig` 주석. 켠 상태의 기존 동작 보전은 비활성 바이트 불변 테스트 · 되돌림 경계 테스트 · 데이터 요청 출구 가드 · 모듈 단위 회귀로 확인한다.
  ⑩ **등록 오인 가드**(W4 — 쓰기 지점 결정적 차단): 등록 대기 목록이 없고 질의가 방법 의문(`is_method_question` — 어떻게·방법·하려면·사용법·절차)이면 질의에 「등록」이 있어도 입력 분석 LLM의 `synonym_registration` 신호를 버린다(`src/nodes/field_mapper.py` · D-252 부기 가드 확장).
  ⑪ **사용법 단락 ③.8 유지**(G-6 (a)) — 「무엇을 조회할 수 있나」는 실시간 소스 목록이 정본이다.
