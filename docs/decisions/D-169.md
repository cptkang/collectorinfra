## D-169. 시멘틱 라우팅 출력 계약 — 지시문 정비 · 응답 처리 가드 · 구조화 출력 채택

- **결정일**: 2026-08-27 | **상태**: 확정(트랙 A·E 구현 완료, 트랙 B·C 이월) | **관련**: `plans/79`(v14) · `plans/80`(v6) · `SPEC-semantic-router-instruction.md` · `SPEC-router-output-contract.md` · `SPEC-structured-output-backend.md` · `SPEC-intent-extraction-typing.md`
- **배경**: IEEE Access 투고본이 label-only 출력의 정확도·신뢰도 이득을 보고했으나, 이 프로젝트는 **멀티 DB 선택**을 제공해야 해서 라벨 하나로 축약할 수 없다. 프롬프트 전수 감사(§3.5) 결과 **저신뢰가 구조적으로 표현 불가**(규칙 5가 모델에게 0.3 미만을 스스로 버리라 지시 → 코드 게이트 `MIN_RELEVANCE_SCORE`가 설계상 no-op)였고, 이어진 **응답 처리 감사(§3.6)** 에서 결함 2건을 추가 발견했다.
- **결정**:
  1. **트랙 A — 분류 지시문 정비**(구현 완료): 규칙 5 제거로 저신뢰 표현 가능화(A-1) · 신뢰도 3대역 예시 보강(A-2) · 클래스 정의 일원화(A-3) · `alarm_query` 예시 편중 37%→28%(A-4) · `fault_diagnosis` 절을 우선순위 절 **앞**으로(A-5). **플래그 없이 즉시 적용**(사용자 승인 · SPEC Q1).
  2. **트랙 E — 출력 계약 견고화**(신설·구현 완료): **E-1** LLM 산출 `intent`를 허용 집합과 대조하고 미상은 `data_query`로 강등 + 사유 로그. 허용 집합의 **정본은 `src/prompts/semantic_router.py`**(D-053 사본 금지)이며 옵트인 플래그에 종속된다. **E-2** `relevance_score` 변환 실패를 **항목 단위로 격리**하고 임의 기본값을 부여하지 않는다(`None`=판정 불가). **E-3** `instructor` 기반 구조화 출력 채택.
  3. **구조화 출력 백엔드**: `Instructor(client=None, create=...)` + **한국어 MD_JSON 핸들러**(영어 주입문 제거) + 모드 자동 선택(평문=`MD_JSON` / vLLM=`TOOLS`). optional extra `structured` · 플래그 기본 `none`(현행 비트동일) · 미설치 graceful 강등. 적용 표면은 **라우터 · DAG 분해 · 요구사항 추출** 3곳.
  4. **트랙 C(logprob 신뢰도)·트랙 B(intent/DB 2단 분리)는 이월** — 운영 LLM이 FabriX **KBGenAI 모드**라 요청·응답 스펙에 logprobs 자리가 **원천적으로 없다**. vLLM 전환 후 재개한다.
  5. **트랙 D(순수 label-only)는 배제** — `plans/79` §1.1 불변식(멀티 DB 선택 제공)과 정면 충돌. 신뢰도 이득만 C-0(라벨 선행 하이브리드)로 취득한다.
- **근거(실측)**:
  - `intent` 미검증(`semantic_router.py:439`): 가드는 `fault_diagnosis` 강등 하나뿐이라 오타·환각 intent가 하류 동등 비교에 걸리지 않고 **조용히 DB 조회 경로로 낙하**.
  - `float(...)` raw 호출(`:452`): 한 항목의 형식 오류(`"높음"`)가 호출부 `except`에 삼켜져 **분류 전체를 버리고 단일 DB 폴백** — **임계와 무관하게 멀티 DB가 축소되는 경로**.
  - `instructor` 1.15.4 격리 venv 실측: `client=None` + 커스텀 `create`로 **평문 모델 부착 가능** · 재질의에 **pydantic `ValidationError` 원문 탑재** · 커스텀 핸들러로 **영어 주입문 완전 제거**(`"genius expert"`·`"Correct your JSON"` 둘 다 소멸) 확인.
- **대안**:
  - `pydantic-ai` — **미채택**. LangChain 모델 브리지가 없어 `Model` ABC 재구현이 필요하고, 이는 **세 번째 FabriX 프로토콜 구현**이 되어 Plan 69 P2의 단일 출처 정리를 되돌린다(`plans/78` §4.7.5).
  - 자체 구현(40~60줄) — 적용 표면이 하나면 유리하나, 표면이 셋이 되어 미채택.
- **후속 확정(2026-08-27 인터뷰)**:
  - **A-6 `unknown` 신설 확정** — 현행 `general_inference`(*DB 미접근 일반 응답*)와 **의미를 분리**한다.
    `unknown`은 *분류 불가*이며 **역질문으로 사용자에게 되돌린다**(기존 되묻기 인프라 재사용 — 신규 인프라 0).
    "라벨만 늘고 처리가 없는 상태"를 피하는 것이 채택 이유다. 허용 집합(E-1 정본)에 함께 등재해야 강등되지 않는다.
    **⚠ 착수는 S-1(골든셋 회귀) 이후** — 프롬프트 변경이라 지금 넣으면 트랙 A 효과와 분리 측정이 불가능하다.
    **⚠ 소형 모델 위험**: 논문 Table 11에서 Qwen2.5-1.5B가 unknown recall 10%→50%인 대신
    **정확도 74.8%→52.0%로 붕괴**했다 — 도입 후 다른 클래스 recall을 골든셋으로 반드시 대조한다.
  - **라우터 평면 이동 = 보류 확정** — 라우터는 **워커 평면(FabriX) 유지**. 트랙 C(logprob)·트랙 B·
    `pydantic-ai`(78 §4.7.5)는 **이월 상태 유지**하고, vLLM 전환 계획 수립 시 **세 건을 한 번에 재평가**한다.
    (트랙 E-3 Instructor는 어댑터가 모드를 자동 선택하므로 **이 결정과 무관하게 이미 랜딩**했다.)
- **주의**: 트랙 A의 **분류 정확도는 아직 측정되지 않았다**. `MIN_RELEVANCE_SCORE=0.3`은 자기보고 스케일 기준 **잠정값**이며 A-1로 게이트가 처음 실동작한다 — 정산은 C-4(이월). 측정에는 **D-127 건별 승인**이 필요하다.
