## D-175. 호스트 가용성 사전 판정 — **차단은 DOWN 하나, 판정은 본체, 게이트는 양쪽**

- **결정일**: 2026-08-28 | **상태**: 확정 (구현 완료 · `plans/81` · `SPEC-host-availability-precheck.md`) | **번호**: 등재 최댓값 D-174 → **D-175**(등재 직전 `## D-` 헤더·「변경 이력」·「채번 이력」 표 재확인)
- **배경(실측)**: 전원이 꺼졌거나 가용성이 비정상인 서버에 실시간 프로세스 조회를 요청하면 **원인을 말하지 못하는 두 응답** 중 하나가 나갔다 — ①프로세스 API 미응답 시 *"잠시 후 다시 시도해 주세요"*(재시도해도 같다 — 오안내) ②API 200 + 빈 목록 시 *"현재 실행 중 프로세스 0건"*(`is_sufficient=True`로 반환돼 후단이 **정상 결과로 서술** — 거짓 단정). 가용성 표기는 이미 `realtime_usage.py:73-78`(Plan 71)에 있었고 **프로세스·조사 경로에만 없었다** — 신규 발명이 아니라 **경로 비대칭 해소**다.
- **결정**:
  - **판정은 본체가, 게이트는 양쪽이 둔다.** 본체(`src/domain/host_availability.py`, 순수 함수)가 `cmm_resource.avail_status`·`is_maintenance`로 결정적으로 판정하고, `sre_agent`는 **페이로드로 받은 사실만 소비**하는 6번째 가드를 둔다. `sre_agent`가 DB를 직접 읽지 않으므로 D-118 경계(양방향 import 0)가 유지된다.
  - **차단은 `avail_status == 1`(DOWN) 하나뿐이다 — fail-open.** 인가(`host_authz`, fail-closed)와 **정반대**인 이유: 이 판정은 보안 통제가 아니라 *성공할 수 없는 호출을 생략하는* 낭비 방지 게이트다. 근거가 약할 때(값 2·미상 코드·조회 실패·미등록) 차단하면 **정상 조회를 잃는다**. 이 게이트의 유일한 회귀 위험이 그것이다.
  - **"전원 off"로 단정하지 않는다.** `avail_status`는 Power off와 에이전트 통신 이슈를 구분하지 못한다(`realtime_usage.py:73-74` 2026-07-24 실측). 사용자 문구는 *"가용성이 비정상(중지/통신이상)이며 확인 시각은 …"* 까지다. `unavailable` 응답에는 **재시도 유도를 붙이지 않는다**(재시도해도 같다).
  - **추가 DB 왕복 0.** 단일 경로는 기존 hostname 해소 SELECT(D-046)에 컬럼 2개를 더해 판정 근거를 함께 가져오고, fan-out은 `build_host_status_sql`의 IN 절 **1쿼리**로 처리한다.
  - **`sre_agent`에도 필요하다**(사용자 검토 지시에 대한 답): 본체 게이트는 **본체 경유 조사만** 막는다(`docs/25` L-4와 같은 구조). 원격 프로파일은 bash를 확장하지 않아 죽은 호스트에서 도구가 **에러가 아니라 빈 데이터**를 돌려주고, ReAct 루프가 전체 타임아웃(300s·조사 1건 실측 161s)까지 돈다. `docs/25`에 **L-5**로 등재했다.
- **게이트 확정(사용자 2026-08-28)**: **G-1 플래그 기본 on**(아래 예외 근거) · **G-2 `unavailable` 조사 요청 = 거부 + 사실 브리핑** · **G-3 DOWN 계열 알람은 게이트 예외**(막으면 "왜 내려갔나" 조사가 사라진다) · **G-4 실측 해소**(b0(DB2)도 `AVAIL_STATUS`·`IS_MAINTENANCE` 보유 — `testdata/01_create_tables.sql:39,60` → **양 엔진 대칭**) · **G-5 `maintenance`는 경고 후 진행**.
- **★ 기본값 규약의 명시적 예외**: `COMPOSITE_AVAILABILITY_PRECHECK_ENABLED=**true**`. `plans/80` §5.4-③("플래그 기본값은 현행 동작과 비트 동일")의 예외이며 근거는 **현행 동작 자체가 결함**이라는 것이다(위 배경 ①②). off 경로의 비트 동일성은 테스트로 계속 고정한다(`tests/test_composite/test_process_availability.py::TestPrecheckOffIsBitIdentical`).
- **구현**: `src/domain/host_availability.py`(신규 · 판정·문구) · `noise_gate/infrastructure/polestar_hostname_resolver.py`(`resolve_with_status`·`build_host_status_sql`·`lookup_many`·**세 경로 공용** `lookup_host`/`lookup_hosts`) · `src/orchestration/process_query.py`(단일·fan-out 대칭 · 실패 **사유별 분해**) · `src/nodes/fault_diagnosis.py`(인가 **다음**, 위임 **직전**) · `noise_gate/application/nodes/investigation_trigger.py`(+`is_availability_alarm` G-3 예외) · `noise_gate/domain/investigation_payload.py`(`meta.target_state` — **값이 있을 때만 키 생성**) · `sre_agent`(`GUARD_TARGET_UNAVAILABLE` 가드 · `sre_diagnose(target_state=)` 선택 인자) · `CompositeConfig` 플래그 3종.
- **주의**: ①`target_state`가 없는 호출자는 **통과**한다(fail-open · 의도된 설계). ②가용성 거부는 dedup·예산·in-flight 슬롯을 **잡지 않는다**(거부될 조사가 슬롯을 쓰면 정작 필요한 조사가 밀린다). ③감사 `outcome` 어휘를 늘리지 않고 `degraded[].reason="target_unavailable"`로 구분한다(소비처 호환). ④PAGE 티어 알람마다 판정 쿼리 1회가 추가된다(가벼운 인덱스 SELECT — 300s 조사를 막는 대가).
