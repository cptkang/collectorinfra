## D-367. 서버 정보 직접 수집 — SSH 채택(원격 진단 「SSH 미채택」 개정) · 존별 읽기 전용 수집 게이트웨이 `host_gateway/`

- **결정일**: 2026-11-05 | **상태**: 확정 · 계획(`plans/214` · 코드 0 · 남은 게이트 G-5·G-7~G-14) · 부기 1(본체 연결 — 스냅샷 조회만) · 부기 2(셸스크립트 방안 · RHEL 기준) · 부기 3(LLM 역할 경계 — 선택·초안만) | **관련**: SREAgent D-004·D-019(`plans/sre-agent/06` §1 — **개정**) · D-003 · D-035 · D-117 · D-189 · D-118 · D-139 · D-119 · D-233 · D-274 · D-161 · D-303
- **배경**: 사용자 지시 *"서버의 정보를 수집하여 정확한 장애 진단을 해야 한다. 지금은 서버의 정보를 수집하기 위한 장치가 없다. 따라서 ansible와 같은 IaC 도구를 이용하여 OS 명령어를 통해 정보를 수집하는 등의 작업을 할 수 있다."* 실측(2026-11-05): 진단이 보는 서버 정보는 폴스타 DB·Prometheus(공동존 관제 요청 서버만 · 은행존 없음)·제니퍼·ITAM의 간접 관측뿐이다. `noise_gate/infrastructure/host_diagnostic_collector.py`(ssh 허용목록 실행)는 플래그 off·운영 미배치이고, `sre_agent` 원격 프로파일은 bash를 꺼(D-233) OS 원시 신호가 0이다.
- **결정**(사용자 2026-11-05 확정 — *"SSH 미채택 결정을 바꾸자. ansible을 미사용중이다. python은 미설치되어 있다. 은행존, 공동존 망은 분리되어 있다."*):
  ① **SSH 채택** — `plans/sre-agent/06` §1(SREAgent D-019)의 「원격 VM 진단은 Prometheus + 폴스타 2축 · SSH 미채택」을 개정해 **서버 직접 수집 축을 더한다**(3축). 기각 근거였던 「LLM이 `ssh host <임의 명령>`을 만든다」는 ②③으로 없앤다.
  ② **LLM은 명령을 고르지 않는다** — 수집은 독립 패키지 `host_gateway/`(D-274)가 MCP 도구로만 노출하며, 입력은 인벤토리 키(host)·카탈로그 항목(`profile_id`)·항목별 정규식 인자뿐이다. 조사 LLM에 셸·SSH를 직접 주지 않는다(D-233 유지).
  ③ **대상 서버 쪽 강제** — 권고안은 전용 계정 `authorized_keys`의 강제 명령(`command=` · `from=` · `restrict`)으로 카탈로그에서 생성한 POSIX sh 디스패처를 거는 것이다. 키가 유출돼도 카탈로그 밖 명령은 실행되지 않는다. 배포 허용 여부는 G-10(대기).
  ④ **실행 엔진 = OpenSSH 클라이언트 직접 실행** — 대상에 Python이 없어 Ansible 모듈이 돌지 않고(`raw`만 가능 = 직접 SSH와 같음), 운영팀도 Ansible을 쓰지 않아 재사용 이점이 없다. Ansible은 쓰지 않는다.
  ⑤ **존별 인스턴스** — 은행존·공동존 망이 분리돼 있으므로 같은 코드를 존마다 배치하고 존·인벤토리·SSH 키를 존별로 둔다(키 공유 금지).
  ⑥ **수집 모드 2종** — 정기 구성 스냅샷(일 1회 + 수동 · 이전과 비교 = 변경 이력) + 장애 시점 진단 프로파일(`noise_gate` `L3_PROFILES`·`sre_agent` `VM_DIAG_ALLOW`를 단일 카탈로그로 통합).
  ⑦ **경로 단일화** — `sre_agent`·`noise_gate`는 MCP로만 호출한다(import 0). `noise_gate` `build_ssh_runner`는 게이트웨이 경로 검증 뒤 폐기를 판정한다(D-161 · D-189 근거 4).
- **불변식**: 읽기 전용(D-003 — 변경 명령 물리 부재 · 조치는 권고만) · 부하 가드(`timeout 20 nice -n 10 ionice -c3` · 호스트별 진행 1건) · `StrictHostKeyChecking=yes`(`accept-new` 금지) · 비밀번호 인증 금지 · 전 호출 감사 · 출력 마스킹 · 수집 실패는 사유로 반환(침묵 폴백 금지) · 소비처 플래그 기본 off = 현행 비트 동일.
- **근거**: D-189(경로 B 허용목록 명령 실행이 이미 확정 경로) · D-274(별도 자격증명 = 독립 게이트웨이) · 2026-07-21 설치 제약(데몬·패키지 설치 없음 — 대상 배포물은 계정·`authorized_keys` 1줄·sh 스크립트 1개) · holmes 0.36.0 `resolve_tool_name_collisions`가 같은 이름의 MCP 도구를 `<toolset>__<tool>`로 나눠 존별 인스턴스 동시 등록이 가능함(설치본 실측).
- **대안 기각**: Ansible(대상 Python 미설치) · 에이전트 설치형 osquery·Salt·Telegraf(설치 제약) · AWX(운영 부담 · 미사용) · `asyncssh`(반입 1건 증가 · 이점 없음).
- **주의**: `sre_agent`는 조사 대상 db_id로 존 도구를 고르는 일이 LLM에 남는다 — 잘못 고르면 `host_not_in_inventory`로 SSH 없이 거부된다. 결정화(중앙 라우터)는 G-11. 로그 중앙 전송·node_exporter 설정 확장은 범위 밖 후속 후보.
- **부기 1(2026-11-05 · 본체 연결 · `plans/214` v1.2 §8.1)**: 사용자 지시 *"본체에 전달하는게 필요한지 검토하여 적용하라."* 검토 결과 본체 연결은 **필요하되 저장된 스냅샷 조회로 한정**한다.
  ① **원인 분석 질의는 본체 변경 없음** — `fault_diagnosis` → `sre_agent` 위임이 이미 있고, `sre_agent`가 host 도구를 쓰면 위임 응답에 서버 직접 수집 근거가 실린다. 본체가 따로 부르면 실시간 수집 경로가 둘이 된다(D-189 근거 4).
  ② **서버 구성·변경 단건 조회는 편입** — 패키지·서비스·sysctl·포트·cron·변경 이력은 폴스타에 없어 지금 본체가 답할 수 없다. `host_inspect`에 프로파일 `host_config`·`config_changes`를 키워드 맨 끝(최저 우선순위)에 더하고 `host_facts`·`host_snapshot_diff`만 부른다. 「커널」·「OS 정보」는 계속 `os_config`(폴스타)가 받는다.
  ③ **본체는 실시간 수집(`host_collect`)을 부르지 않는다** — 채팅 질의 수만큼 운영 서버 SSH가 늘고, 실시간 수집은 조사 권한(`HOST_AUTHZ_MODE`) 대상이라 `fault_diagnosis`가 이미 그 인가를 거친다. 게이트웨이가 본체 토큰의 `host_collect`를 거부해 결정적으로 고정한다(본체 경로 SSH 유발 0).
  ④ **주소는 `MCP_SOURCE_ENDPOINTS` 하나** — 존 키 `host_bankjon`·`host_gongjon`(`plans/125` A-2 · 키가 없으면 비활성). `noise_gate`도 같은 키를 쓴다(D-364 선례). `sre_agent`는 독립 패키지라 자기 설정 키를 둔다.
  ⑤ **존 선택은 결정적** — 대상 db_id → db_registry zone → 존 키. 스냅샷 조회에도 조사 인가를 적용하는 안을 권고했다(G-12 대기 — 열린 포트·패키지 버전은 공격 표면 정보). 사용자가 쓰는 새 질의 유형이므로 매뉴얼을 함께 갱신한다(D-255).
- **부기 2(2026-11-05 · 셸스크립트 방안 · RHEL 기준 · `plans/214` v1.3 §4.2)**: 사용자 지시 *"대부분의 OS가 레드햇리눅스이다. 쉘스크립트를 이용하는 방안도 같이 검토하여 반영하라."*
  ① **배포형 bash 수집 스크립트 + 강제 명령 채택** — 결정 ③의 대상 쪽 디스패처를 「카탈로그에서 생성한 bash 수집 스크립트(항목 = 함수)」로 구체화한다. 프로파일 1개 = SSH 세션 1개 · 가드 접두·출력 상한·구분자를 스크립트가 붙인다 · `shellcheck`·`bash -n` 통과 필수 · Python 호출 0.
  ② **cron 주기 실행은 1차 미채택(G-13)** — 상주 작업은 사실상 경량 에이전트이고 포화 서버에서도 돈다. 과거 시스템 지표는 RHEL `sysstat` `sa` 파일로 얻는다. 파일럿에서 프로세스 이력 공백이 진단을 막으면 재판단.
  ③ **접속 때 스크립트 전송 실행(`ssh host bash -s < x.sh`)·대상 → 중앙 push는 기각** — 전자는 임의 명령 실행과 같아 강제 명령과 양립하지 않고, 후자는 대상에 바깥 연결·자격증명이 필요하다.
  ④ **RHEL 기본 도구 편입(신규 설치 0)** — `sar -f /var/log/sa/saDD`로 장애 시각 전후 과거 값(`diag.history` 신설 · 시각 인자는 소비처가 알람 시각에서 결정적으로 만든다) · `rpm` 설치 시각 · `getenforce`·`tuned-adm`·`/var/crash` · 조건부 `yum`/`dnf history`·`needs-restarting`. `sos report`는 범위 밖, PCP·Insights는 제외.
  ⑤ **카탈로그·권한·픽스처를 RHEL 기준으로** — Debian 분기는 실재할 때만 · `/var/log/messages`(root 0600)는 journal 우선, 비영속 journal 서버만 sudoers 정확 일치 1줄 · SELinux 레이블 확인 · 픽스처는 Rocky Linux 8·9. RHEL 버전 분포·`sysstat` 활성률·journald 영속은 W0 실측.
- **부기 3(2026-11-05 · LLM 역할 경계 · `plans/214` v1.4 §7.3·§7.4)**: 사용자 질의 *"수집하기 위한 명령어를 생성하기 위해 LLM을 사용해야 할 것으로 보이는데 이 역할은 어디서 하면 적절하냐?"*에 권고안을 냈고, 사용자 지시 *"권고에 맞게 정리하라."*로 확정했다. 결정 ①(LLM은 명령을 고르지 않는다)을 유지하고 LLM의 자리를 둘로 한정한다.
  ① **실행 시점 명령 생성 금지** — LLM 출력이 셸 명령이 되는 실행 시점 경로는 두지 않는다(D-233 유지). 존 인스턴스의 MCP 서버 프로세스는 LLM 클라이언트를 갖지 않는다(경계 테스트로 고정).
  ② **실행 시점 LLM = 프로파일 선택** — `sre_agent`가 카탈로그 프로파일과 검증 가능한 인자만 고른다. 카탈로그에 없는 정보가 필요하면 명령을 만들지 않고 `collection_gaps`(구조화 필드 · jsonl)로 남기고 결론에 「수집 불가 항목」으로 밝힌다.
  ③ **오프라인 LLM = 카탈로그 초안 작성** — `host_gateway` 작성 CLI(`catalog draft`)가 공백 기록(`sre_agent` `collection_gaps` + 게이트웨이 `profile_unknown`·`arg_invalid` 감사)으로 YAML 초안을 `proposals/`에 쓴다. 활성 카탈로그는 건드리지 않는다. 초안은 신뢰하지 않는 입력이다.
  ④ **결정적 검사 → 사람 승인 → 재배포** — `catalog check`(인자 정규식·허용값 필수 · 읽기 전용 바이너리 허용목록 · 금지 명령·메타문자·파이프 0 · `bash -n`·`shellcheck` · 픽스처 실행)를 통과해도 승인을 대신하지 않는다. 승인자·보안팀 재확인 범위는 G-14. 재생성 뒤 해시 대조로 미배포 서버가 드러난다.
  ⑤ **매개변수형 항목으로 생성 수요를 줄인다** — `diag.log_tail <path_id> <lines>`(경로는 카탈로그 상수 · 호스트별 허용은 인벤토리) · `diag.mw.<kind>`(기존 결정적 식별 규칙 `config/middleware_signatures.yaml` 재사용).
