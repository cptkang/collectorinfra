## D-200. '가동률' 의미 확정 — 가용성(uptime) 계열, CPU 사용률 매핑 금지

- **번호**: 원 채번 **D-197** → **2026-09-09 `test_update` 병합 시 D-200 재부여**(원격 `multiintent`가 D-197을 `plans/50` 장애진단에 선점 — 「채번 이력」 표 참조)
- **결정일**: 2026-09-07 | **상태**: 확정 (**구현 완료** — 3존 실측상 Availability/Uptime 지표 부재로 분기 ② 확정 → `intent_planner` ③.7 pre-gate(`UPTIME_RATE_GUIDANCE` direct_response, D-150 동형) + 골드셋 yd-005·README 갱신(안내 단락이 정답, SQL 생성 시 회귀). 폐쇄망 검증 대기)
- **결정**: '가동률'은 실무 통용대로 **VM 가동 시간 비율(uptime/availability) 계열**로 정의한다. CPU 사용률(Utilization) 유사어 등재는 **금지** — C 스위트 C-08에서 CM 존이 LLM 임의 해석으로 CPU 기준 취합한 것도 오답으로 판정한다(사용자 확정). 기존 어휘 체계(`config/global_synonyms.yaml`의 '가동 상태'/'가동'/'가동중' → `avail_status`)와 정합.
- **구현 방향(2분기, `scripts/diag_metric_definitions.sql` 실측으로 확정)**: ①폴스타 `cmm_metric_stat_m`에 Availability/Uptime 계열 `definition_name`이 **존재하면** 시맨틱 모델 aliases에 '가동률' 등재(단일 출처 D-067 → synonym_seeds derive/load → catalog_diff 동등성) ②**부재하면** '가동률' 감지 시 결정적 안내 pre-gate(A-10/A-12 계열 — 지원 지표 안내 + 대체 질의어 제시, LLM 미호출)로 B0 재계획 폭주·CPU 오매핑을 함께 차단.
- **근거**: C-08 실측 — B0는 '가동률' 미해석으로 재계획 카운트 폭증 후 무의미 결과, CM은 CPU Utilization으로 임의 해석(의미 오류). '가동률→사용률'은 어간이 달라 퍼지 매칭 원리상 도달 불가(docs/standardization_literature_review.md §"가동률")라 수동 결정이 필수였다.
- **주의**: 골드셋 `yd-005`('가동률'=사용률 의역, E5-4 임베딩 대상)가 본 결정과 정면 충돌 — **골드셋 정답을 본 결정에 맞춰 갱신**(사용자 동의 완료)하고, 임베딩 유사어 계단(schema_analyzer 의미 검색)이 '가동률'→'사용률'로 근접 매칭하지 않는지 구현 시 확인한다.
- **관련**: D-067(유사어 단일 출처) · D-035(결정적 게이트 — LLM 의도 분류 비의존) · docs/29 C-08(coverage=outside 실패 허용 → 본 결정으로 정식 커버 전환).
