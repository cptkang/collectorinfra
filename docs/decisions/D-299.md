## D-299. 제니퍼 전체 읽기 기능의 광범위 활용 — 전수 대응표·복수 조회·분석·장기 작업·조사 연계

- **결정일**: 2026-10-02 | **상태**: **확정(계획 · 코드 0)** — 사용자 “계획에서 조회 기능을 광범위하게 사용해야 한다. 이에 맞게 재 검토하라.” 후 재검토 권고에 “권고에 맞게 계획을 수정하라.” | **번호**: 본문·변경 이력 최댓값 D-298, 채번 표와 전체 D-번호 대조 최댓값 D-298 → D-299. 기존 미커밋 D-298 보존.
- **결정**:
  ① **전체 기능 완료 기준**: 읽기 API·선택 인자·반환 필드 → 도구·보기·진입 경로·테스트를 `spec/CAPABILITY-MAP-134.md`에 전수 대응한다(착수 W0 산출). 43예문은 최소 회귀 집합이고 조회 기능의 상한이 아니다. metrics 전체 카탈로그도 사용자가 직접 조회한다.
  ② **복수 조회·분석**: 보기 3개 절단과 다건 hostname 제외를 없애고 인스턴스·업무·서비스·소스·기간·지표를 조합한다. 기간 비교·변경 전후·GUID 연계·전수 순위는 원자료 수집과 결정적 계산, 단위/가중치/누락/부분 실패 계약까지 구현한다. 상한 제거는 D-296 유지, 조사 프로파일 5회·정체 가드 유지.
  ③ **도구·조사 활용**: D-195 ①의 APM 도구 ≤8 제한을 기능 응집성과 선택 검증으로 개정한다(9개도 새 상한으로 고정하지 않음). 관리·환경변수·활성 요청 상세 등을 조사에 일괄 숨기지 않는다. 채팅 위임은 사용자 인가, 자동 조사는 명시된 서비스 인가 맥락을 적용하고 필드를 마스킹한다. 기존 인가를 해제하거나 개인정보 원값을 허용한 결정은 아니다.
  ④ **대용량 실행 선행**: W0-B에서 작업 큐·진행·취소·MCP 호출 마감·파일 스풀·소유자/권한·만료/정리·재기동 실패 처리를 먼저 넣는다. 동시 실행 수/메모리 제어는 분할 수단이며 총 범위를 자르지 않는다. 긴 읽기는 예상 소요를 알리고 반복 확인 없이 요청 기반 작업으로 실행한다. 일반 D-267 상한 유지, 접수/진행은 데이터 답변 완료와 분리한다. 상시 전수 스냅샷 수집은 아니다.
  ⑤ **보기 선택**: APM 카탈로그·예문·요청 영역 검증, 선택 실패 시 필요한 APM task만 재선택 최대 1회 후 선택 질문/미해결. 명시 기능을 무관한 기본 보기로 대체하는 동작을 개정한다(D-293 한정). 일반 현황 기본값·D-004/295 소스 선택 원칙 유지. 추가 LLM 0 권고는 이 재선택에 한해 변경하고 지연/정확도를 매 Wave 측정한다.
  ⑥ **소유권·완료**: 134가 게이트웨이·본체·매뉴얼과 125 A-6①②③·A-8을 함께 수행한다. 130 대상 해석을 재사용한다. 121이 F-13 2단 조사 위임을 소유하되 해당 통합 전에는 전체 완료로 선언하지 않는다. F-11/12 알람·F-13 조사·F-14 복합 등 실제 진입점별로 검증한다.
  ⑦ **불변·미결**: D-296의 GET 읽기·자격증명 제거, D-262 마스킹/소유권, D-120/240 유지. 환경변수 기능을 안전한 키만 조회하도록 축소하지 않는다. 개인정보 원값의 역할/표시 경로(G-11)는 별도 결정 대기, 관리자 원본 CSV도 미승인. 소스 속도 값(G-12)은 운영 협의 전 5. 두 미결은 현행 마스킹 아래 읽기 기능 구현을 막지 않는다.
- **근거**: `plans/134` 재검토 7건 — 예문 중심 범위 누락, 보기 3개 절단, 분석 단계 부족, 조사 일괄 비노출, 장기 실행 기반 후행, 무관한 기본 보기 폴백, 진입 경로별 완료 조건 오류. 사용자 권고 채택.
