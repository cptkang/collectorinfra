## D-260. TICKET 일배치 요약의 소비 측을 워커 주기 루프로 배선하고, 요약 큐에 보존 한도를 둔다 (사용자 지시 2026-09-27 · `plans/116` §11.8.3 ⑬ · D-048.9 후속)

- **결정일**: 2026-09-27 | **상태**: 확정·구현(아래 2건 포함 — 사용자 확정 2026-09-27 *"권고대로 진행하라"*)
- **결함**: D-048.9가 정한 「일배치 요약 큐」는 적재만 있고 읽는 호출부가 없어(`read_pending`·`summarize` 운영 호출 0) 요약이 한 번도 나가지 않았고, 큐 파일이 무한히 커졌다.
- **결정**: ① `noise_gate/orchestration/ticket_summary.py`의 루프를 `AlarmWorker.run()`이 큐가 있을 때만 띄운다(워커 종료 시 취소). ② 발송이 켜져 있으면(`NOISE_TICKET_BATCH_SUMMARY_ENABLED`, **밖으로 나가는 새 동작이라 기본 off**) 매일 `NOISE_TICKET_BATCH_SUMMARY_HOUR`(기본 9, 로컬)시에 지문별 건수 요약 한 통(상위 20종 + 「외 N종 M건」)을 worKB 기본 수신자에게 보낸다. 성공하면 읽은 바이트만 큐에서 지운다(최소 1회 전달). worKB 미설정은 D-243대로 한 줄 경고, 발송 실패는 traceback 경고 — 둘 다 항목 유지 · 워커를 멈추지 않는다. ③ 요약에 읽을 수 있는 이름을 쓰려고 큐 레코드에 `alarm_name`·`server_name`을 더했다(결정 기록 규약과 같음 · 추가만). ④ 보존 한도 `NOISE_TICKET_BATCH_QUEUE_MAX_LINES`(기본 20000, 0이면 무제한)는 **「기본 off」 원칙의 명시적 예외**로 기본 적용한다 — 큐는 감사 정본이 아니고(감사는 결정 기록 · D-048.4), 발송 기본 off에서 한도까지 끄면 무한 증가가 기본 설정에 남는다. 지울 때마다 경고 로그. ⑤ `NOISE_AI_SEVERITY_ESCALATE_ONLY` 등 읽는 코드 없는 키는 삭제하지 않고 도움말만 사실대로 고쳤다.
- **사용자 확정(2026-09-27)**: (a) 채널을 worKB 하나로, 수신자를 기본 수신자(`WORKB_USER_IDS_CSV`)로 한 것 — 설계(D-048.9·Plan 52 §7)는 「일배치 요약」만 정했다. (b) 보존 한도를 기본으로 켠 것 — 결정 기록을 끈 환경(`NOISE_DECISION_STORE_ENABLED=false`)에서는 지운 항목의 기록이 어디에도 남지 않는다.
- **대안(기각)**: 기동 시점 기준 24시간 주기(재시작이 잦으면 발송되지 않음) · 적재마다 회전(폭주 시 처리 경로에서 파일 전량 읽음) · `.1` 보관 회전(보관 파일이 다시 무한 증가) · webhook 동시 발송(기계 연동 채널 — 후속 브리핑 선례로 제외).
- **검증**: `noise_gate/tests/test_ticket_batch_summary.py` 20건(수정 전 소비 모듈 없음으로 실패) · 외부 발송은 대역만(네트워크 0) · 설정 카탈로그 필드 수 353 → 356.
