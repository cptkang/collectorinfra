## D-343. sre_agent 조사 — 조사 LLM의 Gemma 도구 호출 마크업을 클라이언트 측에서 `tool_calls`로 파싱(기본 on 예외)

- **결정일**: 2026-10-19 | **상태**: 확정 · 구현(`plans/188` W5 · 커밋 없음)
- **결정**: holmes `DefaultLLM.completion` 경계에 **응답 후처리 가드**를 건다(`infrastructure/tool_call_markup_guard.py` · D-213 가드와 같은 꼴 — 멱등 표식 · 설치 실패는 예외 없이 warning). 응답 `choices[0].message.tool_calls`가 비고 content에 Gemma 4 블록(`<|tool_call>call:이름{인자}<tool_call|>` · 문자열 `<|"|>…<|"|>`)이 있으며 **호출에 `tools`가 실리고 `tool_choice`가 auto일 때만** 블록마다 litellm `ChatCompletionMessageToolCall`(id 고유 · `type="function"` · arguments JSON 문자열)을 만들고 블록을 지운 **사본**을 돌려준다(남은 서술 없으면 content `None` · `finish_reason="tool_calls"` · usage 보존). 인자는 문자열 구간을 먼저 소비하는 결정적 재귀 하강 파서로 읽는다. 블록 하나라도 해석 실패(중복 키·비유한 숫자·블록 밖 마크업 잔존 포함)면 **부분 변환 없이 원본 그대로** + warning(원문은 `markup_log_excerpt`) → D-342 W4 부기의 「[미결] 조사 실패」 종결이 그대로 작동한다. 그 밖의 응답은 입력 객체 그대로(no-op). 플래그 `TOOL_CALL_MARKUP_PARSE_ENABLED`(`AgentSettings.tool_call_markup_parse_enabled`) **기본 on — 명시적 예외**(마크업이 없으면 no-op이라 정상 경로 비트 동일 · off는 곧 「파서 불일치 환경에서 조사 전건 실패」) · **만료일 2027-04-19**(D-161). 마크업 리터럴은 `domain/answer_markup.py` `GEMMA_*` 상수가 단일 출처다.
- **근거**: 폐쇄망 2026-10-19 실측 원문에서 모델이 holmes 내장 `TodoWrite`를 정확한 인자 구조로 불렀다 — vLLM은 tools를 렌더링하고 있고 **응답 파싱만** 빠졌다. 운영 측은 vLLM `--tool-call-parser`를 바꾸기 어렵다(사용자 2026-10-19). W4 방어만으로는 조사가 1턴에서 끝나므로 클라이언트 측 파싱이 조사를 진행시키는 유일한 코드 경로다. holmes 0.36.0의 조사 루프 호출은 모두 `DefaultLLM.completion`을 지나고 holmes는 `message.model_dump(exclude_defaults/unset/none)`·`t.function.arguments`(`json.loads`)·`t.id`로 읽는다(실측). `tools` 없는 호출(컨텍스트 압축 `compaction.py:132`·요약 `llm_summarize.py:156`)은 content만 읽으므로 변환하면 요약이 사라지고 짝 없는 `tool_calls`가 대화에 남는다 — 그래서 제외한다(verifier 지적).
- **구현**: `sre_agent/sre_agent/infrastructure/tool_call_markup_guard.py` · `domain/answer_markup.py`(GEMMA_* 상수 · `markup_log_excerpt` 경계 절단 보강) · `settings.py` · `diagnosis.py`(`install_system_message_guard` 옆 설치) · `sre_agent/.env.example`. 단언 `sre_agent/tests/test_plan188_w5_tool_call_parse.py`(실 holmes + 가짜 OpenAI 호환 LLM 1턴 마크업 → 가짜 세계 MCP 도구 실행 → 2턴 결론 · 플래그 off → W4 미결) · `test_plan188_w5_verify.py`. 문서 `docs/26` §5.6.3 · 매뉴얼 admin 25절.
- **주의**: ①**운영 확인 항목(로컬 실측 불가)** — holmes는 다음 요청에 assistant `tool_calls` + `role=tool` 메시지를 싣는다. vLLM 대화 템플릿이 이를 Gemma 형식으로 렌더링하는지는 내부망에서만 판정된다 — **첫 실조사에서 도구 호출이 2턴 이상 이어지는지**로 판정하고, 이어지지 않으면 파서 교정(운영자)이 유일한 해법이다. ②파서는 의도적으로 엄격하다(일반 큰따옴표 문자열·꼬리 쉼표·대문자 리터럴·중복 키는 실패 → W4). ③Gemma 4 표기 한정 — Hermes·`[TOOL_CALLS]`·`<|python_tag|>` 등은 범위 밖(실측되면 상수·파서 추가). ④설치는 프로세스 전역·1회(D-213과 같음). ⑤근본 조치(vLLM 파서 교정)는 여전히 운영자 권장 사항이다.
