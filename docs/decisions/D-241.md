- **결정**: ①**계약 칸** — raw 행의 별도 칸 `unevaluated_reason: "invalid" | "timeout" | "clarify_blocked" | null`(36과 합의). `func_verdict` 어휘는 늘리지 않는다 ②**벤치 헬퍼 `sweep.unevaluated_reason_of(row)`** — 칸이 있으면 그 값(러너가 정본), 없으면 도출: `func_verdict=="invalid"` → `invalid` · 타임아웃 문구(`처리 시간이 초과`, `error`·`mode_evidence` 의 단어 경계 `504`) 또는 `forbidden_mode=="hang"` 이 오류로 끝남 → `timeout` · `response_mode=="clarify"` 로 끝나고 단언이 통과하지 않았으며 **그 턴이 역질문을 기대하지 않았음** → `clarify_blocked`. 역질문을 기대한 턴(러너 칸 `expects_question`, 없으면 실패 단언 키가 `clarification`·`options_contains` 로 시작 — `status` 는 추정에 쓰지 않는다)은 역질문 모양이 틀려도 **결함이므로 분모에 불합격으로 남긴다**(36 제안 · 2026-09-21 보강). run 20260914 실측: 역질문으로 끝난 비합격 3,453턴 중 `clarify_blocked` 3,088 · 역질문 기대 결함 365(분모 잔류) ③**기능 합격률(정확도 비교) 분모에서 뺀다** — `compare._scored` 가 `manual` 과 함께 거른다. **완주율·SQL 생성·지연 신호에서는 빼지 않는다**(타임아웃은 성능 축의 사건이다). `invalid` 는 종전대로 모든 신호에서 뺀다(D-218) ④**사유별 건수를 드러낸다** — 건전성 블록 한 줄 · 판정표(`axis_verdicts.md`) 머리 · 캠페인 합산 리포트(끝난 구간 합) · 구간 기록(`health.unevaluated`). **0 도 적는다** — 「없음」과 「안 셌음」은 다르다 ⑤**기대된 역질문은 평가된 턴이다** — 역질문이 정답인 시나리오에서 단언이 통과했으면 분모에 남는다(합격을 빼지 않는다)
