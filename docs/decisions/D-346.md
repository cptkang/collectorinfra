## D-346. 본체 uvicorn 자동 재시작(`reload`)은 옵트인 `API_RELOAD` — 운영 기본 꺼짐

- **결정일**: 2026-10-23 | **상태**: 확정 · 구현(미커밋) | **번호**: 등재 직전 `ls docs/decisions/` 최댓값 D-345 확인
- **배경**: 내부망에서 자동 조사를 켜자 파이썬 코어 하나가 100%로 보였다(사용자 `ps` 실측). 상위는 sre_agent(3%)가 아니라 본체 `src.main --server`(37%)와 그 `multiprocessing.spawn` 자식(76%)이었다. `src/main.py`가 최초 커밋부터 `uvicorn.run(..., reload=True)  # 개발 시에만`을 하드코딩해 운영에서도 감시 프로세스(StatReload — `watchfiles` 미설치)가 작업 디렉터리의 `.py` 전부를 0.25초마다 stat 하고, 앱은 spawn 자식으로 떴다. 로컬 실측: 감시 파일 39,217개(저장소 안 `.venv` 포함) · 스캔 1회 약 2.5s CPU · 코어 82%.
- **결정**: ① `ServerConfig.reload`(`API_RELOAD`) 신설 · **기본 false** — 운영은 단일 프로세스(감시자 0). 개발 맥에서만 `.env`에 `API_RELOAD=true` ② 다중 워커(`workers>1`)는 하지 않는다 — AlarmWorker·실시간 허브가 같은 프로세스에 있어 워커 수만큼 중복된다.
- **근거**: 감시 프로세스의 CPU는 순수 낭비이고, 코드 배포 중 `.py`가 바뀌면 앱이 재시작돼 진행 중 조사·후속 poll이 끊긴다. 「신규 플래그 기본 off = 현행 비트 동일」(D-162) 원칙의 명시 예외 — 현행이 운영 결함이다.
- **구현**: `src/config/services.py`(`reload`) · `src/main.py`(`reload=config.server.reload`) · `.env.example` 주석 · 테스트 `tests/test_d346_server_reload.py`.
- **주의**: 개발 맥에서 자동 재시작이 필요하면 `.env`에 `API_RELOAD=true`를 직접 넣는다. 끈 뒤 남는 앱 프로세스 CPU(자식 76%였던 몫)는 별도 원인(조회 API의 JSONL 전체 재파싱 등) 실측 대상이다.
- **관련**: D-162 · D-139 · `plans/187`
