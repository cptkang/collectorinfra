## D-257. 노이즈 관제 API 결함 2건 — 상위 억제 알람명 마스킹 · 관제 스트림의 운영자 토큰 인가 (사용자 지시 2026-09-27 · `plans/116` §11.8.3 ⑧⑨ · D-196 ⑤·D-245 ③ 유지 · D-069 정합)

- **결정일**: 2026-09-27 | **상태**: 확정·구현(사용자 지시 — *"나머지 결함도 에이전트를 통해 수정하라"*)
- **결함**: ⑧ `top-suppressed`가 결정 목록·추적과 달리 알람명을 가리지 않아 같은 알람이 한 화면에서만 원문으로 보였다. ⑨ 운영자 로그인은 쿠키를 세팅하지 않고 EventSource는 헤더를 실을 수 없어, 운영자 토큰만 가진 관리자가 401 → 재연결 루프에 빠졌다(남은 일반 사용자 쿠키면 403 루프).
- **결정**: ① 저장소 `top_suppressed`에 `mask_fn`을 더해 **묶기 전에** 목록과 같은 규칙으로 가리고, 가린 이름은 단계별 한 행으로 모은다(가산 필드 `masked`). 화면은 가린 행에 알람명 정확 일치 드릴다운을 걸지 않는다(S7 「패널 건수 = 행 건수」). ② 스트림 핸들러는 Authorization 헤더의 운영자 토큰을 `require_admin_user`와 같은 함수(운영자 시크릿 서명·만료·`type=="admin"`·`sub`)로 **쿠키보다 먼저** 판정하고, 아니면 종전 `resolve_stream_user`와 역할 확인을 거친다. 운영자 토큰은 쿼리로 받지 않는다. 화면은 EventSource 대신 fetch 스트림으로 토큰을 헤더에 싣고(URL 미사용), 401·403이면 재연결하지 않고 「스트림 인가 실패」를 표시한다. `noise.js?v=10`. 스트림은 여전히 관리자 전용이다.
- **대안(기각)**: 운영자 로그인에 HttpOnly 쿠키(인증 라우트 수정·로그아웃 정리 신설) · 쿼리 토큰·단기 티켓(URL이 접근 로그·프록시에 남는다) · `resolve_stream_user`에 운영자 판정 추가(알람 스트림 D-082 동작까지 바뀐다).
- **검증**: `tests/test_api/test_noise_dashboard_api.py` 신규 18건(수정 전 실패 8) · 루프백 uvicorn + Node fetch 실측(운영자·관리자 수신 · 일반 사용자 403 · 위조 `type` 401 · 재시도 없음).
- **잔여**: 사용자 토큰 검증 `_verify_user_token`은 `type=="user"`를 확인하지 않는다(모든 사용자 경로 공통 · D-070 시크릿 분리에 기댐 · 이번 범위 밖).
