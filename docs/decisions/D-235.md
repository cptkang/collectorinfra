## D-235. 로컬 조사 프로파일의 bash 쓰기 형태 거부 — **허용목록은 그대로, 파일을 만드는 형태만 경계에서 막는다** (D-233 후속 · SREAgent D-004 전제 보강)

- **결정일**: 2026-09-21 | **상태**: 확정 · 구현 완료 (사용자 위임 — *"로컬 프로파일은 수정이 필요하면 수정하라"*) | **번호**: 등재 직전 재실측 — `## D-` 헤더 최댓값 D-234 · 「변경 이력」 최댓값 D-234 · 「채번 이력」 예약 최댓값 D-232 → **D-235**(작업 중 병행 세션이 D-234를 선점해 재부여)
- **배경**: D-233이 원격 프로파일의 bash를 제거하며 **로컬 `vm_profile()`에도 같은 리다이렉트 쓰기 구멍**이 있음을 보고 사항으로 남겼다. 실측(LLM 0 · 실행 0): `uptime > /tmp/x` · `ps aux >> /tmp/x` · `free -m &> /tmp/x` · `sort -o /tmp/x` · `uniq in out`이 **전부 `allowed`**. 원인은 holmes 0.36.0 구조다 — 허용목록이 **prefix 매칭**이고 `bashlex`는 세그먼트 분해에만 쓰여 리다이렉트가 세그먼트 문자열 안에 남는다.
- **왜 원격처럼 끄지 않는가**: 로컬 배치의 bash는 **그 배치의 유일한 L3 증거 수집 수단**이다(`plans/sre-agent/02` §8 — 에이전트와 대상이 같은 호스트일 때만 bash가 L3). 끄면 프로파일의 존재 이유가 사라진다. 원격은 데이터 경로가 MCP뿐이라 제거가 가능했지만(D-233) 로컬은 유지할 대상이 **실재**한다(`VM_DIAG_ALLOW` 읽기 명령 · 부하 가드 형태 `timeout N nice -n P …`).
- **네이티브 수단 조사(먼저 실측)**: 없다. `BashExecutorConfig` 필드는 `allow`·`deny`·`builtin_allowlist` **셋뿐**이고, `validation.py`에는 리다이렉션·`tee` 판정이 **0건**이다(소스 grep). `deny`도 prefix 매칭이라 `>`를 표현할 수 없다.
- **결정**: `sre_agent` 경계 가드 `infrastructure/bash_write_guard.py` 신설 — `RunBashCommand._validate_command`(= `requires_approval()`·`_invoke()`가 **둘 다** 지나는 단일 관문)를 감싸 **파일을 만드는 형태만 DENIED**로 돌린다. 허용목록·프로파일은 **건드리지 않는다**.
  ① 거부 대상: 출력 리다이렉트(`>`·`>>`·`>|`·`&>`·`>&` — `/dev/null`·표준 스트림·fd 복제 `2>&1` 제외) · `sort -o|--output` · `uniq <입력> <출력>` · `tee` · `dd of=`. 입력 리다이렉트(`<`)·heredoc은 읽기라 통과.
  ② **사유를 모델에 전달** — holmes `DenyReason.DENY_LIST` 경로를 타 도구 결과 `error`에 사유와 대안(*"파일을 만들지 말고 출력을 그대로 받아 읽어라"*)이 실린다. 조용히 막으면 같은 시도를 반복한다(9B 퇴행 실측).
  ③ **승인으로 뚫리지 않는다** — 거부는 승인 대상이 아니라 `requires_approval()`이 `None`을 돌려주고 `_invoke()`가 다시 거부한다.
  ④ **단일 출처** — 설치는 `DiagnosisAgent.__init__` 한 곳이며 프로파일별 분기가 없다. `remote_vm_profile`이 되돌려져 bash가 켜져도 같은 가드가 적용된다.
  ⑤ 플래그 `bash_write_guard_enabled` **기본 on**(env `BASH_WRITE_GUARD_ENABLED`). plans/80 §5.4-③(신규 플래그 기본 off=비트 동일)의 **명시적 예외**다 — 쓰기 형태가 아니면 **원본 판정 객체를 그대로 반환**하는 no-op이라 읽기 조사 경로가 비트 동일하고, off는 곧 *"읽기 전용 프로파일이 파일을 쓸 수 있다"*를 뜻한다(D-213 ⑦ 전례). **만료일 2027-03-21**(D-161 ①) — holmes가 리다이렉션을 자체 판정하게 되면 유지/삭제를 판정한다.
- **한계(명시)**: ①설치는 holmes 클래스 경계 교체라 **프로세스 전역·1회**다 — 같은 프로세스에서 한 에이전트라도 켜면 유지된다(`system_message_position_fix`와 같은 성격). ②`bashlex`가 파싱하지 못하는 명령은 가드가 판정하지 않고 holmes에 맡긴다(holmes가 이미 승인 필요 → 비대화형 미실행). ③`date -s`·`hostname <이름>` 같은 **비파일 상태 변경**은 대상이 아니다(root 권한 필요 · 파일 쓰기가 아님) — 필요하면 별건.
- **기존 결정과의 관계**: SREAgent **D-004**(읽기 전용 프로파일)와 `plans/sre-agent/02` §8(*"변경 명령은 toolset에 물리적으로 존재하지 않게"*)의 전제를 **보강**한다 — 종전에는 허용목록에 없는 명령만 막혔고 허용 명령에 붙은 리다이렉트는 통과했다. D-233(원격 bash 제거)과 같은 결함의 로컬 판이며, 수단만 다르다(제거 불가 → 경계 거부).
- **대안(기각)**: ①bash 비활성(로컬 L3 수단 소멸 — 위 「왜」) ②`deny` 목록 확장(prefix라 리다이렉트 표현 불가 · `sort --output=`류 누락) ③`allow`를 리다이렉트 없는 형태로 재작성(허용목록 문법에 그런 표현이 없다) ④holmes 포크·업스트림 PR 대기(운영 일정 밖 — 가드는 holmes가 고치면 만료일에 제거).
- **검증(2026-09-21 · LLM 0회 · 명령 실행 0회 · 파일 생성 0)**: 검증 API(`_validate_command`·`requires_approval`·`invoke`)만 호출. **수정 전 실측**: 쓰기 6형태 중 5형태가 `allowed`(`tee`만 허용목록 밖이라 `approval_required`). **수정 후**: 쓰기 8형태 DENIED · 읽기 유지 11종(가벼운 명령·부하 가드 형태·파이프) ALLOWED · 변경 명령 4종(`kill`·`rm`·`systemctl restart`·`dmesg -C`) 승인 필요 유지 · 거부 사유가 도구 결과 `error`에 노출. `sre_agent/tests` **422 passed·3 skipped → 464 passed·3 skipped**(신규 42) · `arch_check --ci` 위반 0(application → infrastructure 방향 유지) · 루트 `overfit_check --ci` 신규 유입 0.
- **주의**: ①로컬·미들웨어 조사에서 LLM이 결과를 파일로 저장하는 우회가 사라진다 — 조사 산출물은 도구 결과로만 돌아온다(설계 의도). ②가드는 **실행 경계**에만 있다. 프로파일(`VM_DIAG_ALLOW`)을 읽는 쪽(문서·테스트)은 종전과 같다. ③`middleware_profile()`은 `vm_profile()`과 같은 허용목록이라 자동으로 같이 보호된다.
