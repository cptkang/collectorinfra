## D-314. RAG 검색 0건 처분 개정 — **모든 대상 문서군이 0건이면 검색 1회 재시도(`RAG_EMPTY_RETRIES=1` 기본 on · 신규 플래그 기본 off의 명시 예외) · 0건 안내의 「다시 물어도 같은 답」 삭제 · 리트리벌 재구성은 운영 리트리벌 직접 교체 + 교체 전·후 측정 비교 · 기준 질의 세트 도입 · 결과 캐시 보류** (사용자 확정 2026-10-07 — `plans/141` G-1 (a) · G-2 (a) · G-3 (a) · G-4 (b) *"아직 실운영중이 아니므로 교체 예정. 코드 변경되면 설정 변경된 리트리벌로 바로 교체하겠음"* · G-6 (a) · G-7 (b) · plans/126 §3.3 ② 개정)

- **결정일**: 2026-10-07 | **상태**: 확정 · Phase 1 구현(브랜치 `rag_improvement`) — 폐쇄망 배포·리트리벌 교체 전후 측정 대기 · G-5 확정 — 본부 매뉴얼 R2(벡터 기준값 0.5 → 0.0 · 나머지 현행)로 재생성
- **배경**: plans/138 강제 라우팅 적용 후 폐쇄망 시험에서 같은 질의가 채팅과 관리자 「문서 검색 시험」에서 다르게 나왔다. 재현 결과 두 경로의 요청(`retrieval_id`·질의)은 같았고, 같은 요청 5회 반복 진단(`scripts/rag_hyde_repeat.py`)에서 **HyDE 가상 답변이 호출마다 달랐고 본부 매뉴얼은 25회 중 6회(24%) 0건**이었다(0건 회차에도 HyDE 생성 — 판정 P1). 아키텍처 문서는 5/5 안정. 설정 대조 결과 0건이 난 본부 매뉴얼만 벡터 기준값이 0.5(아키텍처 0.0)였다.
- **결정**:
  ① **0건 재시도** — 엔진에서 **대상 문서군 모두**가 `empty`일 때만 검색을 `RAG_EMPTY_RETRIES`회(기본 1) 다시 한다. 오류·타임아웃·자산 폐기·PII 차단은 재시도하지 않는다(종전 판정 그대로). 문서군별 재시도는 하지 않는다(원래 0건이 정상인 문서군에 헛호출). 재시도 횟수·회복 여부는 진단·로그에 남기고 사용자 응답 형태는 바꾸지 않는다. 총 시간 상한(`RAG_TOTAL_TIMEOUT`)은 재시도를 포함해 지킨다.
  ② **기본 on 예외** — 「신규 플래그 기본 off = 현행 동작」(plans/80 §5.4-③ · D-162)의 명시 예외. 근거: 실측 결함(24% 0건) 교정 · 동작이 달라지는 경우는 「모든 대상 문서군 0건」뿐 · `0`이면 종전과 같다. config 주석에 근거를 남긴다.
  ③ **0건 안내 정정** — 「검색 서비스가 관련 근거를 판정하지 못한 결과이므로 같은 질문을 다시 물어도 같은 답입니다」를 삭제하고 「잠시 뒤 다시 묻거나 문서에 쓰인 용어로 표현을 바꿔 보세요」로 바꾼다. 관리자 매뉴얼·런북의 「0건 = 확정 판정」 서술도 정정한다.
  ④ **리트리벌 재구성 방식** — 실험용 병행 리트리벌을 만들지 않고 **운영 리트리벌을 직접 삭제·재생성**한다(실운영 전). 비교는 같은 도구로 **교체 전 측정 → 교체 → 교체 후 측정**을 해 결과 파일을 대조한다. 교체 전 측정을 건너뛰지 않는다(삭제 후에는 옛 설정으로 다시 잴 수 없다).
  ⑤ **기준 질의 세트** — `testdata/rag_gold/rag_gold_v1.yaml`(질의 초안 20개 · 기대 문서는 사용자 기입)로 0건률뿐 아니라 **적중률**(기대 문서가 결과에 든 비율)을 잰다. 설정 교체 판정 · 이후 회귀 점검 · 질의 형태 A/B 판단에 쓴다.
  ⑥ **결과 캐시 보류** — 엔진 캐시(`RAG_CACHE_TTL`)는 채팅에 연결하지 않는다. 재구성 뒤에도 비결정이 남으면 다시 판단한다.
- **근거**: 사용자 결정. 반복 진단 수치(plans/141 §2.1) · 설정 대조(§2.3) · 재시도 효과 추정(독립 가정 시 24% → 약 6%). plans/126 §3.3 ②의 전제(「0건 = 플랫폼의 확정 판정 → 재시도 비권장」)가 실측(같은 요청이 회차마다 0건/정상으로 갈림)과 맞지 않는다.
- **구현**: `plans/141` W1(문구) · W2(`src/doc_qa/service.py` 재시도 · `RagConfig.empty_retries`) · W3(아키텍처 설정 스냅샷 정정) · W4(측정 도구 `--gold`·`--compare`·`--with-retry`) · W5(기준 질의 초안 — 작성 완료).
- **주의**: ① 재시도는 0건을 줄일 뿐 근거 묶음의 회차 변동은 줄이지 않는다 — 근본 처방은 리트리벌 설정(plans/141 §2.4 · G-5). ② 0건 재시도로 늘어나는 것은 검색 호출뿐이고 우리 쪽 LLM 호출은 늘지 않는다. 플랫폼은 호출마다 HyDE를 돌린다.
- **대안(기각)**: 문서군별 재시도(헛호출) · 재시도 2회 이상(2회째 효과는 작고 지연만 늘어남 — 추정 6% → 1.4%) · 기본 off(시연·운영에서 켜는 것을 잊으면 결함이 그대로) · 실험용 병행 리트리벌(실운영 전이라 불필요 — 사용자 판단) · 결과 캐시 지금 연결(일관성은 얻지만 첫 질문의 운은 그대로 · 재구성 결과를 먼저 봄).
- **관련**: D-162 · D-307 · plans/80 §5.4-③ · `plans/126`(§3.3 ② 개정 부기) · `plans/138` · `plans/141`
