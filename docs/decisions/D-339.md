## D-339. 로그 비밀값 가림 — 레코드 팩토리에서 전역으로 가리고 패키지마다 바이트 동일 사본을 둔다

- **결정일**: 2026-10-17 | **상태**: 확정 · 구현(`plans/167` W0·W1 · 커밋 없음)
- **결정**:
  ① **가림 위치**: 로그 레코드가 **만들어질 때** 가린다(`logging.setLogRecordFactory` 감싸기 · 멱등 설치). 가리는 대상은 렌더 결과(`msg % args`), 예외 트레이스백(`exc_text`), `stack_info`다. structlog 경로(본체 `setup_logging`의 `PrintLoggerFactory` — stdlib 우회)는 `JSONRenderer` 바로 앞 프로세서로 가린다. 가린 자리는 `***`로 바꾸고, 호스트·포트·DB 이름·사용자명·SQLSTATE·예외 타입은 남긴다. 비밀 꼴이 없는 레코드는 `msg`·`args`를 그대로 둔다. `uvicorn.access` 레코드는 인자만 가리고 `args` 튜플을 유지한다. 가리다가 예외가 나면 원 레코드를 그대로 통과시키고 표준 오류에 1회만 경고한다.
  ② **패키지 경계(D-139)**: 정본은 `src/utils/log_masking.py`(stdlib 전용)다. 별도 프로세스 패키지에는 **바이트 동일 사본**을 둔다. 사본 위치는 `mcp_server/mcp_server/log_masking.py` · `apm_gateway/apm_gateway/adapters/log_masking.py` · `sre_agent/sre_agent/infrastructure/log_masking.py` · `fabrix_proxy/fabrix_proxy/log_masking.py`다. 사본 일치는 루트 `tests/test_utils/test_log_masking_copies.py`가 파일 바이트로 단언한다. `noise_gate/alarm_server`는 사본 없이 정본을 import한다(D-139 ② 역방향 허용 `utils`).
  ③ 기존 로그 파일은 소급해서 가리지 않는다.
- **근거**: W0 실측(`plans/167` §6) 결과 DB 드라이버 예외 문구(asyncpg·aiomysql·redis)에는 비밀번호가 없었다. 실제로 노출되는 경로는 세 가지다. httpx `HTTPStatusError`·`repr(Request)`의 URL 쿼리(`api_key=`·`token=`), 애플리케이션이 URL·DSN·연결 문자열을 `%s`로 찍는 경우, 트레이스백 소스 줄의 리터럴이다. 루트 핸들러에 필터를 다는 방식은 uvicorn을 놓친다. uvicorn `LOGGING_CONFIG`는 `uvicorn`·`uvicorn.access`에 자기 핸들러를 달고 `propagate=False`로 두기 때문에, `Exception in ASGI application` 트레이스백과 접근 로그(경로·쿼리)가 루트를 거치지 않는다. 그래서 「누락 없는 쪽」(메인 결정 §4 ①)을 따라 레코드 팩토리를 택했다. `sre_agent`(LLM 키 보유)와 `fabrix_proxy`(FabriX 토큰 보유 · auditor M3)도 같은 위험이 있어 포함했다. 포함 비용은 패키지마다 사본 1개와 진입점 2줄이다.
- **구현**: 진입점 7곳에서 설치한다(대개 `basicConfig` 직후). 본체 `src/security/audit_logger.py` `setup_logging`(+ structlog 프로세서), `src/main.py` `main()` 첫 줄(uvicorn reload 부모 프로세스), `noise_gate/alarm_server/__main__.py`, `mcp_server/mcp_server/__main__.py`, `apm_gateway/apm_gateway/__main__.py`, `sre_agent/sre_agent/run_service.py`, `fabrix_proxy/fabrix_proxy/__main__.py`다. 패턴은 URL userinfo, 민감 키 이름의 키·값(`*password`·`*pwd`·`*token`·`*api_key`·`*client_key`·`*passphrase`·`*credential(s)`·`*secret*` · ODBC `PWD={…}` · 따옴표·이스케이프·`b''`), `Authorization`·`Proxy-Authorization`·`x-generative-ai-client`·쿠키 헤더, `Bearer`, 쿼리 `?key=`, JWT, Google API 키(`AIza…`)다. 비밀 후보 낱말이 없으면 치환 없이 바로 통과시킨다. 정규식은 식별자를 한 번만 잡고 판정은 콜백에서 하며 소유 수량자를 쓴다. 64KB 적대 입력이 0.2초 안에 끝남을 테스트로 고정했다. 매뉴얼은 `admin.md` A-10 근처에 1문장을 넣었다.
- **주의**: ⓐ 정본을 고치면 사본 4개에 **파일째 복사**한다(테스트가 바이트 불일치를 잡는다). ⓑ 테스트에서 실 `setup_logging`·진입점 `main()`을 부르면 팩토리가 전역 설치되므로 픽스처로 원래 팩토리를 복원한다. 163·184의 「원문은 로그에 남는다」 caplog 단언은 비밀 아닌 부분(호스트 이후)으로 좁혔다. ⓒ 남은 한계는 이렇다. `extra=` 필드는 팩토리 뒤에 대입돼 가리지 않는다. URL 비밀번호 안에 인코딩 안 된 `/ ? #`가 있으면 가리지 못한다. `sk-`·`ghp_`·PEM 본문 꼴은 다루지 않는다. 경고는 1회만 하고 이후에는 침묵한다. `has_token=`·셸 `PWD=` 값은 과하게 가려진다. ⓓ 범위 밖은 감사 JSONL 직접 쓰기·`mcp_server/sql_log.py`·`print`·`logs/pii_block/`·사내망 `verify=False`(D-332 부기)다. ⓔ 장기 실행 중인 MCP 9099·9097·게이트웨이 9096·본체는 **재기동해야 반영된다**.
