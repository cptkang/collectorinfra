## D-365. 용도별 LLM 평면(역할) — `router`·`planner`·`answer` · 따로 설정하지 않으면 현재 워커 LLM을 항목 단위로 승계

- **결정일**: 2026-11-04 | **상태**: 확정 · 구현(`plans/212` W0~W5 · 기본 off = 현행 비트 동일 · 운영 전환 W6은 별도 결정) | **관련**: D-174(부기 1) · D-037 · D-222 ③ · D-340 ③④ · D-194 · D-169 · D-251 · D-127 · D-240 · D-255
- **배경**: 사용자 지시 *"질의 응답과 시멘틱라우팅, 딥에이전트 등의 LLM모델과 엔드포인트를 각자 다르게 하려고 한다."* 지금까지 LLM 평면은 워커(`LLM_*`)와 오케스트레이터(`ORCHESTRATOR_*`) 2개였다. 시맨틱 라우팅·의도 계획·최종 응답 합성은 모두 그래프가 만든 워커 인스턴스 1개를 썼다.
- **결정**(§7 Q1~Q8 권고안 · 사용자 2026-11-04 확정):
  ① **역할 3종**: `router`(3단 `semantic_router`) · `planner`(2단 `intent_planner`·`replanner` · 3단 계획 루프 `plan`·`replan`) · `answer`(응답 합성). 나머지는 `worker` 그대로다. 딥 에이전트 도구 워커(Q6)와 noise_gate 알람 분석(Q3)도 worker다.
  ② **설정**: 역할마다 공통 5필드 `LLM_<ROLE>_{PROVIDER,BASE_URL,MODEL,API_KEY,TIMEOUT}`(`LLMConfig` 필드 · 기본 빈 값/0). provider 고유 노브(FabriX client_key·llm_config, vllm verify_ssl·thinking, mlx max_tokens 등)는 항상 워커 값을 쓴다.
  ③ **승계 원칙(사용자 지시)** — *"LLM을 별도로 각각 설정하지 않으면 현재 설정된 LLM을 사용"*. 승계는 **항목 단위**다. 역할 항목이 0개면 그래프는 워커와 **같은 객체**(`is`)를 주입한다. 일부만 적으면 적은 항목만 바뀌고, 나머지는 해석된 provider 기준으로 현재 워커 필드 값을 쓴다. 승계는 그래프를 조립할 때마다 다시 해석한다(리로드로 반영 · Q7).
  ④ **필수값 누락은 기동 실패**(D-340 ③과 같은 규칙): 해석 뒤 엔드포인트(gemini 제외), 모델(vllm·fabrix), gemini 키 중 하나라도 비면 `ValueError`다. 워커로 몰래 대체하지 않는다. 확정 단에서 쓰지 않는 역할이라도 설정이 잘못됐으면 조립이 실패한다.
  ⑤ **`answer` 연결**: `create_llm(purpose="answer")`는 `role="answer"`를 자동 적용한다(호출부 무변경 · Q2). W0 실측 결과 채팅 그래프는 응답 노드에 워커를 주입해 그 분기가 실행되지 않았다. 그래서 응답 합성 노드 4곳(2단 `result_aggregator` · `general_inference` · 3단 `finalize` · `output_generator`)에 answer 인스턴스를 노드 단위로 주입한다(노드 안 중간 합성 포함).
  ⑥ **과금 판정 확장**(D-127 우회 차단): `scripts/scenario/preflight.py` `external_planes(worker, orchestrator, *, roles=)`는 명시된 역할 provider를 워커 비과금 집합으로 판정한다. 판정 정의는 1곳 그대로다. 설정을 못 읽으면 외부로 판정한다. cfg를 가진 소비처(시나리오·벤치·eval_routing·demo·itam_bench·apm_bench)는 모두 역할을 넘긴다. `_mlx_planes`는 역할 mlx 평면을 포함하고, 서로 다른 base_url마다 1회씩 점검한다.
  ⑦ **오케스트레이터는 승계 대상이 아니다**(Q8): `ORCHESTRATOR_*`의 키와 동작은 무변경이다. 기동 로그·과금 판정·문서 표에만 함께 적는다.
- **근거**: 기존 provider 팩토리에 「역할 값으로 덮어쓴 설정 사본」을 넘기므로, provider별 처리(D-042 thinking 가드 · D-060 SSL · D-222 스트림 청크 타임아웃 · D-194 프로파일)를 고치지 않고 그대로 재사용한다. 기준 경로(2단)에 효과를 내려면 3단 라우터만이 아니라 `planner`도 분리해야 한다(D-251). 역할 provider를 과금 판정이 보지 못하면 `LLM_ROUTER_PROVIDER=gemini`가 승인 없이 실행된다.
- **구현**: `src/config/llm.py`(필드 15) · `src/llm.py`(`LLM_ROLES`·`_ROLE_WORKER_FIELDS`·`resolve_role_config`·`create_llm(role=)`·`create_role_llm`·`describe_llm_planes`) · `src/graph.py`(역할 해석·주입 · 기동 로그 `LLM 평면: …` 1줄 · URL은 호스트만, 키 없음) · `src/routing/semantic_router.py`·`src/orchestration/{intent_planner,replanner}.py`(내부 생성 `role=`) · `scripts/scenario/preflight.py` 외 하네스 소비처 · `src/api/settings_catalog.py`(API_KEY 3개 시크릿 · 나머지 12개 리로드 · 승계 힌트 `inherited_hint`) · `src/static/js/admin.js` · `config/settings_help/llm.yaml` · `.env.example`·`.encenv.example` · `docs/03_setup_guide.md` §7.6 · `docs/21_orchestration_ladder.md` §5 · 관리자 매뉴얼 A-91. 테스트 `tests/test_llm_roles.py`·`tests/test_graph_llm_roles.py`·`tests/test_preflight_role_planes.py`·`tests/test_api/test_settings_llm_roles.py`(설정 카탈로그 항목 수 484 → 499).
- **주의**: `LLM_<ROLE>_API_KEY`는 시크릿이라 바꾸면 재시작해야 반영된다(리로드 대상에서 제외 — 카탈로그 규칙). `.env`에 `LLM_<ROLE>_TIMEOUT=`처럼 빈 값을 두면 정수 파싱이 실패한다(`.env.example`은 주석 줄). 채팅 경로에 D-194 answer 프로파일이 걸리지 않는 현행 사실은 answer 역할을 설정하지 않으면 그대로 남는다. 운영 전환(라우터·계획을 사내 vLLM 등으로 옮기는 것)은 별도 사용자 결정이고, 그때 D-174 ②(`MIN_RELEVANCE_SCORE` 재정산 · 모델·시점 기록)와 ③(3건 일괄 재평가)을 함께 처리한다.
