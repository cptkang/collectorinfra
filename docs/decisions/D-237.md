## D-237. 축 판정의 비교 단위를 둘로 나눈다 — **레벨 간 직접 비교 · 대조군 arm 자동 판정 · arm 실효 설정 스냅샷** (plans/97 v3 · plans/93 §4.5·§5.3 · D-219 후속)

- **결정일**: 2026-09-21 | **상태**: 확정 (구현 완료 · 실 스위프 재측정은 사용자 승인 대기) | **번호**: 등재 직전 실측 2026-09-21 — `## D-` 헤더 최댓값 **D-236** · 「변경 이력」 표 최댓값 **D-236** · 「채번 이력」 표 예약(D-105·115·134·158·163~168·176·195·210·212·214·223·226·232) 대조 → **D-237**
- **배경**: 사용자 지시 *"이 설정이 되어 있는 경우와 되어 있지 않은 경우를 모두 검증하여 효과적인 설정을 선택하는 것이 이 벤치마크 테스트의 목적이다 … 왜 설정이 되어 있는지를 묻는거냐?"* 가 드러낸 것은 「기준선 실효값을 모른다」가 아니라 그보다 앞선 결함이었다. **`compare.judge()` 는 모든 arm 을 기준선하고만 비교한다**(`compare.py`) — `axes.expand_ofat`(`axes.py:172-186`)가 축마다 레벨별 arm 을 펴는데, 불린 축이면 `-true`·`-false` 두 줄이 **각각 기준선과** 비교돼 나오고 **"켰을 때 vs 껐을 때"는 어디에도 계산되지 않는다.** 기준선 실효값이 `true` 면 `-true` 줄은 대조군(순수 노이즈)인데 판정표가 구분 없이 축 효과로 렌더링했다 — run `20260914-185540` 에서 그런 arm 3건이 지연 -1,430ms·+1,419ms·+4,009ms 를 축 효과처럼 실어 보냈다. 그 판정을 자동화하려면 arm 실효 설정이 필요한데 `run.json` arm 레코드 키는 9개뿐이라(`name·port·valid·tier·degraded_reason·echo_ok·echo_mismatch·auth_enabled·reasons`) **`plans/93` §4.5의 「arm: 실효 설정 전체 스냅샷」계약이 미이행**이었다.
- **결정**: ①**비교 단위를 둘로 명시한다** — `arm ↔ 기준선`("이 값이 지금 설정보다 나은가")과 **`레벨 ↔ 레벨`**("이 축의 최적 레벨은 무엇인가"). 후자를 `compare.compare_levels()`·`compare.optima()` 로 신설하고, 축 1개당 판정 1줄을 낸다. ②**축 판정 어휘는 전용 2종**(`BEST_LEVEL`「최적 레벨」·`LEVELS_TIED`「레벨 간 차이 없음」) + `판정 불가`다 — arm 판정 5어휘(§5.5 폐쇄 집합)와 **섞지 않는다**. 묻는 것이 다르기 때문이다. ③**arm ↔ 기준선 판정은 유지한다** — 기준선 대비 절대 위치는 §6.7 마이그레이션 판단의 입력이고 지우면 회귀다. 리포트는 축 표를 **먼저**, arm 표를 근거로 낸다. ④**레벨 3개 이상인 축은 축 안에서도 Benjamini–Hochberg 보정**을 한다(축 사이 보정과 같은 장치). 우세 레벨이 둘 이상으로 갈리면 **최적을 만들어내지 않는다**(`판정 불가`). ⑤**대조군 arm 을 자동 판정한다** — 실효 설정 지문(비결정 필드 제외)이 기준선과 같은 arm 은 `(대조군)` 으로 표기하고 축 문장에 어느 레벨인지 적는다. **비교에서 빼지는 않는다** — 대조군 vs 다른 레벨이 가장 깨끗한 대비다. ⑥**그 arm 들의 쌍체 델타가 노이즈 바닥이다** — `--repeat 1` 런에서도 바닥을 실측할 수 있는 유일한 경로이고, 그 값이 `judge(noise_floor_pp=…)` 로 들어간다. ⑦**93 이 자기 스냅샷을 만든다**(§4.5 이행) — 서버 기동 **전에** arm 마다 자식 파이썬으로 `load_config()` 를 한 번 돌려 `config_snapshot.json` 을 산출한다. **기준선 에코가 실패하면 대조군 판정을 아예 하지 않는다**(추정 금지 · 과거 런은 자동 판정 대상 아님).
- **근거**: 신규 수집 경로를 만들지 않고 전부 기존 장치를 재사용했다 — 자식 에코는 `probe.echo_config`(`probe.py:131`, D-129 pydantic 인트로스펙션이 SSOT), 비결정 필드 제외는 `probe.detect_nondeterministic_keys`(`probe.py:220` — `auth.jwt_secret` 이 미설정 시 기동마다 생성되는 것을 이미 잡는다. 하드코딩 목록을 새로 만들면 낡는다), 지문은 `probe.config_fingerprint`, 다중비교는 `compare.benjamini_hochberg`, 쌍체 검정은 기존 `paired_binary`·`paired_metric`(두 관측 집합을 받을 뿐 `baseline`/`variant` 는 이름일 뿐이라 arm-vs-arm 에 그대로 쓰인다 — 실측 확인). 민감값은 에코 단계에서 `sha256:` 해시로 바뀌므로 스냅샷에 평문이 남지 않는다. 비용은 arm 당 1~2초(62 arm ≈ 2분 / 93시간 런의 0.04%).
- **대안(기각)**: 기준선 실효값을 **사람에게 묻기**(사용자가 명시 기각 — 하네스가 기록·판정할 값이다) · 대조군 arm 을 **전개에서 빼기**(가장 깨끗한 대비를 버린다) · arm↔기준선 판정을 레벨 간 비교로 **대체**(마이그레이션 판단 입력 소실 · 회귀) · 축 판정에 arm 5어휘 재사용(묻는 것이 달라 문장이 거짓이 된다) · 라이브 서버 에코를 94에서 받아오기(§1.5 소유 경계 · 잔여 R-9로 등재)
