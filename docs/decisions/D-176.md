## D-176. 복합 질의 **실행 그룹** — 순차 실행 · 선행 스코프 배관 · 방언 그물 (1차)

- **결정일**: 2026-08-28 | **상태**: 확정 (**1차 4개 모듈 구현 완료**; 2차는 `plans/82` §13 U1~U13 확정 후)

- **실측 정정 4건**(설계 전제를 바꿨다):
  1. **"쿼리가 DB 종류에 맞게 작성되지 않는다"는 생성 문제가 아니다.** 방언 힌트는 이미 DB별로 주입되고, 실제 결함은 **멀티 경로 검증기에 방언 그물이 없다**는 것 — 단일 경로는 `sql_validation`이 엔진별 행 제한 절을 자동 보정하는데 `_validate_sql_simple`에는 그 검사가 없어 **DB2 대상의 `LIMIT`이 검증을 통과하고 실행 시점에 죽으며 재생성 기회가 없었다**(`graph.py` 무조건 전진).
  2. **순차 순회는 이미 있고 없는 것은 순서 보장**이다 — 순서가 `relevance_score`(LLM 자기보고)에 달려 있었다.
  3. **`"abd00 서버의 프로세스"`는 막다른 안내로 끝난다** — `_resolve_db_id` 3순위가 전부 실패해 *"위치를 지정해 주세요"*. 그런데 운영 `.env`는 **세 존 전부 프로세스 API가 매핑**돼 있어 순회 탐색이 기술적으로 가능했다.
  4. ★ **선행 스코프 배관 결손** — 병합 행에 `_source_db`가 있고 `TargetRef.db_id` 필드도 있는데, `build_prior_targets`가 **호출부가 준 db_id 하나를 전 대상에 도장**하고 `_resolve_db_id`는 `prior_targets`를 보지도 않았다. abd00이 공동존에 있어도 후속 조회가 은행존 API를 쳤다.
- **비용 실측**(감사로그 `query_execution` 918건): **존당 SQL 실행 p50 49~53ms**(b0 49 / gp 49 / yd 53). 존 수 증가의 비용은 SQL이 아니라 **스키마 분석(존당 ≤20s)·LLM 생성(스키마 키당 1회, 90k~136k tok)** 에 있다 → **탐색 단계에 사용자를 붙잡는 것은 순손실**이다.
- **결정 (1차 구현분)**:
  1. **방언 그물** — 멀티 경로 간이 검증에 행 제한 절 방언 검사를 넣는다. **보정이 아니라 거부**다(`LIMIT`↔`FETCH FIRST` 치환은 중첩·서브쿼리에서 틀린다). 최상위만 보고 문자열 리터럴을 제거해 위양성을 막으며 **행 제한 절 부재는 문제로 보지 않는다**(기존 동작 보존). 더해 **실행 오류 후 재생성 1회** — **문법·식별자 오류만** 대상이고 연결·타임아웃은 제외한다(재생성해도 같다).
  2. **레지스트리 축** — `solutions`(1차 축)·`zone_groups`(2차 축) 신설. **조회 순서 정본은 `query_order`**(은행존 10 → 공동존 20)이며 **`zones:` 선언 순서는 재정렬하지 않는다**(그것은 알림 RBAC 선택지 순서 — 겹치면 한쪽 요구가 다른 쪽을 흔든다). `partition_execution_groups`는 **입력 순서에 불변**이다(그룹 내부 순서도 레지스트리 선언 순서).
  3. **선행 스코프 배관** — 행별 `_source_db`를 **`TargetRef.db_id` 정본**으로 승격(태그 없으면 폴백 → 단일 DB 경로 비트 동일), `_source_db`는 **식별자 컬럼 후보에서 배제**. `_resolve_db_id` 우선순위는 **`task.db_ids` > `prior_targets` > `previous_db_ids` > 위치어** — 이번 턴 결과가 직전 턴 승계보다 강하되 **존 선택 UI 확정은 여전히 최우선**이다(D-143 보존).
  4. **그룹 순차 루프** — `execution_groups` 미설정이면 **종전 경로와 호출 순서·반환 키 동일**(회귀 0). 그룹마다 `_prepare_multi_run`을 새로 불러 `sql_by_schema`를 그룹 스코프로 격리(gp/yd 공유·b0 분리 — b0+gp PII 가설 검증에도 필요). 그룹은 **실패 격리 단위**. **부분 결과는 peer 그룹만** 적재(discovery는 경과, dependent는 앞 그룹만으로 답이 안 된다). `result_merger`가 만들고 **버리던 `db_result_summary`를 승격**.
  5. **계측을 범위 선택보다 먼저** — **P13(측정이 최적화보다 먼저)**. 유형별 p50/p90과 **표본 수**를 내고 **표본 <20이면 예상 시간 문구를 만들지 않는다**(근거 없는 임계가 무기한 실동작한 D-174 ② 전례 차단).
