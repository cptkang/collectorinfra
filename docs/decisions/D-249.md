- **배경(사용자 지시)**: *"82번 계획 파일의 구현 현황을 점검하고 현재 구현되어 있는 현황을 분석하여 계획을 업데이트하라."* → v7 재실측이 결함·갭 R-1~R-6을 찾았다(`plans/82` §0.5.3). 이어서 *"발견된 문제를 개선하여 계획을 업데이트하라."* R-4는 사용자 결정으로 `plans/103` P1-3에 넘겼다. 작업 중 R-7을 찾아 함께 고쳤다.
- **결정**:
  - **① 동일 스키마 소급 복구(D-153)는 run 단위로 한다 (R-1)** — `_retro_recover_same_schema(run)`으로 떼어, 단일 run 경로는 종전 위치에서, 그룹 경로(D-206 존 동시 조회)는 **그룹 run마다** 부른다. 병합 run에서 부르면 첫 그룹(은행존)의 `sql_by_schema`만 보여 공동존 gp 실패를 yd SQL로 복구하지 못하고 **로그 없이** 건너뛰었다. 운영에서 실제로 도는 경로의 결함이다.
  - **② 존별 부분 결과를 그룹 완료 즉시 보여 준다 (R-2)** — 전용 SSE 패킷(`plans/82` §4.9 `_emit_group_packet`)을 새로 만들지 않고 **D-204 진행 이벤트 채널에 `group` 종류**를 더한다(`_emit_group_event` — 시작·완료). 완료 이벤트에는 건수·소요와 **`DataMasker`로 마스킹한 앞 N행**을 싣는다. N은 `API_SSE_GROUP_PREVIEW_ROWS`(기본 10, 0이면 행 미리보기 없음)다. 오류는 에러 문자열이 아니라 **DB 표시 이름만** 싣는다(SQL·값 혼입 방지). 미리보기는 peer 그룹만 싣는다. UI는 커서 아래에 존별 카드를 그리고 완료 시 접으며, 중단·오류가 나도 카드를 남긴다. 최종 응답은 종전대로 두 존을 합친 한 번이다.
  - **③ 그룹 경과는 노드 안에서 낸다 (R-3)** — ②가 노드 안에서 나가므로 사다리 1·2·3단 모두 처리현황에 그룹 경과가 보인다. 종전에는 task 경로(1·2단 `_summarize_tasks`)에서만 보였다.
  - **④ 그룹 소요는 감사 파일에 남긴다 (R-5)** — 이벤트 `group_execution`(group_key·label·kind·db_ids·row_count·elapsed_ms·error_db_ids). `elapsed_ms`는 스키마 분석·생성·재생성·소급 복구를 포함한 **그룹 전체** 소요다. 인메모리 계측(`group_metrics`)은 그대로 두고 **신규 저장소는 만들지 않는다**. 감사 기록 실패가 실행을 막지 않는다.
  - **⑤ 범위 선택의 상쇄 장치를 이행한다 (R-6)** — 범위 질문을 시간 임계 없이 그룹 2개 이상이면 묻기로 한 결정(U9·U11)은 **발동률 관측**을 전제로 했다. ⓐ파이프라인 전 역질문 발동을 `clarification_issued`(kind·axis·option_count)로 남긴다. 발동률의 분자이고 분모는 같은 파일의 `user_request`다. 원문은 싣지 않는다(D-183). 진입점 4곳(텍스트 2 · 파일 2)에 배선한다. ⓑ좁힌 턴을 `scope_narrowed`(selected·skipped·skipped_db_ids)로 남긴다(§5.3 불변식 6 ③).
  - **⑥ 예상 시간 문구를 배선한다 (R-7)** — 라우트가 `group_stats`로 그룹별 p50·p90을 싣고, **표본이 가장 적은 그룹**의 표본 수를 `samples`로 넘긴다. 한 그룹이라도 표본이 20 미만이면 합계 추정의 근거가 없으므로 문구를 내지 않는다. 종전에는 `samples`를 넘기지 않아 문구가 영영 나오지 않았다.
