## D-264. 매뉴얼 녹화에서 드러난 제품 결함 일괄 수정 — **사용법 답변은 코드가 조립 · 조회 권한 밖 DB·존은 안내·역질문에도 보이지 않는다 · 실행 SQL은 작업별 결과에서 모은다 · 양식 없는 파일 요청은 사실대로 안내 · EAV 값 정렬은 D-199 환산식** (`plans/116` §10.3 · 사용자 지시 2026-09-23 *"발견한 오류를 수정하라."* · D-038 좁힘 · D-199·D-232 후속)

- **결정일**: 2026-09-23 | **상태**: 확정(구현 완료 · 단위·회귀 테스트 · 매뉴얼 사례는 운영 설정으로 재녹화) | **번호**: 등재 직전 3곳 grep — `## D-` 헤더 최댓값 D-255 · 「채번 이력」 D-253(예약) · 안내 라인 「다음 D-256」 → **D-256** → 2026-09-28 원격 `multiintent` 병합 시 **D-264로 재부여**(원격이 D-256~D-263을 먼저 푸시)
- **결정**:
  ① **사용법 문의는 LLM 없이 코드가 답을 조립한다**(D-038 「사실은 코드, 문장만 LLM」을 사용법 문의에 한해 「전문 코드 조립」으로 좁힘). 판정 `src/utils/usage_query.py` `is_usage_query`(「지원 가능한 소스」·「조회 가능한 데이터」·「뭘 할 수 있」 등 강한 표현 단독 · 「사용법·도움말」은 에이전트 지칭이거나 대상 없을 때만 — 「쿠버네티스 사용법」 제외). 2단 `intent_planner` 계층 A ③.8 · 3단 `semantic_router` 우선순위 4.5에 **결정적 단락**(둘 다 양식 업로드 판정 뒤) — LLM 분해·분류와 무관하게 `general_inference`로 간다. 답은 활성∩허용 소스 + 지원 조회 유형 + 사용 요령이고, 조회 가능한 소스가 0이면 권한 요청 안내(`ACCESS_DENIED_MESSAGE`)만 낸다.
  ② **조회 권한 밖 DB·존은 안내에도 노출하지 않는다**(D-232 후속). 「DB 목록」(`cache_management._handle_db_guide`)과 존 역질문 선택지(라우트 pre-gate 4종 · 3단 후단 게이트)를 `db_authz.authorized_db_ids`(활성∩허용 · 관리자 = 활성 전체)로 거른다. 존 선택지: 권한 내 존 ≥1이면 종전대로 묻고 0이면 묻지 않는다(빈 목록을 「제한 없음」으로 읽는 `build_zone_clarification` 폴백을 명시 차단). 관리자도 DB 목록에서 비활성 DB 캐시는 보지 않는다. **2단 후단 게이트(`subagents._zone_clarification_or_none_task`)는 병행 세션의 2단 인가 우회 수정에 넘겼다.**
  ③ **「실행된 SQL 보기」는 작업별 결과에서 SQL을 모은다.** 스트림 라우트가 첫 `final_response` 출력에서 끝나고, 2단은 SQL을 `task_results[tid].generated_sql`에만 담는다(최종 상태 top-level은 빈 값 — 녹화 24건 실측). 라우트가 루트 직속 노드 출력의 `generated_sql`·`task_plan`·`task_results`·`db_executed_sqls`를 누적해 top-level → 작업별(계획 순서 · 여러 건이면 `-- [t1]` 머리 주석) → 멀티 DB 순으로 고른다. 스트림·비스트림 10곳 공통.
  ④ **양식 없이 「엑셀로/워드로」를 요청하면 파일을 만들지 않았다고 사실대로 알린다.** 양식 없는 새 통합문서 생성은 요구사항(Phase 2 = 양식 채우기)에 없다 — 기능을 만들지 않고 안내를 바로잡는다: 첨부가 없으면(`file_type` 없음) 텍스트 결과 앞에 「양식 파일이 첨부되지 않아 … 만들지 않았습니다」 + 행이 있을 때만 CSV 안내. 첨부했는데 양식이 유실된 경우는 종전 D-059 사유 유지.
  ⑤ **EAV 값 정렬은 D-199 환산식으로 한다.** 피벗 조립(`assembler.eav_sort_expr`)과 LLM SQL 교정(`validators.ensure_eav_value_order`)이 숫자 속성은 NUMERIC 캐스트, 크기 속성(`TotalSize`)은 `query_gen_common._unit_normalized_expr`(TB×1024·GB·MB÷1024·KB÷1048576·**무단위=원값**)로 정렬한다 — 화면 값('8.0 GB')은 바꾸지 않는다. 순위 질의는 식별 칼럼을 주입한다. **무단위를 MB로 보는 안은 기각**(사용자 확정 — D-199 ① 유지 · 운영 3존 무단위 0건 · 샌드박스 시드 모양은 D-199 ③).
  ⑥ **결정적 결함 2건**: `sql_validation._has_limit_clause`가 주석을 먼저 걷는다(주석 안 괄호로 바깥 LIMIT을 못 봐 `LIMIT 1000 LIMIT 1000` 문법 오류 · 주석 안 `LIMIT`을 제한으로 오판) · 알람 조립 `_parse_alarm_severity`가 「심각**도**」를 등급어로 읽지 않는다. 활성 상태 리터럴 검증기는 함수 감싼 비교(`LOWER(x)='active'`)·역순 비교도 반려.
  ⑦ **`POLESTAR_DB_IDS` 코드 기본값은 빈 값 유지 + 기동 경고**(사용자 확정). 활성 DB의 레지스트리 솔루션이 등록 어댑터 이름과 같은데 담당 ID(`<어댑터>_DB_IDS`)에 없으면 기동 로그 WARNING 1줄(`db_adapters.log_adapter_ownership_startup` · `build_graph`). 동작은 바꾸지 않는다.
  ⑧ **관리자 화면 토큰 만료 반복 이동 수정** — `admin.js`가 실제로 보낸 토큰 키를 지운다(noise.js D-247 수정과 같은 방식) · `dashboard.html` 캐시 버전 `v=9`.
  ⑨ **샌드박스 시드 정정** — `testdata/pg/init` 07·09의 서버 모델 속성명 `MODEL` → `Model`(운영 프로필·나머지 42대와 일치 · CPU 모델 `MODEL`은 유지). 실행 중인 샌드박스 DB는 바꾸지 않았다(재초기화 시 반영).
- **근거**: 매뉴얼 사례 녹화·샘플 대조(`plans/116` §10.3). **§10.3의 결함 중 4건은 제품 결함이 아니었다** — 녹화 스냅샷 `.env`가 `POLESTAR_DB_IDS`·`TEXT2SQL_SEMANTIC_COMPOSE`를 적지 않아 폴스타 검증기·결정적 조립·시맨틱 컴파일러가 꺼진 채 녹화됐다(활성 알람 `'active'` 리터럴 0건 · 복합 제조사 null · 경고 이상 심각도 조건 누락 · 「논리코어 43대」는 기준 SQL 오류로 정답 23대). 운영 설정으로 재현하면 맞게 나온다(로컬 MLX). 스냅샷은 이제 질의 동작 키를 명시 고정하고 `verify()`가 어댑터·컴파일러 활성을 단언한다(docs/18 2026-09-23).
- **남은 것**: 요약 문장의 심각도 이름·기준일 오기(LLM 품질 — 요약 프롬프트에 결과 기간값·심각도 매핑 주입 제안) · 활성 알람 조립에 정렬 정보 없음(「심각도 높은 순」도 발생 시각 순) · 2단 후단 존 게이트(병행 세션) · 수정별 실서버 브라우저 확인은 「실행된 SQL 보기」(재생 캡처)만.
- **대안**: ①을 프롬프트 보강으로 — 기각(플래너·라우터 LLM이 버튼 문장을 `data_query`로 보내는 것을 목 테스트로 재현 · 소스 목록이 비면 LLM이 원천을 지어냄). ④ 양식 없는 Excel 생성 기능 신설 — 기각(요구사항 밖 · 이번 지시는 오류 수정).
- **부기(2026-09-28 · 운영 설정 재녹화에서 드러난 결함 3건 · 같은 지시)**: ⑩ **턴을 넘는 복수 지시어(「그 서버들」)가 앞 턴 서버로 좁혀지지 않았다** — 결정적 조립의 서버 범위가 같은 턴 선행 결과에서만 만들어져 54대 전체를 조회(2단)하고, 3단은 `subagents._inject_demonstrative_hostname`이 첫 1대만 서버명을 `hostname` 필드로 붙여 0건. `prompt_blocks.demonstrative_entity_scope`(원문 지시어 · 이번 턴 서버 필터 없음 · 직전 결과 ≤ 엔티티 표본일 때만)로 앞 턴 엔티티를 범위로 넘기고, 주입은 대상 2대 이상이면 생략 · 1대면 해소 컬럼(`hostname`/`name`)에 맞춘다. 로컬 MLX 2·3단 모두 3행 확인. ⑪ **폼필 피벗이 서버 IP·호스트명을 EAV 속성으로 뽑아 8/50대가 비었다** — 프로필 `value_joins`가 「EAV Hostname/IPaddress = 엔티티 컬럼」을 선언하고 프롬프트도 금지하는데 결정적 조립기(`assembler._pivot_select_parts`)만 반영하지 않았다. 조립기가 `value_joins`를 읽어 엔티티 직접 컬럼으로 뽑는다(지식은 프로필에서 — 코드 리터럴 없음) → 50/50. ⑫ **Word 표 밖 자리 표시(`{{부서}}`·`{{서버수}}`)가 빈칸** — 매핑 불가 자리 표시를 결정적으로만 채운다: 질의의 「<이름>은/는/:/= 값」 → 그 값, 개수 명사(수·건수·개수·대수)로 끝나면 결과 행 수, 둘 다 아니면 빈칸(지어내지 않음). 역질문 답변(`form_fill_literals`)이 우선.
