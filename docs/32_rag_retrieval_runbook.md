# 32. RAG 리트리벌 접속 정보 교체 런북 (FabriX Retrieval Connector)

> **목적**: 사내 GenAI 플랫폼의 리트리벌 자산이 바뀔 때(문서 추가·수정·재청킹·파라미터 변경) **무엇을 어디에 넣어야 기능이 다시 도는지**를 잊어도 찾을 수 있게 남긴다.
> **설계 근거**: `plans/126` §3.1b(자산 수명) · §4.1a(접속 세트 수명 관리) · §4.12(설정)
> **작성일**: 2026-09-29 · **상태**: 골격 완성 · **플랫폼 화면 조작 절차(§2)는 사용자 1회 실행 후 채운다**(내가 그 화면을 본 적이 없다 — 추측으로 적지 않는다)

## 0. 값 반입 — 도구 경로와 수동 경로 (가장 먼저 볼 절)

> 도구로 넣는 길(§0.1·§0.2)과 **에디터만으로 넣는 길(§0.3)** 을 모두 적었다. 폐쇄망에서
> 값을 밖으로 내보낼 수 없으므로, 문제를 물어볼 때 **무엇만 전달하면 되는지**도 §0.4에 있다.

토큰·클라이언트 키는 사람이 타이핑할 길이가 아니고, **붙여넣기에 섞인 개행 하나로 인증이 실패**한다.
그래서 `.env`를 직접 편집하지 않고 도구로 넣는다 — 값을 **복사 → 붙여넣기**만 하면 된다.

### 0.1 권장: 메모장에 4줄 붙여넣고 파일로 읽히기 (가장 실수가 적다)

플랫폼 화면에서 값을 복사해 아무 텍스트 파일에 **4줄**로 붙인다(순서: 주소 · 토큰 · 클라이언트 키 · 자산 ID).

```text
http://kbgenai-chat-trrn.cloudengineering.com/generative-ai-connector/kb0/<난수>/1/retrieval
<x-openapi-token 값>
<x-generative-ai-client 값>
20260928181958_9c84fa6da4684dee9fb4c2f3c21566bd
```

그 파일을 읽혀 `.env`에 쓴다(문서군마다 1회):

```bash
python scripts/rag_conn.py set hq_manual  --from-file hq.txt      # 전산관리규정
python scripts/rag_conn.py set arch_docs  --from-file arch.txt    # 아키텍처 설계문서
python scripts/rag_conn.py show                                          # 확인(토큰 마스킹)
```

도구가 대신 해 주는 것:
- **4종을 함께** 쓴다. 하나라도 비면 거부한다(부분 교체는 «다른 자산을 가리키는 조합»이 된다).
- 개행·앞뒤 공백·감싼 따옴표를 제거한다(인증 실패의 흔한 원인).
- **순서가 바뀌어도** URL·자산 ID는 형태로 알아보고 자리를 바로잡는다.
- `.env` 관례를 지킨다(값 뒤 인라인 주석 금지 · 기존 줄 제자리 갱신 · 다른 키 불변).
- 저장 전 **백업**(`.env.bak-rag-<시각>`) · 기존 값이 있으면 `--force` 없이는 쓰지 않는다.
- 화면·로그에 **토큰을 찍지 않는다**(끝 4자만).

`키=값` 형식도 인식한다 — 플랫폼 화면을 통째로 복사해 붙여도 대개 읽힌다.

```text
endpoint = http://.../retrieval
token: <값>
client_key=<값>
retrieval_id=20260928181958_...
```

### 0.2 대화형 (파일 만들기도 번거로울 때)

```bash
python scripts/rag_conn.py set hq_manual
```
네 번 붙여넣고 Enter를 누른다. 토큰은 화면에 표시되지 않는다.

### 0.3 도구 없이 손으로 넣기 (에디터만 있으면 된다)

스크립트를 쓸 수 없는 상황(파이썬 미기동·권한·긴급)에도 **이 절만 보고 끝낼 수 있다.**
저장소 루트의 **`.env`** 를 에디터로 열고 아래 8줄을 넣는다(없으면 새로 만든다).

```dotenv
RAG_ENABLED=true
RAG_HQ_MANUAL_ENDPOINT=<규정 문서군 주소 전문>
RAG_HQ_MANUAL_TOKEN=<규정 문서군 x-openapi-token>
RAG_HQ_MANUAL_CLIENT_KEY=<규정 문서군 x-generative-ai-client>
RAG_HQ_MANUAL_RETRIEVAL_ID=<규정 문서군 자산 ID>
RAG_ARCH_DOCS_ENDPOINT=<설계문서 주소 전문>
RAG_ARCH_DOCS_TOKEN=<설계문서 x-openapi-token>
RAG_ARCH_DOCS_CLIENT_KEY=<설계문서 x-generative-ai-client>
RAG_ARCH_DOCS_RETRIEVAL_ID=<설계문서 자산 ID>
```

**반드시 지킬 것 5가지** — 어기면 조용히 깨진다.

| # | 규칙 | 어기면 |
|---|---|---|
| 1 | **값 뒤에 주석을 붙이지 않는다**(`KEY=값  # 설명` 금지). 주석은 별도 줄에 | 값에 주석이 섞여 인증 실패 · 빈 값 뒤는 특히 위험 |
| 2 | **따옴표로 감싸지 않는다**(값에 공백이 없다) | 따옴표가 값의 일부가 된다 |
| 3 | **한 줄에 하나**, 개행이 값 중간에 들어가지 않게(에디터의 자동 줄바꿈은 화면만 접는 것이므로 무해하나, 직접 Enter 를 누르면 값이 끊긴다) | 토큰 절단 → 인증 실패 |
| 4 | **4종을 같은 발급 건에서** 가져와 함께 바꾼다(주소·토큰·클라이언트 키·자산 ID) | 다른 자산을 가리키는 조합 → 인증 실패 또는 엉뚱한 문서 |
| 5 | 줄 앞의 `#` 를 지워 **활성화**한다(`.env.example` 을 복사해 왔다면 주석 처리되어 있다) | 값을 넣었는데 읽히지 않는다 |

적용:

- **서버가 꺼져 있으면** — 그냥 기동하면 읽는다.
- **서버가 돌고 있으면** — 관리자 화면 → 「환경변수 설정」 탭 → **「설정 리로드」** 버튼(재기동 없이 적용된다).
  이 9개 키는 모두 「리로드」 대상으로 등재돼 있다.
- 값을 지우고 싶으면 값만 비운다(`RAG_HQ_MANUAL_TOKEN=`) — 그 문서군은 «접속 정보 미입력»으로
  비활성이 되고 사유가 로그·화면에 남는다.

`.env` 가 아니라 `.env.example` 을 고치는 실수가 흔하다 — **`.env.example` 은 키 이름 사전일 뿐
런타임이 읽지 않는다.**

### 0.4 값을 보여 주지 않고 문제를 물어보는 방법 (폐쇄망)

값(토큰·자산 ID)은 **밖으로 내보내지 않아도 된다.** 문제가 생겼을 때 전달하면 충분한 것:

1. `python scripts/rag_probe.py --list` 출력 — **토큰은 이미 마스킹**되어 끝 4자만 나온다.
2. status 값과 **종료 코드**(`0·2·3·4·5·6`) 또는 사용자에게 보인 문구 첫 줄.
3. 서버 로그의 해당 1줄(`문서 검색 [문서군] status=… 건수=… 점수=…`) — 본문·토큰은 찍히지 않는다.
4. 도구를 못 쓰면: **어느 키를 채웠는지 이름만**(값 없이) + 화면에 나온 사유 문구.

이 네 가지로 §6 판독표의 어느 행인지 판정할 수 있다. **토큰·클라이언트 키 원문은 어떤 경우에도
문서·채팅·이슈에 붙이지 않는다.**

### 0.5 넣은 뒤 확인 (LLM 호출 0회)

```bash
python scripts/rag_probe.py --list                                  # 무엇이 채워졌나
python scripts/rag_probe.py -c hq_manual -q "계정 신청 절차" --search-only   # 검색만
```
`--search-only`가 1차 진단 수단이다 — **검색이 되는가**와 **답을 잘 쓰는가**를 분리해 본다.
`RAG_ENABLED=true`가 아니면 `--list`가 그 사실도 함께 알려준다.

### 0.6 미리 알아 둘 것

- 값 4종은 **문서군마다 다르다**. 규정과 설계문서의 토큰을 섞으면 인증이 실패한다.
- 문서가 추가·수정되거나 청킹이 다시 되면 **자산 ID가 새로 발급되고 옛 ID는 폐기**된다 →
  사용자에게 "문서 색인이 갱신되어…"가 나가고, 그때 §3으로 4종을 다시 넣는다.
- `.env`는 git에 올라가지 않는다(`.gitignore`). **토큰을 이 문서나 채팅·이슈에 붙이지 말 것.**

### 0.7 상황별 한눈에

| 상황 | 할 일 |
|---|---|
| 사용자가 *"문서 색인이 갱신되어 조회할 수 없습니다"* 를 받았다 | §3 교체 절차 — 값 4개를 새로 받아 넣는다 |
| 문서를 추가·수정했다 / 청킹을 다시 했다 / 리트리벌 파라미터를 바꿨다 | **자산 ID가 바뀐다.** 바꾼 사람이 §2에서 값 4개를 받아 §3으로 넘긴다 |
| 새 문서군(코퍼스)을 추가한다 | §5 — 이건 설정만으로 안 되고 **코드·YAML 변경이 필요**하다 |
| 값이 맞는지 확인하고 싶다 | §4 검증 |
| 오류가 나는데 원인을 모르겠다 | §6 오류 판독표 |

**한 줄 원칙: 값 4개는 항상 세트로 함께 바꾼다.** 하나만 바꾸면 인증 실패거나 엉뚱한 자산을 가리킨다.

## 1. 무엇이 필요한가 — 접속 4종 세트

문서군(컬렉션) **하나당** 아래 4개가 필요하다. 플랫폼이 리트리벌을 발급할 때마다 **4개 모두 달라질 수 있다.**

| # | 값 | 예시 형태 | 성격 |
|---|---|---|---|
| 1 | **엔드포인트 URL**(전문) | `http://kbgenai-chat-trrn.cloudengineering.com/generative-ai-connector/kb0/<난수>/1/retrieval` | 호스트(`trnn`/`trrn`)·세그먼트(`bk0`/`kb0`)·난수가 발급마다 다르다 → **조립하지 말고 플랫폼 화면의 URL을 그대로 복사** |
| 2 | **x-openapi-token** | 긴 문자열 | **비밀** — 문서·채팅·로그에 남기지 않는다 |
| 3 | **x-generative-ai-client** | 긴 문자열 | **비밀** — 같음 |
| 4 | **retrieval_id**(자산 ID) | `20260928181958_9c84fa6da4684dee9fb4c2f3c21566bd` | 접두 14자리는 발급 시각으로 읽힌다(`YYYYMMDDHHMMSS` · **추정**) |

### 1.1 현재 발급분 기록 (2026-09-29 · 회전하므로 곧 낡는다)

> **런타임 정본은 이 문서가 아니라 `.env`(또는 관리자 화면)다.** 아래는 이력 참고용이며, **토큰·클라이언트 키는 여기에 적지 않는다.**

| 문서군 | 자산 ID(수령 2026-09-29) | 엔드포인트 경로 세그먼트(수령 2026-09-29) |
|---|---|---|
| 전산관리규정(본부 전산관리매뉴얼) | `20260928181958_9c84fa6da4684dee9fb4c2f3c21566bd` | `u0b45ul6l73w5dmslu0vzy926jusxg` |
| 아키텍처 설계문서 | `20260929160345_4d8f9941f6dd4790ae430edad1869b06` | `p6u609wknl6ocj9844` |

**⚠ 세그먼트 → URL 조립은 추정이다.** 위 세그먼트가 `…/generative-ai-connector/{kb0|bk0}/<세그먼트>/1/retrieval`의 `<세그먼트>` 자리라는 것은 형식 관찰에 따른 추정이고, 호스트(`trnn`/`trrn`)와 `kb0`/`bk0` 중 무엇인지는 **문서군마다 확인해야 한다.** 그래서 설정에 넣는 값은 세그먼트가 아니라 **URL 전문**이다 — 플랫폼 화면에서 URL을 통째로 복사하면 이 추정이 필요 없어진다.

## 2. 플랫폼에서 값 받기 (GenAI 플랫폼 화면 — **미작성**)

> **여기는 비워 둔다.** 이 화면을 본 적이 없어 추측으로 적으면 나중에 틀린 절차를 따라가게 된다.
> 사용자가 **한 번 실제로 교체할 때** 아래 6칸을 채워 주면 이후로는 이 문서만 보고 할 수 있다.

```
(1) 접속 주소:                      ← GenAI 플랫폼 URL
(2) 메뉴 경로:                      ← 예) 커넥터 > 리트리벌 커넥터 > 목록
(3) 문서군 식별 방법:                ← 어느 항목이 「전산관리규정」인지 화면에서 구별하는 법
(4) 자산 ID·URL·토큰·클라이언트 키가 보이는 위치:
(5) 재발급/갱신 버튼 위치와 이름:
(6) 발급 후 옛 ID가 즉시 폐기되는지(시차가 있는지):
```

**알고 있는 것(확인된 계약)**: 파라미터나 문서를 바꾸면 **새 자산 ID가 발급되고 기존 ID는 폐기**된다 — 폐기된 ID로 호출하면 §6-A 오류가 온다. 따라서 *"바꿨는데 언제 반영되나"* 를 기다릴 필요가 없다. 옛 값은 즉시 못 쓰고, 새 값은 넣는 즉시 쓴다.

## 3. 교체 절차 (가장 자주 하는 작업)

### 3.1 관리자 화면

> 전용 「접속 정보」 폼은 **없다**. `plans/126` W4가 그 폼을 만들지 않고 기존 설정 화면에서 키별로 편집하게 했다
> (두 번째 `.env` 쓰기 경로를 만들면 백업·검증 규율이 갈린다). 그래서 **4종 동시 입력을 강제하는 것은 도구
> (`scripts/rag_conn.py` · §0.1)뿐이다** — 화면은 부분 저장을 막지 않는다. 실수를 줄이려면 §0.1 도구 경로가 먼저다.

1. 관리자 → **「환경변수 설정」** 탭 → 그룹 **「문서 검색(RAG)」**을 펼친다.
2. 대상 문서군의 4키 — `RAG_HQ_MANUAL_*` 또는 `RAG_ARCH_DOCS_*`의 `ENDPOINT`·`TOKEN`·`CLIENT_KEY`·`RETRIEVAL_ID` —
   를 **한 번에 모두** 새 값으로 편집한다. 주소·토큰·클라이언트 키는 끝 4자만 보이게 마스킹돼 있고, 마스킹된 값을
   그대로 두면 그 키는 저장되지 않는다(기존 값 유지).
3. **「저장」** → 변경 확인 창에서 4키가 모두 들어 있는지 보고 저장한다.
4. **「설정 리로드」**를 누른다(9키 모두 「리로드」 대상 — 재기동은 필요 없다).
5. §4 검증 — 「문서 검색 시험」 탭의 접속 상태 표부터 본다.

**주의 — 키별 저장의 중간 상태**: 4키 중 일부만 바꾼 채 저장·리로드하면 ① 비운 키가 있으면 그 문서군은
사유(「접속 정보 미입력 — `RAG_…`」)와 함께 **비활성**이 되고(로그·접속 상태 표에 사유가 남는다) ② 비지는 않았지만
다른 발급 건의 값이 섞이면(예: 자산 ID만 새 값) 인증 실패나 엉뚱한 자산이 된다(§6-B · §6-A).

### 3.2 `.env` 직접 편집 (도구를 못 쓸 때만)

> **먼저 §0.1의 `scripts/rag_conn.py`를 쓴다.** 직접 편집은 개행·공백·인라인 주석으로
> 조용히 깨지는 경로다. 아래는 도구를 쓸 수 없을 때의 형식 참고용이다.

저장소 루트의 **`.env`** 를 연다(이 파일은 `.gitignore`에 있어 커밋되지 않는다 — `.gitignore:2`).

```dotenv
# ── RAG 리트리벌 접속 정보 (문서군별 4종 세트) ─────────────────────
# 전산관리규정 / 본부 전산관리매뉴얼
RAG_HQ_MANUAL_ENDPOINT=http://…/generative-ai-connector/kb0/<난수>/1/retrieval
RAG_HQ_MANUAL_TOKEN=
RAG_HQ_MANUAL_CLIENT_KEY=
RAG_HQ_MANUAL_RETRIEVAL_ID=20260928181958_9c84fa6da4684dee9fb4c2f3c21566bd

# 아키텍처 설계문서
RAG_ARCH_DOCS_ENDPOINT=http://…/generative-ai-connector/kb0/<난수>/1/retrieval
RAG_ARCH_DOCS_TOKEN=
RAG_ARCH_DOCS_CLIENT_KEY=
RAG_ARCH_DOCS_RETRIEVAL_ID=20260929160345_4d8f9941f6dd4790ae430edad1869b06
```

**`.env` 작성 규칙(이 저장소 관례 — 어기면 조용히 깨진다)**

- **값 뒤에 인라인 주석을 붙이지 않는다.** 주석은 별도 줄에. *(특히 빈 값 뒤 금지 — 파싱이 깨진 이력이 있다)*
- 값에 따옴표를 두르지 않는다(공백이 없으면 불필요).
- 토큰을 붙여넣을 때 **줄바꿈·앞뒤 공백이 섞이지 않게** 한다(긴 문자열이라 에디터가 줄을 접어 보일 뿐, 실제 개행이 들어가면 인증이 실패한다).
- 편집 후 **서버 재기동** 또는 관리자 화면 「환경변수 설정」 탭의 「설정 리로드」.

**키 이름을 잊었으면 `.env.example`을 본다** — 전체 키가 빈 값으로 들어 있다(복사해서 `.env`에 붙이고 값만 채운다).

## 4. 검증 — 값이 맞는지 확인

### 4.0 CLI 프로브 (**가장 확실한 첫 확인**)

라우팅 없이 엔진만 직접 부른다(`plans/126` §4.17 T-1).

```bash
python -m scripts.rag_probe --list                                   # 컬렉션·접속 세트 유효성
python -m scripts.rag_probe --collection hq_manual --query "계정 신청은 누가 승인하나요?" --search-only
python -m scripts.rag_probe --collection hq_manual --query "계정 신청은 누가 승인하나요?"
```

- `--search-only`를 **먼저** 돌린다 — LLM을 부르지 않으므로 「검색이 되는가」와 「답을 잘 쓰는가」를 분리해 판정할 수 있다.
- 종료 코드가 §6 판독표와 1:1이다: `0` 정상 · `2` 결과 0건 · `3` 자산 폐기 · `4` 오류·타임아웃·PII 차단 · `5` 비활성 · `6` 사용법 오류(`--query`·`--collection` 누락 — `scripts/rag_probe.py` `main`).

### 4.1 서버 로그

기동·reload 직후 1줄을 확인한다.

```
문서 검색 활성 — 컬렉션 2 (hq_manual · arch_docs) / 비활성 0
```

- 비활성이 있으면 그 컬렉션의 **4종 세트 중 하나가 비었다**(로그가 어느 키인지 말한다).
- 자산 ID 접두로 기준일이 함께 찍힌다(`hq_manual: 2026-09-28 18:19`).

### 4.2 실제 질의 1건

**관리자 화면 「문서 검색 시험」 탭**에서 문서군을 고르고 묻는다 — 예: *"계정 신청 승인 절차"*. (**일반 채팅 연결은 기본 off다.** `RAG_CHAT_ROUTING_ENABLED=true`로 두고 **재시작**하면 채팅 질문 가운데 규정·절차·설계 근거를 묻는 것이 문서 검색으로 간다 — `RAG_ENABLED=true`도 함께 필요하다 · `plans/127`. 켜기 전에 이 탭에서 검색·답변이 되는지 먼저 확인한다. 명시 접두 `/문서`(시험용 T-4)는 2026-09-30 **제거**했다 — 웹 채팅(스트리밍)에서는 원래 닿지 않았다.)

**채팅 연결을 켠 뒤 확인**: 채팅에 *"계정 신청은 누가 승인하나요?"*를 묻는다 → 처리 현황에 「문서 검색」 작업이 보이고 답 아래에 「참고 문서」가 붙으면 정상이다. 「요청하신 정보를 조회할 권한이 없습니다」면 그 사용자의 「조회 가능 소스」에 **사내 문서**가 없다(관리자 「사용자 관리」 · 신규 가입자는 `AUTH_DEFAULT_ALLOWED_SOURCES`에 `doc`이 없으면 막힌다). 사용법 질문(*"무엇을 할 수 있나요?"*)에 「사내 문서」 행이 보이는지도 함께 본다.

- **정상**: 답변 + 「참고 문서」 각주(파일명·부제)가 붙는다.
- **`문서 색인이 갱신되어…`**: 자산 ID가 폐기됐다 → §3으로 교체.
- **`문서 검색이 설정되지 않았습니다`**: 4종 세트가 비었거나 기능이 off(`RAG_ENABLED`).
- **`관련한 내용을 찾지 못했습니다`**: **접속은 정상**이고 검색 결과가 0건이다(§6-D).

### 4.3 curl (서버 없이 값만 검증)

```bash
curl -s -X POST "<ENDPOINT>" \
  -H "x-openapi-token: <TOKEN>" \
  -H "x-generative-ai-client: <CLIENT_KEY>" \
  -H "Content-Type: application/json" \
  -d '{"retrieval_id":"<RETRIEVAL_ID>","query":"계정 신청 절차"}'
```

- 폐쇄망 안에서만 도달한다(사내 도메인).
- 셸 이력에 토큰이 남는다 — 검증 후 이력을 지우거나 파일 변수로 넘긴다.

## 5. 새 문서군(코퍼스) 추가 — 설정만으로는 안 된다

교체와 달리 **추가는 코드·YAML 변경이 필요**하다(1회).

| 단계 | 파일 | 내용 |
|---|---|---|
| 1 | `config/rag_collections.yaml` | 의미 등록 — `id` · 제목 · 설명 · 형제 차이 · 표면어 · 답변 영역 · 민감 여부 |
| 2 | `src/config.py` (`RagConfig`) | 그 컬렉션의 접속 4필드 추가(`RAG_<ID>_*`) |
| 3 | `.env.example` | 같은 4키를 **빈 값으로** 추가(키 이름을 보고 따라 적을 수 있게) |
| 4 | `config/settings_help/rag.yaml` | 4키의 설명 추가(없으면 도움말 가드 테스트가 실패한다) |
| 5 | `.env`(또는 관리자 화면) | 실제 값 입력 |
| 6 | 배포 | 폐쇄망은 파일 단위 수동 복사 → 재기동 |

**왜 2단계(코드)가 필요한가**: 설정 스키마가 pydantic 필드 introspection으로 관리자 화면·도움말·검증에 자동 반영되는 구조라, 필드가 없으면 화면에도 안 나오고 검증도 안 된다. 컬렉션 **추가**는 드물고(코퍼스 신설), **교체**는 잦은데 교체는 코드를 건드리지 않는다 — 이 분업이 설계 의도다(`plans/126` §4.1a).

## 6. 오류 판독표

| # | 증상 | 응답/로그 | 원인 | 조치 |
|---|---|---|---|---|
| **A** | 사용자에게 *"문서 색인이 갱신되어 현재 설정으로는 조회할 수 없습니다"* | `{"message":"retrieval does not exist. retrieval id: …","error":"data is invalid","errorCode":"NoContent"}` · 로그 `status=stale_id` | **자산 ID 폐기** — 문서·청킹·파라미터가 바뀌어 새 ID가 발급됐다 | §3 교체. **재시도는 무의미하다**(회복되지 않는다) |
| **B** | 401/403 또는 인증 관련 오류 | 로그 `status=error` + HTTP 상태 | 토큰·클라이언트 키가 그 리트리벌 것이 아니다(다른 발급분의 값을 섞었다) | 4종 세트를 **한 발급분에서** 다시 받아 통째로 교체 |
| **C** | 404 / 경로 오류 | 로그 `status=error` | URL을 조립했거나 호스트·세그먼트가 틀렸다(`trnn`/`trrn` · `bk0`/`kb0`) | 플랫폼 화면의 **URL 전문**을 복사해 붙인다 |
| **D** | *"관련한 내용을 찾지 못했습니다"* | 로그 `status=empty` · 건수 0 | **접속은 정상.** 플랫폼이 자기 임계(vector 0.5 · rerank 0.3)로 «쓸 만한 근거 없음»을 판정했다 | 우리가 완화할 수단이 **없다**. ①질문 표현을 바꿔 본다(용어·문서명·조항 번호를 그대로 넣는다) ②그래도 안 나오면 문서에 실제로 없는지 확인 ③플랫폼 파라미터 조정은 플랫폼 담당자에게 |
| **E** | 답이 주제만 맞고 질문에 답하지 않는다 | 로그 `rank_score` 하위권 | rerank 하한이 0.3으로 낮아 주변 문서가 상위 3에 들어왔다 | 질문을 좁힌다. 반복되면 문서 자체에 해당 내용이 없을 가능성 |
| **F** | 타임아웃 | `status=timeout` | 플랫폼 지연 또는 네트워크 | 재시도. 반복되면 플랫폼 상태 확인 |
| **G** | 기능이 아예 안 뜬다 | *"문서 검색이 설정되지 않았습니다"* | `RAG_ENABLED=false` 또는 4종 세트 미입력 | §3.2 + `RAG_ENABLED=true` |

## 7. 교체 시 남는 기록

> **전용 교체 감사(`rag_connection_updated`)는 없다.** `plans/126` §4.1a 3·부록 C가 약속했지만 `src/`에 구현 0건이다
> (2026-09-30 실측 · 126 잔여). 실제로 남는 기록은 **교체한 경로**에 따라 다르다.

| 경로 | 남는 기록 |
|---|---|
| 관리자 화면 「환경변수 설정」 → 「저장」 | 일반 설정 변경 감사 **`settings_update`**(`src/api/routes/admin.py` `_log_settings_update` → `src/api/admin_audit.py` `log_admin_event`) — 누가(`user_id` = 관리자) · 언제(`timestamp`) · **비민감 키는 옛값 → 새값**(`changes`) · 민감 키는 **키 이름만**(`sensitive_keys`). RAG 키 중 주소·토큰·클라이언트 키는 민감 키라 값이 남지 않고, **자산 ID(`RAG_*_RETRIEVAL_ID`)는 비민감이라 옛 ID → 새 ID가 전문으로 남는다** |
| 관리자 화면 「설정 리로드」 | **`settings_reload`** — 바뀐 키 **이름만**(`changed_keys`) · 그래프 재빌드 여부 |
| `scripts/rag_conn.py set` | **감사 기록 없음** — 저장 전 `.env` 백업(`.env.bak-rag-<시각>`)만 남는다(서버 밖 도구) |
| `.env` 직접 편집 | 기록 없음 |

*"어제와 답이 다른데?"* 에 답할 근거는 화면 경로의 `settings_update`에 남는 **자산 ID 옛값 → 새값**뿐이다. 도구 경로(§0.1)는
입력 실수를 줄이지만 감사를 남기지 않는다 — 교체 사실을 감사로 남겨야 하면 화면 경로(§3.1)를 쓴다.
