AIOps 기능 구현 분석 및 로드맵

선진사례 벤치마킹(9 플랫폼)·벤더 구현 레퍼런스·학술 문헌(23편) 기반 · collectorinfra · AIOps 아키텍트 · 2026-07
목적. 선진사례 분석에서 도출된 각 기능(이상탐지·RCA·토폴로지·변경상관·예측·자동복구)이 어떻게 구현되며(벤치마크·학술), collectorinfra에 어떻게 반영할지, 그리고 전체 로드맵의 어디에 위치하는지를 하나로 통합한다. 노이즈·상관(Plan 52)은 이미 구현 완료돼 고도화(Plan 60) 단계이며, 나머지는 아래 4단계 페이즈(P1~P4)로 관리된다(상위 로드맵: Plan 62).

1. 전체 로드맵 — 4단계 페이즈

P1 노이즈·상관 완성(진행) → P2 진단·RCA(핵심) → P3 멀티소스 관측(확장) → P4 예측·자동복구(신규·거버넌스). 토폴로지 그래프(P1)가 RCA(P2)의 선행자산이며, 자동복구(P4)는 읽기전용 원칙(D-003) 재검토가 선행 블로커다.

2. 기능별 구현 분석 (선진사례 → collectorinfra)

이상탐지 (동적 baseline)P1 (Plan 60 E3)
선진사례 구현방식Dynatrace Davis·Datadog Watchdog: 계절성 자동학습 후 예측대역 이탈 탐지. Splunk ITSI: adaptive thresholding(시간대별 baseline). 정적 임계 대신 계절·추세 반영.
학술 근거Xu 2018 Donut(VAE 계절 KPI, F 0.75~0.9)·Szmit 2012 Holt-Winters·Choi 2021 리뷰(딥러닝이 항상 우월치 않음)
collectorinfra 현황정적 z-score 수준(Plan 50 §진단). 동적 baseline 없음.
구현 방향Holt-Winters/STL 결정적 baseline(폐쇄망·해석성 우선) → 예측대역 이탈을 anomaly_score로. 게이트의 ai_message_severity 상향 슬롯에 주입. Donut(VAE)은 장래 옵션.
RCA·인과추론P2 (Plan 50·51)
선진사례 구현방식Dynatrace Davis: Smartscape 토폴로지 그래프로 이상 전파 추적, 결정적 인과. BigPanda/Moogsoft: 상관 클러스터→후보. 상관과 인과를 분리.
학술 근거Wu 2020 MicroRCA(속성그래프 이상전파, precision 89%)·Liu 2020 MicroCause(인과경로+시간순 random walk)·Gan 2021 MicroHECL(대규모 실시간)
collectorinfra 현황미구현(Plan 50 계획). evidence_collector→correlation_engine→causal_reasoner 3단 설계만 존재.
구현 방향① 결정적 증거수집(알람·메트릭·프로세스·토폴로지) ② 토폴로지 그래프 BFS로 전파 추적(상관) ③ 시간순 우선 인과추론 ④ LLM은 해석·리포트만. trace 없으므로 의존성그래프+메트릭 상관으로 치환.
토폴로지·의존성 인지P1 선행자산 (Plan 60 E4)
선진사례 구현방식Dynatrace Smartscape·ServiceNow CMDB: 실시간 의존성 그래프가 RCA·상관의 근거. 인과의 기반 인프라.
학술 근거Wu 2020(attributed graph)·MicroHECL(이상전파 체인 탐색)
collectorinfra 현황AVAIL_DEPEND_RESOURCE_ID(1홉)만 노이즈 게이트 step6.4에서 사용. 다홉 그래프 없음.
구현 방향DependencyGraph(is_cascaded·find_root·descendants) 다홉 구축. cmm_resource의 AVAIL_DEPEND·IS_INHERIT_AVAIL_DEPEND. 이상전파 방향을 엣지 가중으로. 노이즈(E2)·RCA(P2) 공용 자산.
변경 상관 (Change)P2~P3 (Plan 60 E5, 소스는 P3)
선진사례 구현방식BigPanda·Datadog: 배포·구성변경 이벤트를 알람과 시간·영향범위로 상관 → '변경이 최대 단일 원인'. change-context 오버레이.
학술 근거(직접 문헌 적음) — 도입사례에서 변경상관이 MTTR 단축 핵심 요인으로 반복 확인
collectorinfra 현황변경관리 피드 연동 없음. 게이트·RCA에 변경 컨텍스트 부재.
구현 방향change_correlation.overlay_changes(타임라인·영향범위 매칭). 게이트 step9에서 억제 아닌 promote 신호(변경 직후 알람은 실장애 가능성↑). CI/CD·변경관리 DB 피드 필요.
예측·선제 탐지P4 (신규 Plan 63)
선진사례 구현방식Dynatrace Davis: 자원 고갈 예측(디스크 full ETA). Datadog: forecast 모니터. 임계 도달 전 경보.
학술 근거Gao 2020 클라우드 작업실패 예측(DL)·디스크 고장 예측(SMART, 2016/2021)·NTAM(2021)
collectorinfra 현황미구현. 전용 계획 없음(갭).
구현 방향Holt-Winters/STL 추세 외삽으로 임계 도달 ETA(E3 baseline 재사용, 경량 통계 우선). 디스크·자원 고갈부터. 딥러닝 고장예측은 폐쇄망·해석성 검토 후 장래.
자동 복구·폐루프P4 (신규 Plan 64, 거버넌스 우선)
선진사례 구현방식PagerDuty·Moogsoft·ServiceNow: 탐지→진단→runbook 실행→검증 폐루프. 저위험 반복장애 자동화, 고위험은 승인.
학술 근거self-healing closed-loop 도입사례(HCL·통신사 MTTR 단축)
collectorinfra 현황미구현. 읽기전용 원칙(D-003)과 정면 충돌.
구현 방향① 초기 human-in-the-loop(runbook 제안까지, 실행은 승인 후) → 점진 자동화 ② 권한·승인게이트·감사·롤백·blast radius 거버넌스 선행 ③ P2 RCA로 원인 확정 후에만.
관통 원칙. 모든 기능은 결정적 계산(규칙·그래프·통계) + 보조 LLM/ML(D-035), 읽기전용·옵트인·회귀 없음(D-003), 폐쇄망 경량 우선으로 구현한다. 딥러닝 옵션(Donut·인과 DL)은 해석성·폐쇄망 검토 후 장래 백로그로 분리한다.
