선진 솔루션 기능별 구현 메커니즘 분석 → collectorinfra 구현 방향

"각 기능이 무엇을 기준으로, 어떤 알고리즘으로, 실제로 어떻게 구현되는가" · AIOps 아키텍트 · 2026-07
분석 관점. 이번 분석은 "무슨 기능이 있다"가 아니라 기능이 어떤 신호로 판단하고 어떤 알고리즘·자료구조로 동작하며 실제로 어떻게 구현되는가를 선진 솔루션(Dynatrace Davis, Moogsoft, BigPanda, New Relic, Nagios, Google SRE)에서 분해하여 collectorinfra 계획에 반영했습니다. 핵심 발견: 선진 솔루션의 노이즈·상관·RCA는 대부분 결정적 규칙/그래프 알고리즘 + 보조적 ML/LLM 구조이며, 이는 collectorinfra가 이미 채택한 "결정적 수치 + LLM 해석" 원칙(D-035)과 정확히 일치합니다 — 즉 방법론이 맞습니다.

1. 노이즈 캔슬링 — 워크드 예제 (질문의 사례)

"어떤 정보를 기준으로 노이즈 여부를 판단하고, 어떻게 줄이는가?" — 선진사례의 답은 단일 임계값이 아니라 다중 신호를 결정적 파이프라인으로 종합하는 것입니다. collectorinfra의 Plan 52(D-048)는 이미 이 구조를 구현했으며, 아래 다이어그램이 신호→판정→라우팅 전체 메커니즘입니다.

판단 기준(신호)은 무엇인가

선진 솔루션과 collectorinfra 모두 이벤트 자체의 심각도 하나가 아니라, 이벤트를 둘러싼 맥락 신호로 판단합니다:

  • 자산 중요도(cmm_resource.IMPORTANCE_ID) × 심각도 → 우선순위 매트릭스 축
  • 유지보수 상태(IS_MAINTENANCE) → 점검 중이면 억제
  • 의존성·부모 상태(AVAIL_DEPEND_RESOURCE_ID+부모 AVAIL_STATUS) → 부모 장애의 연쇄 자식은 억제
  • 폴스타 알림정책(cmm_alarm_def_noti*) → 운영정책상 통보 대상인지 (권위 있는 앵커)
  • 패턴·재발(Plan 47 is_routine) → 보조 입력(판단은 결정적 규칙)
  • 상태전이 이력(플래핑) / 해소 이벤트(자가복구) → 억제 신호

3. 핵심 구현 패턴 — 선진사례가 수렴하는 3가지

패턴 1 — 결정적 계산 + 보조 ML/LLM (환각 차단)

Dynatrace Davis는 결정적 fault-tree 분석으로 "상관이 아닌 인과"를 도출하고 정밀·재현가능성을 확보합니다. 최근 연구(토폴로지 인지 RCA·arXiv 2606.20758)도 인과는 그래프 BFS+시간정렬로 결정적 계산, LLM은 사전계산된 증거의 설명자로만 사용합니다(제목: Separates Root-Cause Derivation from Root-Cause Explanation).
→ collectorinfra 정합: Plan 47 §3.3 / Plan 50 원칙(수치·상관은 Python 결정적, 인과 해석만 LLM)과 정확히 동일. 방법론이 옳다는 외부 검증.

패턴 2 — 위상(topology) 그래프가 인과의 근거

Davis는 Smartscape 실시간 의존성 그래프(수직·수평 의존성)를 순회하여 근본원인을 찾고, 동일 원인 이벤트를 하나의 problem으로 통합해 알람 스팸을 줄입니다. 토폴로지 없이는 연쇄 억제도, 인과 RCA도 불가능합니다.
→ collectorinfra 갭: AVAIL_DEPEND_RESOURCE_ID로 부모-자식 관계는 있으나 전체 의존성 그래프·순회 인과는 없음. 토폴로지 그래프 확보가 RCA의 최우선 선행조건.

패턴 3 — 동적 baseline (정적 임계값 탈피)

New Relic·Dynatrace는 Holt-Winters 지수평활로 계절성(일간·주간 주기)을 학습해 정상 피크는 억제하고 패턴 이탈만 경보합니다. Pinterest 등 실운영은 STL 분해(추세·계절 제거 후 잔차에 가우시안 검정)가 오탐이 가장 적다고 보고합니다.
→ collectorinfra 격상: Plan 50의 z-score+지속성(정적 baseline)을 STL/Holt-Winters 동적 baseline으로 격상하면 계절 오탐이 크게 감소.
