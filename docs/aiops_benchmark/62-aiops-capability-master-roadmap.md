## 1. 개요 및 목적

선진사례 벤치마킹(9개 플랫폼 × 10개 역량)·도입사례(13개 기업)·벤더 구현 레퍼런스·학술 문헌(23편) 조사 결과, collectorinfra가 갖춰야 할 AIOps 기능은 **10개 역량 축**으로 정리된다. 이 문서는 각 역량을 **어떤 계획이·어떤 순서로·무엇에 의존해** 구현하는지를 하나의 로드맵으로 통합한다.

이미 두 개의 부분 로드맵이 있다 — **Plan 53**(장애관리 3계획의 5-Wave 순서)과 **Plan 55**(멀티소스 관측 M0~M5). 본 계획은 이 둘을 **상위에서 포괄**하고, 아직 계획이 없는 **갭 2개(예측·자동복구)**를 신규 슬롯으로 편입해 전체 그림을 완성한다.

### 1.1 설계 원칙 (전 계획 계승 — 불변)

1. **결정적 계산(규칙·그래프·통계) + 보조 LLM/ML** (D-035) — 판단은 결정적, LLM은 해석·설명자.
2. **읽기전용·옵트인·회귀 없음** (D-003) — 신규 기능은 조회만, 기본 off, 비활성 시 기존 경로 무변경.
3. **폐쇄망 우선** — 로컬·사내 설치형만, 외부 SaaS 금지.
4. **어댑터는 분리, 두뇌는 통합** (Plan 55) — 소스 연동은 격리, 분석·상관·판정은 공용 코어.
5. **SSOT 보존·상향 비대칭** — 폴스타 기준선을 낮추지 않고 정밀화로만 얹는다.
6. **재구축이 아니라 조합** — 기존 자산(노이즈 게이트·deepagents·LangGraph·decision_store) 확장.

## 3. 4단계 마스터 페이즈 (Phase P1~P4)

기존 Plan 53 Wave·Plan 55 M단계를 상위에서 4개 페이즈로 묶는다. 각 페이즈는 **독립 배포 가능**하며 옵트인이다.

### Phase P1 — 노이즈·상관 완성 (진행/즉시)
- **내용**: 노이즈 게이트 고도화(Plan 60 E1~E4) — 재발생 관측성·크로스호스트 상관·동적 baseline(C3)·토폴로지 그래프(C7).
- **의존성**: 없음(52 구현 완료 위에 증분). **토폴로지 그래프(E4)가 P2의 선행자산**.
- **비용/계층**: S~M / L1. **가치**: 상시 알람피로 감소(즉시 ROI) + RCA 토대.
- **대응**: Plan 60, Plan 53 Wave 1·3.

### Phase P2 — 진단·RCA (핵심)
- **내용**: 결정적 증거수집→상관→인과추론(Plan 50), OS 3계층 수집(Plan 51). 토폴로지 그래프(P1 E4) BFS 순회 기반 결정적 RCA + LLM 해석.
- **의존성**: P1의 토폴로지 그래프. Plan 47(구현) 재사용.
- **비용/계층**: M~L / L1→L2/L3(보안 게이트). **가치**: on-demand·push 근본원인 분석(C4).
- **대응**: Plan 50·51, Plan 53 Wave 2·4.
- **문헌 근거**: MicroRCA(속성그래프)·MicroCause(인과추론) — trace 없는 환경은 의존성그래프+메트릭 상관으로 치환.

### Phase P3 — 멀티소스 관측 (확장)
- **내용**: APM(앱)·DPM(DB)·미들웨어 읽기전용 커넥터, 노이즈 게이트에 사용자영향 축 추가, RCA end-to-end 교차상관(C1 확장).
- **의존성**: P1(노이즈 게이트)·P2(RCA evidence_collector). 엔티티 매핑(M0) 선행.
- **비용/계층**: M~L / 신규 소스축. **가치**: 인프라↔앱↔DB end-to-end.
- **대응**: Plan 55 M0~M5 전체.

### Phase P4 — 예측·자동복구 (신규·거버넌스)
- **내용**: ① 예측·선제 탐지(C5) — 시계열 예측으로 임계 도달 전 경보. ② 자동복구·폐루프(C6) — 승인 기반 조치 실행.
- **의존성**: P1~P3의 신호·상관·영향도 축적. **자동복구는 읽기전용 원칙(D-003) 재검토가 선행 블로커**.
- **비용/계층**: L~XL. **가치**: 선제 운영 + MTTR 단축.
- **대응**: **신규 Plan 63(예측)·Plan 64(자동복구)** — §5 참조.

```
P1 노이즈·상관 완성 ──┬─► P2 진단·RCA ──┬─► P3 멀티소스 관측 ──► P4 예측·자동복구
 (60 E1~E4)          │   (50·51)        │   (55 M0~M5)          (신규 63·64)
   └ E4 토폴로지그래프 ─┘ (P2 선행자산)     └ evidence_collector 재사용
```

## 5. 갭 2개 — 신규 계획 슬롯 제안

### 5.1 Plan 63 — 예측·선제 탐지 (신규 제안)
- **목표**: 메트릭 시계열 예측으로 임계 도달·자원 고갈·고장을 **사전 경보**(C5).
- **접근(문헌 기반)**: Holt-Winters/STL 예측(Plan 60 E3 baseline 재사용)으로 추세 외삽 → 임계 도달 ETA 산출. 디스크 고장 예측(SMART), 작업 실패 예측은 딥러닝 문헌 존재하나 폐쇄망·해석성 고려해 **경량 통계 우선**.
- **연계**: Plan 60 E3(동적 baseline)의 자연스러운 확장. Plan 55 APM 골든시그널 예측.
- **선행**: P1 E3 완료(baseline 인프라 재사용).

### 5.2 Plan 64 — 자동 복구·폐루프 (신규 제안·거버넌스 우선)
- **목표**: 반복적·저위험 장애에 **승인 기반 자동 조치**(C6, self-healing closed-loop).
- **핵심 블로커**: **읽기전용 원칙(D-003)과 정면 충돌**. 쓰기·명령 실행은 별도 거버넌스 결정(권한·승인 게이트·감사·롤백·blast radius) 없이는 착수 불가.
- **접근(문헌·벤더 기반)**: 탐지→진단→조치→검증 폐루프. 초기엔 **human-in-the-loop 승인**(runbook 제안까지만, 실행은 승인 후) → 점진적 자동화. LogicMonitor/IBM/RedHat 폐루프 패턴.
- **선행**: P2 RCA(원인 확정)·P3 영향도. **거버넌스 결정이 최대 블로커** — D-003 예외 범위·승인 주체·감사 요건을 사용자·보안팀과 확정.

> 두 계획 모두 **본 로드맵 승인 후 별도 상세 계획으로 작성**한다. Plan 번호는 작성 시점 최대+1 재확인(현재 최대 61 → 63·64는 예약 제안일 뿐, 작성 시 빈 번호 확정).

## 8. 한 줄 권고

**노이즈·상관 완성(P1, 진행) → 진단·RCA(P2, 핵심) → 멀티소스 관측(P3, 확장) → 예측·자동복구(P4, 거버넌스)**.
