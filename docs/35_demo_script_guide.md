# 35. 시연 세션 실행기 가이드 (`scripts/demo` · D-326)

> 최종 갱신: 2026-10-13

이 실행기는 시연 세션을 **떠 있는 웹 서버**에 미리 질의해 둡니다. 시연할 때는 웹 화면의 대화 목록을 열어 결과를 보여 주면 됩니다.
남은 대화는 실제 대화이므로 그 자리에서 후속 질문을 이어 갈 수 있습니다.

## 1. `scripts.scenario`와의 차이

| | `scripts.scenario` (판정·측정) | `scripts.demo` (시연) |
|---|---|---|
| 서버 | 자식 서버를 직접 띄움 · 체크포인트를 런 전용 파일로 격리 | **이미 떠 있는 서버**에 질의 |
| 웹에서 이어 묻기 | 안 됨(본체 서버에 체크포인트가 없음) | 됨 |
| 판정 | 기대값 대조 · 리포트 | 없음 — 응답 요약·소요 시간만 |
| 카탈로그 | `testdata/scenarios/*.yaml` (폴스타 기능 회귀) | `testdata/demo/sessions.yaml` (기능·연동·복합 질의를 보여 주는 이야기) |
| 환경 값 | 시나리오에 고정 | `{{자리표}}` + 환경 값 파일 |

## 2. 빠른 시작 (로컬 샌드박스)

```bash
python -m src.main --server                                  # 1) 웹 서버 (다른 터미널)
python -m scripts.demo --list --core                         # 2) 핵심 세트와 채워진 질의 미리보기
python -m scripts.demo --core --user <ID> --password <PW>    # 3) 질의 — 같은 계정으로 웹에 로그인하면 대화 목록에 보인다
```

- 기본 환경 값 파일은 `testdata/demo/env.sandbox.yaml`입니다. 샌드박스의 합성 서버명(`svr-web-01` 등)과 지표가 있는 달(2026년 6월)이 들어 있습니다.
- `sources`에 없는 소스를 요구하는 세션은 사유를 출력하고 건너뜁니다. 예: 샌드박스에서는 `apm`·`docs`·`multi_zone`.
- **인증이 꺼진 서버**는 대화 이력을 브라우저 식별자로 묶습니다. 그래서 `--user` 대신 `--client-id`를 넘겨야 합니다.
  - 값은 시연할 브라우저의 개발자 도구 → Application → Local Storage → `query_client_id`에서 확인합니다.

## 3. 실제 데이터 입력 (폐쇄망 · 운영 데이터)

세션 질의는 서버명·기간처럼 환경마다 다른 값을 `{{server_db}}` 같은 자리표로 씁니다. 자리표 값은 환경 값 파일이 채웁니다.
apm_bench의 `--placeholders`와 같은 방식입니다. 커밋되는 파일에는 합성 값만 넣고, **운영 값 파일은 저장소 밖에** 둡니다.

### 3.1 절차

1. 템플릿을 저장소 밖으로 복사합니다.
   ```bash
   cp testdata/demo/env.closed.template.yaml C:/demo/env.closed.yaml
   ```
2. `sources`를 실제 연동 상태에 맞게 고칩니다(3.2). 연동이 없는 소스를 지우면 그 소스를 요구하는 세션이 빠집니다.
3. `values`를 채웁니다(3.3). 템플릿의 각 칸에 적힌 「찾는 법」대로 웹 화면에서 질의해 실제 값을 고릅니다.
4. 점검합니다. **「점검 통과」가 나올 때까지** 고칩니다. 빈 자리표·없는 업로드 파일·모르는 소스를 세션별로 알려 줍니다.
   ```bash
   python -m scripts.demo --check --env-file C:/demo/env.closed.yaml
   ```
5. 채워진 질의를 눈으로 확인합니다.
   ```bash
   python -m scripts.demo --list --env-file C:/demo/env.closed.yaml
   ```
6. 실행합니다. 시연 **전날 리허설**로 돌려 두는 것을 권합니다. 응답 시간과 결과 품질을 미리 보고 질의나 값을 고칠 수 있습니다.
   ```bash
   python -m scripts.demo --core --env-file C:/demo/env.closed.yaml --user <ID> --password <PW>
   ```

### 3.2 `sources` — 연동 소스 선언

| 소스 | 넣는 조건 | 이 소스가 필요한 세션 |
|---|---|---|
| `polestar` | 폴스타 DB가 하나라도 활성 | 대부분 |
| `multi_zone` | 은행존·공동존 김포/여의도가 모두 활성 | G5-3 존 선택 되묻기 |
| `itam` | 자산관리 DB가 `ACTIVE_DB_IDS`에 있음 | G2-1 · G3-1~3 · G3-5 |
| `prometheus` | 프로메테우스 연동 있음 | G2-2 · G3-4 |
| `apm` | `apm_gateway` 기동 + 제니퍼 연동 켜짐 | G2-3 · G3-5 |
| `docs` | 사내 문서 컬렉션 적재됨 | G2-4 |
| `sre_agent` | 장애 조사 프로세스 기동 | G8-3 |

- 실행 직전에 서버 `/health`의 DB 연결 상태와 대조합니다. `polestar`·`itam`을 선언했는데 연결돼 있지 않으면 경고를 냅니다.
- 비SQL 소스(`prometheus`·`apm`·`docs`)는 헬스로 확인할 수 없어 선언을 그대로 믿습니다.

### 3.3 `values` — 자리표와 고르는 기준

| 자리표 | 쓰는 세션 | 고르는 기준 (웹에서 확인하는 질의) |
|---|---|---|
| `server_db` | G1-2 | OS·IP·코어·메모리가 다 채워진 서버 — 「김포 DB 서버 목록 5건」 |
| `server_was` | G1-5 · G8-3 | 프로세스가 여러 개 보이는 서버 — 「김포 WAS 서버 목록 5건」 |
| `server_web` | G2-2 · G7-3 | 대표 서버 하나. 프로메테우스 세션을 쓰면 프로메테우스에도 있는 서버 |
| `server_prefix_web` | G3-4 | 5~20대가 걸리는 서버명 접두 |
| `server_group_a` · `server_group_b` | G4-1 | 응답이 깔끔하게 나뉘는 묶음 표현 두 개 (예: 「김포 서버」·「여의도 서버」) |
| `process_name` | G1-5 | 여러 서버에 떠 있는 프로세스 — 「`{{server_was}}` 서버의 프로세스 목록」 |
| `month` · `prev_month` | G1-3 · G4-2 · G4-3 · G6-2 | 지표 행이 있는 달 — 「지난달 서버별 CPU 사용률 평균 5건」이 행을 돌려주는지 |
| `alarm_period` | G1-4 | 알람 이력이 충분한 기간 표현 (기본 「최근 3개월」) |
| `zone_scope_text` · `zone_db_id` | G5-3 | 존을 말하지 않은 범위 표현 · 되묻기에 고를 db_id(`polestar_cm_gp` 등) |
| `form_scope` · `form_owner_answer` | G6 | 양식을 채울 대상 표현 · 담당자 열에 넣을 값 |
| `apm_instance` | G2-3 | 「제니퍼 WAS 인스턴스 목록」에 나온 이름 |
| `doc_question_1` · `_2` | G2-4 | 관리자 「문서 검색 시험」에서 결과가 나오는 질문 — `testdata/rag_gold/rag_gold_v1.yaml` 참고 |

**값을 고르는 원칙**
- 0건이 나오는 값은 쓰지 않습니다. 시연에서는 「없습니다」보다 결과 표가 설득력이 있습니다. 0건 안내는 G2-5·G4-6이 따로 보여 줍니다.
- 한 값이 여러 세션에 쓰입니다. 바꾼 뒤에는 `--list`로 그 값이 들어간 모든 질의를 다시 읽어 봅니다.

## 4. 실행 옵션

| 옵션 | 설명 |
|---|---|
| `--core` | 핵심 세트만 실행합니다(`core: true` · 군마다 1~3세션) |
| `--group G3` · `--only G3-1,G4-2` | 군·세션을 골라 실행합니다 |
| `--env-file` | 환경 값 파일 (기본: 샌드박스) |
| `--base-url` | 웹 서버 주소 (기본 `http://127.0.0.1:8000`) |
| `--user` · `--password` | 대화 이력을 남길 계정. 401이 나면 1회만 다시 로그인합니다(계정 잠금 방지) |
| `--client-id` | 인증이 꺼진 서버에서 이력을 붙일 브라우저 식별자 |
| `--clarify auto\|stop` | 예상하지 않은 역질문 처리. `auto`(기본)는 웹 칩 확인 버튼과 같은 구조화 답으로 자동 응답합니다. `stop`은 그 세션을 멈추고, 발표자가 웹에서 직접 답하도록 남깁니다 |
| `--admin-user` · `--admin-password` | 서버의 실효 LLM 프로바이더를 운영자 설정 API로 확인합니다. 없으면 로컬 `.env`로 판정합니다 |
| `--yes` | 과금 프로바이더 확인 프롬프트를 생략합니다 |
| `--list` · `--check` | 서버를 호출하지 않는 미리보기·점검입니다 |

**역질문 자동 응답 규칙**

| 역질문 | 자동 응답 |
|---|---|
| 존·범위 선택 | `zone_preference` 중 제시된 첫 존. 없으면 첫 선택지 |
| 소스 선택 | 제시된 소스 **전부** (교차 조회를 보여 주는 것이 목적) |
| 제니퍼 소스 선택 | `apm_source_preference` 중 제시된 첫 소스. 없으면 첫 선택지 |
| 양식 미해결 열 | 전부 비움 (후보를 임의로 고르면 오답이 채워짐) |
| SQL 승인 | 「승인」 |
| 선택지 없는 글 질문 | 답하지 않고 세션을 멈춤 (웹에서 답함) |

세션 턴에 `expect_clarify: true`를 두면 그 역질문에는 자동 응답하지 않습니다. 다음 턴(`selected_db_ids`·`form_fill_answers`)이 답합니다(G5-3 · G6-3).

## 5. 결과 확인

- **웹 화면**: 같은 계정 또는 같은 브라우저로 대화 목록을 엽니다. 세션 하나가 대화 1건입니다.
- **대화록**: `logs/demo/<실행시각>/transcript.md`. 군·세션별 질의와 응답 원문이 들어 있어 발표 자료나 리허설 검토에 씁니다.
- **원시 기록**: 같은 폴더의 `results.jsonl` (턴별 상태·소요 시간·행 수·오류)
- **양식 산출물**: 같은 폴더의 `files/`에 내려받습니다. 실패하면 웹 이력에서 받습니다.
- **종료 코드**: 0 = 전부 성공 · 1 = 준비 실패(점검·로그인·헬스) · 2 = 파일 형식 오류 · 3 = 오류 턴 있음

- 새 자리표는 두 환경 값 파일(`env.sandbox.yaml` · `env.closed.template.yaml`)에 모두 선언합니다. `tests/test_scripts/test_demo.py`가 이를 검사합니다.

## 7. 주의

- **과금**: 서버의 워커·오케스트레이터 중 하나라도 비과금 집합(`fabrix·ollama·mlx` / `vllm·mlx`) 밖이면 실행 전에 `yes` 입력을 받습니다. 판정 규칙은 `scripts.scenario.preflight.external_planes` 하나를 씁니다(D-222).
- **상태가 남는 세션**
  - G6-3: 양식 답이 그 양식 서명에 기억됩니다. 사용자 범위가 아니라 전역이며, 웹 「?」 저장 값 패널에서 지웁니다.
  - G8-1: 유사어가 등록됩니다. 관리자 화면 유사어 탭에서 지웁니다.
  - G8-2: 스키마 캐시를 갱신합니다.
- **오류가 난 턴**이 있으면 그 세션의 남은 턴은 건너뜁니다. 맥락이 끊긴 후속 질의는 시연에 쓸 수 없기 때문입니다.
- **소요 시간**: 로컬 MLX는 1턴에 수 분이 걸릴 수 있습니다. 시연 당일 라이브로 돌리지 말고, 전날 돌려 둔 이력을 보여 주는 것이 기본입니다.
