# 35. 시연 세션 실행기 가이드 (`scripts/demo` · D-326)

> 최종 갱신: 2026-10-14 — 카탈로그를 장애 대응 시스템 연계(은행존 기준)로 교체

이 실행기는 시연 세션을 **떠 있는 웹 서버**에 미리 질의해 둡니다. 시연할 때는 웹 화면의 대화 목록을 열어 결과를 보여 주면 됩니다.
남은 대화는 실제 대화이므로 그 자리에서 후속 질문을 이어 갈 수 있습니다.

## 1. `scripts.scenario`와의 차이

| | `scripts.scenario` (판정·측정) | `scripts.demo` (시연) |
|---|---|---|
| 서버 | 자식 서버를 직접 띄움 · 체크포인트를 런 전용 파일로 격리 | **이미 떠 있는 서버**에 질의 |
| 웹에서 이어 묻기 | 안 됨(본체 서버에 체크포인트가 없음) | 됨 |
| 판정 | 기대값 대조 · 리포트 | 없음 — 응답 요약·소요 시간만 |
| 카탈로그 | `testdata/scenarios/*.yaml` (폴스타 기능 회귀) | `testdata/demo/sessions.yaml` (장애 대응 흐름을 따라 폴스타·제니퍼·자산관리를 잇는 이야기) |
| 환경 값 | 시나리오에 고정 | `{{자리표}}` + 환경 값 파일 |

## 2. 빠른 시작 (로컬 샌드박스)

```bash
python -m src.main --server                                  # 1) 웹 서버 (다른 터미널)
python -m scripts.demo --list --core                         # 2) 핵심 세트와 채워진 질의 미리보기
python -m scripts.demo --core --user <ID> --password <PW>    # 3) 질의 — 같은 계정으로 웹에 로그인하면 대화 목록에 보인다
```

- 기본 환경 값 파일은 `testdata/demo/env.sandbox.yaml`입니다. 샌드박스의 합성 서버명(`svr-web-01` 등)이 들어 있습니다.
- `sources`에 없는 소스를 요구하는 세션은 사유를 출력하고 건너뜁니다. 샌드박스에는 제니퍼가 없어 A·B·E군은 빠지고 C·D군만 돕니다.
- **인증이 꺼진 서버**는 대화 이력을 브라우저 식별자로 묶습니다. 그래서 `--user` 대신 `--client-id`를 넘겨야 합니다.
  - 값은 시연할 브라우저의 개발자 도구 → Application → Local Storage → `query_client_id`에서 확인합니다.

## 3. 실제 데이터 입력 (폐쇄망 · 운영 데이터)

세션 질의는 서버명·기간처럼 환경마다 다른 값을 `{{was_host}}` 같은 자리표로 씁니다. 자리표 값은 환경 값 파일이 채웁니다.
apm_bench의 `--placeholders`와 같은 방식입니다. 커밋되는 파일에는 합성 값만 넣고, **운영 값 파일은 저장소 밖에** 둡니다.

### 3.1 절차

1. 템플릿을 저장소 밖으로 복사합니다.
   ```bash
   cp testdata/demo/env.closed.template.yaml C:/demo/env.closed.yaml
   ```
2. `sources`를 실제 연동 상태에 맞게 고칩니다(3.2). 연동이 없는 소스를 지우면 그 소스를 요구하는 세션이 빠집니다.
3. `values`를 채웁니다(3.3). 템플릿의 각 칸에 적힌 「찾는 법」대로 웹 화면에서 질의해 실제 값을 고릅니다.
4. 점검합니다. **「점검 통과」가 나올 때까지** 고칩니다. 빈 자리표·없는 업로드 파일·모르는 소스를 세션별로 알려 줍니다.
   ```bash
   python -m scripts.demo --check --env-file C:/demo/env.closed.yaml
   ```
5. 채워진 질의를 눈으로 확인합니다.
   ```bash
   python -m scripts.demo --list --env-file C:/demo/env.closed.yaml
   ```
6. 실행합니다. 시연 **전날 리허설**로 돌려 두는 것을 권합니다. 응답 시간과 결과 품질을 미리 보고 질의나 값을 고칠 수 있습니다.
   ```bash
   python -m scripts.demo --core --env-file C:/demo/env.closed.yaml --user <ID> --password <PW>
   ```

### 3.2 `sources` — 연동 소스 선언

| 소스 | 넣는 조건 | 이 소스가 필요한 세션 |
|---|---|---|
| `polestar` | 폴스타 DB가 하나라도 활성 (은행존 기준이면 `polestar_b0`) | A · B · C · E |
| `apm` | `apm_gateway` 기동 + 제니퍼 연동 켜짐 (은행 소스 `b0`) | A · B · E |
| `itam` | 자산관리 DB가 `ACTIVE_DB_IDS`에 있음 | C · D · E |

나머지 소스 어휘(`multi_zone`·`prometheus`·`docs`·`sre_agent`)는 지금 카탈로그에서 쓰지 않습니다.

- 실행 직전에 서버 `/health`의 DB 연결 상태와 대조합니다. `polestar`·`itam`을 선언했는데 연결돼 있지 않으면 경고를 냅니다.
- 비SQL 소스(`prometheus`·`apm`·`docs`)는 헬스로 확인할 수 없어 선언을 그대로 믿습니다.

### 3.3 `values` — 자리표와 고르는 기준

| 자리표 | 쓰는 세션 | 고르는 기준 (웹에서 확인하는 질의) |
|---|---|---|
| `polestar_name` · `apm_name` · `asset_name` | 전부 | 질의에 넣는 소스 이름. 은행존 기준 `은행 폴스타` · `은행 제니퍼` · `자산관리` — 레지스트리 별칭이라 존·소스가 결정적으로 고정됩니다 |
| `apm_instance` | A1 | 「은행 제니퍼 WAS 인스턴스 목록과 호스트네임 보여줘」에서 **호스트네임이 채워진** 인스턴스. 트래픽이 있어야 지표가 풍부합니다 |
| `was_host` | A1 · E1 | `apm_instance`의 호스트네임(OS 호스트명 그대로). 은행 폴스타·자산관리에서도 행이 나와야 합니다 |
| `was_hosts` | B | 은행 제니퍼 호스트 3~5개(쉼표 구분 · 폴스타 표기). 폴스타 전체 순위·알람에서 출발하면 제니퍼가 없는 서버가 대부분이라 다음 턴이 비므로 대상을 제니퍼 호스트로 한정합니다 |
| `phys_host` | C1 · C2 | **물리 서버**. 자산관리 유지보수 계약·지원 종료(EOS)는 물리 서버에만 있습니다(VM은 개별 유지보수 없음). 은행 폴스타에도 있어야 합니다 |
| `incident_window` | A | 제니퍼 구간(분 단위 데이터 — 「최근 1시간」 등) |
| `metric_window` | A1 · B1 · C1 · E1 | 폴스타 지표 구간. 성능 통계가 시간 단위 집계라 짧은 창은 비거나 적재 지연이 있습니다 (예: 「오늘」) |
| `alarm_period` | C1 | 알람 이력 기간 (기본 「최근 7일」) |
| `eos_window` | D1 | 「지원 종료가 N 안에 도래하는 서버」가 몇~수십 대인 범위 |
| `maint_window` | D2 | 「N 안에 유지보수 계약이 끝나는 서버」가 몇~수십 대인 범위 (은행존 3개월 = 0건 · 6개월 권장 — 2026-10-15) |

**값을 고르는 원칙**
- 0건이 나오는 값은 쓰지 않습니다. 시연에서는 「없습니다」보다 결과 표가 설득력이 있습니다. 특히 B1(지금 발생 중인 심각 알람)은 시연 시각의 실제 발생 여부에 달려 있습니다.
- 한 값이 여러 세션에 쓰입니다. 바꾼 뒤에는 `--list`로 그 값이 들어간 모든 질의를 다시 읽어 봅니다.

## 4. 실행 옵션

| 옵션 | 설명 |
|---|---|
| `--core` | 핵심 세트만 실행합니다(`core: true` · 군마다 1~3세션) |
| `--group A` · `--only A1,C1` | 군·세션을 골라 실행합니다 |
| `--env-file` | 환경 값 파일 (기본: 샌드박스) |
| `--base-url` | 웹 서버 주소 (기본 `http://127.0.0.1:8000`) |
| `--user` · `--password` | 대화 이력을 남길 계정. 401이 나면 1회만 다시 로그인합니다(계정 잠금 방지) |
| `--client-id` | 인증이 꺼진 서버에서 이력을 붙일 브라우저 식별자 |
| `--clarify auto\|stop` | 예상하지 않은 역질문 처리. `auto`(기본)는 웹 칩 확인 버튼과 같은 구조화 답으로 자동 응답합니다. `stop`은 그 세션을 멈추고, 발표자가 웹에서 직접 답하도록 남깁니다 |
| `--admin-user` · `--admin-password` | 서버의 실효 LLM 프로바이더를 운영자 설정 API로 확인합니다. 없으면 로컬 `.env`로 판정합니다 |
| `--yes` | 과금 프로바이더 확인 프롬프트를 생략합니다 |
| `--list` · `--check` | 서버를 호출하지 않는 미리보기·점검입니다 |

**역질문 자동 응답 규칙**

| 역질문 | 자동 응답 |
|---|---|
| 존·범위 선택 | `zone_preference` 중 제시된 첫 존. 없으면 첫 선택지 |
| 소스 선택 | 제시된 소스 **전부** (교차 조회를 보여 주는 것이 목적) |
| 제니퍼 소스 선택 | `apm_source_preference` 중 제시된 첫 소스. 없으면 첫 선택지 |
| 양식 미해결 열 | 전부 비움 (후보를 임의로 고르면 오답이 채워짐) |
| SQL 승인 | 「승인」 |
| 선택지 없는 글 질문 | 답하지 않고 세션을 멈춤 (웹에서 답함) |

세션 턴에 `expect_clarify: true`를 두면 그 역질문에는 자동 응답하지 않습니다. 다음 턴(`selected_db_ids`·`form_fill_answers`)이 답합니다(지금 카탈로그에는 해당 턴이 없습니다).

## 5. 결과 확인

- **웹 화면**: 같은 계정 또는 같은 브라우저로 대화 목록을 엽니다. 세션 하나가 대화 1건입니다.
- **대화록**: `logs/demo/<실행시각>/transcript.md`. 군·세션별 질의와 응답 원문이 들어 있어 발표 자료나 리허설 검토에 씁니다.
- **원시 기록**: 같은 폴더의 `results.jsonl` (턴별 상태·소요 시간·행 수·오류)
- **양식 산출물**: 같은 폴더의 `files/`에 내려받습니다. 실패하면 웹 이력에서 받습니다.
- **종료 코드**: 0 = 전부 성공 · 1 = 준비 실패(점검·로그인·헬스) · 2 = 파일 형식 오류 · 3 = 오류 턴 있음

## 6. 세션 카탈로그 — 장애 대응 시스템 연계 (은행존 기준)

**질의 작성 원칙** (폐쇄망 LLM temperature가 0이 아니라는 전제로 코드 검토 — 2026-10-14)
1. 모든 턴에 소스 이름을 씁니다(「은행 제니퍼」·「은행 폴스타」·「자산관리」 — 결정적 소스 고정).
2. 폴스타·자산관리로 가는 턴은 **서버명을 직접 지목**합니다. 「그 서버(들)」를 폴스타·자산관리 SQL로 넘기는 경로는 LLM 재작성에 의존하고, 여러 대 + 알람이면 서버 조건이 빠질 수 있습니다.
3. 「그 서버들」은 **제니퍼로 가는 턴에만** 씁니다(★). 앞 턴 결과의 hostname(폴스타 등록명이면 hostname으로 변환)을 제니퍼 대상 해석이 결정적으로 이어받습니다. 앞 턴 결과는 20행 이하로 둡니다. **제니퍼 결과를 다시 「그 서버들」로 잇지 않습니다** — 소스 이름을 쓰면 제니퍼 직전 대상 승계(D-334)가 꺼지고, 제니퍼 결과 행은 식별 칸이 많아 직전 엔티티 상한(20개)을 몇 행 만에 채워 뒤쪽 서버가 말없이 빠집니다. 제니퍼에서 볼 것은 「그 서버들」 턴 하나에 묶습니다.
4. 한 시스템 결과를 다른 시스템으로 넘기는 한 문장 복합(연결형)은 쓰지 않습니다(분해·연결이 LLM 몫 · 폴스타 hostname 정확 일치). E1처럼 같은 서버명을 각 시스템에 따로 묻는 병렬 복합만 씁니다.
5. 알람은 「지금 발생 중인」(활성)과 「기간」(이력) 중 하나만 묻습니다.
6. 「OS 정보」·「자원 현황」·「사용률 추세」·「실시간 지표」 표현은 쓰지 않습니다. 호스트 조사 플래그가 켜진 서버에서는 MCP 조사 도구로 가는데, 그 도구는 은행존에서 파일시스템·hostname 지목이 0건입니다.
7. **한 대화 안에서 폴스타 ↔ 자산관리를 오가지 않습니다.** 폴스타 턴 뒤에 자산관리를 지목해도 분류가 고른 폴스타 DB가 함께 조회돼 자산관리 칸이 비어 보입니다(2026-10-15 폐쇄망 C1 · `plans/165` F5). 시스템을 바꿀 때는 새 대화로 엽니다(C1 → C2).
