## 0. 배경과 승인 방법

P3-1은 **동작 불변**이 조건이었다. 준-동일 블록을 공유 빌더(`src/nodes/prompt_blocks.py`)로 합치되 경로별 문구는 통일하지 않고 빌더 **파라미터**로 보존했다. 그 결과 프롬프트 sha256 스냅샷 12키가 무갱신 통과했고, 스냅샷이 안 덮는 경로도 클린 HEAD 대비 23키가 바이트 동일이다.

따라서 **지금 남아 있는 경로별 문구 차이 = 아래 표가 전부**다. 각 건을 승인하면 프롬프트 바이트가 바뀌므로, 승인분만 별도 커밋으로 적용하고 sha256 스냅샷을 사유와 함께 갱신한다.

승인 표기는 각 항목의 「채택안」에 대해 **채택 / 반려 / 보류** 중 하나를 적어 주면 된다.

| 구분 | 건수 | 성격 |
|---|---|---|
| §1 파라미터 보존 차이 | 8건 | 통일 시 프롬프트 바이트 변경 |
| §2 통합 보류 블록 | 1건 | 문구 통일과 통합을 함께 결정해야 함 |
| §3 실동작 비대칭 | 1건 | 문구가 아니라 필터링 동작 차이 |
| 부록 | 4건 | 통합 대상 밖(경로 전용 블록) — 참고용 |

### W-1. 금지 JOIN 컬럼 경고 문구

단일 (`style="section"`):
```
[금지 JOIN 컬럼]
다음 컬럼은 JOIN ON 절에서 절대 사용하지 마세요:
- cmm_resource.resource_conf_id: 운영 DB에서 NULL
```
멀티 (`style="inline"`):
```
[금지] cmm_resource.resource_conf_id는 JOIN ON 절에서 사용할 수 없습니다: 운영 DB에서 NULL
```

- 전달 정보(테이블·컬럼·사유)는 동일하고 표현만 다르다.
- **채택안: 단일(section)로 통일.** 근거 — 소제목+불릿이 독립 규칙 블록으로 읽혀 지시 준수에 유리하고, 멀티의 inline 한 줄은 구조 가이드 본문 흐름에 섞여 묻힌다. 금지 컬럼이 여러 건이면 차이가 더 커진다.
- 영향: 멀티 시스템 프롬프트 바이트 변경(폴스타 프로필에 `excluded_join_columns`가 선언된 DB만).

### W-2. EAV 피벗 alias 지시 — **통일하지 않음**

단일 (`hangul_alias=False`):
```
위 EAV 속성은 core_config_prop 테이블에서 피벗 쿼리로 추출해야 합니다:
  MAX(CASE WHEN p.name = '속성명' THEN p.stringvalue_short END) AS alias
```
멀티 (`hangul_alias=True`):
```
위 EAV 속성은 core_config_prop 테이블에서 피벗 쿼리로 추출해야 합니다.
**결과 alias는 반드시 양식 필드명(왼쪽 한글, 따옴표 포함) 그대로** 하세요(임의 영문 alias 금지 — 결과 컬럼명이 양식 헤더와 일치해야 채워집니다):
  MAX(CASE WHEN p.name = '속성명' THEN p.stringvalue_short END) AS "양식필드명"
```

- **채택안: 현행 유지(통일 금지).** 계획서 §0.3-3 (e)가 명시한 **의도된 차이**다. 멀티는 여러 DB 결과를 하나의 양식으로 병합하므로 결과 컬럼명이 양식 헤더와 정확히 일치해야 `excel_writer`가 채운다(D-066 후속4·5). 단일은 단일 DB 결과라 그 제약이 없고, 오히려 `"테이블명.컬럼명"` alias 규약을 쓴다(부록 A-3 참조).
- 코드에도 양쪽 호출부에 "의도된 차이 — 통일 금지" 주석을 남겨 두었다.

### W-3~W-5. 스키마 텍스트 표기

단일(상세):
```
### t
  - c: int NOT NULL
  샘플 데이터 (2건):
[ … ]

### 테이블 관계 (FK)
  a.b -> c.d
```
멀티(축약):
```
### t
  - c: int
  sample: [ … ]

### FK Relationships
  a.b -> c.d
```

- **W-3(NOT NULL) 채택안: 단일 채택.** NOT NULL은 LLM이 조인 방향·널 처리(COALESCE 필요 여부)를 판단하는 재료이고, 토큰 비용은 컬럼당 몇 자에 불과하다. 멀티만 이 정보를 못 받을 근거가 없다.
- **W-4(샘플 표기) 채택안: 단일 채택.** 프롬프트 나머지가 전부 한국어인데 `sample:`만 영문이고, 건수(N건)는 샘플의 대표성을 판단하는 재료다.
- **W-5(FK 헤더) 채택안: 단일 채택.** 기능 차이 0, 영문/한국어 혼재만 제거하는 가장 안전한 건이다.
- 영향: 세 건 모두 멀티 시스템 프롬프트 바이트 변경. 셋을 한 커밋으로 묶어도 무방하다.

### W-6. 컬럼 설명·유사어·RESOURCE_TYPE/EAV 참조 섹션

단일만 수록한다. 멀티가 미수록인 이유는 문구 취향이 아니라 **재료가 없어서**다 — 단일은 `state`에 실린 `column_descriptions`/`column_synonyms`/`resource_type_synonyms`/`eav_name_synonyms`를 넘기지만, 멀티 경로는 그 값들을 state에 갖고 있지 않다.

- **채택안: 문구 통일 건에서 분리하고 별건으로 다룬다.** 통일하려면 멀티가 DB별 유사어·설명을 캐시에서 조회해야 하고(이미 stepwise 재료 조립이 `cache_manager.get_synonyms(db_id)`로 같은 일을 한다), 이는 프롬프트 문구 승인이 아니라 **재료 조달 배선** 작업이다. 프롬프트 길이(멀티는 DB 수만큼 배수)도 함께 봐야 한다.
- 우선순위 제안: W-1·W-3~W-5·W-8 적용 후, 멀티 프롬프트 길이 실측을 보고 판단.

### W-7. 필터링 경고 로그 문구

단일: `column_mapping 필터링: '필드' -> '컬럼' (테이블 'X' 미존재, schema_tables=['a','b',…])`
멀티: `multi_db column_mapping 필터링: '필드' -> '컬럼' (테이블 'X' 미존재)`

- 프롬프트가 아니라 **운영 로그**다. 승인해도 LLM 출력 분포에 영향이 없다.
- **채택안: 단일 채택(멀티에도 `schema_tables=` 부기).** 0건 원인 추적 시 "어떤 테이블 목록과 대조해 버려졌는지"가 곧바로 보인다. 경로 구분 접두(`multi_db`)는 유지한다.

### W-8. EAV 조인 규칙 삽입 게이트 — 결함 성격

| 경로 | 조건 | 결과 |
|---|---|---|
| 단일 | `if eav_patterns:` | EAV 패턴이 있으면 항상 삽입 |
| 멀티 | `if eav_patterns and structure_guide:` | 프로필 `query_guide`가 **빈 문자열이면 규칙이 통째로 누락** |

- 이것은 P0-③에서 고친 결함(`query_guide` 빈 프로필에서 EAV 조인 규칙 통째 누락)과 **동일한 버그가 멀티 경로에 그대로 남아 있는 것**이다. P0-③ 수정이 단일에만 적용됐다.
- **채택안: 단일 채택(멀티 게이트를 `if eav_patterns:`로).** 조인 규칙 자체는 `query_guide` 유무와 무관하게 유효하다. 규칙이 빠지면 LLM이 entity↔config를 id로 직접 조인해 0건이 난다(D-066 계열 실측 사고 유형).
- 영향: `query_guide`가 빈 프로필을 쓰는 DB의 멀티 프롬프트만 바뀐다. 실측상 폴스타 프로필(`polestar_cm_gp`)의 `query_guide`는 6,641자로 비어 있지 않으므로 **현행 폴스타 경로는 바이트 무변경**이다(적용 시 sha256으로 재확인).
- 현행 코드 위치: 단일 `query_generator.py:109` / 멀티 `multi_db_executor.py:560`

## 2. 통합 보류 — 「자동 매핑 실패 필드」 블록 전문 대조

P3-1에서 유일하게 공유 빌더로 합치지 못한 블록이다. 헤더와 캐스트 예시 줄만 같고 나머지 세 문장이 모두 다르며, 양쪽 문구에 폴스타 스키마 리터럴이 박혀 있어 공용 모듈로 옮기면 D-088/overfit 기준선을 위반한다.

### 단일 (`query_generator.py:896-903`)

```
## 자동 매핑 실패 필드 (스키마에서 직접 조회 필요)
아래 양식 필드들은 자동 매핑에 실패했습니다. 스키마와 사용자 질의를 참고하여 적절한 DB 컬럼 또는 계산식으로 반드시 SELECT에 포함하세요.
**중요**: 각 필드명을 그대로 SQL alias로 사용하세요 (따옴표 포함).
예: {decimal_cast_example(db_engine)}
CPU/메모리/디스크 사용률·통계 관련 필드는 cmm_metric_stat_[h,d,m] 테이블을 활용하고, Template B 패턴을 따르세요:
- "메모리 최고"
```

### 멀티 (`multi_db_executor.py:801-810`)

```
## 자동 매핑 실패 필드 (스키마에서 직접 조회 필요)
아래 양식 필드들은 자동 매핑에 실패했습니다. 스키마와 **위 쿼리 예시**를 참고하여 적절한 DB 컬럼 또는 계산식으로 반드시 SELECT에 포함하세요.
**중요**: 각 필드명을 그대로(따옴표 포함) SQL alias로 사용하세요 — 결과 컬럼명이 양식 헤더와 정확히 일치해야 값이 채워집니다.
예: {decimal_cast_example(db_engine)}
CPU/메모리 사용률(평균/최고) 등 성능 지표는 위 쿼리 예시의 cmm_metric_stat_m 피벗(resource_type + definition_name='Utilization', avg_val/max_val)을 그대로 따르되, **결과 alias는 아래 한글 필드명으로** 하세요(임의 영문명 금지):
- "메모리 최고"
```

### 문장별 대조와 채택안

| 문장 | 단일 | 멀티 | 채택안 | 근거 |
|---|---|---|---|---|
| ① 헤더 | 동일 | 동일 | 그대로 | — |
| ② 참고 대상 | "스키마와 **사용자 질의**를 참고" | "스키마와 **위 쿼리 예시**를 참고" | **멀티 채택** | few-shot 예시 재사용을 유도하는 편이 조인 환각을 줄인다(RC1/D-066에서 멀티에 예시를 주입한 이유와 같은 취지). 사용자 질의는 이미 프롬프트 최상단에 있다 |
| ③ alias 지시 | "그대로 SQL alias로 사용하세요 (따옴표 포함)" | "그대로(따옴표 포함) … — 결과 컬럼명이 양식 헤더와 정확히 일치해야 값이 채워집니다" | **멀티 채택** | 같은 지시에 **이유**를 덧붙인 형태다. 이유가 붙은 지시가 LLM 준수율이 높고, 단일도 폼필 채우기 경로라 이유가 그대로 성립한다 |
| ④ 캐스트 예시 | 동일(`decimal_cast_example`) | 동일 | 그대로 | — |
| ⑤ 지표 안내 | "cmm_metric_stat_[h,d,m] 테이블을 활용하고, **Template B 패턴**을 따르세요" | "위 쿼리 예시의 cmm_metric_stat_m 피벗(resource_type + definition_name='Utilization', avg_val/max_val)을 그대로 따르되…" | **멀티 채택** | ⓐ **`Template B`는 단일 프롬프트에서 미정의 참조다** — 실측상 그 이름은 폴스타 어댑터 프롬프트(`db_adapters/polestar/prompts.py:177`)에만 정의돼 있어, 어댑터 템플릿이 아닌 공통 템플릿을 쓰는 DB에서는 LLM이 해석할 수 없다 ⓑ 멀티 문구는 테이블·피벗 키를 명시해 자립적이다 ⓒ `_[h,d,m]` 열거는 시간·일 테이블 오선택을 유발한다 |
| ⑤ 끝 alias 강제 | 없음 | "**결과 alias는 아래 한글 필드명으로** 하세요(임의 영문명 금지)" | **경로별 유지**(W-2와 동일 정책) | 한글 alias 강제는 멀티 전용 의도(§0.3-3 (e)) |

### 통합 가능성

위 채택안대로 하면 **⑤의 마지막 alias 강제 문장만 경로별로 갈리고 나머지는 동일**해진다. 즉 `hangul_alias` 파라미터 하나를 받는 공유 빌더 `build_unmapped_fields_block(...)`으로 합칠 수 있어, **문구 승인과 동시에 보류가 해소된다.**

폴스타 리터럴(`cmm_metric_stat_m`·`resource_type`·`definition_name`·`avg_val`/`max_val`)은 다른 빌더와 같은 방식으로 호출부 상수에서 인자 주입한다(D-088 준수, overfit 기준선 유지).

- **채택안 요약: ②③⑤를 멀티 문구로 통일 + alias 강제만 파라미터 분기 → 공유 빌더로 통합.**
- 영향: **단일** 경로 사용자 프롬프트 바이트 변경(미매핑 필드가 있는 폼필 질의에 한정).

## 3. `strip_db_prefix` 비대칭 (문구 아님 · 실동작)

`column_mapping` 값에서 테이블 존재를 판정하기 전에 `db_id:` 접두사를 떼는지가 경로별로 다르다.

| 경로 | 동작 | `"polestar_gp:cmm_resource.name"` 처리 |
|---|---|---|
| 단일 (`strip_db_prefix=True`) | 콜론 앞을 떼고 판정 | 테이블 `cmm_resource` 매칭 → **유지** |
| 멀티 (`strip_db_prefix=False`) | 통째로 `.`으로 분해 | 테이블명이 `polestar_gp:cmm_resource` → 미존재 → **폐기** |

### 실측: 현재 이 차이는 발현되지 않는다

`src/document/field_mapper.py`를 추적한 결과, 콜론 표기는 **LLM 프롬프트에 제시하는 키 형식일 뿐**이고 매핑 결과로 저장될 때 접두사가 제거된다:

- `field_mapper.py:963` — LLM에 주는 유사어 키를 `f"{db_id}:{col_key}"`로 만든다
- `field_mapper.py:1037-1042` — LLM 응답이 콜론 표기면 `parts = matched_key.split(":", 1)` 후 **`column = parts[1]`만** `db_column_mapping[db_id][field]`에 저장한다
- `field_mapper.py:432-434` — 통합 뷰 `column_mapping`도 그 값을 그대로 복사한다

즉 두 경로 어느 쪽도 콜론 표기를 받지 않는다. 남은 유입 경로는 외부 힌트(`hint["column"]`에 콜론을 넣는 API 호출)뿐이다.

> 초기 보고에서 이 건을 "멀티 쪽 버그로 보인다"고 전달했으나, 위 추적 결과 **현행 미발현(latent)** 으로 정정한다.

- **채택안: 단일 동작으로 통일(양쪽 `strip_db_prefix=True` 상당).** 근거 — 오늘은 무해하지만 갈라져 있을 이유도 없고, 관대한 쪽(단일)이 외부 힌트 유입 시 침묵 폐기를 막는다. 프롬프트 바이트 무변경(현행 입력에서 결과가 같으므로).
- 대안(반려 시): 양쪽에서 콜론 처리 자체를 죽은 코드로 보고 제거. 다만 외부 힌트 경로가 열려 있어 권하지 않는다.
- 우선순위: 낮음(미발현).
